# GitHubConnection V1.0.0 GitHub 连接模块

> 日期：2026-08-01  
> 状态：实施完成，Debug/Release 与独立 Smoke 通过；待 OHS 2.8.3 部署后同步验收  
> 宿主版本：OneHistoryStudio 2.8.3 / OneHistory.AppShell.Core 3.0.3

## 目标

GitHubConnection 1.0.0 接管原 OneHistoryStudio 内置的 GitHub/GCM/SSH 连接治理，并作为 Studio 工具箱中的独立
WPF 模块发布。模块由 OHS 的工具清单发现、同步到独立模块槽并热加载；模块源码、测试、文档和正式产物均归属于
`2026-019-Studio工具箱`，OHS 不保留实现副本或薄适配层。

模块面向服务器管理员。它读取服务器本机 Git、Git Credential Manager、SSH 和 origin 事实，并允许管理员在明确确认后
登录 GCM、注销凭据账号、修改提交身份或修改 origin。客户端角色不加载该 UI，也不持有服务器凭据治理入口。

## 仓库路径解析

生产解析器每次执行前读取：

```text
%APPDATA%\OneHistoryStudio\settings.json
```

只读取字符串键 `proj.barerepo`，不写入或格式化 OHS 配置。解析顺序固定为：

1. 文件存在、JSON 有效且 `proj.barerepo` 是非空绝对路径时使用该值；
2. 文件缺失、共享读取失败、JSON 损坏、键缺失或值不是绝对路径时，回退到
   `C:\OneHistory\OneHistory-Projects\OneHistory-Projects.git`；
3. 实际执行 Git 前检查目标目录；目录不存在时返回可诊断失败，不自动创建、初始化或切换仓库。

读取使用允许其他进程读写的共享方式，防止与 OHS 设置保存发生锁冲突。路径解析器接受可注入的设置路径和默认路径，
测试不得读取或修改真实 `%APPDATA%`。

## 服务能力

从 OHS 迁入并改为 `GitHubConnection` 命名空间的能力包括：

- Git、GCM 和可选 `gh` CLI 版本检测；
- 有效 `user.name/user.email` 及来源读取；
- origin fetch/push URL、传输类型、主机、owner 和 repository 解析；
- GCM GitHub HTTPS 账号枚举、登录和注销；
- SSH 公钥文件、算法和 SHA-256 指纹读取；
- SSH/HTTPS 连接检测、超时、取消和失败分类；
- 提交身份和 origin 的预览、应用与失败回滚；
- token、userinfo、query secret、凭据和敏感远端 URL 的统一脱敏。

模块继续使用无 Shell 的参数化进程启动，不拼接命令行字符串。进程超时后终止完整进程树并回收输出；所有返回 UI、日志、
命令和异常的文本必须先经过 `GitHubRedactor`。模块不保存 token、密码、私钥或 GitHub 会话，凭据仍由 GCM/SSH 管理。

## 命令合同

模块只公开三条只读命令，方法名使用小写以生成稳定地址：

```text
github.status
github.accounts
github.test transport=auto timeout=15
```

三种方法均标记 `[ModuleCommand(Readonly = true)]`：

- `status` 返回 Git/GCM/gh、提交身份、origin、凭据账号、SSH 公钥和最后检查时间；
- `accounts` 返回已脱敏的 GCM GitHub HTTPS 账号列表；
- `test` 支持 `auto|ssh|https`，超时限制为 1 至 120 秒，返回逐步诊断和最终状态。

模块不得注册 `github.login/logout/identity/remote`，也不得用其他名称重新暴露同等修改能力。manifest 使用
`mcpExposure=readonly`，因此三条只读命令可按当前 readonly/standard 策略投影；任何修改方法都不进入 CommandRegistry、
Web、MCP、Help 或命令手册。

## 内嵌界面

`GitHubConnectionUiModule` 实现 `IUiModule` 和 `IShellUiAware`，只通过 `IShellUiRegistrar` 注册工具窗口：

- ID：`github.account`；
- 标题：`GitHub 连接`；
- 默认位置：`DockSide.Right`；
- 默认比例：`0.38`；
- 单例：`true`；
- 内容：`GitHubConnectionView`。

模块不创建独立顶层 `Window`，不直接引用 AvalonDock，也不修改全局布局。沿用 `github.account` 使 OHS 2.8.2 已保存的
窗口位置在模块注册后继续生效。`DestroyUi` 必须释放注册句柄和事件订阅，支持热重载及可回收 ALC。

页面保留状态、账号、公钥、诊断、提交身份和 origin 编辑区。只读刷新和连接检测可直接调用共享服务。四类修改动作固定为：

- GCM 登录：显示本机确认后启动登录流程；
- GCM 注销：必须选择账号并显示账号名确认；
- 身份修改：先展示 repository/global 作用域、旧值和目标值预览，再确认应用；
- origin 修改：先展示 fetch/push 旧值和目标值预览，再确认应用。

取消确认时不启动外部进程、不写 Git 配置。应用失败时页面保留错误和当前输入，不伪报成功；成功后只刷新一次事实。忙碌期间
禁用重复操作。所有消息均显示脱敏结果。

修改能力只由前端 UI 类型持有；服务宿主虽然加载同一程序集以注册三条只读命令，但 `MainClassType` 无法到达修改方法，
从结构上替代原 OHS 的命令来源检查。

## 正式消费区

`z-GitHubConnection` 是自包含的最新正式版本，不引用 `b-Code-GitHubConnection/bin/Release`。manifest 固定为：

```json
{
  "name": "GitHubConnection",
  "version": "1.0.0",
  "description": "服务器本机 GitHub、GCM、SSH 和 origin 连接治理",
  "artifact": "z-GitHubConnection/GitHubConnection.dll",
  "docs": "z-GitHubConnection/GitHubConnection.xml",
  "mcpExposure": "readonly",
  "ui": true
}
```

Release 构建和 Smoke 全绿后，才允许把同一次构建产生的 DLL/XML 连同 manifest 原子提升到 z 目录。z 目录只保存最新正式版，
不保存候选、历史构建、PDB、AppShell DLL、测试程序集或 `bin/obj`。OHS `tool.sync` 只能从该 z 目录消费正式产物。
