# OneHistory 公共文档区

这里是 **跨项目** 的公共文档区，由 HistoryDiana 托管，供 AI 与人类在任何一个
HistoryXX 项目里查同一份事实。

Diana 自身的项目合同不在这里，在 [`../b-Office-Diana/`](../b-Office-Diana/)。
两者分开的原因：本目录被别的项目消费，Diana 自己的合同只描述 Diana。

## 读取顺序

1. [`定义/OneHistory总览.md`](./定义/OneHistory总览.md) —— 先搞清楚「项目库/ 宿主 /
   模块 / 工作区 / 消费区」这些词各指什么。不清楚这层，后面所有路径和命名都会误读。
2. [`定义/目录与命名规范.md`](./定义/目录与命名规范.md) —— 目录前缀、编号分支、
   指令命名、版本源的跨项目约定。
3. [`消费文档索引.md`](./消费文档索引.md) —— 要接入某个模块时，从这里跳到该模块
   自己仓库里的权威消费文档。

## 一条硬规矩：这里不放副本

消费文档的**唯一权威源永远在各自仓库**（`<项目>/b-Office/package/`）。
本目录只保存**索引**和**跨项目定义**，不保存任何一份消费文档的复制件。

理由是这一整套体系里反复出问题的都是同一件事——同一个事实存了多份，改了一处忘了另一处。
已经踩过的坑：宿主契约版本曾硬编码在 6 处、Mercury 版本存在 3 处（漏改一处直接导致
整个模块静默不装载）、Janus 技术合同停在 3.3.0 落后三个版本。
把 20 份消费文档复制进来，等于再造一批同样的坑。

需要"在一个地方看全部"时，用索引跳转；需要离线快照时，由发布脚本生成，
不手工维护。
