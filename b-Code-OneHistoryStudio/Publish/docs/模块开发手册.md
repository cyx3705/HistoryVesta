# 模块开发手册

> 适用版本：OneHistoryStudio V2.1.7

## 目录和组成

模块目录由 `module.dir` 配置，默认位于 OneHistoryStudio 数据目录的 `Modules`。一个模块通常包含：

```text
DemoModule.dll       指令实现
DemoModule.xml       可选 XML 文档说明
DemoModule.panel.json 可选控制面板
```

查询和打开目录：

```text
module.list
module.open
module.dir path=C:\path\to\Modules
module.reload
```

## 指令约束

- 模块通过既有 SDK/契约注册 `CommandDescriptor`；
- 指令名必须唯一，冲突时模块拒绝装载，不覆盖框架或 App 指令；
- Summary、参数、示例和危险确认都写在 descriptor，Help、命令集、MCP 和命令手册自动复用；
- 文件、Git、数据库操作继续使用宿主服务，不私自启动平行基础设施；
- 需要本地确认的模块指令不会被 MCP 暴露。

## 暴露模式

精准暴露模块只导出声明的指令；全暴露模块按模块约定导出全部公开指令。无论哪种模式，`McpExposurePolicy` 的硬排除和危险确认优先级更高。

## 热重载

模块目录由宿主监听。更新 DLL 时使用新文件原子替换旧文件，宿主会卸载旧 AssemblyLoadContext、重新注册指令并刷新命令集页面。模块旁的 Panel JSON 会同步到 `panels`；新增窗口可能需要重启，已有窗口可通过 `panel.reload` 原地刷新。

Codex/其他 MCP 客户端可能缓存工具目录。模块在 OneHistoryStudio 中热重载成功后，如果客户端仍看不到新工具，需要重启客户端会话。

## 验收

1. `module.list` 显示模块名、版本、暴露模式和指令数；
2. `help command=<模块指令>` 返回参数与示例；
3. 命令集页面来源显示 `module:<模块名>`；
4. MCP `tools/list` 与当前策略一致；
5. 替换 DLL 后旧指令消失、新指令出现；
6. 移除模块后历史提示词提案仍保留，但指令不再可调用。
