# 发布与升级

> 适用版本：OneHistoryStudio V2.3.0

## 单一版本身份

产品名固定为 `OneHistoryStudio`。版本只在 `src/App/App.csproj` 修改一次，`AppIdentity` 将其提供给窗口标题、日志、MCP `serverInfo` 和文件元数据。禁止在页面或网关中维护第二份产品名/版本常量。

## 构建

```powershell
dotnet restore .\OneHistoryStudio.sln -p:NuGetAudit=false
dotnet build .\OneHistoryStudio.sln -c Debug -p:NuGetAudit=false --no-restore
dotnet build .\OneHistoryStudio.sln -c Release -p:NuGetAudit=false --no-restore
dotnet publish .\src\App\App.csproj -c Release -o .\Publish -p:NuGetAudit=false --no-restore
```

发布前运行 V213Smoke、PromptGovernanceSmoke 和 V230Smoke 的 Debug/Release，并用真实项目执行只读回归。

## 命令手册

命令手册必须由当前运行时注册表生成：

```text
command.manual file=b-Code-OneHistoryStudio/docs/命令手册.md apply=false
command.manual file=b-Code-OneHistoryStudio/docs/命令手册.md apply=true
```

生成后核对文件中的 `command-count` 与 `command.list` 总数一致，再复制到 Publish 的 `docs` 目录。不得手工增删命令条目。

## 部署

1. 确认所有 OneHistoryStudio 实例退出；
2. 将旧部署区完整复制为带版本号和时间的回退目录；
3. 将 Publish 全量同步到部署目录；
4. 核对文件清单、SHA-256、ProductName、ProductVersion 和 FileVersion；
5. 从部署目录启动，验证 `help`、`mcp.status`、`proj.list`、`module.list` 和命令集页面。

程序数据位于用户 AppData 的 `OneHistoryStudio` 目录，覆盖部署文件不会删除数据库或设置。SQLite 迁移为幂等操作，仍应在升级前备份 `main.db`。

## 回滚

1. 关闭失败版本；
2. 备份当前数据目录，保留故障日志；
3. 用回退目录恢复部署文件；
4. 若数据库迁移不兼容，再恢复升级前 `main.db`；
5. 启动旧版本并运行只读 Help/MCP/Project 检查。

V2.1.7 没有数据库或 Git 历史迁移，也不会自动修改各 Project 的规则。一次性迁移仅回收已经由正式页面取代的 `panels/projpush.json`；回滚到 V2.1.6 时旧程序会按缺失策略重新生成该面板。Codex MCP 注册变化仍需要重启 Codex 客户端。

V2.3.0 不新增数据库迁移，也不会在升级或打开历史窗口时改写项目提交。旧布局由
`EnsureRegisteredWindows` 自动补入 `history` 窗口，不重置用户已有布局。只有用户显式确认
`proj.rollback`、`proj.reset` 或 `proj.forcepush` 时才会改变 Git 状态。
