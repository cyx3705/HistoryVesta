### 3. `win.list` 的 resource 比例：受控复验结论

初次对账发现 `resource` 窗口比例 v232 为 2%、v233 为 35%，落在 AQ233-11
「`win.list` 输出与整备前逐字节一致」的判据上。查证三步：

1. **工具窗口注册表逐字符比对**（`git show HEAD` vs 工作区，11 行）：比例、停靠位、
   标签目标、内容工厂全部未改——QC-07 只把该表从 `OnStartup` 平移到
   `RegisterToolWindows` 私有方法，值一个没动；
2. **佐证**：`resource` 声明的 `DefaultRatio` 是 **0.18**，而两次采集显示 2% 和 35%，
   **都不等于 18%** → `win.list` 报的是运行时布局（从 `layout\current.layout.xml` 恢复），
   不是注册时的默认值；
3. **受控复验**：在无人操作、布局不再变动的条件下，**连续**运行 2.3.2 部署版与 2.3.3
   发布版各采一次 `win.list`（各 14 行）→ **逐字节一致**。

结论：两次基线之间的差异来自 v232 采集（14:26）与 v233 采集（17:08）之间的一次用户
交互会话（14:30 有 `[cmd:UI] proj.list`，退出时自动保存布局），与 V2.3.3 的代码改动无关。
**AQ233-11 以受控复验为准，判定通过。**

> 教训：`win.list` 含运行时布局状态，不是纯函数式输出。以它做「逐字节一致」判据时，
> 两次采集之间必须无任何 UI 会话；否则须像本次一样做连续受控复验。
> 该注意事项应带入下一个整备版。
