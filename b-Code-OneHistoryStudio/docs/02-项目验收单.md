## 节点 V2-M1 —— proj.* 指令域（出口：纯控制台可管理项目库）

> 本节点验收全程**不使用任何工具窗口**，只在控制台手输指令——这是控制台完备性的落点。
> A1-1 ~ A1-6 在沙盒裸仓库执行；A1-8 在生产仓库以只读指令复核。

- [ ] **A1-1 列表**
  步骤：`proj.list`，再 `proj.list filter=2026`。
  通过标准：输出与 `git worktree list` 一致；过滤生效；含编号/分支/路径/最后提交时间。
- [ ] **A1-2 创建**
  步骤：`proj.create name=9999-901-验收测试`。
  通过标准：分支与同名 worktree 目录生成；基于分支默认 0000-000-Template；
  重复创建、含 `\/:*?"<>|` 的名称、目标目录已存在三种情况分别被明确拒绝且不崩溃。
- [ ] **A1-3 提交与大小检查**
  步骤：在测试 worktree 放入普通文件 + 一个 60MB 文件 → `proj.commit name=9999-901-验收测试 msg=验收`；
  再放入一个 110MB 文件重复提交。
  通过标准：60MB → 警告回显但提交成功；110MB → 触发 LFS 流程（无 LFS 环境则明确失败提示；
  确认对话拒绝时该项目跳过，结果为 Rejected 且不产生半截提交）。
- [ ] **A1-4 推送**
  步骤：`proj.push name=<已配置 remote 的测试分支>`。
  通过标准：成功/失败均有明确回显与 ExitCode 判定，失败不吞错。
- [ ] **A1-5 批量**
  步骤：`proj.commitall msg=批量验收`。
  通过标准：逐项进度回显（n/总数）；结束输出成功/跳过/拒绝/失败四类汇总；全程 UI 不冻结。
- [ ] **A1-6 删除与保护**
  步骤：`proj.delete name=9999-901-验收测试`；再 `proj.delete name=0000-000-Template`。
  通过标准：普通分支弹总线二次确认，确认后 worktree 与分支均消失；
  受保护分支（Template/main/master）在确认之前即被拒绝。
- [ ] **A1-7 继承树与配置**
  步骤：`proj.tree`；`app.get key=proj.bareRepo` 等读配置；`app.set` 改工作树根后 `proj.list`。
  通过标准：树形输出反映真实分支继承关系；配置改动即时生效且重启后保留。
- [ ] **A1-8 控制台完备性（本节点总验收）**
  步骤：生产仓库上，关闭全部工具窗口只留控制台，依次完成：list → tree → create（沙盒名）→
  commit → delete（刚建的沙盒名）。
  通过标准：全流程仅靠手输指令完成，每条均有回显与日志落盘。

## 节点 V2-M2 —— 界面外壳（出口：UI 与指令双向一致）

- [ ] **A2-1 项目总览**
  步骤：打开主窗口总览视图，搜索框输入关键字，双击某行。
  通过标准：列表与 proj.list 同源；过滤即时；双击后资源管理器打开对应文件夹，
  控制台回显等价 `proj.open` 指令。
- [ ] **A2-2 继承树视图**
  步骤：加载继承树，悬停节点，全部展开/折叠。
  通过标准：与生产裸仓库真实分支一致；悬停显示描述；操作流畅。
- [ ] **A2-3 面板 → 指令**
  步骤：「项目操作」面板输入项目名后点创建；「提交推送」面板填分支与描述后点提交。
  通过标准：控制台回显的指令中包含输入框**当前值**（模板验收 6 的机制）；执行结果正确。
- [ ] **A2-4 危险操作双路径拦截**
  步骤：分别通过 UI 按钮和手输指令触发 proj.delete。
  通过标准：两条路径弹出**同一个**总线确认，措辞一致；受保护分支两条路径都直接拒绝。
- [ ] **A2-5 布局整合**
  步骤：按使用习惯摆好总览/继承树/面板/控制台/表窗口布局 → 重启。
  通过标准：布局恢复；此布局另存为命名方案（layout.save）。

## 节点 V2-M3 —— 模块托管（出口：DLL 进目录即成指令）

- [ ] **A3-1 首次装载**
  步骤：将 DemoModule.dll + BaseVariable.dll + DemoModule.xml 复制入 Modules 目录。
  通过标准：约 1 秒内控制台出现装载回显；`help` 中出现 DemoModule 域；
  `DemoModule.Add a=1 b=2` 返回 3。
- [ ] **A3-2 XML 注释即帮助**
  步骤：`help DemoModule.Add`。
  通过标准：显示来自 XML `<summary>` / `<param>` 的中文说明。
- [ ] **A3-3 热更新**
  步骤：修改 DemoModule 源码（如 Add 改为返回 a+b+100）重新编译，覆盖 DLL。
  通过标准：不重启宿主，约 1 秒后同一指令返回新结果。
- [ ] **A3-4 下线**
  步骤：删除 DemoModule.dll。
  通过标准：域内指令全部注销，`help` 不再列出；再次调用提示未知指令。
- [ ] **A3-5 兼容性**
  步骤：取一个此前为 MyAPI-Lite 编写、未重新编译的模块 DLL 放入。
  通过标准：零修改装载成功（鸭子类型契约验证）。
- [ ] **A3-6 隔离性**
  步骤：制作一个方法内抛异常的坏模块并调用；再放入一个缺依赖无法加载的 DLL。
  通过标准：异常被总线捕获红字回显，宿主不崩溃；坏 DLL 仅自身下线并告警，其他模块正常。
- [ ] **A3-7 重名保护**
  步骤：制作含 `proj` 同名域方法的模块放入。
  通过标准：冲突方法被拒绝注册并告警，内置 proj.* 行为不变，模块其余方法可用。
- [ ] **A3-8 module.* 管理指令**
  步骤：`module.list`、`module.reload`、`module.dir`。
  通过标准：列表含名称/版本/描述/方法数；reload 后功能不变；dir 显示当前模块目录。
