- 命令集页面以 `CommandRegistry.All()` 为真值；

- 保持旧 `mcp` 窗口布局兼容。

### V2.1.4 必须完成

- 命令手册由注册表自动生成；
- 现有 `help` 在控制台、UI和 MCP 三端一致；
- 完成全量回归、Publish、部署区和回滚说明。

## 3. 共享工程约束

1. 一切功能先注册指令，页面只调用指令总线；
2. `CommandRegistry` 是全部能力的唯一注册真值；
3. MCP 只投影指令，不旁路调用 Git、模块或数据库；
4. 所有 Git 参数使用结构化 `GitRunner`；
5. 路径写操作必须经过统一 Project 根守卫；
6. 危险操作经 `ConfirmPrompt`，远程 MCP 不得弹 UI 或自动确认；
7. AI 能提出治理修改，但审核、历史重写、批量删除只在本地完成；
8. 不清理或覆盖其他开发者尚未提交的源码、构建产物和文档；
9. 每个版本先完成迁移与回归，再更新 Publish 和部署区；
10. 文档中的“已交付”必须有构建、验收和部署证据。

## 7. 明确顺延项

以下内容不阻塞 V2.1.4：

- MCP 协议级 `prompts/list`、`prompts/get` 和 Resources；
- Codex 当前任务内的工具目录热刷新；
- Git LFS 全历史自动迁移；
- CAD 文件预览、装配依赖和 PDM 锁定；
- 多用户权限和远程公网服务；
- 通用日历、看板和跨 SaaS 工作流引擎。

## 8. 文档状态规则

每份版本文档使用以下状态之一：

```text
草案 → 规划冻结 → 实现中 → 待人工验收 → 已交付
```

状态变更时必须同步实际验收项，不允许一次性将未执行的清单全部勾选。V2.1.4 交付后，本总表保留为 V2.1.x 演进记录，不替代面向使用者的现行手册。
