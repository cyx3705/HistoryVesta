# STC51 直角坐标机器人控制代码（流式循环通信版）

## 1. 设计目标

本版本 MCU 程序采用**流式循环通信**方式，目的是大幅降低内存占用，避免 `DATA` 段溢出。

核心特点：
- **不缓存整条路径**，而是**分批接收 + 运行 + 请求下一批**
- P55 状态灯清晰表示当前状态
- 支持正向运行（反向可后续扩展）
- 每批运行完后主动向上位机请求下一批数据

---

## 2. 硬件引脚定义

| 功能         | 引脚          | 说明                     |
|--------------|---------------|--------------------------|
| X轴脉冲      | P2^0 (CLK_X)  | 步进脉冲                 |
| X轴方向      | P2^1 (DIR_X)  | 方向控制                 |
| Y轴脉冲      | P2^2 (CLK_Y)  | 步进脉冲                 |
| Y轴方向      | P2^3 (DIR_Y)  | 方向控制                 |
| Z轴脉冲      | P2^4 (CLK_Z)  | 步进脉冲                 |
| Z轴方向      | P2^5 (DIR_Z)  | 方向控制                 |
| 状态指示灯   | P5^5 (P55)    | **关键状态灯**           |

### P55 状态灯行为（必须严格遵守）：

- **接收数据阶段**：**P55 = 0（灭）**
- **运行阶段**：**P55 = 1（亮）**
- 收到 `START` 信号后才点亮 P55 并开始运行

---

## 3. 通信协议（流式循环模式）

采用 **请求-响应** 模式，由 MCU 主动控制数据流：

### 上位机 → MCU
- 发送单段数据：`Fx,Fy,Fz`（文本格式，逗号分隔）
- 结束当前批次并开始运行：`END`
- 启动运行信号：`START`（仅在第一批结束后发送一次）

### MCU → 上位机
- 每运行完一段后上报：`POINT:序号\r\n`
- 当前批次运行完成，请求下一批数据：`READY\r\n`

---

## 4. 工作流程（状态机）

```
上电 → STATE_IDLE（P55=灭）
    ↓
接收数据（P55=灭）
    ↓（收到 END）
等待 START（P55=灭）
    ↓（收到 START）
STATE_RUNNING（P55=亮）→ 执行当前批次
    ↓（批次运行完毕）
发送 READY → 回到接收数据状态（P55=灭）
    ↓
循环往复...
```

### 详细流程：

1. MCU 上电后进入待机状态，P55 灭，等待上位机发送数据。
2. 上位机发送多段频率数据（可发送多条 `Fx,Fy,Fz`）。
3. 上位机发送 `END`，表示本批次数据发送完毕。
4. MCU 回复确认后，等待上位机发送 `START`。
5. 收到 `START` 后：
   - P55 = 1（亮）
   - 开始运行当前缓存的路径段
6. 每运行完一段，串口上报 `POINT:x`
7. 当前批次全部运行完毕后，MCU 发送 `READY\r\n` 给上位机。
8. 上位机收到 `READY` 后，可继续发送下一批数据，重复步骤 2~7。

---

## 5. 运行逻辑

- 支持**正向运行**（从第一个点运行到最后一个点）
- 每段运行时间可固定（例如 1 秒），或根据频率动态计算
- 每段运行结束后必须通过串口上报当前点序号
- 支持循环运行（正向跑完后可继续请求新数据继续跑）

**反向运行**：当前版本先实现正向，后面可扩展。

---

## 6. 内存优化策略

- MCU **只缓存当前批次**的数据（建议最多缓存 8~16 段）
- 不保存历史路径，极大降低 `DATA` 和 `xdata` 占用
- 推荐使用小缓冲区循环覆盖

### 推荐实现结构：

- 使用小数组缓存当前批次（例如 `PathSegment buffer[16]`）
- 使用状态机 + 标志位控制流程
- 定时器中断负责脉冲输出和段计时
- 串口中断负责接收数据
