# OneHistoryStudio 使用说明

OneHistoryStudio 是面向个人项目库的 Git 工作树管理、历史查看、文件规则管理、命令执行和模块扩展工具。程序界面与控制台共用同一套指令注册表，因此按钮、脚本、Help 和 MCP 工具具有一致的命令语义。

当前版本继续只发布一个产品入口 `OneHistoryStudio.exe`，但仍保持前端/服务两个进程：普通启动进入 WPF 客户端，
`OneHistoryStudio.exe --service-host` 承载唯一的数据、命令、模块、MCP 与 Web 服务。关闭前端不会停止服务，
显式执行 `svc.stop` 才会停止后台服务。

## 主要窗口

- **项目总览**：浏览、搜索、选择和打开项目。
- **继承树**：查看项目分支的继承关系，并把所选项目同步到其他窗口。
- **Meta文件**：汇总全部项目根目录中的 z/Z 级一级元文件夹，支持搜索、刷新和双击打开。
- **项目操作**：创建项目，提交或推送当前/全部项目，管理 Git 文件格式规则。
- **分支历史**：查看分叉点、提交、HEAD 和远端状态，并预览提交详情与差异。
- **命令集**：搜索全部指令，按域、来源和 MCP 可见性筛选。
- **指令详情**：查看所选指令的参数、示例、风险和 MCP 映射。
- **模块管理**：查看当前加载的扩展模块。
- **控制台**：输入指令并查看统一回显；按 Ctrl + 反引号键可快速聚焦。

中央区域是无标签背景，模块界面统一作为普通工具窗口。已安装的 SE2SW 2.2.0 以“SE2SW 格式转换”
工具窗口嵌入主程序。双击窗口自身带点的蓝色标题拖动条可铺满主窗口，再次双击同一标题条恢复；不要双击
上方标签。窗口可从蓝色标题条拖出为浮动窗口并重新停靠。控制台可执行 `win.show name=se2sw`、
`win.hide name=se2sw`、`win.float name=se2sw`、`win.max name=se2sw` 和 `win.restore`。

## Help 和命令

在控制台输入：

```text
help
help command=proj.list
command.list
command.show name=proj.list
```

`help` 列出全部可用指令；指定命令名后显示参数和示例。`command.list` 适合搜索和筛选，`command.show` 显示单条指令的完整元数据。按钮操作也会回显对应命令，便于复用到脚本。

## 项目操作原则

- 项目选择来自项目总览或继承树，并同步到项目操作和分支历史。
- 提交、推送、回滚、硬重置和强推等写操作必须先看清项目名、范围与确认提示。
- 分支历史默认读取本地 Git 信息；只有显式刷新远端时才访问远端。
- Git 文件规则只在用户明确应用时写入，不会因为浏览页面自动提交或推送。
- 遇到脏工作树、路径越界、受保护分支或远端状态不明确时，程序会优先拒绝危险操作。

## Meta 文件

每个已登记项目根目录下，名称以 `z` 或 `Z` 开头的直接子文件夹称为元文件夹。例如
`2026-016-AD学习\z-AD库文件汇总`。程序只识别一级文件夹，不递归二级目录，也不把同前缀的普通文件
算作元文件夹。

“Meta文件”窗口与项目总览使用同一份工作树清单。首次显示或点击刷新时重新扫描；搜索会同时匹配项目名、
元文件夹名和完整路径；双击一行会在资源管理器中打开该元文件夹。等价控制台命令为：

```text
proj.metalist
proj.metalist filter=AD
proj.metaopen name=2026-016-AD学习 meta=z-AD库文件汇总
```

该功能只负责发现和打开，不创建、重命名、删除或索引元文件夹内容。项目工具清单也放在这类目录中，
具体格式见《模块开发手册》。

## GitHub 账号

在“工具 > GitHub 账号”打开普通工具窗口。页面分别显示 Git 提交身份、GCM 中的 HTTPS 凭据账号、
origin owner/仓库和 fetch/push URL；这些字段不是同一种身份，不能互相代替。当前 origin 使用 SSH 时，
GCM 账号只表示本机已有的 HTTPS 凭据候选。

状态刷新和连接测试只读，不执行 push。登录/注销、修改提交身份和修改 origin 只允许服务器本机 Shell；
写操作先预览，再经确认应用。程序不接收或保存 PAT、密码、SSH 私钥，只列出公钥文件名、算法和 SHA-256 指纹。

## 连接与端口

在“工具 > 连接与端口”选择当前设备角色：

- **服务器端**：持有 SQLite、项目 Git、模块和 GitHub 凭据；旧用户默认保持服务器端和本机回环连接。
- **客户端**：只承载窗口和交互，必须填写 `https://host:port/`、人工核对服务器 SHA-256 证书指纹，
  再用服务器页面生成的两分钟一次性配对码完成配对。设备 token 由当前用户 DPAPI 保存，不写入配置 JSON。

服务器端默认不开放 LAN。启用时只能选择当前活动网卡的 Private IPv4，不能使用 `0.0.0.0`、Public 网络或
明文 HTTP。应用配置会显示 UAC，以受控模式安装 HTTPS 证书、URLACL 和仅 Private profile 的防火墙规则；
关闭 LAN 会对称移除本版本创建的规则。证书轮换后所有客户端都必须重新核对指纹。

新配对设备默认只有 `read` 权限。服务器可把设备改为 `operate`/`admin` 或撤销设备；权限变化和撤销会立即
断开该设备的现有 WebSocket，使其重新鉴权。GitHub 登录/注销、全局 Git 身份和 LAN 机器配置仍只允许服务器本机执行。

## MCP

MCP 网关只监听本机回环地址，默认端口为 `8737`，并随后台服务启动自动监听。在控制台执行：

```text
mcp.status
```

只有显式关闭自动启动、手动停止或启动失败后才需要执行 `mcp.start`。前端关闭后网关仍可用。需要远程工具接入时，
先阅读《MCP 接入与安全》，确认暴露策略、令牌和危险指令确认模式。

正式 Web API 默认监听 `127.0.0.1:8738`，提供 `/api/health`、`/api/commands`、
`/api/command`、`/api/events`、`/api/pair` 和 `/api/confirm`。LAN 设备使用各自的 Bearer token，
非回环只接受 HTTPS/WSS，并固定服务器证书 SHA-256 指纹。MCP 8737 仍只监听本机回环，不随 LAN 开放。

## 扩展模块

模块 DLL 放入当前模块目录后由程序自动装载，文件变化会触发热重载。使用：

```text
module.list
module.open
module.reload
```

模块新增后，程序内的 Help 与命令集会刷新；部分 MCP 客户端会缓存工具目录，需要新建任务或重启客户端后才显示新工具。
