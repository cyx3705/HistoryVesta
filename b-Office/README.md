> 当前版本：V2.7.8

> 面向对象：仓库开发者、维护者与 AI

这里是 OneHistoryStudio 仓库内文档的唯一导航入口。现行手册、一次性证据和版本记录分区保存，彼此不能混用。
AppShell 权威文档已迁至平级 `2026-023-AppShell/b-Office`，本仓不保留可漂移副本。

> **长期治理规则（2026-07-28 起强制执行）**：治理目标不是删除历史文件，而是隔离 AI 的默认读取。
> 未来开发只以当前源码、运行时注册表和 `meta/` 现行手册为基线，不得要求开发者或 AI 阅读 V 版本文档
> 才能继续工作。V 文档原文可以保留在
> `versions/` 或 Git 历史中，但“保留”不等于“进入 AI 上下文”：根目录 `README.md` 的 AI 工作边界禁止默认列举、搜索、
> 批量读取或概括这些文档，根目录 `.ignore` 将其排除在常规全文检索之外。只有任务明确指定版本追溯或指定
> 文档维护时，才允许最小范围读取。版本交付时，必须把仍有效的行为、架构、安全、升级和回滚合同融入
> 对应 `meta/` 手册并重新生成命令手册；V 文档即使继续留存，也不得成为后续开发依赖。这样既保留历史原文，
> 又避免日常检索重复消耗上下文和 token，或把过期结论带入当前开发。

## 目录结构

```text
b-Office/
├─ README.md       仓库文档导航
├─ meta/           随程序发布的六份现行 Help 源文件
├─ evidence/       小型、不可替代的一次性文本证据
└─ versions/       V 版本留存记录；默认不进入 AI 检索与上下文
```

| 区域 | 性质 | 维护规则 |
|---|---|---|
| `meta/` | 当前产品手册，也是 `b-Publish\current\docs\` 候选和 `z-Package\docs\` 正式发布的唯一来源 | 随当前版本更新 |
| `evidence/` | 部署、清理、迁移和实验形成的小型文本事实 | 形成后保持原文；禁止数据库、压缩包、完整发布物和可再生成的原始输出 |
| `versions/` | 当前或历史版本的设计、实施与验收记录 | 不得成为现行基线；有效结论抽入 `meta/`，原文可保留但默认禁止 AI 读取，详细规则见 `versions/README.md` |

`b-Office/snapshots/` 已于 2026-07-28 整体删除。它没有代码、测试或发布消费方，完整输出副本不能形成

## 版本施工文档

[治理与生命周期](./versions/README.md) 是该目录唯一允许 AI 默认读取的文件。其余 V 文档可以继续留存，
但本索引不逐份链接，仓库级搜索也通过根目录 `.ignore` 默认排除它们。当前施工文档必须只描述相对六份
现行手册的增量，不得复制历史基线，也不得引用其他 V 文档作为前置条件。

注意：ripgrep 的正向 `-g` / `--glob` 会覆盖 `.ignore`。仓库级或 `b-Office/` 范围的带 glob 检索必须同时
追加 `-g '!b-Office/versions/**'`，不能先读取全部版本文档再从结果中过滤；该约束记录在根目录 `README.md`。

已交付版本的用户可见变化、迁移和回滚摘要统一见 [发布与升级](./meta/发布与升级.md)。只有用户明确要求
追溯某个版本时，才可直接读取指定的留存文件；文件已不在工作树时再使用：

```powershell
git log --all -- b-Office/versions
git show <提交>:b-Office/versions/<历史文件名>.md
```

读取历史仅用于调查，范围必须限于任务指定的版本和文件。历史文件是否保留在工作树不改变其地位：AI
不得默认读取，开发也不得依赖；真正需要长期生效的结论必须融入对应 `meta/` 手册。
