# AppShell 3.1 界面现代化方案

- 状态：**3.1.1 已实施；作为 3.2.0 的历史界面专项保留，待人工 GUI 验收**
- 日期：2026-08-05 立案 / 2026-08-06 实施
- 适用范围：3.1.x 界面专项；3.1.0 外观改造已并入 3.1.1，本文只保留仍有效的 Shell 表现层要求
- 实施与遗留项见第 13 节；本文作为历史专项保留，最终顶栏规则以 `技术合同.md` 与 `V3.2后台服务化方案.md` 为准
  `技术合同.md` 与 `有效决策.md`，本文迁入 `../history/`

## 1. 背景与问题

3.0.3 的外观来自「菜单栏 + AvalonDock VS2013 浅色主题 + 状态栏」的默认组合，问题集中在四点：

| 编号 | 现状 | 问题 |
| --- | --- | --- |
| P-1 | 每个停靠窗格、每条工具条、每个视图内部都用 1px 灰线分隔（`ShellWindow.xaml`、`ConsoleView.xaml`） | 一屏出现十几条横竖线条，界面被切碎，视觉噪声大于信息量 |
| P-2 | 顶部整行 `Menu`（`MainMenu`）常驻 | 一整行像素只承载 5 个很少点开的菜单，且与 Windows 原生标题栏叠成两条横带 |
| P-3 | 窗口最大化（`DockingHost.BuildMaximizedLayout`）后仍保留窗格标题条与页签 | 「专注单页」的诉求没有兑现，页面没有真正铺满 |
| P-4 | 底部 `StatusBar` 常驻（`ShellWindow.xaml:53`） | 26px 常驻带只显示一句话，且信息（最近结果、错误数、布局名）多数时间无人看 |

3.1 的任务是在**不动 API、不动命令合同、不动停靠引擎**的前提下，把这四点改掉，并统一整体视觉语汇。

## 2. 目标与非目标

### 目标

- G1 页面之间不再用线条分隔，改为「从背景中上浮」的卡片：背景压深、页面提亮、圆角 + 柔和投影、以间隙代替边框。
- G2 取消常驻菜单栏；菜单折叠成顶栏右上角一个按钮，位置在最小化/最大化/关闭三个窗口控件的左侧。
- G3 页面最大化时不显示任何标题条、页签或边距，内容铺满整个 Shell 工作区；退出路径必须仍然存在且可发现。
- G4 取消底部状态栏；原有信息（最近指令结果、错误计数、布局名/最大化状态）改用非常驻方式呈现，行为不丢。
- G5 内置视图（控制台、资源、命令集、指令详情、模块管理）统一到同一套设计令牌：统一圆角、间距、字号、悬停与选中反馈。

### 非目标

- 不新增、不修改、不删除任何公开 API；四份 `PublicAPI.Shipped.txt` 保持不变，`PublicAPI.Unshipped.txt` 保持仅 `#nullable enable`。
- 不改命令名、参数、结果结构和 MCP 投影；`win.*` / `layout.*` / `app.*` 行为不变。
- 不更换停靠引擎（仍是 AvalonDock 4.72.1），不改布局持久化 XML 格式，用户既有 `layout` 文件继续可读。
- 不改 3.0.x：`DEC-006` 冻结纪律继续有效，本方案全部落在 3.1 版本线。
- 本期不交付深色主题，只在令牌层预留切换点（S-04 仍为 P2）。
- 不重写视图的业务逻辑与 code-behind 交互（只改 XAML 呈现与必要的事件接线）。

## 4. 设计令牌

全部令牌集中在新文件 `Themes/ShellTokens.xaml`，键名前缀 `Shell.`，视图与模板一律引用令牌，不再写字面颜色。

### 颜色（浅色，默认）

| 键 | 值 | 用途 |
| --- | --- | --- |
| `Shell.Brush.Canvas` | `#EEF0F3` | Shell 底板，即卡片「浮起」的那层背景 |
| `Shell.Brush.Surface` | `#FFFFFF` | 页面卡片主体 |
| `Shell.Brush.SurfaceAlt` | `#F7F8FA` | 卡片内工具条、只读框、表头 |
| `Shell.Brush.SurfaceHover` | `#F0F2F5` | 悬停 |
| `Shell.Brush.TextPrimary` | `#1F2328` | 正文 |
| `Shell.Brush.TextSecondary` | `#6B7280` | 次要说明、路径、计数 |
| `Shell.Brush.TextDisabled` | `#9CA3AF` | 禁用 |
| `Shell.Brush.Accent` | `#2F6FEB` | 选中页签指示、焦点边、主按钮 |
| `Shell.Brush.AccentSoft` | `#E8F0FE` | 选中行、选中页签底色 |
| `Shell.Brush.Danger` | `#C42525` | 错误徽章、删除按钮 |
| `Shell.Brush.Hairline` | `#E6E9ED` | **仅**用于卡片内部必要分隔（表头下沿等），不用于卡片之间 |

### 形状、投影与间距

圆角规则（Win10 IoT LTSC 2021 目标平台，已定）：**窗体外缘一律直角，窗体内部一律同一个圆角值**。
系统本身不提供 Win11 的窗口圆角，自绘圆角外框会露出黑角或抗锯齿毛边，因此外框取 0；内部只用
一个半径，避免出现 10/8/6 三档并存的杂乱观感。

| 键 | 值 | 用途 |
| --- | --- | --- |
| `Shell.Radius.Window` | `0` | 窗体外缘、顶栏外缘、最大化态工作区：**恒为直角** |
| `Shell.Radius.Inner` | `8` | 窗体内部**唯一**圆角值：页面卡片、按钮、输入框、下拉、页签（上两角）、菜单弹出层、列表选中块、Toast |
| `Shell.Shadow.Card` | Blur 18 / Depth 1 / Opacity 0.10 / `#000` | 常态卡片 |
| `Shell.Shadow.CardActive` | Blur 24 / Depth 2 / Opacity 0.14 | 含焦点的卡片 |
| `Shell.Shadow.Flyout` | Blur 28 / Depth 4 / Opacity 0.18 | 菜单弹出层、浮动窗 |
| `Shell.Space.Gap` | `3` | 单个卡片的外缘留白；相邻两卡片合成 6px 间隙（替代原来的分隔线） |
| `Shell.Space.Pad` | `12` | 卡片内缘 |
| `Shell.Size.TitleBar` | `40` | 顶栏高度 |
| `Shell.Size.Control` | `28` | 标准控件高度 |
| `Shell.Font.Body` / `.Small` / `.Mono` | 13 / 11 / Consolas 12 | 字号 |

字族：`Microsoft YaHei UI, Segoe UI`；等宽区（控制台、Schema、示例）保持 Consolas。

## 5. 需求条目

### UI-01 页面以悬浮卡片替代边框分隔

- 目的：消除 P-1，用层次而非线条表达边界。
- 要求：
  1. `DockingManager` 背景使用 `Shell.Brush.Canvas`；每个停靠窗格（含中央文档区、四边工具区、浮动窗）渲染为 `Shell.Brush.Surface` 卡片，圆角 `Shell.Radius.Inner`，投影 `Shell.Shadow.Card`，窗格外缘留 `Shell.Space.Gap` 间隙。
  2. 窗格之间不得出现 1px 边框线；`GridSplitter`（拖拽分隔条）改为透明命中区，宽度保持不小于 6px 以免拖拽变难，悬停时才显示一条 2px 圆角提示条。
  3. 视图内部的横向分隔线全部去除，改用 `SurfaceAlt` 底色块 + 间距区分；确需分隔时只允许 `Shell.Brush.Hairline`，同一视图内不超过 1 条。
  4. 含键盘焦点的窗格使用 `Shell.Shadow.CardActive`，替代原主题的高亮边框。
- 验收：默认布局下截图中不存在窗格级 1px 边框；拖拽停靠、拖出浮动、四边合并等交互与 3.0.3 一致；`DockingContractTests` 全绿。
- 关联组件：`Themes/`、`ShellWindow.xaml`、五个内置视图
- 关联验证：`VERIFY-FULL`

### UI-02 自定义顶栏承载标题与窗口控件

- 目的：把 Windows 原生标题栏与应用菜单栏两条横带合并成一条，为 UI-03 提供落点。
- 要求：
  1. 主窗体启用 `WindowChrome`（`CaptionHeight=0`、`ResizeBorderThickness=6`、`GlassFrameThickness=0`、`CornerRadius=0`）。窗口控制栏挂在中央文档页签行的 `ShellChromeHost`，工具窗格顶部不再被全窗隐藏标题区覆盖。
  2. 中央文档页签行自左至右：页签 → 弹性空白 → 错误徽章 → **菜单按钮** → 最小化 / 最大化还原 / 关闭。
  3. **控件组的构成与次序在任何形态下都不变**：始终是「菜单按钮 + 最小化 + 最大化还原 + 关闭」四个按钮；工具窗格和浮动窗不承载这组按钮。
  4. 中央文档页签行空白处拖动整个 AppShell，双击按主窗口规则最大化/还原；嵌入工具页顶栏空白处超过系统拖动阈值后执行 `win.float`，新浮窗继续跟随鼠标。真实页签、按钮、菜单和文本输入均排除在空白拖动命中之外。
  5. 窗体最大化时补偿 `WindowChrome` 溢出（按 `SystemParameters.WindowResizeBorderThickness` 给根容器加 padding），避免顶栏被裁切。
- 验收：拖动、双击、贴边、系统菜单、任务栏还原、多显示器与 125%/150% DPI 下顶栏无裁切、无 8px 溢出。
- 关联组件：`ShellWindow.xaml`、`ShellWindow.xaml.cs`
- 关联验证：`VERIFY-FULL` + 人工 GUI 冒烟

### UI-03 菜单折叠为顶栏右上角溢出菜单

- 目的：消除 P-2，常驻菜单行清零。
- 要求：
  1. 删除 `MainMenu` 常驻行；新增顶栏菜单按钮（图标 `≡`，`ToolTip` 为「菜单 (Alt)」），位置紧邻最小化按钮左侧。
  2. 点击弹出 `ContextMenu`/`Popup`，内容与 3.0.3 `BuildMenus()` 完全一致：文件、编辑（预留禁用）、视图（每个窗口的显示/隐藏/浮动/复位 + 退出最大化 + 重置默认布局）、工具（打开数据目录 + `ShellConfig.ToolMenuActions`）、帮助（指令手册、关于）。层级由「顶级菜单 = 二级子菜单」承载。
  3. 保留全部现有约束：菜单项点击仍走 `CommandBus.ExecuteAsync(text, "UI")`（S-02）；`Validate` 失败在首次构建时抛出、其后置灰并显示原因；`WindowsChanged` 仍触发重建。
  4. 键盘可达：`Alt` 或 `F10` 打开菜单，方向键导航，`Esc` 关闭；原有助记符（`文件(_F)` 等）保留在弹出层内。
- 验收：`ToolMenuActions` 中的消费方入口仍可见可用；菜单在窗口注册/注销后正确重建；无鼠标情况下可完成「打开数据目录」。
- 关联组件：`ShellWindow.xaml.cs`(`BuildMenus`/`Item`)
- 关联验证：`VERIFY-FULL`

### UI-04 页面最大化时全幅无壳（默认行为，无开关）

- 目的：兑现 P-3，最大化 = 专注模式。**这是默认且唯一的最大化形态**，不提供「保留标题栏」的选项（提供开关就等于新增 API，与第 3 节冲突）。
- 要求：
  1. `DockingHost.MaximizeWindow(id)` 生效期间，该页所在窗格不显示标题条、页签条、卡片圆角、间隙与投影；内容铺满 `DockingManager` 整个可视区。
  2. 顶栏同步进入专注形态：主 `ChromeBar` 完全脱离视觉树，应用菜单、主窗口最小化/最大化/关闭和错误徽章不占用页面区域；页面自身控制区保留真实页签、恢复按钮和原页面动作。所有专注页的空白顶栏都只移动/双击主窗口；工具页空白顶栏拖出仅限普通嵌入态。真实页签沿用自身拖放规则，专注页需要拖出时使用真实页签，不与空白顶栏状态机混用。
  3. 实现方式：`DockingHost` 暴露内部（非公开 API）最大化态通知，`ShellWindow` 据此把 `AnchorablePaneControlStyle` / `DocumentPaneControlStyle` 切到无头模板 `ChromelessPaneTemplate`，把 `DockingManager` 的 `Padding` 归零，并切换顶栏到专注形态；退出时全部还原。
  4. 退出路径三条，互为兜底：
     - 页面控制区的恢复按钮（发 `win.restore`）；
     - `Esc`（仅当处于最大化态、且焦点不在文本输入控件内时生效）与 `F11`（切换当前活动页最大化）；
     - 顶栏菜单「视图 → 退出窗口最大化」（原有，`win.restore`）。
  5. `EnableMaximizeOnDoubleClick=true` 时的双击进入路径不变；最大化态下的布局保存语义不变（仍保存 `_layoutBeforeMaximize`）。
- 验收：专注态视觉树中主 `ChromeBar` 不存在，页面控制区只有一层真实页签和页面动作；退出后布局逐像素还原；独立浮窗只保留 AvalonDock 内容宿主和一层页面顶栏。
- 关联组件：`Docking/DockingHost.cs`、`ShellWindow.xaml(.cs)`、`Themes/`
- 关联验证：`VERIFY-FULL`

### UI-05 取消状态栏并重新落位其信息

- 目的：消除 P-4，同时不丢 S-03 的既有能力。
- 要求：
  1. 删除 `StatusBar`、`StatusLeft`、`StatusRight`、`StatusErrors`。
  2. 最近指令结果（原 `StatusLeft`）：改为工作区右下角的瞬时提示（Toast），成功 2.5s、失败 6s 后淡出；失败提示可点击，点击后聚焦控制台。控制台仍是完整真值，Toast 只做回执。
  3. 错误计数（原 `StatusErrors`）：改为顶栏错误徽章，`_errorCount > 0` 时显示，颜色 `Shell.Brush.Danger`，点击行为不变（聚焦控制台 + `FilterErrorsOnly()`）。
  4. 布局名（原 `StatusRight`）：显示为顶栏标题右侧的次要文本；专注态按 UI-04.2 一并隐藏，页名不在顶栏重复显示（页面本身已铺满全屏，标题是冗余信息），仅在「退出专注」按钮的 `ToolTip` 中给出。
- 验收：错误徽章计数与点击跳转与 3.0.3 等价；指令失败一定有可见回执；窗口高度全部让给工作区。
- 关联组件：`ShellWindow.xaml(.cs)`
- 关联验证：`VERIFY-FULL`

### UI-06 页签与页头现代化

- 目的：页签是唯一保留的「页面身份」控件，必须自成体系而不靠边框。
- 要求：
  1. 页签置顶（沿用 W-04 已有的 `TabsTopAnchorablePaneTemplate` 思路），选中页签用 `AccentSoft` 底 + 顶部 2px `Accent` 指示条，未选中无边框、悬停 `SurfaceHover`。
  2. 页签高度 32，左右内边距 12，标题超长时 `CharacterEllipsis` + `ToolTip` 全名。
  3. 中央文档区页签行在只有一页时仍然可见（保持 `DockingContractTests` 现有断言与 REQ-DOCK-001）。
  4. 窗格右上角操作（关闭、浮动、菜单）改为悬停时才显示的浅色图标按钮，常态只留页签。
- 验收：既有拖放、页签重排、拖出浮动全部可用；单页与多页情形下 `DocumentPaneTabPanel` 均为 `Visible`。
- 关联组件：`Themes/`、`ShellWindow.xaml`
- 关联验证：`VERIFY-FULL`

### UI-08 令牌化主题与深色预留

- 目的：为 S-04 深色主题留出零重构的切换点。
- 要求：`Shell.Radius.Inner` 是窗体内部唯一允许的圆角来源，`Shell.Radius.Window` 是窗体外缘唯一允许值（0）；`AppShellTheme.xaml` 合并顺序改为「VS2013 浅色基底 → `ShellTokens.xaml` → `ShellControls.xaml`（控件样式）→ `ShellDocking.xaml`（AvalonDock 覆盖）」；所有颜色只在 `ShellTokens.xaml` 定义，其余文件一律 `DynamicResource` 引用。深色主题将来只需替换令牌字典。
- 验收：全仓搜索 Shell 层 XAML，除 `ShellTokens.xaml` 外无颜色字面量（`#RRGGBB`）与圆角字面量（`CornerRadius="…"`）。
- 关联组件：`Themes/`
- 关联验证：`VERIFY-FAST`

### UI-09 兼容降级

- 目的：自绘顶栏不得让非常规宿主启动即坏。
- 要求：
  1. 在 `SourceInitialized` 时判定：若消费方把 `WindowStyle` 改为 `None`/`ToolWindow`/`ThreeDBorderWindow`（例如现有 `DockingContractTests` 用 `ToolWindow` 建窗），则**不套用** `WindowChrome`——只降级窗口边框的接管方式，**不降级顶栏内容**：菜单按钮与最小化/最大化还原/关闭四个按钮按 UI-02.3 的次序全部保留并可用（分别驱动 `WindowState.Minimized`、`Maximized`/`Normal` 与 `Close()`），错误徽章位置不变。
  2. 降级态下宿主若仍带原生按钮（如 `ToolWindow` 的关闭按钮），允许与顶栏按钮并存；顶栏按钮是唯一保证在所有 `WindowStyle` 下都存在的入口，不得因可能重复而省略。`WindowStyle=None` 时顶栏按钮是唯一的窗口控制入口，必须可用。
  3. 系统开启「高对比度」时禁用投影与圆角，改用系统主题色边框，保证可见性。
  4. 投影只加在窗格级 `Border` 上（数量等于窗格数，通常 ≤ 8），不在列表项等高频元素上使用；控制台每秒上千行注入时（`debug.logflood rate=1000`）帧率不低于 3.0.3。
- 验收：`WindowStyle=ToolWindow` 的测试宿主可正常构造、显示、关闭，且顶栏四个按钮均可命中并生效；高对比度下可读；承压场景无明显掉帧。
- 关联组件：`ShellWindow.xaml.cs`、`Themes/`
- 关联验证：`VERIFY-FULL`

### 6.2 顶栏关键细节

- `WindowChrome.CaptionHeight` 固定为 `0`，避免不可见命中区覆盖工具窗格；中央文档页签行空白由 `ShellWindow` 显式处理拖动，按钮继续设置 `WindowChrome.IsHitTestVisibleInChrome=True` 作为兼容保护。

- 菜单弹出层用 `Popup`（`StaysOpen=False`、`Placement=Bottom`、右对齐），`AllowsTransparency=True` + `Shell.Shadow.Flyout`。
- `RestoreWindowBounds()` / `SaveWindowBounds()` 逻辑不变，最大化标志仍取 `RestoreBounds`。

### 6.3 悬浮卡片关键细节

- AvalonDock 的窗格样式必须经 `DockingManager.AnchorablePaneControlStyle` / `DocumentPaneControlStyle` 属性下发（隐式 `Style` 不命中），这一点沿用 3.0.3 `ApplyTabsTopStyle()` 的既有结论，新模板在其基础上扩展而非另起。
- 基底样式键随主题版本变化（`AvalonDockThemeVs2013*`），保留现有「取不到基底就告警并退回主题默认」的容错，不得让主题查找失败变成启动崩溃。
- 卡片间隙由窗格 `Margin` 提供；`LayoutGridResizerControl` 改透明后，其命中宽度不得小于 6px。

### 6.4 最大化全幅关键细节

- 现有 `BuildMaximizedLayout` 重建 `LayoutRoot` 的做法保留（内容实例从 `_contents` 复用，不重建视图状态）；本期只换模板与边距，不改布局构建逻辑，从而不影响 `_layoutBeforeMaximize` 的还原语义。
- `Esc` 处理接在 `ShellWindow.PreviewKeyDown`，命中条件：`_docking.MaximizedId != null` 且 `Keyboard.FocusedElement` 不是 `TextBoxBase`/`ComboBox` 编辑区，避免抢走控制台输入的 `Esc`。

实现上的三个关键结论（都由运行期失败逼出来，值得留档）：

1. **页签容器是普通 `TabItem`**，AvalonDock 的 `LayoutDocumentTabItem` /
   `LayoutAnchorableTabItem` 是容器模板内部承担拖拽与激活的那一层。
   直接把 `LayoutXxxTabItem` 的样式赋给 `ItemContainerStyle` 会抛
   「样式不适用于类型 TabItem」并**崩溃整个测试宿主**。正确做法是
   外层 `TargetType=TabItem` 的容器样式里承载 `LayoutXxxTabItem`，再给后者换视觉模板。
2. **页签的 DataContext 就是 `LayoutContent`**（经运行期探针确认），
   所以 `Title` / `IsSelected` / `CanClose` 可直接绑定，关闭命令走
   `TemplatedParent` 的 `LayoutItem.CloseCommand`。
3. **窗口按钮与页签同处一行带来两个必须处理的耦合**：
   - 页签必须声明 `WindowChrome.IsHitTestVisibleInChrome`，否则落在标题区内点不到；
     页签之外的空白正好成为拖动窗体的区域。
   - 中央文档页签行通过 `ShellChromeHost` 的独立 Auto 列承载 `ChromeBar`，工具窗格不再
     为它预留右边距。专注态没有页签行，改为把 `CaptionHeight` 归零，
     以免页面顶部 32px 的点击被当成拖动窗体。

四个根因，全部由「渲染像素采样」而不是属性值查出来，值得留档：

1. **`TabControl` 默认模板把内容区刷成 `#F4F4F4`** —— 只设 `Background` 没用，必须换模板。
2. **`ListBox`/`ListView` 默认模板带一条 `IsEnabled=False → Background=#F4F4F4` 的触发器**，
   直接改模板内 Border 的底色，`TemplateBinding` 拦不住。「指令详情」的表格未选中指令时
   正是禁用态 —— 这才是「表格里还是白的」的真正原因。换模板时必须保留
   `GridView.GridViewScrollViewerStyleKey`，否则整行表头会消失。
3. **浮动窗口自带一份 AvalonDock 主题字典**（里面是浅色令牌），优先级高于应用级资源，
   必须逐窗口替换。
4. **不能挂 `DockingManager.LayoutUpdated` 做这件事**：该事件每帧都发，回调里任何写操作
   都会再触发布局，实测直接跑成 100% CPU 死循环（测试宿主挂死）。改为 400ms 低频巡检 +
   幂等写入（令牌字典已是目标主题就整窗跳过），并在关窗时停表 —— 窗体关闭后再碰浮动窗口，
   AvalonDock 会因设置 `Owner` 抛异常。
