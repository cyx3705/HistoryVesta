# AppShell 3.2.0 后台服务化方案

## 运行模型

3.2.0 使用一个发布 EXE 的双进程模式：

- `AppShell.exe --service`：用户会话后台，使用 `%AppData%\AppShell\service` 保存端点、设置和日志。
- `AppShell.exe`：WPF 前端，只拥有窗体、停靠布局、主题和 UI 模块实例。

后台服务使用现有用户级单实例互斥锁。前端启动时读取 `service\endpoint.json`；端点不存在会先拉起
`--service` 并等待 HTTP 健康检查。前端重复启动只激活已有窗口，不创建第二套布局。

## 命令与事件

后台是命令目录、非 UI 模块、MCP/Web、日志和全局快捷键的权威宿主。前端通过 loopback HTTP/WebSocket
发布自己的 UI 命令目录；后台收到 UI 命令后回送前端执行。后台日志通过事件流进入前端控制台内存，不在
前端重复落盘。模块目录由后台监听，修订事件驱动前端 UI-only 模块重载。

前端生命周期命令：

- `app.frontend.show`
- `app.frontend.hide`
- `app.frontend.focus-console`
- `app.frontend.exit`

`app.exit` 由后台协调前端退出后再停止服务；关闭按钮和 `Alt+F4` 在独立宿主中只执行隐藏。

## 全局快捷键

模块实现 `IGlobalShortcutModule` 后，由后台提供带 owner 的 `IGlobalShortcutRegistrar`。快捷键只能映射到
命令文本，执行来源为 `Hotkey:<owner>/<shortcut-id>`。支持修饰键和 1 至 4 步序列，默认间隔 350ms；冲突、
前缀冲突、自动重复和注入事件会被拒绝或忽略。内置无修饰 `VK_OEM_2` 双击映射到
`app.frontend.focus-console`，不吞掉其他程序的 `/` 输入，也不保存原始按键数据。

## 消费边界

NuGet 消费方默认不启用后台或快捷键；独立 AppShell 宿主显式组装 `ServiceComposition`。OHS 后续作为
AppShell UI/业务模块接入，不再维护第二套模块管理页面。本版本不改变全局 `z-*` 扫描和现有模块目录抽象。
