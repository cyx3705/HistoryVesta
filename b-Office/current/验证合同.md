# HistoryVulcan 验证合同

## 3.5.0 Candidate Checks

Add service, frontend, and remote-relay checks for `vulcan.app.focusconsole`; verify `--focus-console` executes that command, and verify Tab confirmation refreshes the next completion layer. The candidate version is `3.5.0`; no formal Z snapshot or publication is performed in this task.

## 验证原则

- 命令权威声明位于根 `project.manifest.json`；本文解释验证层级、环境和证据。
- 3.0.3 冻结门禁不得因 runner 差异而删除或弱化测试；3.1.1 至 3.3.2 新增合同不得绕过冻结门禁。
- **门禁只验证本仓库自身。** 依赖其他项目实现（HistoryMercury 等）的联调用例归各自仓库；
  本仓库的解决方案与 CI 不得出现跨仓库 `ProjectReference`（DEC-023）。
- CI 验证源码与冻结合同，不执行正式发布、打标签、推 NuGet.org 或消费方部署。
- 未执行、失败、偶发失败和不适用必须分别记录；重跑通过不得抹去首次失败原因。

## CI 合同

- 触发：推送到 `2026-023-HistoryVulcan`，或 `workflow_dispatch`。
- Runner：`windows-latest`，超时 30 分钟，仓库权限只读。
- 工具链：`global.json` 固定 SDK 9.0.315；官方 Action 使用 Node 24 兼容主版本。
- 顺序：锁定还原、Debug build/test、Release build/test、格式、公开 API、失败摘要、TRX 上传。
- 失败证据：`Write-TrxFailureAnnotations.ps1` 将失败用例和错误首行写入注释与 job summary；
  `historyvulcan-test-results` 制品保存 Debug/Release TRX。
- 边界：候选构建不访问下游工作树、不写正式发布目录；正式提升只由 Diana 事务执行。

## 环境前提

- Windows 10/11 或 GitHub Windows runner；WPF 测试需要 STA/Dispatcher 支持。
- .NET SDK 9.0.315；目标运行时为 .NET 8。

- 本机 CET 不兼容时可设置 `DOTNET_EnableWriteXorExecute=0`；CI 不携带该机器特例。
