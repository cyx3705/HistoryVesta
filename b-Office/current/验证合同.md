# HistoryJanus 验证合同

## 验证原则

- 日常开发只运行相关 Contracts、Debug 构建、定向功能 Smoke 和 ModuleSmoke。
- 正式发布运行 Debug/Release 构建、Contracts、完整功能 Smoke、ModuleSmoke、包静态门禁、checksum、双槽部署和回滚验证。
- 功能 Smoke 固定为 `VersionProjection`、`TestArchitecture`、`GitRules`、`BranchHistory`、`SubmoduleSafety`、`RepositoryTargets` 和 `ProjectOperations` 七套；宿主装载、卸载和热重载只由独立 ModuleSmoke 验证。
- 正式流程不得运行或修改开机自启动，也不得替用户启动 HistoryVulcan。
- 运行时命令目录、module manifest 和正式包文件集合是可执行事实；文档必须与其一致。

## 验证层级

| 编号 | 层级 | 适用时机 | 命令或步骤 | 通过标准 |
| --- | --- | --- | --- | --- |
| VERIFY-FAST | 快速检查 | 相关功能完成 | `dotnet build HistoryJanus.sln -c Debug`；定向 Contracts/Smoke；ModuleSmoke | 0 warning、0 error，选定测试全绿 |
| VERIFY-FULL | 完整回归 | 正式候选 | `b-Code-Studio/eng/Publish-Janus.ps1` | Debug/Release、Contracts、功能 Smoke、ModuleSmoke 和包门禁全绿 |
| VERIFY-PUBLISH | 正式提升 | 源码已提交且洁净 | `b-Code-Studio/eng/Publish-Janus.ps1 -Publish` | z 级正式树原子更新，旧正式包进入 history |
| VERIFY-ACCEPT | 人工验收 | 用户重启 HistoryVulcan 后 | 模块管理、三个页面、项目与 Meta 列举、Git 规则与分支历史 | 模块可见，页面功能生效，UI 与后台命令来源一致 |

## 环境前提

- Windows 与 .NET 8 SDK。
- HistoryVulcan current-host 快照位于 `C:/OneHistory/HistoryVesta/2026-023-HistoryVulcan/z-HistoryVulcan`；版本和 `sourceDirty` 以其 manifest 为准。
- 正式发布前 Janus 的 `b-Code-Studio`、`b-Code-Verify`、`b-Office` 和根发布配置必须已提交且洁净。
- 部署前 HistoryVulcan 应保持关闭；脚本只检测，不负责停止或启动进程。

## 证据保存

| 证据类型 | 保存位置 | 是否入库 | 保留规则 |
| --- | --- | --- | --- |
| 最新正式模块及校验 | `z-Package-HistoryJanus` | 是 | 只保留最新版本 |
| 被替换的正式包 | `b-Publish/history/package-*` | 否 | 只保存历史正式包，不保存构建工作区 |
| 当前候选 | `b-Publish/current/HistoryJanus` | 否 | 下一次候选原子覆盖 |
| 部署回滚 | HistoryVulcan Modules 同级 `HistoryJanus-rollback-*` | 否 | 至少保留本次部署前版本 |

## 明确不执行

- 开机自启动测试。
- 自动启动 HistoryVulcan 或旧 Janus。
- 真实 GitHub 凭据修改、真实推送、UAC、防火墙和双机 LAN 测试。
