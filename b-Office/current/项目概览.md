# HistoryJanus 项目概览

更新日期：2026-08-09

## 一句话定义

HistoryJanus 是运行在 HistoryVulcan 中的自用项目与 Git 治理模块，统一管理编号项目、分支继承、Meta 文件、Git 文件规则、提交、推送和分支历史。

## 目标与边界

### 目标

- 以单个 HistoryVulcan 模块提供两个业务页面和稳定命令集合；项目总览同时展示项目与 z/Z 级元文件夹；项目操作页以底部同一行分段切换 Git 文件规则、分支历史与 GitHub 连接治理三个面板（3.7.0 起 github 不再独立成页）。
- 保留原有项目库与 Git 数据，移除独立 Janus 进程和第二套宿主运行时。
- 通过两层发布区交付可校验、可回滚的正式模块快照。

### 范围

- `b-Code-Studio/Module` 的模块入口，以及其链接使用的项目、Git、视图和业务组合源码。
- `b-Code-Verify` 的 Contracts、功能 Smoke、模块装载和发布门禁。
- `b-Publish` 的单槽候选、正式历史包和事务目录。
- `z-HistoryJanus` 的最新正式消费快照。

### 非目标

- 不提供独立 `HistoryJanus.exe`、独立 ServiceHost、独立 Shell、Web/MCP 网关或开机自启动项。
- 不复制或发布 HistoryVulcan 运行库；宿主从 `2026-023-HistoryVulcan/z-HistoryVulcan` 独立交付。
- 不把 Janus CLR 类型作为跨模块二进制 API；其他模块通过宿主命令总线协作。

## 关键约束

- 平台：Windows、.NET 8 WPF、HistoryVulcan 3.1.9 current-host 宿主合同；HistoryVulcan 是否洁净以其 z 快照 manifest 为准。
- 兼容性：模块名 `HistoryJanus` 和现有业务命令名保持稳定；3.2.0 移除 `tree`、`meta` 两个 UI 窗口 ID，3.3.0 移除 `history` 窗口 ID；Meta 命令、继承树后台命令和分支历史全部命令继续可用。
- 数据：模块数据根由 HistoryVulcan `IModuleContext.DataDirectory` 提供，并在其下使用 `HistoryJanus` 子目录。
- 安全：MCP 只投影只读命令；写操作仍由宿主确认策略控制。
- 发布：不执行开机自启动测试，不从 Janus 包发布或启动宿主进程。
