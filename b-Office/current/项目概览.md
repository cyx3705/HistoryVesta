# AppShell 项目概览

更新日期：2026-08-07

## 一句话定义

AppShell 是供 OneHistory 桌面应用和服务宿主固定版本消费的通用 .NET 8/WPF 壳框架，统一提供
命令、停靠布局、日志、设置、面板、模块、MCP/Web 接入与服务生命周期能力；资源浏览由独立模块提供。

## 目标与边界

### 目标

- 以当前宿主程序提供可直接运行、可测试、可回滚的 AppShell，并为嵌入式框架消费保留固定公共合同。
- 以单一窗口模型承载中央主工作区和四边工具页，并保留布局持久化与模块生命周期。
- 以默认最小能力、安全边界、公开 API 基线和自动化门禁守住 3.0.3 冻结契约。
- 让消费方和 AI 从稳定入口定位当前宿主、UI 风格、API、命令和限制，无需扫描历史归档。

### 范围

- AppShell 单 EXE 双进程宿主，以及 `Core`、`Services`、`Shell`、`ServiceHost` 四个嵌入式框架合同。
- AppShell 演示宿主、根级 `b-Code-Tests` 自动化测试、隔离包消费测试和示例模块。
- 消费合同编辑源、候选打包、正式归档及 Z 级当前消费快照。

### 非目标

- 不承载 OHS、WBall 或其他消费应用的业务功能和数据模型。
- 不提供已在 3.0 删除的数据库服务、通用表窗口或 `db.*` 命令。
- CI 不自动发布包、更新正式快照、创建标签或部署消费方。
- 3.0.x 不新增公开 API 或一般性功能；后续演进进入新版本线。

## 当前里程碑

V3 冻结基线仍为 `3.0.3`（标签 `v3.0.3`），只收致命缺陷。当前源码候选版本为
`3.1.9`：在 3.1.7 正式宿主和 UI 风格合同基础上，承接 3.1.8 的控制台输入体验，并增加面向外置模块的
公开宿主上下文和可配置部署模块目录。3.1.8 是不受支持的内部过渡版本；稳定消费者仍固定在 3.1.7。
控制台按运行期命令注册表自动显示
命令、参数名和允许值候选；控制台聚焦时使用 `Shift+W`/`Shift+S` 上下选择、`Tab` 写入候选、`Enter` 执行命令，
普通布局由控制台输入实时检索中央命令集，命令集不再维护独立搜索框；`Shift+W/S` 选择列表结果，`Tab` 把命令名
写回控制台但不执行。

## 关键约束

- 平台：Windows、WPF、`net8.0` / `net8.0-windows`、win-x64 演示宿主。
- 工具链：根 `global.json` 固定 .NET SDK `9.0.315`；C# 检出行尾固定为 CRLF。
- 兼容性：3.1.1 对资源/Workspace 公开面是破坏性收缩；3.1.2 修复双进程命令目录数据解码；3.1.3、3.1.4、3.1.7 与 3.1.8 不改变公开 API。
  3.1.9 新增 `IModuleContext`/`IModuleContextAware`、完整 `ModuleHost.Attach` 重载和 `ShellConfig.ModuleDirectory`，
  供外置模块取得权威宿主服务并让打包宿主显式选择模块目录。
  四份 `PublicAPI.Unshipped.txt` 仍只有 `#nullable enable`，公开基线以 shipped 文件为准。
- 默认消费合同：`EnableMcp=false`、`EnableModules=false`，消费方按需显式启用；仓库内 AppShell 独立可执行宿主
  明确设置 `EnableModules=true`，提供模块管理页并承担唯一模块生命周期。
- 安全：MCP 暴露需要描述符显式允许；敏感值不得进入日志、历史或未授权响应。
- 发布：宿主先进入 `b-Publish/current` 审核，再整体部署到 Z；脚本不生成 NuGet 包，也不自动推送远端。
