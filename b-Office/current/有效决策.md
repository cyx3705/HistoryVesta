# HistoryVulcan 有效决策

## DEC-035 3.5.0 semantic console focus

`vulcan.app.focusconsole` is the single stable focus-console capability shared by service, frontend, remote relay, and `--focus-console` startup. Mercury owns the global `//` registration but only dispatches this Vulcan semantic command. The old `mercury.shortcut.wakeconsole` remains a compatibility wrapper.

这里只保留仍会影响后续维护的决策。实现过程、已关闭问题和旧方案属于历史证据。

## DEC-001 包消费取代源码复制

- 状态：已接受
- 日期：2026-07-28
- 决策：023 是 HistoryVulcan 源码与合同唯一权威；消费方使用精确版本 `PackageReference`。
- 原因：消除 Janus、WBall 与框架源码分叉，建立独立版本和回滚边界。
- 后果：框架变化必须先发布包，再由消费方显式升级并复验。
- 替代条件：无；仅可由新的跨仓库分发架构显式替代。

## DEC-002 默认最小能力

- 状态：已接受
- 日期：2026-07-29
- 决策：MCP 与模块默认关闭；消费方显式启用。命令集和本地 `command.*` 不依赖 MCP。
- 原因：库不得因被引用就监听端口、扫描目录或创建治理状态。
- 后果：需要 MCP/模块的宿主必须在 `ShellConfig` 中声明。
- 替代条件：不得在 3.0.x 替代；新版本也必须单独安全评审。

## DEC-003 中央区使用原生文档主区

- 状态：已接受
- 日期：2026-07-29
- 决策：命令集是默认中央文档；中央区显示独立页面头和页签，普通工具页可拖入/拖出中央。
- 原因：避免空文档占位和并排工具窗导致的中央区塌缩，同时保留原生拖放。
- 后果：命令集不可隐藏、浮动或侧停靠；业务中央页与命令集共享文档组。
- 替代条件：仅在更换停靠引擎并完整重验交互合同时评估。

## DEC-004 模块窗口默认右置并合并同侧窗格

- 状态：已接受
- 日期：2026-07-29
- 决策：保留模块注册器和模块 UI 修改能力；运行期工具窗默认 `Right/0.25`，复用同侧标签组。
- 原因：避免每个模块生成独立右侧窗格并持续挤压中央主区。
- 后果：历史布局加载时合并同侧窗格，侧栏总占比不超过 50%。
- 替代条件：模块可显式覆盖有效配置，但不得突破布局安全上限。

## DEC-005 编辑源、归档与 Z 级快照分离

- 状态：已接受
- 日期：2026-07-29
- 决策：消费合同编辑源位于 `b-Office/package/`；正式历史归档在 `b-Publish/`；
  `z-Package-AppShell/` 只保存一个当前正式消费快照和稳定复用入口。
- 原因：避免副本漂移，并让跨项目索引直接命中稳定元地址。
- 后果：发布副本不得手改，历史版本不得堆入 Z 根目录。
- 替代条件：只有新的发布协议能同时提供版本寻址、校验和稳定入口时替代。

## DEC-006 V3 以 3.0.3 最终冻结

- 状态：已接受
- 日期：2026-07-29
- 决策：`v3.0.3` 是 V3 最终冻结基线；3.0.x 只接受致命崩溃、数据丢失或安全漏洞修复。
- 原因：Janus/WBall 已固定消费，继续功能演进会把不确定性转嫁给下游。
- 后果：不新增公开 API；一般功能和结构改造进入新版本线。
- 替代条件：启动并完成新版本线的公开合同、发布和消费门禁。

## DEC-007 CI 只自动化只读冻结门禁

- 状态：已接受
- 日期：2026-07-30
- 决策：`2026-023-HistoryVulcan` 每次推送自动执行锁定还原、双配置构建测试、格式和 API 基线检查；
  CI 不调用 `Publish-AppShell.ps1`，不发布、不打标签、不部署。
- 原因：持续防漂移，同时把不可逆发布动作留在人工审批边界内。
- 后果：GitHub Actions 结果是持续证据，但不能替代正式发布和消费方验收。
- 替代条件：只有建立受保护分支和明确发布授权模型后再扩展。

## DEC-008 固定工具链和 C# 检出行尾

- 状态：已接受
- 日期：2026-07-30
- 决策：SDK 固定为 9.0.315，C# 文件通过 `.gitattributes` 以 CRLF 检出。
- 原因：Windows Roslyn 格式结果受 SDK 和检出行尾影响，必须保证本机与干净 runner 输入一致。
- 后果：升级 SDK 或改变行尾规则前必须先验证 `dotnet format` 和分析器输出。
- 替代条件：工具链升级并在本机、CI 同时通过完整门禁。

## DEC-009 开启 3.1 界面版本线且不动公开面

- 状态：已接受
- 日期：2026-08-06
- 决策：界面现代化进入新版本线 `3.1.0`，只改 `HistoryVulcan.Shell` 表现层；四份 `PublicAPI.Shipped.txt`
  不变、`Unshipped` 保持仅 `#nullable enable`；不新增任何外观开关。
- 原因：`DEC-006` 把功能演进挡在 3.0.x 之外，而外观开关一旦加入 `ShellConfig` 就是新增公开 API。

  `protected override` 一类改法不可用，钩子一律走事件订阅。
- 替代条件：只有在确实需要按宿主切换外观时，才另开公开面评审。

## DEC-010 以层次替代线条，并取消常驻菜单行与状态栏

- 状态：已接受
- 日期：2026-08-06
- 决策：停靠窗格改圆角卡片（间隙 + 投影），菜单折叠进顶栏且恒在三个窗口按钮左侧，
  页面聚焦时铺满工作区并保留真实页签与唯一完整主 ChromeBar，底部状态栏取消，信息改由瞬时回执与顶栏承载；
  工具页和独立浮窗都只允许一层页面顶栏，窗体外缘直角、内部统一 `Shell.Radius.Inner`。
- 原因：一屏十几条 1px 分隔线把界面切碎；两条常驻横带各自只承载少量信息。
  目标平台 Win10 IoT LTSC 2021 无系统窗口圆角，自绘外圆角会露黑角。
- 后果：AvalonDock 窗格模板由 Shell 接管（`ShellDocking.xaml`），主题版本升级时需同步复核；
  颜色与圆角只允许在 `ShellTokens.xaml` 定义。
- 替代条件：更换停靠引擎或扩展新的主题/高对比模式时重新评估令牌层。

## DEC-011 3.1.1 命令管线与模块化收口

- 状态：已接受
- 日期：2026-08-06
- 决策：控制台顶部只保留级别和来源，其余检索与操作统一注册为 `log.*` 命令；窗口、复制示例、
  面板文件/目录选择等业务入口通过 `CommandBus` 执行。删除 HistoryVulcan 内置资源页、Workspace/res.*
  公开面和演示电机页；保留 `ModulesView` 作为唯一模块管理实现，Janus 只负责停靠位置与消费配置。
- 原因：让 UI、脚本、模块和 MCP 使用同一命令描述符，缩小复用包上下文，并避免 HistoryVulcan 与消费方重复维护资源/模块管理。
- 后果：3.1.1 接受资源 API 的破坏性移除；全局 `HistoryVesta\\*\\z-*` 模块扫描不在本版本范围，仍沿用现有模块目录抽象。
- 替代条件：资源浏览由独立模块提供；全局扫描另行完成安全边界、目录槽和热重载设计后再评审。

## DEC-012 单 EXE 双进程与后台命令权威

- 状态：已接受
- 日期：2026-08-07
- 决策：`HistoryVulcan.exe --service` 是用户会话后台，普通 `HistoryVulcan.exe` 是 WPF 前端。后台拥有非 UI 模块、
  全局快捷键、日志和远程命令权威；前端只拥有 WPF、布局、主题和 UI 模块实例，通过 loopback 中继命令。
- 原因：关闭或崩溃前端后，快捷键、模块和服务仍需持续运行，同时避免两套命令目录和模块生命周期。
- 后果：独立宿主关闭默认隐藏；`app.exit` 协调两端退出；重复前端只激活已有实例。双 `/` 只映射
  `app.frontend.focus-console`，不吞键、不保存原始按键。
- 替代条件：仅在新的进程模型能保持单一命令权威、模块 owner 回收和前端崩溃恢复时替代。

## DEC-013 顶栏按宿主和页签职责分离

- 状态：已接受
- 日期：2026-08-07
- 决策：嵌入/聚焦页面的空白顶栏只移动或切换主 HistoryVulcan；独立浮窗空白顶栏只控制自身；只有真实页签
  能拖出页面。普通主窗口越过系统阈值即移动，主窗口最大化和独立浮窗保留 120ms 延时；移动立即作废
  双击候选，双击窗口固定为 250ms。
- 原因：消除主窗口、页面专注、浮窗移动和页面拖出之间的命中冲突。
- 后果：顶栏协调器成为唯一手势实现；不得依赖 AvalonDock internal API 或再增加外层标题行。
- 替代条件：更换停靠引擎并完整重验页签拖出、DPI 几何和 Windows 窗口语义时替代。

## DEC-014 控制台与命令集统一按域筛选

- 状态：已接受
- 日期：2026-08-07
- 决策：3.1.5 起命令集只保留命令域筛选；控制台把原“来源”选择器改为运行期域选择器。两页都通过
  `command.domains` 从命令总线读取完全相同的已注册域集合，不维护控制台私有目录。命令名按首个 `.` 提取域，
  无点命令归 `core`；普通日志类别前缀未命中已注册域时归入 `core`。命令结果与进度在既有公开类别常量后
  附加本次执行的域，`log.source` 作为兼容命令名继续存在。控制台水平滚动禁用，文本只做响应式软换行。
- 原因：注册来源、执行入口和业务域混在同一界面会产生重复且不可靠的筛选；水平 extent 会让长行反向撑宽停靠窗格。
- 后果：注册来源仍保留在结构化目录和模块管理合同中，但不再出现在命令集筛选/列；命令注册或注销后两页
  同步刷新，未注册日志类别不会产生候选域，不存在的域会被拒绝。复制和导出仍使用原始逻辑文本，不包含视觉换行。
- 替代条件：若未来更换运行期命令目录协议或新增公开筛选 API，需单独评审兼容性与性能边界。

## DEC-015 继续收口会改变状态的 UI 入口

- 状态：已接受
- 日期：2026-08-07
- 决策：会改变应用状态或执行外部操作的 UI 入口必须复用 `CommandBus` 中的命令描述符；3.1.5 将顶部回执、
  全局控制台快捷键、帮助菜单唤出控制台、关闭即隐藏手势及文档浮窗最大化/还原继续收口。文档浮窗状态使用
  `win.float-state`，命令集、模块管理、命令详情与 MCP 治理页面通过运行期命令读取和执行，不保留私有业务通道。
  原生窗口移动、拖动期间的几何恢复、菜单展开、确认对话框内部选择、文本焦点、列表选择和 Tab 导航仍属于
  宿主或视图交互，不为增加命令数量而包装成业务命令。
- 原因：总线托管可让 UI、手输、脚本、模块和 MCP 共享校验、日志与回执；但纯视图手势进入总线会制造无业务
  语义的伪命令，并破坏 WPF/AvalonDock 原生交互时序。
- 后果：`断头指令审计表.md` 必须同时列出已托管入口与明确例外；新增业务按钮或离散状态手势时，需先检查能否
  复用现有命令，不能直接调用停靠、日志过滤、剪贴板或文件选择服务。该收口不新增公开 .NET API。
- 替代条件：若未来引入可声明的 UI 动作层，可在保留相同命令描述符与审计能力的前提下替代手写事件转发。

## DEC-016 控制台轻松指令与命令集共享输入

- 状态：已接受
- 日期：2026-08-07，2026-08-08 修订
- 决策：3.1.8 仅在控制台自身处于聚焦态时，从运行期权威命令目录生成命令名、参数名和参数允许值候选，
  并在输入框上方显示不抢焦点的 Popup。`Shift+W` 反向循环到上一项，`Shift+S` 正向循环到下一项，`Tab` 只把
  选中项写入当前 token，`Enter` 才执行命令；`Shift+Tab` 不参与候选逻辑，无候选时 Tab 保持输入焦点且不修改文本。
  普通布局首次输入非空文本时经 `win.show name=mcp` 激活中央命令集页面，不调用 `win.max`；命令集删除独立搜索框，
  由控制台完整输入实时过滤命令名、说明和示例。`Shift+W/S` 循环选择列表结果，`Tab` 把所选命令名写回控制台但
  不执行，`Enter` 仍是唯一执行入口；聚焦 Popup 与普通命令集检索不得同时工作。
- 原因：独占 Shift 组合容易被系统快捷键劫持；W/S 组合提供明确的上下选择，同时把可见候选限定在真正需要快速
  输入的聚焦控制台。普通布局直接使用命令集页面，避免在底部控制台嵌入第二套快速指令 UI。
- 后果：候选、列表检索和选择属于 Shell 视图交互，但切换动作仍通过现有 `win.show`/`CommandBus`；不新增命令或
  公开 API。命令注册/注销会刷新两种候选；聚焦候选只替换当前 token，普通列表 Tab 替换完整输入。候选弹层必须
  遵守 Shell 主题令牌且不能改变控制台窗格宽度。
- 替代条件：只有未来引入统一、可声明且能覆盖模块动态命令的输入编辑器时，才可替代该内部候选引擎。

## DEC-018 3.1.10 共享命令目录会话

- 状态：已接受
- 日期：2026-08-08
- 决策：控制台补全、普通布局命令集检索和指令详情共享一个 Shell 内部 `CommandCatalogSession`。会话只经
  `CommandBus` 读取 `command.list`、`command.domains` 和 `command.show`，统一维护目录快照、延迟详情缓存、
  查询、筛选和选择；本地未注册目录命令的最小宿主才回退到 `CommandRegistry`。`ConsoleView` 与
  `McpToolsView` 保持独立呈现职责，不合并为单个 WPF 页面。
- 原因：双进程前端的本地注册表不包含后台模块命令，分别维护目录和详情会造成搜索、候选、列表及详情不一致。
- 后果：3.1.10 不新增公开 API 或命令；模块注册变化只使共享快照失效，远程参数详情按需加载并缓存。
  命令工作台未来可以作为 UI 模块外置，但 HistoryVulcan 继续拥有命令总线、控制台、日志和全局快捷键。
- 替代条件：只有引入版本化进程外目录协议，并能继续保证同一快照、详情缓存和共享选择语义时才可替代。

- 状态：已接受
- 日期：2026-08-10
- 决策：分四条同时生效。

## DEC-025 3.4.0 无类直接方法回归、域聚焦与注册域权威源

- 状态：已接受
- 日期：2026-08-10
- 取代：DEC-023 第 1 条中「「无类」概念一并废止」与「所有内置指令一律三段式」两句。
  DEC-023 的其余内容（九类命名、模块域去品牌前缀、门禁解耦、无人工交互）继续有效。
- 决策：分四条同时生效。
  1. **无类直接方法正式回归，成为受控类别**。命令名允许两段 `<域>.<方法>`，
     表示「该域的直接方法」，不属于任何类。三段 `<域>.<类>.<方法>` 仍是业务指令的默认形态。
     判定规则改为纯结构式：段数为 2 即无类；段数 ≥ 3 取第二段为类；
     描述符显式声明的 `CommandClass` 永远优先。
     两段名不再回退首段作为类——`arena.cell` 从此读作「域 arena 的直接方法 cell」，
     而不是「类 arena 的方法 cell」。
  2. **注册域是绝对名解析的唯一权威源**。`CommandRegistry` 暴露已注册命令名首段的集合，
     域清单随模块装载/卸载动态变化，任何地方都不得硬编码域名字面量。
  3. **域聚焦（domain focus）**。控制台输入可聚焦到某个域；聚焦期间：
     - 输入首段命中**已注册域**时按绝对名解析，不拼前缀；
     - 否则自动补上当前聚焦域前缀。
     因此 `mercury.go`、`vulcan.*` 等在任意聚焦状态下都能直接输入，
     无需每个域各自提供一条退出指令。聚焦状态与控制台域筛选下拉双向同步，
     下拉选「全部」即退出聚焦。
  4. **补全按域 → 类 → 方法 → 参数分段推进**，不再一次性平铺全名候选。
     参数候选只能来自模块注册时提供的 `ParameterSpec`，宿主与 Mercury 都不得猜测参数名。
- 原因：
  1. 上一轮把无类一并废止是矫枉过正。域的直接方法是一个真实且长期需要的类别——
     它给「插一条快捷方法」留出位置，而不必为一两条命令硬造一个类。
     受控地保留它，比让每个模块各自发明变通更可控。
  2. 绝对名脱固若依赖硬编码域清单，每接入一个新模块都要改宿主，
     这正是 DEC-023 第 3 条要消除的那种跨仓库耦合。
  3. 退出域聚焦如果做成每个域一条退出指令，会让每个模块都被迫耦合一份与自身业务无关的命令；
     用「首段是已注册域就按绝对名解析」这一条规则，退出能力自然涌现，零新增指令、零域耦合。
- 后果：
  - **影响面**：仍在注册两段式指令的消费方，其命令从「类.方法」改判为「域的直接方法」，
    在命令集与控制台里改为「无类」分组显示。命令名与调用方式不变，只是归类显示改变；
    其首段同时成为已注册域，参与绝对名解析。
    OneHistory 体系内已无此类消费方，本条只对体系外的独立分支适用。
  - 命令集与控制台恢复「无类」筛选项；DEC-023 删除的 `NoneLabel` 以受控形式回归，
    但只作为显示标签，不再承担类推导逻辑。
  - `mercury.go` 是无类直接方法的第一个正式用例：`mercury.go <域>` 进入聚焦，
    `mercury.go` 无参退出。
- 替代条件：若某个域的直接方法超过 5 条，应重新评估是否该为它们建类。

## DEC-024 3.3.2 诊断指令退出正式命令集，测试套件按执行效率与功能内聚重整

- 状态：已接受
- 日期：2026-08-10
- 决策：分两部分。
  1. **诊断指令不属于正式命令集**。承压注水 `vulcan.log.flood`（3.3.1 的 `debug.logflood`）
     三重收口：宿主默认**不注册**，需显式设置 `diagnostics.commands=true`；描述符标记
     `Dangerous` 并带确认提示；`McpExposurePolicy` 按名硬排除，MCP/Web 永不可达。
     保留能力而非删除——它是技术合同验收 8 / N-03 的承压入口，也是异步长任务 + Progress 的示范。
  2. **测试套件以执行效率为首要目标，按功能内聚组织**。不以拆分热点类为目的：
     - 「推进 UI」收敛为唯一所有者 `UiTestHost`（`Pump` / `PumpUntil` / `PumpFor` + `RunSta`），
       替换散落在三个文件里的三份拷贝；
     - 测试集合按**争用的独占资源**分组（`ui-foreground`、`network-gateway`），组内串行、组间并行，
       取代程序集级的一刀切串行开关；
     - UI 用例有 60 秒硬上限，超时抛出具名 `TimeoutException`。
- 原因：
  1. 影子域 `debug` 退役后，原先按 `"debug."` 前缀生效的 MCP 硬排除失配，承压注水一度可被远程
     触发（`rate=100000 × seconds=600` 即 6000 万条日志），这是对自身的拒绝服务面。
     且它本就不该出现在最终用户的命令集里。
  2. `PumpDispatcher` 无条件固定睡 300ms，43 个默认调用点占掉整轮约三分之二墙钟时间；
     `RunSta` 裸 `Join()` 使任何阻塞变成整轮静默挂死（曾出现 25 分钟零输出、
     testhost 累计 CPU 仅 9.5 秒），CI 上表现为 job 超时被杀且日志无线索。
- 后果：
  - 命令集不再出现 `debug` 类；需要承压时由宿主显式开启诊断开关。
  - 全量测试从 42 秒降到约 25 秒，用例数不减（159）。`DockingContractTests` 5.9 秒 → 1.1 秒。
  - 盲等被替换为具名等待：`PumpUntil` 表达「在等什么」，`PumpFor` 仅用于被测对象真的依赖时间
    （控制台 100ms 批量合并、`DockingHost` 200ms 缩放去抖）。这些时间常量此前被 300ms 盲等掩盖。
  - 剩余耗时的两个大头是结构性的，本轮不动：`ShellChromeContractTests` 每个用例构造完整
    `ShellWindow`（14.4 秒 / 33 用例）；`RemoteConfirmationQueueTimesOutWithoutExecutingOrDuplicatingAudit`
    受 `McpGateway` 确认超时下限 `Math.Clamp(t, 10, 600)` 约束固定耗时 10 秒——
    缩短它需要放宽一个安全相关的下限，不做。
- 替代条件：诊断指令若要进入正式命令集，需同级决策并重新评估远程暴露面；
  测试分组若要改为共享 `ShellWindow` 夹具，必须先证明用例间不存在状态污染。
