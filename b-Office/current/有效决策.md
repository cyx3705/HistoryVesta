# AppShell 有效决策

这里只保留仍会影响后续维护的决策。实现过程、已关闭问题和旧方案属于历史证据。

## DEC-001 包消费取代源码复制

- 状态：已接受
- 日期：2026-07-28
- 决策：023 是 AppShell 源码与合同唯一权威；消费方使用精确版本 `PackageReference`。
- 原因：消除 OHS、WBall 与框架源码分叉，建立独立版本和回滚边界。
- 后果：框架变化必须先发布包，再由消费方显式升级并复验。
- 替代条件：无；仅可由新的跨仓库分发架构显式替代。

## DEC-002 默认最小能力

- 状态：已接受
- 日期：2026-07-29
- 决策：MCP 与模块默认关闭；消费方显式启用。命令集和本地 `command.*` 不依赖 MCP。
- 原因：库不得因被引用就监听端口、扫描目录或创建治理状态。
- 后果：需要 MCP/模块的宿主必须在 `ShellConfig` 中声明。
- 替代条件：不得在 3.0.x 替代；新版本也必须单独安全评审。

## DEC-003 中央区使用原生文档主区

- 状态：已接受
- 日期：2026-07-29
- 决策：命令集是默认中央文档；中央区显示独立页面头和页签，普通工具页可拖入/拖出中央。
- 原因：避免空文档占位和并排工具窗导致的中央区塌缩，同时保留原生拖放。
- 后果：命令集不可隐藏、浮动或侧停靠；业务中央页与命令集共享文档组。
- 替代条件：仅在更换停靠引擎并完整重验交互合同时评估。

## DEC-004 模块窗口默认右置并合并同侧窗格

- 状态：已接受
- 日期：2026-07-29
- 决策：保留模块注册器和模块 UI 修改能力；运行期工具窗默认 `Right/0.25`，复用同侧标签组。
- 原因：避免每个模块生成独立右侧窗格并持续挤压中央主区。
- 后果：历史布局加载时合并同侧窗格，侧栏总占比不超过 50%。
- 替代条件：模块可显式覆盖有效配置，但不得突破布局安全上限。

## DEC-005 编辑源、归档与 Z 级快照分离

- 状态：已接受
- 日期：2026-07-29
- 决策：消费合同编辑源位于 `b-Office/package/`；正式历史归档在 `b-Publish/`；
  `z-Package-AppShell/` 只保存一个当前正式消费快照和稳定复用入口。
- 原因：避免副本漂移，并让跨项目索引直接命中稳定元地址。
- 后果：发布副本不得手改，历史版本不得堆入 Z 根目录。
- 替代条件：只有新的发布协议能同时提供版本寻址、校验和稳定入口时替代。

## DEC-006 V3 以 3.0.3 最终冻结

- 状态：已接受
- 日期：2026-07-29
- 决策：`v3.0.3` 是 V3 最终冻结基线；3.0.x 只接受致命崩溃、数据丢失或安全漏洞修复。
- 原因：OHS/WBall 已固定消费，继续功能演进会把不确定性转嫁给下游。
- 后果：不新增公开 API；一般功能和结构改造进入新版本线。
- 替代条件：启动并完成新版本线的公开合同、发布和消费门禁。

## DEC-007 CI 只自动化只读冻结门禁

- 状态：已接受
- 日期：2026-07-30
- 决策：`2026-023-AppShell` 每次推送自动执行锁定还原、双配置构建测试、格式和 API 基线检查；
  CI 不调用 `Publish-AppShell.ps1`，不发布、不打标签、不部署。
- 原因：持续防漂移，同时把不可逆发布动作留在人工审批边界内。
- 后果：GitHub Actions 结果是持续证据，但不能替代正式发布和消费方验收。
- 替代条件：只有建立受保护分支和明确发布授权模型后再扩展。

## DEC-009 开启 3.1 界面版本线且不动公开面

- 状态：已接受
- 日期：2026-08-06
- 决策：界面现代化进入新版本线 `3.1.0`，只改 `AppShell.Shell` 表现层；四份 `PublicAPI.Shipped.txt`
  不变、`Unshipped` 保持仅 `#nullable enable`；不新增任何外观开关。
- 原因：`DEC-006` 把功能演进挡在 3.0.x 之外，而外观开关一旦加入 `ShellConfig` 就是新增公开 API。
- 后果：消费方升级只改版本号、不改代码；需要旧外观者继续固定 3.0.3。因此
  `protected override` 一类改法不可用，钩子一律走事件订阅。
- 替代条件：只有在确实需要按宿主切换外观时，才另开公开面评审。

## DEC-010 以层次替代线条，并取消常驻菜单行与状态栏

- 状态：已接受
- 日期：2026-08-06
- 决策：停靠窗格改圆角卡片（间隙 + 投影），菜单折叠进顶栏且恒在三个窗口按钮左侧，
  页面最大化默认无壳铺满，底部状态栏取消，信息改由瞬时回执与顶栏承载；
  窗体外缘直角、内部统一 `Shell.Radius.Inner`。
- 原因：一屏十几条 1px 分隔线把界面切碎；两条常驻横带各自只承载少量信息。
  目标平台 Win10 IoT LTSC 2021 无系统窗口圆角，自绘外圆角会露黑角。
- 后果：AvalonDock 窗格模板由 Shell 接管（`ShellDocking.xaml`），主题版本升级时需同步复核；
  颜色与圆角只允许在 `ShellTokens.xaml` 定义。
- 替代条件：更换停靠引擎或引入深色/高对比主题时重新评估令牌层。

## DEC-011 3.1.1 命令管线与模块化收口

- 状态：已接受
- 日期：2026-08-06
- 决策：控制台顶部只保留级别和来源，其余检索与操作统一注册为 `log.*` 命令；窗口、复制示例、
  面板文件/目录选择等业务入口通过 `CommandBus` 执行。删除 AppShell 内置资源页、Workspace/res.*
  公开面和演示电机页；保留 `ModulesView` 作为唯一模块管理实现，OHS 只负责停靠位置与消费配置。
- 原因：让 UI、脚本、模块和 MCP 使用同一命令描述符，缩小复用包上下文，并避免 AppShell 与消费方重复维护资源/模块管理。
- 后果：3.1.1 接受资源 API 的破坏性移除；全局 `OneHistory-Projects\\*\\z-*` 模块扫描不在本版本范围，仍沿用现有模块目录抽象。
- 替代条件：资源浏览由独立模块提供；全局扫描另行完成安全边界、目录槽和热重载设计后再评审。

## DEC-008 固定工具链和 C# 检出行尾

- 状态：已接受
- 日期：2026-07-30
- 决策：SDK 固定为 9.0.315，C# 文件通过 `.gitattributes` 以 CRLF 检出。
- 原因：Windows Roslyn 格式结果受 SDK 和检出行尾影响，必须保证本机与干净 runner 输入一致。
- 后果：升级 SDK 或改变行尾规则前必须先验证 `dotnet format` 和分析器输出。
- 替代条件：工具链升级并在本机、CI 同时通过完整门禁。
