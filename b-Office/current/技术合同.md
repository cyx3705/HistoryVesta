# HistoryVulcan 技术合同

本文件合并当前有效的需求与架构。详细公共 API、命令参数和消费示例以
`../package/` 下的消费合同为准；历史设计和冻结施工记录不再作为现行实现依据。

## 现行需求

### REQ-PKG-001 宿主部署与兼容框架消费

- 目的：消除复制 HistoryVulcan 源码造成的分叉和隐式耦合。
- 要求：HistoryVulcan 自身以正式 Z 快照宿主部署（当前 **3.3.2** 位于 `z-HistoryVulcan/host/HistoryVulcan.exe`；
  3.1.x 曾位于旧名 `z-Package-AppShell/`），不复制源码、不从源码工程运行正式实例。
  需要把框架嵌入其他宿主时，四包必须从单独批准的兼容包源取得并锁定同一版本；当前源码与
  正式稳定消费版本同为 **3.3.2**，包 ID 为 `OneHistory.HistoryVulcan.*`（3.1.x 及以前为旧名 `OneHistory.AppShell.*`），
  正式部署不承诺提供 NuGet feed；3.1.8 不作为稳定支持版本。
- 验收：宿主候选和 Z 快照的版本、文件清单及 SHA-256 一致；兼容框架消费继续由公开 API 基线守住。
- 关联组件：`b-Code-HistoryVulcan/src/`
- 关联验证：`VERIFY-HOST`

### REQ-DOCK-001 单一窗口与中央主工作区

- 目的：在统一停靠模型中保证中央业务区可用，同时允许工具页自由停靠。
- 要求：命令集是默认中央文档；中央区显示自己的页面头和页面选择区。普通工具页可拖入中央
  成为标签，再拖出或停回四边；运行期同侧工具页复用同一标签窗格。
- 验收：真实 WPF 视觉树、拖放、持久化和恢复测试通过；左右或上下侧栏合计不超过对应轴 50%。
- 关联组件：`b-Code-HistoryVulcan/src/HistoryVulcan.Shell/`
- 关联验证：`VERIFY-FULL`

### REQ-DOCK-002 顶栏手势与页面拖出边界（3.1.3）

- 目的：避免慢速连点或轻微拖动误触窗口切换，并消除页头与页签对“拖出页面”的职责冲突。
- 要求：自定义双击必须是同一目标在 250ms 内、且指针未超出系统双击范围的两次有效点击。嵌入或聚焦
  页面的空白顶栏只控制 HistoryVulcan 主窗口；主窗口处于普通状态时越过系统拖动阈值即开始移动，不增加按住延时。
  主窗口最大化状态及独立浮窗仍需按住满 120ms 才允许移动；最大化状态使用两倍系统阈值，并在启动拖动时
  按鼠标横向比例恢复。延时场景的提前位移必须保留至 120ms 到期，任何一次按下只要越过移动阈值，就必须
  立即作废该次双击候选，即使 120ms 尚未到期；释放、失去捕获或双击必须取消拖动。主窗口移动不得
  改变当前聚焦页面。只有真实页签能够拖出页面：普通页签
  使用 AvalonDock 原生流程，聚焦页签执行 `win.restore` 后再执行 `win.float`。拖出尺寸来自恢复后的嵌入窗格
  实际宽高，鼠标维持原页签抓取点；跨显示器定位必须区分物理像素与 WPF DIP，并限制在目标显示器工作区。
- 验收：`ShellTopBarGestureTests` 覆盖普通主窗口无延时、其余宿主 119/120ms、提前位移、释放取消、
  250/251ms、两倍阈值、DPI、工作区裁剪和鼠标锚点；`ShellChromeContractTests` 覆盖普通、聚焦及
  独立浮窗动作矩阵。
- 关联组件：`b-Code-HistoryVulcan/src/HistoryVulcan.Shell/`
- 关联验证：`VERIFY-FULL` 与 Windows GUI 冒烟

### REQ-CMD-010 指令分类法：三段业务指令与两段直接方法（3.4.0，DEC-025）

- 目的：让「域|类|方法」模型只有两种合法形态且判定纯结构化，使目录筛选、控制台补全和
  MCP schema 三处共用同一套判定，不再为影子域留特例路径。
- 要求：
  1. 合法形态恰有两种，全小写、无连字符、不留别名：
     - **三段 `<域>.<类>.<方法>`** —— 业务指令的默认形态；
     - **两段 `<域>.<方法>`** —— 该域的**无类直接方法**，为「插一条快捷方法」保留，
       不属于任何类。
  2. 类推导是纯结构式判定，不做语义猜测：
     段数 ≥ 3 取第二段为类；段数 = 2 判为无类（**不再回退首段作为类**）；
     描述符显式声明的 `CommandClass` 永远优先。
  3. `vulcan` 域内置**三段**指令归入且仅归入九类：`app`、`command`、`ui`、`log`、`mcp`、
     `module`、`prompt`、`svc`、`web`。新增内置三段指令必须并入既有类，不得为单条指令新开一类。
     内置直接方法（两段）不受九类约束，但同一域的直接方法超过 5 条时应重新评估是否建类。
  4. 「无类」是受控的显示类别：目录与命令集的类筛选含「无类」项，
     该标签只用于显示，不参与类推导。
  5. 不存在没有所有者的域。内置指令域恒为 `vulcan`，模块域由 owner 强制（见 REQ-CMD-011）。
  6. **已注册域是绝对名解析的唯一权威源**：`CommandRegistry` 暴露全部已注册命令名首段的集合，
     随模块装载/卸载动态变化。任何组件都不得硬编码域名字面量。
- 影响面：任何仍在注册两段式指令的消费方，其命令按第 2 条从「类.方法」改判为
  「域的直接方法」，归类显示变为「无类」。命令名与调用方式不变，其首段同时成为已注册域
  并参与绝对名解析。OneHistory 体系内已无此类消费方——本条只对体系外的独立分支适用。
- 验收：`CommandTaxonomyContractTests` 断言运行期注册表内每条指令都是两段或三段、
  域 ∈ {`vulcan`, 模块域}、三段指令的类 ∈ 九类、两段指令判为无类；
  `vulcan.command.domains` 只报 `vulcan` 与已装载模块域。
- 关联组件：`HistoryVulcan.Core/Commands/CommandRegistry`、各 `BuiltinCommands.*`
- 关联验证：`VERIFY-FULL`

### REQ-CMD-012 域聚焦与绝对名脱固（3.4.0，DEC-025）

- 目的：让用户在长时间只操作某一个域时不必反复输入域前缀，同时**不要求任何域**
  为「退出聚焦」提供指令。
- 要求：
  1. 控制台输入可聚焦到某个已注册域。聚焦期间输入解析恰有两条规则：
     - 输入首段命中**已注册域** → 按绝对名解析，不拼前缀；
     - 否则 → 自动补当前聚焦域前缀。
  2. 由第 1 条推出：`mercury.go`、`vulcan.*` 等在任意聚焦状态下都可直接输入。
     **不得**为退出聚焦在各域内新增指令。
  3. 聚焦状态与控制台域筛选下拉双向同步；下拉选「全部」即退出聚焦。
  4. 首段同时是已注册域、又是当前聚焦域下某个类时按绝对名优先，
     并在补全候选中同时给出两种解释，由用户选择。
- 验收：`CommandTaxonomyContractTests` 与控制台用例覆盖上述四条；
  域清单取自注册表而非常量表。
- 关联组件：`HistoryVulcan.Shell/Console/ConsoleView`、`CommandRegistry`
- 关联验证：`VERIFY-FULL`

### REQ-CMD-011 模块指令域去品牌前缀（3.3.2）

- 目的：模块名的 `History` 品牌前缀标识产品族归属，但在指令域段里对所有模块都相同，
  不携带区分信息，只是让每条指令、每行目录和每份 schema 变长。
- 要求：模块注册名（manifest `name`、程序集、目录、Z 快照）**保留** `History` 前缀；
  指令域取去掉前缀后的小写主体。归一化唯一真值为
  `HistoryVulcan.Core.Commands.ModuleDomainNaming.ToDomain(moduleName)`：
  大小写不敏感剥离开头 `History` 并转小写；剥离后为空时退回原名小写；不以 `History`
  开头者原样转小写。`CommandRegistry.ResolveDomain` 与 `ModuleHost` 强制 owner 时调用同一函数，
  描述符自填的 `Domain` 一律被覆盖。
- 验收：`ModuleDomainNamingTests` 覆盖 `HistoryJanus`→`janus`、`HistoryMercury`→`mercury`、
  `WBall`→`wball`、`History`→`history`、大小写与空白输入；`ModuleHost` 装载用例断言
  模块指令域为归一化结果而非 manifest 原名。
- 关联组件：`HistoryVulcan.Core/Commands/ModuleDomainNaming`、`HistoryVulcan.Services/Modules/ModuleHost`
- 关联验证：`VERIFY-FULL`

### REQ-CMD-012 指令不得依赖人工交互（3.3.2）

- 目的：能经 MCP、Web 或前端转发触发的指令，若其成功路径需要人工点击，
  会在非交互宿主上阻塞 UI 线程直到超时——这是断头指令的第二种形态。
- 要求：所有指令必须存在一条不弹模态对话框即可完成的默认路径。
  `vulcan.log.export` 省略 `path` 时写入 `AppPaths.Root/exports/console-<yyyyMMdd-HHmmss>.txt`
  并在 `CommandResult` 中返回绝对路径，不得弹 `SaveFileDialog`。
  以「请用户选择」为产品语义本身的指令（`vulcan.ui.selectfile`、`vulcan.ui.selectdirectory`）
  标注为交互式，只在有 UI 的宿主注册。
- 验收：`ConsoleExportWithoutPathWritesDefaultFileWithoutDialog` 在无人值守下断言文件落盘且路径回传；
  `断头指令审计表.md` 逐条标注交互式指令。
- 关联组件：`HistoryVulcan.Shell/Console/ConsoleView`、`BuiltinCommands.Log`
- 关联验证：`VERIFY-FULL`

### REQ-CONSOLE-001 域/类筛选与响应式输出（3.1.5，3.2.1 分类升级，3.2.2 严格层级）

- 目的：让命令集与控制台使用同一域概念，并保证任意长度的输出不改变控制台窗格宽度。
- 要求：3.2.1 起一个宿主或模块对应一个域，域内功能分支对应命令类；HistoryVulcan 内置命令统一属于 `vulcan` 域。`CommandRegistry.GetDomain/GetCommandClass` 是运行期分类真值，`vulcan.command.domains` 按有效域统计；控制台与命令集显示同一已注册域集合，命令集提供域/类/MCP 筛选但不提供注册来源筛选或来源列；
  `CommandCatalogRow.Source/SourceDetail`、`CommandRegistry.GetSource` 与 `FrontendCommandCatalog.Source` 继续保持注册来源语义。
  控制台已注册命令回显从注册表取有效域，结果/进度在既有 `cmd:result` / `cmd:progress` 前缀后携带域；普通日志
  类别的首个 `:` 或 `.` 前缀仅在命中已注册域时采用，否则归入 `core`，不得形成控制台私有域。
  `vulcan.log.source source=...` 保留为兼容入口，只接受运行期已注册域；`vulcan.log.class class=...` 查询或设置当前域内类。
  3.2.2 起 `CommandCatalogSession` 是域、类、检索词和选择状态的唯一持有者：域为“全部”时类必须为“全部”且
  类选择器禁用；选中具体域后只列出该域的类，域变化时不存在的类自动收敛到“全部”。控制台和命令集的
  域/类 UI 都必须通过 `CommandBus` 修改同一会话，补全、检索、W/S 选择和 Tab 写入使用同一过滤结果。
  输出列表禁用水平滚动，行文本按当前可用宽度软换行；窗格变窄或变宽时由 WPF 重新排版，不写入逻辑换行。
- 验收：内置单域、模块域所有权、类回退、跨进程传播、结果与进度并发隔离、两页同集、注册/注销同步、
  未知域拒绝和域/类联动筛选测试通过；
  真实 WPF 测试确认无空格长串 `ScrollableWidth == 0`、水平条折叠、窄时行高增加、宽时行高降低，导出文本无软换行。
- 关联组件：`HistoryVulcan.Core/Commands/CommandBus`、`HistoryVulcan.Shell/Console`、`McpToolsView`、`ShellControls.xaml`
- 关联验证：`VERIFY-FULL` 与停靠/浮动/最大化控制台 GUI 冒烟

### REQ-CONSOLE-002 轻松指令与共享命令目录（3.1.8，3.1.10 内聚重构）

- 目的：让用户无需记住完整命令、参数名和枚举值，同时保持命令文本仍是唯一执行合同。
- 要求：Shell 内部只持有一个 `CommandCatalogSession`，通过 `CommandBus` 的 `vulcan.command.list` / `vulcan.command.domains`
  取得权威目录，通过 `vulcan.command.show` 延迟取得并缓存参数详情；本地无目录命令时才回退到 `CommandRegistry`。
  仅当控制台自身处于 `DockingHost.MaximizedId == StandardWindowIds.Console` 聚焦态时，非空输入按当前光标
  token 从该共享目录生成命令名、参数名和 `AllowedValues` 候选，并以不抢焦点的 Popup 显示在输入框上方；
  `Shift+W` 反向循环到上一项，`Shift+S` 正向循环到下一项，`Tab` 只替换当前 token，`Enter` 才提交 `CommandBus`。
  `Shift+Tab` 不参与候选逻辑；命令注册或注销后候选同步刷新，半输入、未闭合引号和行中光标不得破坏原文本其他部分。
  普通布局下控制台仍可执行完整手输命令，首次非空输入通过 `vulcan.ui.show name=mcp` 切换中央命令集页面且不最大化；
  命令集不再提供独立搜索框，控制台完整输入实时按命令名、说明和示例过滤列表。列表自动选中首个有效结果，
  `Shift+W/S` 循环选择，`Tab` 将所选命令名写回控制台但不执行；清空、提交或 `Esc` 后恢复全部列表。聚焦 Popup
  与普通布局命令集检索必须互斥，命令注册或注销后使共享快照失效并按当前输入重新收敛结果和选择。
  `CommandSurfaceFeature` 统一拥有控制台、命令集、指令详情、共享目录会话、补全引擎、窗口描述符和聚焦门面；
  `ShellWindow` 不得直接编排这些具体视图。3.2.2 仍为内建特性，不建立独立程序集。
- 验收：目录会话与补全引擎由 HistoryMercury 实现，其 `CommandCatalogSessionTests` / `ConsoleCompletionTests`
  自 3.3.2 起在 **HistoryMercury 仓库**执行（DEC-023 门禁解耦）；Vulcan 侧只验证 Core 合同与
  `DeferredCommandCatalogSession` 无 Mercury 时的降级路径。
  `ShellChromeContractTests` 确认命令集无搜索框、控制台检索与指令详情联动，并确认 `vulcan.ui.show name=mcp` 不设置
  `MaximizedId`。浅色/深色及窄控制台人工冒烟无系统默认颜色、遮挡或水平撑宽。
- 关联组件：`HistoryVulcan.Shell/Console`、`HistoryVulcan.Shell/Views/CommandCatalogSession`
- 关联验证：`VERIFY-FULL` 与 Windows GUI 冒烟

### REQ-CAP-001 默认最小能力

- 关联组件：`HistoryVulcan.Shell/ShellConfig`、`HistoryVulcan.Services`
- 关联验证：`VERIFY-FULL`

### REQ-SVC-001 双进程后台服务与快捷键（3.1.2，方案源自 3.2 历史设计）

- 目的：让命令、非 UI 模块、日志、MCP/Web 和全局快捷键在用户会话后台持续运行，前端只承载 WPF 与 UI 模块。
- 要求：独立宿主使用同一 EXE 的 `--service` 分支；前端通过 loopback 端点连接，重复启动只激活已有前端；
  独立宿主关闭默认隐藏，`app.exit` 协调两端退出。快捷键只映射命令文本、不吞键、不保存原始按键，
  模块卸载释放其 owner 的全部注册；整体热重载必须先释放旧快照的快捷键 owner，再登记新快照，
  不得因同一模块的旧注册尚在而拒绝新注册。
- 要求：双 `/` 执行 `app.frontend.focus-console` 时，无论控制台原先隐藏或已经显示，都必须将主窗口提升到 Windows
  前台、切换控制台聚焦布局并把键盘焦点落入命令输入框；提升只改变当前 Z 序，不得让窗口永久保持 `Topmost`。

## 系统架构

### 系统边界

HistoryVulcan 管理通用壳层能力和扩展合同，不拥有消费应用的业务模型。Core 不依赖 WPF；Services
实现通用服务；Shell 是唯一直接封装 AvalonDock 的层；ServiceHost 提供用户会话无窗后台进程。资源浏览/文件
操作不属于 HistoryVulcan，未来由独立模块提供。

### 组成

| 组件 | 路径 | 职责 | 主要输出 |
| --- | --- | --- | --- |
| Core | `b-Code-HistoryVulcan/src/HistoryVulcan.Core` | 命令、停靠、日志、MCP、存储等契约 | `OneHistory.HistoryVulcan.Core` |
| Services | `b-Code-HistoryVulcan/src/HistoryVulcan.Services` | 设置、文件状态、日志、MCP、模块实现 | `OneHistory.HistoryVulcan.Services` |
| Shell | `b-Code-HistoryVulcan/src/HistoryVulcan.Shell` | WPF 主壳、停靠 UI、控制台、面板与模块管理 | `OneHistory.HistoryVulcan.Shell` |
| ServiceHost | `b-Code-HistoryVulcan/src/HistoryVulcan.ServiceHost` | 无窗服务宿主和 `svc.*` 生命周期 | `OneHistory.HistoryVulcan.ServiceHost` |
| App | `b-Code-HistoryVulcan/src/App` | 单 EXE 前端/后台入口与 GUI 验收宿主 | win-x64 framework-dependent ZIP |
| Tests | `b-Code-Tests/HistoryVulcan.Tests` | 公开合同、安全、布局与冻结回归 | TRX 与进程退出码 |

### 关键流程

1. 消费方固定包版本，创建 `ShellConfig`，只显式启用需要的模块或 MCP 能力。
2. 普通 EXE 启动 WPF 前端；`--service` 启动后台权威宿主，前端通过 loopback 发布 UI 命令目录并接收中继。
3. Shell 组装日志、布局和窗口；模块通过注册合同增加命令与工具页；全局快捷键只向后台命令总线提交命令文本。
4. 候选流水线隔离还原、构建、测试、审计、打包和 PackageSmoke，人工批准后才提升正式快照。

### 不变量与生成物边界

- Core 保持零 WPF 依赖；AvalonDock 只从 Shell 直接引用。
- 所有命令执行进入同一总线；危险命令进入统一确认边界。
- 正式包和 Z 级快照不直接编辑；权威源是源码、`b-Office/package/` 与发布模板。
- HistoryVulcan 只保留 `ModulesView` 这一套模块管理页面；独立 HistoryVulcan 可执行宿主显式启用 `EnableModules` 并成为
  模块生命周期所有者。Janus 只提供停靠位置与消费配置，后续业务能力以模块接入，不复制页面或第二个 `ModuleHost`。
- 3.1.1 删除内置资源浏览能力和演示电机页面；`res.*`、`motor.*` 不再注册。
- `b-Publish/current/`、`b-Publish/virtual/`、`bin/`、`obj/`、`artifacts/` 是可重建生成物。
- `b-Publish/` 的版本化正式归档和 `z-HistoryVulcan/` 当前快照是发布资产。
