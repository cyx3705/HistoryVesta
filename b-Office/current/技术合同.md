# AppShell 技术合同

本文件合并当前有效的需求与架构。详细公共 API、命令参数和消费示例以
`../package/` 下的消费合同为准；历史设计和冻结施工记录不再作为现行实现依据。

## 现行需求

### REQ-PKG-001 宿主部署与兼容框架消费

- 目的：消除复制 AppShell 源码造成的分叉和隐式耦合。
- 要求：AppShell 自身以 `z-Package-AppShell/host/AppShell.exe` 部署，不复制源码、不从源码工程运行正式实例。
  需要把框架嵌入其他宿主时，四包必须从单独批准的兼容包源取得并锁定同一版本；当前 3.1.7 Z 快照
  不承诺提供 NuGet feed。
- 验收：宿主候选和 Z 快照的版本、文件清单及 SHA-256 一致；兼容框架消费继续由公开 API 基线守住。
- 关联组件：`b-Code-AppShell/src/`
- 关联验证：`VERIFY-PACKAGE`

### REQ-DOCK-001 单一窗口与中央主工作区

- 目的：在统一停靠模型中保证中央业务区可用，同时允许工具页自由停靠。
- 要求：命令集是默认中央文档；中央区显示自己的页面头和页面选择区。普通工具页可拖入中央
  成为标签，再拖出或停回四边；运行期同侧工具页复用同一标签窗格。
- 验收：真实 WPF 视觉树、拖放、持久化和恢复测试通过；左右或上下侧栏合计不超过对应轴 50%。
- 关联组件：`b-Code-AppShell/src/AppShell.Shell/`
- 关联验证：`VERIFY-FULL`

### REQ-DOCK-002 顶栏手势与页面拖出边界（3.1.3）

- 目的：避免慢速连点或轻微拖动误触窗口切换，并消除页头与页签对“拖出页面”的职责冲突。
- 要求：自定义双击必须是同一目标在 250ms 内、且指针未超出系统双击范围的两次有效点击。嵌入或聚焦
  页面的空白顶栏只控制 AppShell 主窗口；主窗口处于普通状态时越过系统拖动阈值即开始移动，不增加按住延时。
  主窗口最大化状态及独立浮窗仍需按住满 120ms 才允许移动；最大化状态使用两倍系统阈值，并在启动拖动时
  按鼠标横向比例恢复。延时场景的提前位移必须保留至 120ms 到期，任何一次按下只要越过移动阈值，就必须
  立即作废该次双击候选，即使 120ms 尚未到期；释放、失去捕获或双击必须取消拖动。主窗口移动不得
  改变当前聚焦页面。只有真实页签能够拖出页面：普通页签
  使用 AvalonDock 原生流程，聚焦页签执行 `win.restore` 后再执行 `win.float`。拖出尺寸来自恢复后的嵌入窗格
  实际宽高，鼠标维持原页签抓取点；跨显示器定位必须区分物理像素与 WPF DIP，并限制在目标显示器工作区。
- 验收：`ShellTopBarGestureTests` 覆盖普通主窗口无延时、其余宿主 119/120ms、提前位移、释放取消、
  250/251ms、两倍阈值、DPI、工作区裁剪和鼠标锚点；`ShellChromeContractTests` 覆盖普通、聚焦及
  独立浮窗动作矩阵。
- 关联组件：`b-Code-AppShell/src/AppShell.Shell/`
- 关联验证：`VERIFY-FULL` 与 Windows GUI 冒烟

### REQ-CMD-001 统一命令合同

- 目的：让 UI、脚本、模块、MCP、Web 和服务宿主共享可查询、可治理的命令模型。
- 要求：命令必须经注册表和总线执行，具备来源、参数、安全级别、执行站点和 MCP 允许标记；
  基础命令组由 `AppShell_API与指令手册.md` 固定。
- 验收：命令解析、注册冲突、确认、线程编组、前端代理和目录导出测试通过。
- 关联组件：`AppShell.Core/Commands`、`AppShell.Shell`
- 关联验证：`VERIFY-FULL`

### REQ-CMD-002 业务入口统一走命令管线（3.1.1）

- 目的：消除 UI 按钮直接改服务或窗口状态造成的断头指令。
- 要求：会改变应用状态或执行外部操作的控制台、窗口、复制示例和面板选择入口必须调用
  `CommandBus`；检索与控制台操作使用 `log.level/source/keyword/mute/autoscroll/clear/export/copy/focus`。
  浮窗宿主状态使用 `win.float-state`；顶部回执、全局控制台快捷键、系统关闭隐藏、命令集、模块管理和
  命令详情/治理入口也必须复用现有命令描述符。`cls` 仅作为 `log.clear` 兼容别名保留。
  不改变窗格或业务状态的文本框焦点、列表选择和 Tab 导航不作为业务命令。
- 验收：`断头指令审计表.md`、`ShellChromeContractTests` 和命令注册测试全部通过。

### REQ-CONSOLE-001 域筛选与响应式输出（3.1.5）

- 目的：让命令集与控制台使用同一域概念，并保证任意长度的输出不改变控制台窗格宽度。
- 要求：命令域取命令名第一个 `.` 前缀，无点命令归 `core`。`command.domains` 是运行期域目录的唯一真值，
  控制台与命令集都通过命令总线读取并显示完全相同的已注册域集合；命令集不再提供注册来源筛选或来源列；
  `CommandCatalogRow.Source/SourceDetail`、`CommandRegistry.GetSource` 与 `FrontendCommandCatalog.Source` 继续保持注册来源语义。
  控制台命令回显从命令文本取域，结果/进度在既有 `cmd:result` / `cmd:progress` 前缀后携带域；普通日志
  类别的首个 `:` 或 `.` 前缀仅在命中已注册域时采用，否则归入 `core`，不得形成控制台私有域。
  `log.source source=...` 保留为兼容入口，只接受运行期已注册域。
  输出列表禁用水平滚动，行文本按当前可用宽度软换行；窗格变窄或变宽时由 WPF 重新排版，不写入逻辑换行。
- 验收：域提取、未知/根命令、结果与进度并发隔离、两页同集、注册/注销同步、未知域拒绝和单一命令集域筛选测试通过；
  真实 WPF 测试确认无空格长串 `ScrollableWidth == 0`、水平条折叠、窄时行高增加、宽时行高降低，导出文本无软换行。
- 关联组件：`AppShell.Core/Commands/CommandBus`、`AppShell.Shell/Console`、`McpToolsView`、`ShellControls.xaml`
- 关联验证：`VERIFY-FULL` 与停靠/浮动/最大化控制台 GUI 冒烟

### REQ-CAP-001 默认最小能力

- 目的：框架包不得在消费方未授权时启动监听、扫描模块或建立治理状态。
- 要求：`ShellConfig.EnableMcp` 与 `EnableModules` 默认均为 `false`；本地 `command.*` 和中央
  命令集不依赖 MCP 网关。消费方必须显式开启所需能力。
- 验收：默认配置下不创建 MCP 网关、模块宿主或监听端口，本地命令与主工作区仍可用。
- 关联组件：`AppShell.Shell/ShellConfig`、`AppShell.Services`
- 关联验证：`VERIFY-FULL`

### REQ-SVC-001 双进程后台服务与快捷键（3.1.2，方案源自 3.2 历史设计）

- 目的：让命令、非 UI 模块、日志、MCP/Web 和全局快捷键在用户会话后台持续运行，前端只承载 WPF 与 UI 模块。
- 要求：独立宿主使用同一 EXE 的 `--service` 分支；前端通过 loopback 端点连接，重复启动只激活已有前端；
  独立宿主关闭默认隐藏，`app.exit` 协调两端退出。快捷键只映射命令文本、不吞键、不保存原始按键，
  模块卸载释放其 owner 的全部注册。
- 要求：双 `/` 执行 `app.frontend.focus-console` 时，无论控制台原先隐藏或已经显示，都必须将主窗口提升到 Windows
  前台、切换控制台聚焦布局并把键盘焦点落入命令输入框；提升只改变当前 Z 序，不得让窗口永久保持 `Topmost`。
- 验收：服务端点健康检查、前端重连/单实例、`app.frontend.*` 命令、双 `/` 与快捷键冲突测试通过；
  `FrontendFocusConsoleRaisesTheWindowAndRefocusesExistingConsole` 覆盖隐藏唤醒和已显示时再次上浮聚焦。
- 关联组件：`AppShell.ServiceHost`、`AppShell.Services/Input`、`AppShell.Shell`
- 关联验证：`VERIFY-FULL`、双进程烟测

### REQ-MOD-001 模块 UI 生命周期

- 验收：模块装载、热重载、回收、右侧合并和 SE2SW 真实窗口冒烟通过。
- 关联组件：`AppShell.Services/Modules`、`AppShell.Shell`
- 关联验证：`VERIFY-FULL`

## 系统架构

### 系统边界

AppShell 管理通用壳层能力和扩展合同，不拥有消费应用的业务模型。Core 不依赖 WPF；Services
实现通用服务；Shell 是唯一直接封装 AvalonDock 的层；ServiceHost 提供用户会话无窗后台进程。资源浏览/文件
操作不属于 AppShell，未来由独立模块提供。

### 组成

| 组件 | 路径 | 职责 | 主要输出 |
| --- | --- | --- | --- |
| Core | `b-Code-AppShell/src/AppShell.Core` | 命令、停靠、日志、MCP、存储等契约 | `OneHistory.AppShell.Core` |
| Services | `b-Code-AppShell/src/AppShell.Services` | 设置、文件状态、日志、MCP、模块实现 | `OneHistory.AppShell.Services` |
| Shell | `b-Code-AppShell/src/AppShell.Shell` | WPF 主壳、停靠 UI、控制台、面板与模块管理 | `OneHistory.AppShell.Shell` |
| ServiceHost | `b-Code-AppShell/src/AppShell.ServiceHost` | 无窗服务宿主和 `svc.*` 生命周期 | `OneHistory.AppShell.ServiceHost` |
| App | `b-Code-AppShell/src/App` | 单 EXE 前端/后台入口与 GUI 验收宿主 | win-x64 framework-dependent ZIP |
| Tests | `b-Code-Tests/AppShell.Tests` | 公开合同、安全、布局与冻结回归 | TRX 与进程退出码 |

### 关键流程

1. 消费方固定包版本，创建 `ShellConfig`，只显式启用需要的模块或 MCP 能力。
2. 普通 EXE 启动 WPF 前端；`--service` 启动后台权威宿主，前端通过 loopback 发布 UI 命令目录并接收中继。
3. Shell 组装日志、布局和窗口；模块通过注册合同增加命令与工具页；全局快捷键只向后台命令总线提交命令文本。
4. 候选流水线隔离还原、构建、测试、审计、打包和 PackageSmoke，人工批准后才提升正式快照。

### 不变量与生成物边界

- Core 保持零 WPF 依赖；AvalonDock 只从 Shell 直接引用。
- 所有命令执行进入同一总线；危险命令进入统一确认边界。
- 正式包和 Z 级快照不直接编辑；权威源是源码、`b-Office/package/` 与发布模板。
- AppShell 只保留 `ModulesView` 这一套模块管理页面；独立 AppShell 可执行宿主显式启用 `EnableModules` 并成为
  模块生命周期所有者。OHS 只提供停靠位置与消费配置，后续业务能力以模块接入，不复制页面或第二个 `ModuleHost`。
- 3.1.1 删除内置资源浏览能力和演示电机页面；`res.*`、`motor.*` 不再注册。
- `b-Publish/current/`、`b-Publish/virtual/`、`bin/`、`obj/`、`artifacts/` 是可重建生成物。
- `b-Publish/` 的版本化正式归档和 `z-Package-AppShell/` 当前快照是发布资产。
