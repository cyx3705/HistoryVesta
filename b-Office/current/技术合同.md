# AppShell 技术合同

本文件合并当前有效的需求与架构。详细公共 API、命令参数和消费示例以
`../package/` 下的四份消费合同为准；历史设计和冻结施工记录不再作为现行实现依据。

## 现行需求

### REQ-PKG-001 固定版本包消费

- 目的：消除复制 AppShell 源码造成的分叉和隐式耦合。
- 要求：桌面消费方引用 `OneHistory.AppShell.Shell 3.0.3`；服务宿主额外引用
  `OneHistory.AppShell.ServiceHost 3.0.3`，不得直接引用本仓库源码工程。
- 验收：隔离 NuGet 缓存可从正式 Z 级 feed 还原、构建并报告 3.0.3。
- 关联组件：`b-Code-AppShell/src/`
- 关联验证：`VERIFY-PACKAGE`

### REQ-DOCK-001 单一窗口与中央主工作区

- 目的：在统一停靠模型中保证中央业务区可用，同时允许工具页自由停靠。
- 要求：命令集是默认中央文档；中央区显示自己的页面头和页面选择区。普通工具页可拖入中央
  成为标签，再拖出或停回四边；运行期同侧工具页复用同一标签窗格。
- 验收：真实 WPF 视觉树、拖放、持久化和恢复测试通过；左右或上下侧栏合计不超过对应轴 50%。
- 关联组件：`b-Code-AppShell/src/AppShell.Shell/`
- 关联验证：`VERIFY-FULL`

### REQ-CMD-001 统一命令合同

- 目的：让 UI、脚本、模块、MCP、Web 和服务宿主共享可查询、可治理的命令模型。
- 要求：命令必须经注册表和总线执行，具备来源、参数、安全级别、执行站点和 MCP 允许标记；
  基础命令组由 `AppShell_API与指令手册.md` 固定。
- 验收：命令解析、注册冲突、确认、线程编组、前端代理和目录导出测试通过。
- 关联组件：`AppShell.Core/Commands`、`AppShell.Shell`
- 关联验证：`VERIFY-FULL`

### REQ-CAP-001 默认最小能力

- 目的：框架包不得在消费方未授权时启动监听、扫描模块或建立治理状态。
- 要求：`ShellConfig.EnableMcp` 与 `EnableModules` 默认均为 `false`；本地 `command.*` 和中央
  命令集不依赖 MCP 网关。消费方必须显式开启所需能力。
- 验收：默认配置下不创建 MCP 网关、模块宿主或监听端口，本地命令与主工作区仍可用。
- 关联组件：`AppShell.Shell/ShellConfig`、`AppShell.Services`
- 关联验证：`VERIFY-FULL`

### REQ-MOD-001 模块 UI 生命周期

- 目的：保留模块注册和修改能力，同时避免模块窗口挤压主工作区或重复生成窗格。
- 要求：UI 模块通过 `IShellUiRegistrar.RegisterToolWindow` 注册；默认位置为右侧、默认比例 0.25，
  同侧优先合并为标签。owner 卸载时回收其窗口和命令；模块可显式覆盖有效停靠配置。
- 验收：模块装载、热重载、回收、右侧合并和 SE2SW 真实窗口冒烟通过。
- 关联组件：`AppShell.Services/Modules`、`AppShell.Shell`
- 关联验证：`VERIFY-FULL`

### REQ-MCP-001 MCP 与 Web 安全边界

- 目的：提供可选远程接入而不扩大默认攻击面或泄露敏感信息。
- 要求：端口按应用身份稳定派生并有界顺延；命令只有显式 `AllowMcpExecution=true` 才能暴露；
  鉴权、限流、确认、会话隔离、消息上限、固定时长令牌比较和脱敏审计必须保持。
- 验收：协议、鉴权、坏帧、分片、限流、确认、脱敏和审计测试通过。
- 关联组件：`AppShell.Core/Mcp`、`AppShell.Services/Mcp`、`AppShell.ServiceHost`
- 关联验证：`VERIFY-FULL`

### REQ-REL-001 发布真值与不可变性

- 目的：区分可编辑源、审核候选、历史归档和当前正式快照。
- 要求：消费文档只编辑 `b-Office/package/`；候选覆盖写入 `b-Publish/current/`；正式发布先更新
  Z 当前快照，再把同一最小快照写入 `b-Publish/history/<版本>/`。CI 不得调用正式发布路径。
- 验收：manifest、文件清单、包身份、文档副本和 SHA-256 一致；正式来源提交洁净。
- 关联组件：`b-Code-AppShell/eng/Publish-AppShell.ps1`
- 关联验证：`VERIFY-RELEASE`

### REQ-FREEZE-001 3.0.x 冻结纪律

- 目的：让固定消费方能够长期依赖可预测合同。
- 要求：3.0.x 不新增公开 API，`PublicAPI.Unshipped.txt` 不得出现有效条目；冻结后只处理致命
  崩溃、数据丢失或安全漏洞。其他变化进入后续版本线。
- 验收：公开 API 脚本、双配置构建测试、格式门禁和消费方回归通过。
- 关联组件：四个公共项目与 `.github/workflows/appshell-freeze-gate.yml`
- 关联验证：`VERIFY-CI`

## 系统架构

### 系统边界

AppShell 管理通用壳层能力和扩展合同，不拥有消费应用的业务模型。Core 不依赖 WPF；Services
实现通用服务；Shell 是唯一直接封装 AvalonDock 的层；ServiceHost 提供无窗 WPF 服务进程。

### 组成

| 组件 | 路径 | 职责 | 主要输出 |
| --- | --- | --- | --- |
| Core | `src/AppShell.Core` | 命令、停靠、日志、MCP、存储等契约 | `OneHistory.AppShell.Core` |
| Services | `src/AppShell.Services` | 设置、工作区、日志、MCP、模块实现 | `OneHistory.AppShell.Services` |
| Shell | `src/AppShell.Shell` | WPF 主壳、停靠 UI、内置命令 | `OneHistory.AppShell.Shell` |
| ServiceHost | `src/AppShell.ServiceHost` | 无窗服务宿主和 `svc.*` 生命周期 | `OneHistory.AppShell.ServiceHost` |
| Demo | `src/App` | 独立运行与 GUI 验收宿主 | win-x64 framework-dependent ZIP |
| Tests | `tests/AppShell.Tests` | 公开合同、安全、布局与冻结回归 | TRX 与进程退出码 |

### 关键流程

1. 消费方固定包版本，创建 `ShellConfig`，只显式启用需要的模块或 MCP 能力。
2. Shell 组装命令、日志、布局和窗口；模块通过注册合同增加命令与工具页。
3. 候选流水线隔离还原、构建、测试、审计、打包和 PackageSmoke，人工批准后才提升正式快照。

### 不变量与生成物边界

- Core 保持零 WPF 依赖；AvalonDock 只从 Shell 直接引用。
- 所有命令执行进入同一总线；危险命令进入统一确认边界。
- 正式包和 Z 级快照不直接编辑；权威源是源码、`b-Office/package/` 与发布模板。
- `b-Publish/current/`、`b-Publish/virtual/`、`bin/`、`obj/`、`artifacts/` 是可重建生成物。
- `b-Publish/` 的版本化正式归档和 `z-Package-AppShell/` 当前快照是发布资产。
