# HistoryJanus 技术合同

## 现行需求

### REQ-001 宿主化运行

- Janus 必须作为 `HistoryJanus` 模块由 AppShell 加载，不创建独立应用、后台服务或第二套 Shell。
- UI 宿主注册 `overview`、`tree`、`meta`、`projops`、`history` 五个单例窗口。
- UI 与无 UI Service 宿主都必须注册同一组 Janus 业务命令，来源统一为 `module:HistoryJanus`。

### REQ-002 业务能力

- 模块提供项目列举、创建、提交、推送、继承树、Meta 文件、分支历史、回滚和 Git 文件规则治理。
- 页面通过宿主 `CommandBus` 调用业务命令；跨 HTTP 的结构化结果必须先从 JSON 投影为页面模型。
- 卸载或热重载后不得残留窗口或旧命令注册。

### REQ-003 正式交付

- `b-Publish/candidate` 只保存本次验证候选；旧正式版本只以扁平历史包保存在 `b-Publish/history`。
- `z-Package-HistoryJanus` 只保存最新正式快照。
- 正式快照只允许 `HistoryJanus.dll`、`HistoryJanus.xml`、`module.manifest.json`、`SHA256SUMS` 和 `package/模块API.md`。
- 部署只把正式快照中的运行文件同步到 AppShell UI 与 Service 两个模块槽；API 文档留在 z 级消费区供开发者读取。

## 系统架构

| 组件 | 路径或位置 | 职责 | 输入 | 输出 |
| --- | --- | --- | --- | --- |
| 模块入口 | `b-Code-Studio/Module` | 接收宿主上下文，注册命令和窗口 | `IModuleContext`、`IShellUiRegistrar` | 命令注册与五个页面 |
| 业务组合 | `b-Code-Studio/StudioBusinessComposition.cs` | 组合项目、Git 规则、历史和调试命令 | 宿主设置、日志、数据根 | 31 条模块命令 |
| 页面 | `b-Code-Studio/Views` | 展示项目与 Git 工作流 | 宿主 CommandBus 结果 | WPF 页面状态 |
| 验证 | `b-Code-Verify` | 契约、功能和模块生命周期回归 | 源码与候选包 | 通过/失败结果 |
| 正式消费区 | `z-Package-HistoryJanus` | 保存最新模块和 API 合同 | 已验证候选 | 跨项目可消费快照 |

### 关键流程

1. AppShell 从自身 Modules 目录读取 manifest 并装载 `HistoryJanus.dll`。
2. `IModuleContextAware.Attach` 使用宿主 registry、bus、settings、log 与 data directory 注册业务组合。
3. `IUiModule.CreateUi` 把五个页面登记到宿主布局；页面只通过宿主总线执行业务命令。
4. 发布管道验证源码、模块生命周期和包集合后提升到 z 级正式消费区。
5. 部署管道原子更新 UI/Service 两个模块槽，并保留上一正式部署用于回滚。

### 不变量与生成物边界

- 唯一产品版本源：`b-Code-Studio/JanusVersion.props`。
- 模块 manifest 源：`b-Code-Studio/Module/module.manifest.json`，版本必须与版本源一致。
- AppShell API 权威源：`2026-023-HistoryVulcan/z-Package-AppShell`；Janus 不复制其运行库。
- 可重建生成物：`bin/`、`obj/`、`b-Publish/work`、`b-Publish/quarantine`。
- 正式消费快照：`z-Package-HistoryJanus`。
