# HistoryVulcan 3.3.2 断头指令审计表

本表盘点会改变应用状态或执行外部操作的 UI 入口。业务入口必须通过 `CommandBus.ExecuteAsync`；纯焦点、
选择和 Tab 导航属于视图交互，不单独注册业务命令。命令名称以运行时 `vulcan.command.list` 为最终真值。

本版（3.3.2）除按 DEC-023 九类对齐全表命令名外，另确立一条硬约束：

> **断头指令的第二种形态：需要人工点击才能完成的指令。**
> 命令处理器可以持有对话框、剪贴板、文件系统等系统交互，但**不得让指令的成功路径依赖人工操作**。
> 凡是能经 MCP、Web 或前端转发触发的指令，必须存在一条不弹窗即可完成的默认路径，
> 否则该指令在非交互宿主上会阻塞 UI 线程直到超时。
> 3.3.2 据此修复了 `vulcan.log.export`（省略 `path` 时改写默认文件而非弹 `SaveFileDialog`）。
> `vulcan.ui.selectfile` / `vulcan.ui.selectdirectory` 是例外：它们的**产品语义就是**「请用户选一个」，
> 弹窗是结果本身而不是副作用；两者标注为交互式指令，不得在非交互宿主注册。

> 3.3.1 之前本表长期停留在 3.2.2 命名（`win.max`、`command.copy-example`、`panel.select-file`、
> `win.float-state` 等），未随 3.3.0 硬切更新。3.3.2 一次性对齐，后续改名必须同步本表。

## 静态复核重点

业务 `Click`/双击处理器只构造命令文本并调用 `CommandBus`；不得直接调用日志过滤服务、停靠服务、
剪贴板或文件选择服务。命令处理器可以持有这些系统交互，以保证手输、脚本、模块和 MCP 使用同一描述符与回执，
但必须满足本文开头的「不得依赖人工点击」约束。

主窗口/独立浮窗的原生移动属于窗口宿主交互；浮窗拖动过程中为保持鼠标锚点而执行的几何恢复不另建命令，
但离散的最大化/还原必须使用 `vulcan.ui.floatstate`，且不得改变 HistoryVulcan 停靠模型。
普通真实页签拖出沿用 AvalonDock 原生停靠流程；专注真实页签改变布局时必须依次执行
`vulcan.ui.restore` 与 `vulcan.ui.float`。空白顶栏不得推断停靠目标或触发页面拖出。
