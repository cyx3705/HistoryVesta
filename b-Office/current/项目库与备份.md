# 项目库与备份

## 存储模型

OneHistoryStudio 使用一个裸仓库保存全部分支，并把每个 Project 登记为工作树：

```text
OneHistory-Projects.git   裸仓库
0000-000-Template        模板工作树/分支
2026-xxx-Project         普通工作树/分支
```

一个 Project 同时对应一个 Git 分支和一个同名工作树目录；裸仓库是提交历史真值，工作树目录是日常文件入口。
`0000-000-Template` 是新项目的默认基础分支，`0000-000-Template`、`main` 和 `master` 均按受保护分支处理，
拒绝删除、硬重置和强推。

关键配置：

```text
app.get key=proj.barerepo
app.get key=proj.worktreeroot
app.get key=proj.basebranch
```

修改位置前先关闭其他 Git 操作，并确保裸仓库和工作树根是稳定的本地路径。程序只接受裸仓库登记的直接工作树，拒绝越界、重解析点和 `.git` 管理路径。

继承树以裸仓库提交图为依据，并要求候选父分支含有自己的提交且编号早于子分支。默认读取
`data\branch-tree.json` 缓存；需要重新计算时执行 `proj.tree refresh=true`。项目描述写入
`branch_notes`，可用 `proj.note name=<项目> text="<说明>"` 更新，并显示在继承树中。

`proj.tree` 的 HTTP/JSON 数据使用纯传输树：节点包含 `branchName`、`description`、`lastPushTime` 和可递归
反序列化的 `children`，不携带 WPF 展开状态。`IsExpanded` 只属于前端包装项，不进入服务合同。前端收到
空节点、错误数据类型、非法分支名或无法反序列化的递归数据时，必须清空旧树、禁用展开/折叠操作并显示
包含命令名与 JSON 类型的诊断，不得继续展示上一轮缓存结果。

## Meta 元文件夹

元文件夹是每个已登记工作树根目录下、名称以 `z` 或 `Z` 开头的直接子文件夹。匹配不区分大小写，
但不递归二级目录、不识别普通文件，也不解析目录内部内容。

```text
proj.metalist
proj.metalist filter=关键字
proj.metaopen name=2026-016-AD学习 meta=z-AD库文件汇总
proj.metaopen path=C:\OneHistory\OneHistory-Projects\2026-016-AD学习\z-AD库文件汇总
```

`filter` 同时匹配项目名、元文件夹名和路径。`proj.metaopen` 只允许打开当前项目清单中可枚举到的一级
元文件夹；不存在、越界或不属于已登记工作树的路径会被拒绝。“Meta文件”窗口只是这些命令的表格入口，
刷新后可发现新建或已删除的目录，双击行等价于执行 `proj.metaopen`。

## 项目操作

“项目操作”窗口用于创建、打开 Project，提交/推送当前或全部 Project，并管理其 Git 文件格式规则。
“项目总览”只负责浏览、搜索、选择和打开；总览选择会同步到项目操作的“基础分支 / 当前项目”。

控制台等价指令：

```text
proj.list
proj.create name=2026-001-Demo base=0000-000-Template
proj.open name=2026-001-Demo
proj.commit name=2026-001-Demo msg="说明"
proj.push name=2026-001-Demo
proj.commit name=2026-001-Demo msg="说明" target=submodules
proj.commit name=2026-001-Demo msg="说明" target=both
proj.push name=2026-001-Demo target=submodules
proj.push name=2026-001-Demo target=both
```

删除、批量提交和批量推送均属于高风险操作，必须阅读预览并完成本地确认。

创建、提交、推送、删除、回滚等项目写操作会记录到 `push_history`，用于审计程序执行过的动作与结果；
它不能替代 Git 提交历史，也不能证明某次提交已经成功推送到远端。查看真实代码历史始终以裸仓库 Git
提交图和远端跟踪引用为准。

页面入口固定为：

- 项目操作：`proj.commit`、`proj.push`，项目名取当前选择；
- 项目操作的“全部”范围：`proj.commitall`、`proj.pushall`，继续经过既有本地二次确认；
- 项目总览：不包含提交、推送或子模块写入口；
- 原独立“提交推送”窗口已在 V2.1.7 退役。

### 断链修复

`proj.repair` 不是普通刷新，而是全库高危重建：它会删除工作树根目录下全部现有工作树文件夹，执行
`git worktree prune`，再按裸仓库分支清单重建同名目录。已提交到裸仓库的内容不受影响，但所有工作树中
尚未提交或未跟踪的文件会永久丢失。

执行前必须分别备份裸仓库和未提交文件，关闭所有占用工作树的程序，确认 `proj.barerepo`、
`proj.worktreeroot` 与分支清单正确，再阅读完整确认提示。日常目录缺失应先用 `proj.list` 和
`git worktree list` 诊断；不得把 `proj.repair` 当作自动修复或启动步骤。

### 子模块联动提交与推送

程序以父仓库索引中的 `160000 gitlink` 为识别依据，既支持标准 `.gitmodules` 子模块，也支持
没有 `.gitmodules` 的历史嵌入式 Git 仓库。V2.3.2 将全部写入口集中到项目操作页，使用一个描述框、
一个四段范围选择器和“提交/推送”两个按钮；项目总览只负责浏览和选择。

四段范围为“当前·仅子模块 / 当前·分支及子模块 / 全部·仅子模块 / 全部·分支及子模块”。
页面使用 `target=submodules|both`；CLI/MCP 省略 target 时继续兼容旧 `submodules=false/true`。

`target=submodules` 只提交或推送子仓库，允许父 gitlink 暂时待收口，结果会明确提示随后执行
“分支及子模块”。`target=both` 会先预检全部直属子仓库，再按“子仓库 `git add -A`/commit ->
父仓库记录新指针”执行；联动推送要求子仓库工作树干净、存在 origin、当前 HEAD 与父提交中的
gitlink 一致，并固定先推子仓库、全部成功后再推父仓库。任一子仓库失败都会阻止父操作，已经
成功的子提交或子推送会保留并在结果中明确标记，不自动 reset 或强推。

本版只处理直属 gitlink。第二层子模块有变化、子仓库 detached HEAD、未初始化、路径越界或缺少
提交身份时会在写入前拒绝。OneHistoryStudio 不自动创建或修改 `.gitmodules`，也不扫描索引外的
普通嵌套 `.git` 目录。

## 分支历史与安全回滚

V2.3.0 起，项目总览或继承树选择项目后，左侧“分支历史”窗口显示该分支从父分支
分叉点到当前 HEAD 的第一父链提交。第一行固定为分叉点基线；`push_history` 仍是程序操作
留痕，不作为 Git 提交或真实推送批次的替代数据源。

```text
proj.history name=2026-001-Demo
proj.history.show name=2026-001-Demo sha=<提交>
proj.history.diff name=2026-001-Demo sha=<提交>
```

“生成恢复提交”会把内容恢复到目标节点并追加新提交，保留全部原历史；`proj.reset` 只硬重置
非保护本地分支，不修改远端。需要改写远端时必须另行执行 `proj.forcepush`，程序固定使用
`--force-with-lease`，不会降级为普通 `--force`。回滚与硬重置要求工作树完全干净，基础分支和
其他受保护分支禁止硬重置与强推。

## Git 文件格式规则

每个 pattern 只有三个状态：纳入 Git、使用 LFS、统一 LF。LFS 与 LF 互斥；不纳入 Git 时另外两项关闭。

V2.2.2 起，选择项目会自动把扫描到的全部扩展名与已声明规则合并进规则表。未声明格式显示
“未决”，不会伪装成已有规则；`Git + LF（文本，非 LFS 指针）`、`Git + LFS（仓库存指针）`
和“普通 Git（非 LFS，未强制 LF）”使用完整文字区分。`(无扩展名)` 只作统计，仍通过目录规则管理。

```text
git.rule.list name=2026-001-Demo
git.rule.set name=2026-001-Demo pattern=*.xlsx track=true lfs=true lf=false apply=false
git.rule.batch-set name=2026-001-Demo changes=<JSON数组> apply=false
git.rule.remove name=2026-001-Demo pattern=*.xlsx apply=false
git.rule.scan name=2026-001-Demo refresh=true
```

文件规则页允许连续修改多行，按钮显示“保存修改（N）”。一次保存会先提交当前单元格编辑，再统一预览全部
修改、只确认一次、批量写入，最后只重新扫描一次。恢复某行的原始值会自动取消该行的待保存状态；切换项目、
重新读取、扫描或删除规则前存在未保存修改时，程序会要求保存、放弃或取消，不会再用扫描结果静默覆盖编辑。

规则只写项目根 `.gitignore` 与 `.gitattributes` 的 OneHistoryStudio 托管块。`track=false` 只从索引移除匹配文件，不删除本地文件；任何规则操作都不会自动 commit、push 或重写历史。

`.gitattributes` 与 `.gitignore` 应保存为 UTF-8；UTF-16 的 `FF FE` BOM 会使 Git/OneHistoryStudio 无法按普通属性文本解析。子目录可以有自己的 `.gitattributes`，并会覆盖根目录同名属性。例如子目录的 `* text=auto` 会覆盖根目录的 `*.cs text`，页面按 Git 最终 `check-attr` 结果显示实际生效数量。

## LFS

需要预先安装 Git LFS：

```powershell
git lfs version
git lfs install
```

OneHistoryStudio 使用最终 `git check-attr` 结果和索引中的 LFS 指针共同判断状态。历史中已经提交的大文件不会因为新增规则自动迁移，`git lfs migrate` 必须作为独立人工任务执行并备份。

## 备份

建议备份三部分：

1. 整个裸仓库目录；
2. OneHistoryStudio 数据目录中的 `main.db`、`settings.json`、`panels`、`Modules`；
3. 尚未提交的工作树文件。

裸仓库备份完成后执行：

```powershell
git -C C:\OneHistory\OneHistory-Projects\OneHistory-Projects.git fsck --full
```

恢复时先还原裸仓库，再恢复数据目录，最后用 `git worktree list` 核对登记路径。不要手工编辑工作树根下的 `.git` 指针文件。

正式程序部署在 `C:\OneHistory\OneHistory-Push\OneHistoryStudio`。升级时必须先退出程序，
把旧部署目录整体改名为 `OneHistoryStudio-rollback-<版本>-<时间>`，再从 `z-Package` 创建全新目录。
禁止从 `b-Publish` 暂存区部署，禁止增量覆盖旧目录，也禁止产生 `OneHistoryStudio\Publish\...` 嵌套结构。
