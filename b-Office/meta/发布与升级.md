# 发布与升级

> 适用版本：OneHistoryStudio V2.7.6

## 独立版本身份

产品名固定为 `OneHistoryStudio`。OHS 产品版本在 `b-Code-Studio/StudioVersion.props` 修改；
当前为 `2.7.6`。`AppIdentity` 将产品版本提供给窗口标题、日志、MCP `serverInfo` 和文件元数据。

OHS 的唯一版本源是 `StudioVersion.props` 中的 `OneHistoryStudioVersion`。AppShell 自 3.0.0 起使用独立版本线，
OHS 的五处 `PackageReference` 固定为 `3.0.0`。发布脚本的 `-Version` 只用于声明 OHS 期望值并与版本源核对，
不能覆盖或决定构建版本。

## 开发入口与边界

020 以根级 `OHS.sln` 为产品构建入口。各目录职责如下：

| 目录 | 职责 |
|---|---|
| `b-Code-Studio` | OneHistoryStudio 产品装配与 Smoke |
| `b-Code-Studio.Service` | OneHistoryStudio 常驻后台服务入口 |
| `b-Publish` | 可覆盖的本机发布暂存快照，生成物不入 Git |
| `z-Package` | 经 manifest/checksum 验证的正式可消费快照 |
| `b-Code-OneHistory-V1` | 只读历史组件，不参与构建 |
| `b-Office` | 现行手册、当前版本施工增量与必要证据 |

OHS 通过 `PackageReference` 使用平级 `2026-023-AppShell` 发布的固定包。禁止复制框架源码、包仓或文档，
也禁止跨项目目录使用源码 `ProjectReference`。

框架契约见 023 的 `b-Office/appshell/README.md`；OHS 模块开发见 [模块开发手册](./模块开发手册.md)。
历史文档中的 `z-APPShell`、模板复制和回灌叙述只代表当时事实，不能指导 V2.4.0 之后的改动。

变更必须遵守以下纪律：

1. 新能力先有命令、Help 与 MCP schema，再连接 UI；按钮和控制台不得形成两套执行逻辑。
2. 公共契约、指令语法、停靠核心和数据格式按 AppShell 演进手册评审；框架变更扩大到演示宿主和 OHS 回归。
3. Git 进程调用统一使用结构化执行器；自动测试只使用临时工作树、临时裸仓库和本地远端。
4. 未获明确授权，不在真实项目执行提交、推送、回滚、重置、强推或规则写入。
5. 一次变更只有在源码、命令契约、自动化、GUI、手册、暂存、正式包和部署证据一致后才算完成。

### 管道化开发规则

- 命令名称、参数、默认值、允许值、执行站点、只读性和危险性只在生产 `CommandDescriptor` 或共享定义中
  声明；桌面、Service、Help、Web、MCP、GUI 和命令手册从最终注册表投影，不维护平行名单。
- 测试从生产 composition root 或共享 feature 集合取得期望目录，逐项比较契约；固定命令总数只能作为
  临时诊断，不能成为完整性真值。
- 新命令、新命令域或新菜单动作必须有自动校验能够在漏接消费者、域冲突或命令文本无效时失败；菜单动作
  使用注册表校验语法和参数，但仍由命令总线执行。
- OHS 版本号只修改 `StudioVersion.props`；命令手册、manifest、checksums 和发布目录都是生成物，不得手工同步。
- 完成一项变更时，必须同时通过相关 Debug/Release 构建与 Smoke，并从空 staging 形成可追溯候选；不能以
  当前工作树“看起来最新”或要求后续开发者阅读版本施工文档作为完成证据。

## 构建

```powershell
$env:DOTNET_EnableWriteXorExecute='0'
dotnet restore .\OHS.sln -p:NuGetAudit=false
dotnet build .\OHS.sln -c Debug -p:NuGetAudit=false --no-restore
dotnet build .\OHS.sln -c Release -p:NuGetAudit=false --no-restore
.\b-Code-Studio\eng\Publish-Studio.ps1 -Version 2.7.6
```

根级 `Directory.Build.props` 开启 nullable、隐式 using，并把全部警告视为错误。根级 `.editorconfig` 进一步
把 CA2012、CA2016、CA2208、CA5351 和 CA5394 设为构建阻断，分别保护 `ValueTask` 消费、取消令牌传播、
参数异常、密码学算法和安全随机数。新增资源所有权转移必须在 API 或局部代码中说明并由测试覆盖；不得通过
降低全局分析级别、批量 suppression 或吞掉异常来取得零警告。CA2000 暂不作为全仓门禁，因为公开所有权
转移 API 在 .NET 8 分析器下存在误报；真实资源泄漏仍必须修复。

OHS 发布必须通过 `eng\Publish-Studio.ps1`；它会执行锁定还原、Debug/Release 构建、两套 Smoke、Release
发布、运行时命令手册重生成、六份 Help 校验、版本身份校验、SHA-256 和 manifest。普通模式把新候选
原子替换到 `b-Publish`，形成可覆盖的本机暂存快照；不得用独立 `dotnet publish` 或手工复制替代。

`b-Publish` 与 `stage` 都由根级 `.gitignore` 排除。`stage\ohs-*`、`stage\b-Publish-*` 和
`stage\z-Package-*` 只承担事务候选、回滚或故障隔离；不得提交进 Git，也不得作为开发或 AI 检索的事实来源。
正式可消费快照只位于 `z-Package`，并由 Git LFS 保存其中的 DLL、EXE 和 PDB。

只有在 `b-Code-Studio`、`b-Code-Studio.Service`、`b-Office` 三个源码域都洁净时，才允许显式执行：

```powershell
.\b-Code-Studio\eng\Publish-Studio.ps1 -Version 2.7.6 -Publish
```

每次运行都先把 App、manifest 和 checksum 复制到同卷临时候选，逐文件核对完整集合、字节数和 SHA-256，
再原子替换 `b-Publish`。显式 `-Publish` 会继续复制已验证暂存，把 manifest channel 改为 `package`，
复验后原子替换 `z-Package`；任一阶段失败都隔离新目录并恢复原目标。manifest 和 checksum 分别位于
`b-Publish\release` 与 `z-Package\release`。脚本不执行 Git commit、tag、push、部署、程序重启，也不删除
用户数据或 AppData 数据库。

manifest 固定记录 schema、产品与版本、`staging/package` 通道、源码 commit 与 dirty 状态、SDK、目标框架、
RID、self-contained 状态、命令手册 SHA-256，以及每个发布文件的相对路径、字节数和 SHA-256。暂存、正式包
和部署都必须拒绝 manifest、checksum 与实际文件集合之间的缺项、多项、重复项或内容漂移。

## AppShell 包消费

AppShell 由 `2026-023-AppShell` 独立构建与发布，OHS 发布链不得调用其发布脚本。正式消费源为
`..\2026-023-AppShell\z-Package-AppShell\feed`；冻结审核期间可用 023 的 3.0.0 review staging 做还原验证，
但不得把候选包复制进 020 或覆盖正式 feed。AppShell 正式提升、tag 与推送都在 023 单独审核执行。

## 验收基线

原始需求和累计验收流水已按长期职责收口到现行手册。新版本不再维护跨版本增长的总验收单；当前施工文档
只记录本版增量、证据和未完成人工项；交付后有效合同抽入 `meta/`，施工原文可以留存但不得成为后续开发依赖。
最低验收面如下：

| 变更面 | 必须验证 |
|---|---|
| 命令或业务逻辑 | Debug/Release Smoke；Help、`command.list`、`command.show` 与结构化结果同源 |
| Git 写操作 | 临时仓库中的成功、拒绝、部分成功和回滚边界；真实项目默认只读 |
| 模块 | 首装、XML Help、热更新、下线、异常隔离、重名拒绝和依赖槽隔离 |
| UI 或停靠 | 页面可见、选择同步、按钮回显等价命令、布局恢复、窄窗口无重叠 |
| 运行质量 | 冷启动、长日志承压、中文/空格路径、异常不崩溃和损坏布局回退 |
| MCP/Web | 协议握手、工具目录、只读/标准/危险策略、鉴权、确认、审计和会话隔离 |
| 框架 | 标准 `dotnet test` 项目、AppShell 独立演示宿主、OHS 全套 Smoke、OHS GUI 三层回归 |
| 发布 | 版本身份、自动命令手册、文件清单、SHA-256、数据备份、全新目录部署和回滚冒烟 |

自动化受环境限制而无法完成的鼠标、UAC、LAN 第二设备或重启验证，必须明确记为人工待验，不得写成通过。

`VersionProjectionSuite` 是版本、发布和现行文档的投影门禁。它核对程序集、四个 AppShell 包、发布脚本、
manifest、README/PACKAGE 示例与两个版本源，并解析根导航、产品 README、PACKAGE 和六份 `meta` 手册的
本地 Markdown 链接。本地链接必须留在仓库内且目标存在；现行文档只能链接 `versions/README.md` 治理说明，
六份 `meta` 不得依赖任何 `versions` 或 `evidence` 内容。HTTP/HTTPS 外链不做联网可用性断言。

AppShell 发布必须把还原、Debug/Release 构建、标准测试、打包和消费验证放入候选目录下的隔离
`ArtifactsPath`，不得复用工作树 `bin/obj` 判断候选是否合格。`PackageSmoke` 固定为 framework-dependent
`win-x64`，完整输出不得超过 10 MB，且不得包含 Linux、macOS、移动端或其他 Windows 架构的 RID 资产；
超限时发布门禁必须报告最大的 20 个文件。仓库根 `stage/` 是本机事务、回退和隔离区，`b-Publish/` 是
可覆盖暂存区，两者必须整体忽略；正式发布只把校验后的 `z-Package` 快照纳入 Git。

Docking 的真实鼠标回归是显式 opt-in 门禁，因为它会占用当前交互桌面并短暂移动物理鼠标。测试从隔离 WPF
窗口的实时可视树计算坐标，不使用截图或固定盲坐标；默认完整 Smoke 不执行它。可交互桌面执行：

```powershell
.\b-Code-Studio\tests\Smoke\bin\Debug\net8.0-windows\Smoke.exe --suite Docking --real-mouse
.\b-Code-Studio\tests\Smoke\bin\Release\net8.0-windows\Smoke.exe --suite Docking --real-mouse
```

通过标准同时包括：工具标签真实拖出后成为浮窗；向中央空 `LayoutDocumentPane` 释放时仍保持浮动且不生成
合法停靠命令；随后可从浮窗真实标题拖回外侧工具窗标签组；无关的自定义边、中央空背景和保存后重载状态
全部保持。用例结束必须释放鼠标、关闭隔离窗口并恢复原光标位置，不得读取或写入正式 OHS 布局。

## 命令手册

命令手册必须由当前运行时注册表生成：

```text
command.manual file=b-Office/meta/命令手册.md apply=false
command.manual file=b-Office/meta/命令手册.md apply=true
```

生成后核对文件中的 `command-count` 与 `command.list` 总数一致，再由发布过程放入
`b-Publish/docs`，正式提升后进入 `z-Package/docs`。不得手工增删命令条目。

## 部署

1. 运行 `eng\Deploy-Studio.ps1`，只读验证 `z-Package` 并预览固定目标；
2. 确认所有 OneHistoryStudio 实例退出；脚本不会代替用户停止或重启进程；
3. 使用 `eng\Deploy-Studio.ps1 -Apply`，先备份 `main.db`，再把旧部署目录整体移入带版本和时间的回退目录；
4. 部署只消费 `z-Package`，通过同卷临时候选原子替换 `C:\OneHistory\OneHistory-Push\OneHistoryStudio`；
5. 核对文件清单、SHA-256、ProductName、ProductVersion、FileVersion，且不存在 `OneHistoryStudio.Service.*`；
6. 用户从部署目录启动前端，验证服务就绪、`help`、`mcp.status`、`web.status`、`proj.list` 和 `module.list`。

程序数据位于用户 AppData 的 `OneHistoryStudio` 目录，覆盖部署文件不会删除数据库或设置。SQLite 迁移为幂等操作，仍应在升级前备份 `main.db`。

## 回滚

1. 关闭失败版本；
2. 备份当前数据目录，保留故障日志；
3. 用回退目录恢复部署文件；
4. 若数据库迁移不兼容，再恢复升级前 `main.db`；
5. 启动旧版本并运行只读 Help/MCP/Project 检查。

V2.1.7 没有数据库或 Git 历史迁移，也不会自动修改各 Project 的规则。一次性迁移仅回收已经由正式页面取代的 `panels/projpush.json`；回滚到 V2.1.6 时旧程序会按缺失策略重新生成该面板。Codex MCP 注册变化仍需要重启 Codex 客户端。

V2.3.0 不新增数据库迁移，也不会在升级或打开历史窗口时改写项目提交。旧布局由
`EnsureRegisteredWindows` 自动补入 `history` 窗口，不重置用户已有布局。只有用户显式确认
`proj.rollback`、`proj.reset` 或 `proj.forcepush` 时才会改变 Git 状态。

V2.3.1 不新增数据库迁移，也不会在启动或选择项目时自动提交、推送子仓库。页面默认启用
`submodules=true`，但实际 Git 写入仍只发生在用户点击提交/推送后；CLI 与 MCP 省略参数时继续
保持父仓库模式。回滚到 V2.3.0 不需要恢复数据库，但旧版不会处理子仓库文件内容。

V2.3.2 不新增数据库迁移。项目总览恢复为纯浏览页面，全部提交/推送入口移动到项目操作页。
仅子模块模式可能留下待提交父 gitlink，这是显式允许的清理中间态；使用“分支及子模块”即可收口。
回滚到 V2.3.1 不需要恢复数据库，但旧页面没有四段 target 范围。

V2.4.1 不新增数据库迁移，不改变命令、MCP、页面或真实项目 Git 行为。源码、样例和发布快照改为
根级平行组件；回滚只需退出 2.4.1 并恢复整目录 2.4.0 回滚包。旧组件最后残留的 `bin/obj`
均为可再生成构建产物，经用户二次确认后已连同空壳目录删除，不进入新结构。

V2.4.0 不新增数据库迁移，也不修改真实项目 Git 历史。源码与文档改为 020 伞形结构，但产品数据目录
仍为 `%AppData%\OneHistoryStudio`，既有设置、模块、布局和数据库直接沿用。回滚到 2.3.3 只需退出
2.4.0 并恢复整目录回滚包；AppShell 唯一源码和根级解决方案只影响开发工作树，不进入用户数据迁移。

## V2.7.6 双缺陷修复

- 模块管理页把 `module.list` 与 `command.list` 作为同一次远端目录快照，按 `Source=module` 和
  `SourceDetail=<模块名>` 关联详情；数量不一致、重载、失败或选择失效都会清空旧详情，不再读取前端本地注册表。
- `proj.tree` 改用可递归 JSON 反序列化的纯传输节点，WPF `IsExpanded` 只存在于前端包装层；空、非法、
  错类型或反序列化失败会清空旧树并输出有限诊断。标准契约测试覆盖四节点递归往返、未知字段兼容和非法节点。
- AppShell 与 OHS 增加可由 `dotnet test` 直接发现的 xUnit 项目；真实 WebGateway/HTTP Smoke 验证递归树跨
  JSON 边界仍保留两层子节点，模块目录测试验证同源过滤及跨代数量不一致拒绝。
- AppShell 发布使用隔离 artifacts，PackageSmoke 固定 `win-x64`、framework-dependent、10 MB 上限并拒绝
  异构 RID 资产；`stage/` 整体退出 Git 跟踪，只作为本机候选与回退区。
- 本版不新增数据库迁移，也不修改项目 Git 历史。回滚只需关闭 2.7.6、保留故障日志与数据备份，再恢复
  2.7.5 整目录发布物；旧版不会获得本版的模块详情与递归树失效清理行为。

  Service 目录、动态模块保留域、菜单引用和命令手册均由生产定义或注册表投影，不再依赖平行名称、参数、
  只读性、版本或固定总数名单。

  现行手册不得反向依赖版本施工记录或一次性证据。

- 当前质量轮次中，OHS 与 AppShell 的 Debug/Release 构建均为 0 warning / 0 error；两种配置各 11 套
  默认 Smoke 全部通过，真实鼠标用例在 Debug/Release 均通过。测试没有操作正式 OHS、真实项目 Git 或
