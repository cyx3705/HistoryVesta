## 2. 伞形结构职责

```text
2026-020-OneHistoryStudio/
├─ OHS.sln                         统一构建入口
├─ Directory.Build.props           平台无关公共质量规则
├─ b-Code-AppShell/                AppShell 唯一源码与独立演示宿主
├─ b-Code-Studio/                  OHS 业务应用与 Smoke
├─ b-Code-Samples/                 模块开发样例
├─ b-Publish/                      当前正式发布快照
├─ b-Code-OneHistory-V1/           只读历史组件，不参与构建
├─ b-Office/                       OHS 文档、版本记录和行为快照
└─ z-Package-AppShell/             未来伞外使用的版本包，不参与伞内构建
```

- `b-Code-AppShell/src/AppShell.Core|Services|Shell` 是框架唯一源码，禁止复制到 OHS。
- `b-Code-Studio` 是 OHS 业务装配点，通过 `ProjectReference` 引用 AppShell。
- `b-Code-AppShell/src/App` 是框架独立演示宿主，不承载 OHS 业务。
- 未来其他项目不得跨项目目录直接引用 020 工作树；应使用 `z-Package-AppShell` 发布的固定版本包。
- `b-Code-OneHistory-V1` 仅用于追溯历史，不应重新接入 `OHS.sln`。

## 3. 变更纪律

1. **一切操作皆指令**：新增能力先注册命令并补 Help/MCP schema，再接 UI。
2. **框架改动直接改唯一源码**：不再复制、回灌或做框架副本哈希对账。
3. **冻结区先上报**：公共契约、指令语法、DockingHost 核心机制和数据格式按 AppShell 演进手册处理。
4. **同源改动扩大验收面**：AppShell 改动必须同时通过 AppShell 演示宿主、OHS Smoke 和 OHS GUI 实跑。
5. **版本唯一真值**：OHS 产品版本从 `b-Code-Studio/Studio.csproj` 读取；禁止在握手、窗口标题或文档生成器中另写版本常量。
6. **结构化 Git 参数**：所有 Git 调用统一经过 `GitRunner`，不得散落 `Process.Start("git")` 或拼接未转义参数。
7. **真实项目只读优先**：自动测试使用临时工作树、临时裸仓库和本地远端；未获明确授权，不对真实项目执行提交、回滚、重置或强推。

## 4. 构建与回归

```powershell
cd C:\OneHistory\OneHistory-Projects\2026-020-OneHistoryStudio
$env:DOTNET_EnableWriteXorExecute='0'

# 伞形项目统一构建
dotnet build OHS.sln -c Debug -p:NuGetAudit=false
dotnet build OHS.sln -c Release -p:NuGetAudit=false

# AppShell 独立构建
dotnet build .\b-Code-AppShell\AppShell.sln -c Debug -p:NuGetAudit=false
dotnet build .\b-Code-AppShell\AppShell.sln -c Release -p:NuGetAudit=false
```

发版前还必须完成：

- Wiring、V213、PromptGovernance、V230、V231、V232 六套 Smoke 的 Debug/Release；
- AppShell 演示宿主独立启动；
- OHS 命令集、指令详情、模块管理三个窗口和 MCP 的 GUI 实跑；
- 运行时重新生成命令手册，并核对 Help、`command.list`、MCP schema 数量和安全级别；
- Publish 产品身份、文件布局、RID 裁剪及正式部署逐文件 SHA-256 对账。

## 5. 发布边界

- OHS 发布产物固定在根级 `b-Publish`。
- 正式部署只能整目录替换，旧部署目录重命名或备份失败时立即停止，禁止增量覆盖。
- `z-Package-AppShell` 目前只是发布包治理壳；020 内部构建不得依赖其中的包。
- 不清理或改写 Git 历史中的旧 MyAPI/AppShell 血缘；从 020 当前工作树开始保持边界干净。

## 6. 完成定义

一次改动只有在源码、命令契约、自动化测试、GUI 行为、文档、Publish 和部署证据相互一致时才算完成。
构建通过但未做 GUI 实跑，或源码版本已升级但运行时手册仍是旧版本，都不能标记为已交付。
