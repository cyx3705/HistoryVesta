# versions 施工文档治理

> 自 2026-07-28 起强制执行。未来开发必须遵循本规则。

`versions/` 是当前版本的临时施工区，不是历史知识库，也不是开发前置资料。当前源码、运行时注册表和
`b-Office/meta/` 六份现行手册共同构成唯一开发基线。

历史文档本身可以完整保留，但保留位置是 Git 历史，而不是当前工作树。让已交付文档退出工作树，主要是
为了缩小 AI 的默认检索范围，避免重复读取旧文档消耗上下文和 token，也避免过期设计污染当前判断；这不
代表抹除或改写历史。

## 允许内容

- 当前尚未交付版本相对 `meta/` 的需求增量、决策、实施步骤、风险和验收记录；
- 一份 `README.md` 治理说明；
- 不得同时保留多个已交付版本的施工文档。

当前施工文档必须自包含本次增量，不得要求读者先阅读任何已交付版本文档。需要引用稳定合同，应链接
`meta/` 对应手册；需要解释代码，应直接引用当前源码。

## 禁止事项

- 禁止代码、测试、构建脚本、仓库 README 或现行手册依赖已交付版本文档；
- 禁止把旧版本中的“必须、禁止、固定、唯一”等措辞直接当作现行规则；
- 禁止把历史施工步骤、旧路径、旧哈希、旧测试数量和已废弃方案复制进 `meta/`；
- 禁止手工维护《命令手册》中的命令条目；它只能由当前运行时注册表生成；
- 禁止为保留历史而把已抽干文档移动到仓库内的 `archive/`、`history/` 等新目录；换目录仍会被 AI 搜索，
  不能解决上下文和 token 消耗问题。

## 交付抽干

版本交付前，逐项完成：

1. 用户行为和操作方式融入 `meta/使用说明.md`；
2. 项目库、Git、安全回滚和备份合同融入 `meta/项目库与备份.md`；
3. 模块、工具窗口和扩展契约融入 `meta/模块开发手册.md`；
4. MCP、Web、鉴权、确认和结构化协议融入 `meta/MCP接入与安全.md`；
5. 构建、测试、发布、升级、回滚和简明版本摘要融入 `meta/发布与升级.md`；
6. 从当前运行时重新生成 `meta/命令手册.md`；
7. 删除已交付施工文档，修复所有现行链接，并验证仓库不存在对它的依赖。

不进入 `meta/` 的内容由 Git 历史完整保留。确需调查时使用 `git log` 和 `git show` 只读访问；允许临时
查看，但不得长期恢复到工作树或重新成为 AI 的默认阅读材料。

## 判定优先级

```text
当前源码和运行时行为
> 自动生成命令手册
> meta 现行手册
> 当前未交付版本的增量文档
> Git 中的已交付历史
```

当前施工文档与前三项冲突时，先修正文档或代码并完成验证；不得引用更早版本为冲突内容背书。
