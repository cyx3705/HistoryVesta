# versions 留存与 AI 读取治理

> 自 2026-07-28 起强制执行。未来开发必须遵循本规则。

`versions/` 保存当前及历史 V 版本的施工记录，但不是现行知识库，也不是开发前置资料。当前源码、运行时
注册表和 `b-Office/meta/` 六份现行手册共同构成唯一开发基线。

历史文档本身可以完整保留在工作树或 Git 历史中，删除不是治理目标。治理目标是把“文件留存”与“AI 读取”
分开：根目录 `AGENTS.md` 禁止 AI 默认列举、搜索、批量读取或概括 V 文档，根目录 `.ignore` 将除本 README
外的 `versions/` 整个内容树排除在常规全文检索之外。这样可以避免重复读取旧文档消耗上下文和 token，也避免过期
设计污染当前判断。只有用户或任务明确指定版本追溯或指定文档维护时，才可最小范围读取直接相关文件。

## 允许内容

- 当前尚未交付版本相对 `meta/` 的需求增量、决策、实施步骤、风险和验收记录；
- 已交付版本的原始施工记录；
- 一份 `README.md` 治理说明。

当前施工文档必须自包含本次增量，不得要求读者先阅读任何已交付版本文档。需要引用稳定合同，应链接
`meta/` 对应手册；需要解释代码，应直接引用当前源码。

## 禁止事项

- 禁止代码、测试、构建脚本、仓库 README 或现行手册依赖已交付版本文档；
- 禁止把旧版本中的“必须、禁止、固定、唯一”等措辞直接当作现行规则；
- 禁止把历史施工步骤、旧路径、旧哈希、旧测试数量和已废弃方案复制进 `meta/`；
- 禁止手工维护《命令手册》中的命令条目；它只能由当前运行时注册表生成；
- 禁止把版本文档复制到 `archive/`、`history/` 等新目录形成重复历史；统一留在 `versions/` 才能由根级规则
  和检索忽略项稳定隔离。

## 交付抽干

版本交付前，逐项完成：

1. 用户行为和操作方式融入 `meta/使用说明.md`；
2. 项目库、Git、安全回滚和备份合同融入 `meta/项目库与备份.md`；
3. 模块、工具窗口和扩展契约融入 `meta/模块开发手册.md`；
4. MCP、Web、鉴权、确认和结构化协议融入 `meta/MCP接入与安全.md`；
5. 构建、测试、发布、升级、回滚和简明版本摘要融入 `meta/发布与升级.md`；
6. 从当前运行时重新生成 `meta/命令手册.md`；
7. 将施工文档标记为已交付，移除现行文档对它的依赖并完成检查；原文可以继续留存在 `versions/`。

不进入 `meta/` 的过程信息可以由 `versions/` 原文和 Git 历史完整保留，但不得重新成为 AI 的默认阅读材料。
任何新任务开始时，先读取当前源码、运行时行为和 `meta/`，不得因为历史文件仍在工作树或 Git 中就主动展开
版本文档或提交历史检索。确需调查已移出工作树的文件时，才使用 `git log` 和 `git show` 只读访问指定对象。

## 判定优先级

```text
当前源码和运行时行为
> 自动生成命令手册
> meta 现行手册
> 当前未交付版本的增量文档
> Git 中的已交付历史
```

当前施工文档与前三项冲突时，先修正文档或代码并完成验证；不得引用更早版本为冲突内容背书。
