# AppShell 文档中心

本目录把现行项目合同、消费合同、发布输入和历史证据分开。默认只读取 current 与任务需要的
`package` 消费文档，避免把已完成的冻结方案或整改过程误当作当前要求。

## 现行文档

`current/` 保存持续有效的项目级真值：

- [项目概览](current/项目概览.md)：目标、边界、冻结状态、交付物和最近验证。
- [技术合同](current/技术合同.md)：现行需求、质量属性、组件边界和关键流程。
- [有效决策](current/有效决策.md)：仍会影响后续维护的架构与工程决策。
- [目录规范](current/目录规范.md)：AppShell 的 a/b/z 分级、所有权和生成物边界。
- [验证合同](current/验证合同.md)：本地、CI、包、发布和消费方验证层级。
- [升级与发布](current/升级与发布.md)：消费方升级、候选验证、正式发布与回滚合同。
- [断头指令审计表](current/断头指令审计表.md)：3.1.1 业务 UI 入口、对应命令和纯视图交互边界。
- V3.1 界面现代化方案和 V3.2 后台服务化方案已迁入 `history/`，仅作为版本背景，不作为当前合同。

只有单份 current 文档已经明显影响维护时才拆专题文件，并同步更新 manifest。不得继续按每次
问题、整改或版本创建新的默认元文件。

## 消费文档包

`package/` 是随版本发布的消费合同编辑源：

- [复用说明](package/复用说明.md)：源码维护与正式包消费的建议读取顺序。
- [API 与指令手册](package/AppShell_API与指令手册.md)。
- [模块与 MCP 接入](package/AppShell_3.0_模块与MCP接入.md)。
- [运行时约束与已知限制](package/AppShell_3.0_运行时约束与已知限制.md)。
- [3.0 消费变更摘要](package/AppShell_3.0_消费变更摘要.md)。

其他项目和 AI 实际消费正式包时优先读取 `../z-Package-AppShell/AppShell.reuse.md`；
`package` 是发布权威源，Z 级 docs 是生成副本。

## 发布输入与维护

- `../b-Code-AppShell/eng/release/`：消费文档清单、复用入口和当前快照 README 模板等机器输入。
- [升级与发布](current/升级与发布.md)：维护者和消费方长期使用的升级、候选、发布与回滚合同。
- [AppShell 版本记录](history/AppShell版本记录.md)：完整版本沿革；不作为当前技术合同。

## 历史与发布证据

- `history/`：已结束方案、审查、整改和冻结执行证据；默认不读取。
- `b-Publish/`：版本化正式包、manifest、校验和、Demo 和发布证据；不直接编辑。
- `z-Package-AppShell/`：当前正式消费快照；只由发布流程整体更新。

旧专题文档和版本记录已迁入 history；一次性 CI 实施方案已在 CI 验收后抽干，长期规则由 current
验证合同和实际 workflow 承担。current 已是现行规则入口。
