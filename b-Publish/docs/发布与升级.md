# 发布与升级

> 适用版本：OneHistoryStudio V2.4.3

## 单一版本身份

产品名固定为 `OneHistoryStudio`。版本只在 `b-Code-Studio/Studio.csproj` 修改一次，
`AppIdentity` 将其提供给窗口标题、日志、MCP `serverInfo` 和文件元数据。禁止在页面或网关中维护第二份产品名/版本常量。

## 构建

```powershell
dotnet restore .\OHS.sln -p:NuGetAudit=false
dotnet build .\OHS.sln -c Debug -p:NuGetAudit=false --no-restore
dotnet build .\OHS.sln -c Release -p:NuGetAudit=false --no-restore
dotnet publish .\b-Code-Studio\Studio.csproj -c Release -o .\b-Publish -p:NuGetAudit=false --no-restore
```

发布前运行合并后的 Smoke 全部套件 Debug/Release，并分别独立构建 AppShell 演示宿主；框架变更还必须完成 GUI 实跑。

## 命令手册

命令手册必须由当前运行时注册表生成：

```text
command.manual file=b-Office/meta/命令手册.md apply=false
command.manual file=b-Office/meta/命令手册.md apply=true
```

生成后核对文件中的 `command-count` 与 `command.list` 总数一致，再由发布过程放入
`b-Publish/docs`。不得手工增删命令条目。

## 部署

1. 确认所有 OneHistoryStudio 实例退出；
2. 将旧部署目录整体改名为带版本号和时间的回退目录；改名失败立即停止；
3. 从 Publish 创建全新的部署目录，禁止增量覆盖和嵌套 `Publish`；
4. 核对文件清单、SHA-256、ProductName、ProductVersion 和 FileVersion；
5. 从部署目录启动，验证 `help`、`mcp.status`、`proj.list`、`module.list` 和命令集页面。

程序数据位于用户 AppData 的 `OneHistoryStudio` 目录，覆盖部署文件不会删除数据库或设置。SQLite 迁移为幂等操作，仍应在升级前备份 `main.db`。

## 回滚

1. 关闭失败版本；
2. 备份当前数据目录，保留故障日志；
3. 用回退目录恢复部署文件；
4. 若数据库迁移不兼容，再恢复升级前 `main.db`；
5. 启动旧版本并运行只读 Help/MCP/Project 检查。

V2.1.7 没有数据库或 Git 历史迁移，也不会自动修改各 Project 的规则。一次性迁移仅回收已经由正式页面取代的 `panels/projpush.json`；回滚到 V2.1.6 时旧程序会按缺失策略重新生成该面板。Codex MCP 注册变化仍需要重启 Codex 客户端。

V2.3.0 不新增数据库迁移，也不会在升级或打开历史窗口时改写项目提交。旧布局由
`EnsureRegisteredWindows` 自动补入 `history` 窗口，不重置用户已有布局。只有用户显式确认
`proj.rollback`、`proj.reset` 或 `proj.forcepush` 时才会改变 Git 状态。

V2.3.1 不新增数据库迁移，也不会在启动或选择项目时自动提交、推送子仓库。页面默认启用
`submodules=true`，但实际 Git 写入仍只发生在用户点击提交/推送后；CLI 与 MCP 省略参数时继续
保持父仓库模式。回滚到 V2.3.0 不需要恢复数据库，但旧版不会处理子仓库文件内容。

V2.3.2 不新增数据库迁移。项目总览恢复为纯浏览页面，全部提交/推送入口移动到项目操作页。
仅子模块模式可能留下待提交父 gitlink，这是显式允许的清理中间态；使用“分支及子模块”即可收口。
回滚到 V2.3.1 不需要恢复数据库，但旧页面没有四段 target 范围。

V2.4.1 不新增数据库迁移，不改变命令、MCP、页面或真实项目 Git 行为。源码、样例和发布快照改为
根级平行组件；回滚只需退出 2.4.1 并恢复整目录 2.4.0 回滚包。旧组件最后残留的 `bin/obj`
均为可再生成构建产物，经用户二次确认后已连同空壳目录删除，不进入新结构。

V2.4.0 不新增数据库迁移，也不修改真实项目 Git 历史。源码与文档改为 020 伞形结构，但产品数据目录
仍为 `%AppData%\OneHistoryStudio`，既有设置、模块、布局和数据库直接沿用。回滚到 2.3.3 只需退出
2.4.0 并恢复整目录回滚包；AppShell 唯一源码和根级解决方案只影响开发工作树，不进入用户数据迁移。
