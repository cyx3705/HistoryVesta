# MyAPI V4 模块开放说明

## 目录定位

`Module/` 是 MyAPI V4 的临时源码和工程实验区，供 OHS、AppShell 以及其他上层模块逐步建构、接入和验证。它不是 MyAPI 内核源码目录，不是正式发布目录，也不替代 `2026-023-AppShell` 的 3.0.3 冻结仓库。

当前只建立模块边界和实验入口，不预先复制 OHS 或 AppShell 的完整工程。模块成熟后，必须经过独立的 API、权限、审计、版本和消费者评审，才能决定是否迁移到独立项目或发布包。

## 模块分层

一个上层功能按页面或能力拆成独立模块：

| 类型 | 负责内容 | 允许依赖 |
| --- | --- | --- |
| 后端模块 | 能力、命令、服务和命令管线注册 | `MyAPI.Abstractions`；需要运行时编排时再引用 `MyAPI.Runtime` |
| 前端模块 | 页面、交互和能力呈现 | 命令合同或前端宿主合同；不得复制后端业务实现 |
| 宿主层 | AppShell、Web、Console 等页面之间的承载、导航和调用适配 | 已评审的前端宿主合同；AppShell V4 当前只依赖页面合同 |

AppShell 和 Web 的特殊性在于它们是页面之间的层，不把宿主层本身当作业务页面。OHS 的页面和业务能力仍应作为独立模块接入。

### AppShell V4 特殊边界

AppShell V4 是纯桌面 Shell 前端，不属于 MyAPI 后端命令管线的消费者。它不引用 `MyAPI.*`、`CommandBus` 或 `ICommandDispatcher`，也不实现 HTTP、MCP、ServiceHost 或前后端适配。页面模块通过 `DesktopPageDefinition` 注册并由 Shell 承载；需要后端能力的页面由其所属模块自行决定接入方式。

## 开放规则

1. 模块必须有稳定的模块 ID、版本和清晰的能力边界。
2. 后端命令必须显式注册；不得通过 public 方法反射自动暴露命令。
3. 业务前端页面只能通过命令合同调用后端；不得直接访问宿主内部类型或复制 AppShell 源码。AppShell V4 本身只实现页面宿主合同；页面可在宿主内激活、浮动、停靠、关闭和重开。
4. HTTP、MCP、模块扫描、热重载和后台监听默认关闭；由明确的消费方配置启用。
5. 模块不得在加载或构造时自行打开端口、扫描目录、启动后台线程或扩大宿主权限。
6. 实验模块不得把密钥、个人路径、机器状态或生成物写入仓库。
7. `Module/` 内容默认不随 MyAPI V4 发布；发布必须有单独版本和消费者验收记录。

## 临时目录约定

```text
Module/
├─ 模块开放说明.md
├─ OHS/
│  └─ README.md
└─ AppShell/
   └─ README.md
```

每个模块实验区至少包含自己的 README、模块 ID、当前状态和验证方式。实现尚未开始时只保留说明文件；开始迁移后只建立能独立验证的最小工程，不创建虚假的发布清单。

## 启用与验证

后端模块实验必须由宿主显式启用，并优先通过 `b-Code-TestModule` 的真实 DLL 加载路径验证。后端最小验收应覆盖：模块未启用时无监听和无命令；启用后命令元数据可见；HTTP、MCP 或 Console 适配调用同一个命令管线；失败加载不会破坏现有命令快照。AppShell V4 单独验证页面注册、活动切换、浮动、停靠、关闭、重开和注销，不要求也不允许接入命令管线。
