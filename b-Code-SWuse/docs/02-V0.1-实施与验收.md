# SWuse V0.1 实施与验收

> 状态：实现、离线 Smoke 和真实 CAD 基线均已通过；尚未注册或部署到 OHS 正式槽。

## 交付内容

- `SWuse.Api` 是用户 C# 唯一可引用的受控 API：`PartProgram`、`PartBuilder`、`SketchBuilder`、`SketchRef` 与 `FeatureRef`。
- 工作区支持多个 `.cs` 文件；帮助类可互相引用，但一个构建只能有一个 `[SwuseEntry] PartProgram`。
- `SWuse.Worker.exe` 是 x64 STA 独立进程。它用 Roslyn 内存编译，再在自身进程中调用 SolidWorks COM；UI 和 AppShell 从不持有 CAD COM 对象。
- `SWuse` 是普通顶层桌面窗口，不注册 AppShell 停靠窗口。桌面 Shell 被注入 `IShellUiRegistrar` 时主动弃权；无窗服务宿主创建窗口。窗口可在任务栏中找到、可获得焦点和正常拖动/缩放。
- 默认拒绝覆盖已有 `.SLDPRT`。Dry-run 既检查 C# 编译，也检查唯一入口，且不会启动 SolidWorks 或创建输出目录。

## 本机真实 CAD 结论

验收使用 SolidWorks 2025 的真实 COM 注册和默认模板配置，生成了一个 60 mm × 40 mm × 10 mm 的矩形凸台，随后在同一前视基准面上切除中心圆孔。

独立重开产物后，特征树包含 `BaseBoss` 与 `CenterHole`；输出非空，源代码 SHA-256 前后相同。验收完成后检查不到新建的 `SLDWORKS` 或 `SWuse.Worker` 进程。

运行命令：

```powershell
dotnet build .\src\SWuse\SWuse.csproj -c Release -p:NuGetAudit=false
dotnet run --project .\tests\SWuse.Smoke\SWuse.Smoke.csproj -c Release -p:NuGetAudit=false
dotnet run --project .\tools\SWuse.CadGate\SWuse.CadGate.csproj -c Release -p:NuGetAudit=false
```

`SWuse.CadGate` 为避免碰触用户正在编辑的 SolidWorks 会话，要求启动时没有 `SLDWORKS` 进程。追加 `--keep` 才保留其临时工作区；默认总会清理。

## 真实环境适配

本机暴露了三个必须固化的实际差异：

1. 默认零件模板是 `~BLANK_PART_TEMPLATE.prtdot`，不能直接传给 `INewDocument2`。Worker 改为选择物理 `.prtdot`，优先 `gb_part.prtdot`，不写入用户偏好。
2. 模板中的标准面显示为“前视基准面 / 上视基准面 / 右视基准面”，所以不以 `Front Plane` 这种英文显示名选择。Worker 使用模型前三个标准 `RefPlane` 的固定顺序并以 `IFeature.Select2` 选择。
3. 当前 COM IDispatch 对动态绑定返回 `TYPE_E_ELEMENTNOTFOUND`。Worker 改由 COM 注册目录中的官方 `SolidWorks.Interop.sldworks.dll` 接口反射调用；模块包不携带厂商 DLL。`FeatureCut3` 的 `Dir` 参数在这套真实零件基线中必须为 `true`，才可稳定生成切除。

## 离线门禁

`tests/SWuse.Smoke` 覆盖版本单一来源、API 参数与草图关闭、工作区多文件/忽略目录、路径边界、重复清单、Roslyn 跨文件编译、C# 诊断、零/多入口拒绝、真正 Worker dry-run JSON 往返，以及 Shell 注入时的窗口弃权。

## 发布边界

当前模块清单在项目根的 `z-SWuse`，只声明 Release 二进制与 Worker 运行依赖；设计、COM 记录和验收材料只保留在本模块 `docs/` 与 `tools/`，不进入 OHS 的 `b-Office/evidence`。

SWuse 的建模 API、Contracts、Worker 和工作区 UI 已与 OHS 业务层隔离。未来如果需要脱离 OHS 独立发布，只需替换模块发现/命令宿主和顶层窗口启动器；用户工作区格式、Worker 协议及 SolidWorks COM 管线无需迁移。本版本仍不执行独立安装或 OHS 正式部署。
