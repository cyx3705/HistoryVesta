# SWuse V0.1 架构与 API 设计

> 状态：已实施并完成真实 CAD 基线验收  
> 边界：静态零件代码生成；不替代 SolidWorks API 文档，也不构建通用 IDE。

## 架构

```text
SWuse 独立窗口
  ├─ 工作区文件树 / 代码编辑器 / 输出路径 / 日志
  ├─ SWuse.Contracts JSON 请求
  └─ SWuse.Worker.exe（独立 x64 STA 进程）
       ├─ Roslyn：仅 Runtime + SWuse.Api 引用
       ├─ 可回收 AssemblyLoadContext：加载用户构建程序集
       ├─ PartProgram.Build(PartBuilder)
       └─ SolidWorks COM：草图、特征、保存
```

AppShell 仅发现模块、调用 `CreateUi/DestroyUi` 和运行模块指令。工作区格式、编辑体验、代码 API、Worker
协议与 COM 生命周期都由 SWuse 自己维护。因此未来独立部署时，只需替换窗口宿主和启动器，不需要迁移建模核心。

## 为什么采用“句柄依赖”而非纯继承树

每个业务零件类继承 `PartProgram`，帮助类可以自由互相引用。几何依赖不是由复杂的类继承表达，而是由
`SketchRef → FeatureRef` 的显式代码引用表达。这保留了代码层级、可复用性和可读的模型树，同时防止用户把
STA 线程亲和的 COM 对象存进任意静态字段。

`PartBuilder` 每次 API 调用即时转发到 Worker 内的 COM 后端；V0.1 不建立第二套几何内核，也不保存可重放的
隐式命令列表。将来若需要增量重建或时间线，可以在 API 后端下增加可序列化命令 IR，而不破坏用户源码。

## COM 预研结论

已从本机 SolidWorks 2025 官方 Interop 反射读取并在真实 CAD 中调用 V0.1 所需签名：

- `ISldWorks.GetDocumentTemplate` / `NewDocument`；`swDocPART=1`；
- `IModelDocExtension.SelectByID2` 与 `ISketchManager.InsertSketch`；
- `ISketchManager.CreateLine` / `CreateCircleByRadius`；
- `IFeatureManager.FeatureExtrusion2`（23 参数）与 `FeatureCut3`（26 参数）；
- `IModelDocExtension.SaveAs3`；`swSaveAsCurrentVersion=0`、`swSaveAsOptions_Silent=1`。

数值单位遵循 SolidWorks API：米。V0.1 只调用上述最小集合；真实 CAD 验收另行记录，不把离线 Smoke 伪称为
COM 成功。

## 编译与安全

Worker 使用 Roslyn 在内存编译用户源码，并在可回收加载上下文执行。它固定使用
`Microsoft.CodeAnalysis.CSharp 4.11.0`，并把 `Microsoft.CodeAnalysis*.dll` 随 Worker 复制；受控构建环境
在恢复镜像暂时不可达时只使用已经存在的本地包缓存。它不接受用户代码的 NuGet、`#r`、项目引用或自定义 DLL
路径；唯一的专用程序集引用是 `SWuse.Api`。这保证模块槽的依赖和 API 版本是可控的。

但 .NET 基类库本身仍允许文件、网络和进程操作，且用户代码以当前 Windows 用户运行。因此 V0.1 的边界是
“不执行未经信任的本地代码”，不是沙箱。后续若需要共享工作区或远程运行，必须在独立低权限进程/容器与
权限模型完成前拒绝该场景。

## 验收

离线 Smoke 覆盖 API 依赖、跨文件编译、诊断、入口选择、路径限制、窗口宿主弃权、版本与清单。真实 CAD 验收
至少需要：默认零件模板、矩形凸台、圆孔切除、重开 `.SLDPRT`、特征树名称与输出文件稳定性、源代码 SHA-256
不变、Worker/SolidWorks 自有进程清理。
