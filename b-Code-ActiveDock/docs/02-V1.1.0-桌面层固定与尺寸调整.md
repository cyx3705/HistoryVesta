# V1.1.0 桌面层固定与尺寸调整

> 日期：2026-08-02  
> 状态：已实施并同步入槽；自动项与可编程验证通过，交互项待人工确认  
> 前置：`01-V1.0.0-活动坞独立模块.md`

## 目标

活动坞从"永远压在最上层、可随意拖动、高度自适应"的浮窗，改为"贴在桌面层、锁定在主显示器右下角、可从左边与
上边调整尺寸"的固定面板。三项要求：

1. 降到桌面层，任何普通窗口都能盖住它，它不再遮挡任何页面；
2. 锚点固定在主显示器工作区右下角，取消拖动换位；
3. 可拖左边框改宽度、拖上边框改高度，右下角在调整过程中不动。

只改 `2026-019` 的 ActiveDock 模块。OHS 与 AppShell 均不改动，模块命令域、六条命令签名和 manifest 字段
不变，模块版本 `1.0.0` → `1.1.0`。

## 当前实现

`ActiveDockUiModule.DockWindow` 现状：

| 属性 | 当前值 | 本次去向 |
|---|---|---|
| `Topmost` | `true` | 改 `false`，并额外贴桌面层 |
| `ResizeMode` | `NoResize` | 改为可调，但只开左边、上边与左上角 |
| `SizeToContent` | `Height` | 关闭，高度改为用户控制并持久化 |
| `Width` | 固定 `360` | 改为持久化值，带上下限 |
| `MinHeight` / `MaxHeight` | `112` / `390` | 保留为调整下限与上限 |
| `DragMove` | 边框左键拖动 | 移除 |
| `LocationChanged` → `SavePosition` | 持久化 Left/Top | 移除，改为持久化 Width/Height |
| `RestorePosition` | 读偏好，回退到右下角 | 改为无条件吸附右下角 |
| `WindowStyle` / `AllowsTransparency` | `None` / `true` | 保留 |
| `ShowInTaskbar` / `ShowActivated` | `false` / `false` | 保留，另加 `WS_EX_NOACTIVATE` |

## 第 1 项：桌面层

### 做法

主路径是把窗口重定父到桌面的 `WorkerW`：向 `Progman` 发 `0x052C` 促使系统生成承载壁纸的 `WorkerW`，
枚举顶层窗口找到那个**不含** `SHELLDLL_DefView` 子窗口的 `WorkerW`，再 `SetParent` 过去。效果是活动坞成为
桌面的一部分：任何普通窗口都盖在它上面，`Win+D` 显示桌面时它随桌面一起露出。

这一步在 `SourceInitialized` 之后、拿到 `HwndSource` 时执行。

### 兜底

`WorkerW` 的存在与层次依赖 Explorer 版本与是否启用壁纸幻灯片，不是稳定契约。找不到目标 `WorkerW` 时降级为：
`Topmost = false` + 每次被激活或 z-order 变化时 `SetWindowPos(HWND_BOTTOM)` 把自己压回最底。降级路径同样满足
"不遮挡其他页面"，只是 `Win+D` 时会跟普通窗口一起被隐藏。

降级必须写日志，不得静默。

### 必须处理的副作用

- **坐标系变化**：`SetParent` 后窗口坐标变成相对父窗口客户区。`WorkerW` 通常覆盖整个虚拟桌面且原点未必是主
  显示器原点，因此重定父之后必须重新计算并设置一次位置，不能沿用重定父前的值；
- **不抢焦点**：加 `WS_EX_NOACTIVATE`，避免点击活动坞把前台窗口的焦点抢走；
- **点击仍需可用**：桌面层窗口只在桌面可见时可点。这是本项要求的直接后果，不是缺陷；
- **Explorer 重启**：Explorer 崩溃重启后 `WorkerW` 句柄失效，窗口会失去父级。需监听并重新执行一次贴附，
  或在下次刷新时检测父窗口是否仍有效。

## 第 2 项：锚定右下角

取消 `DragMove` 与 `LocationChanged` 持久化。位置改为在以下时机无条件重算：窗口 `Loaded`、尺寸变化、
`SystemParameters.StaticPropertyChanged`（分辨率或工作区变化）、以及桌面层贴附完成后。

锚点公式（主显示器工作区，WPF 设备无关单位）：

```text
Left = WorkArea.Right  - ActualWidth  - 16
Top  = WorkArea.Bottom - ActualHeight - 16
```

`SystemParameters.WorkArea` 取的是**主显示器**工作区，已自动避开任务栏。这解决了 1.0.0 实测时活动坞漂到副屏
`(3297,421)` 的问题——那是旧版持久化位置被恢复的结果。

多显示器不做额外支持：始终吸附主显示器。

## 第 3 项：左/上调整尺寸

### 命中测试

窗口是 `WindowStyle=None` + `AllowsTransparency=true` 的分层窗口，没有原生非客户区，因此系统不会自动给出
边框命中区。需在 `HwndSource` 上挂钩 `WM_NCHITTEST`，按光标位置返回：

| 区域 | 返回值 |
|---|---|
| 左边框 6px 内 | `HTLEFT` |
| 上边框 6px 内 | `HTTOP` |
| 左上角 6×6 内 | `HTTOPLEFT` |
| 其余 | 交回默认处理 |

右边框、下边框和其余三个角**不返回任何调整值**，因此右下角在调整过程中天然不动，无需额外补偿位置。这也顺带
保证用户无法从右/下方向改尺寸而破坏锚定。

`ResizeMode` 设为 `CanResize`，`SizeToContent` 必须关闭——它会与手动高度互相打架。

### 尺寸边界与持久化

- 宽度范围 `[240, 720]`，高度范围沿用 `[112, 390]`，超出由 `MinWidth/MaxWidth/MinHeight/MaxHeight` 钳制；
- 尺寸写入 `ActiveDockState`，字段由 `Left/Top` 换成 `Width/Height`；
- 内容区 `WrapPanel` 本就按宽度重排，宽度变化无需额外处理；高度被调小时内容可能溢出，需要给 `WrapPanel`
  外面套一层 `ScrollViewer`（`VerticalScrollBarVisibility=Auto`），否则项目会被裁掉且无法访问。

### 偏好迁移

`state.json` 现有 `Left` / `Top` 字段作废。反序列化时忽略未知字段即可，不做迁移脚本；新字段缺省时用
`Width=360`、`Height=200`。旧文件不删除，避免回退到 1.0.0 时丢失固定项。

## 影响与边界

- 命令域、六条命令与 MCP 投影完全不变，`dock.hide` / `dock.show` / `dock.pin` 行为不变；
- 宿主判据不变：仍靠 `IShellUiAware` 是否被注入决定在服务宿主建窗、在桌面 Shell 弃权；
- 用户可感知的行为变化有三处，需要在 OHS `current/使用说明.md` 补一句：活动坞不再置顶、不能拖动、
  改为拖左/上边框调整尺寸；
- 桌面层贴附是 Win32 层面的 Explorer 行为依赖，不属于 AppShell 契约，风险由本模块自担。

## 已知风险

`WorkerW` 重定父是本方案唯一的不确定项：它依赖 Explorer 的窗口层次实现，Windows 版本、壁纸幻灯片和第三方
桌面工具都可能改变它。目标机为 Windows 10 IoT Enterprise LTSC 2021 (19044)，该版本上是成熟做法。降级路径保证
即使贴附失败，"不遮挡其他页面"这一核心诉求仍然成立。

## 修订 1.1.1：尺寸调整失效修复

1.1.0 人工验收结果：`Win+D` 随桌面露出通过，**拖左/上边框完全不能调整尺寸**。

两处缺陷，都由"窗口已重定父到 WorkerW"这一前提引出：

1. **命中测试坐标基准错误（主因）**。`WM_NCHITTEST` 原先用 `PointFromScreen` 把屏幕坐标换算成窗口局部
   坐标。重定父之后 WPF 的 `Left`/`Top` 不再是屏幕坐标（真实位置由 `SetWindowPos` 按父窗口客户区设定），
   换算基准失效，光标永远落不进 6px 边框，`HitTest` 因此恒返回 `HitNone`，系统拿不到 `HTLEFT`/`HTTOP`，
   表现为完全拖不动。改为用 `GetWindowRect` 取窗口真实屏幕矩形做基准，全程物理像素，边框宽度按 DPI 缩放。
2. **重贴合与系统尺寸循环打架**。`SizeChanged` 每次都调用 `ApplyAnchor()` → `SetWindowPos`，会打断正在
   进行的交互式调整。改为监听 `WM_ENTERSIZEMOVE` / `WM_EXITSIZEMOVE`：调整期间不自行摆位，交给系统的尺寸
   循环；调整结束后统一保存尺寸并重新贴合一次。

`DesktopLayer` 新增 `TryGetWindowRect`。模块版本 `1.1.0` → `1.1.1`，Release 构建 0 warning / 0 error，
Smoke 通过，已同步入槽并热重载（`模块 dock 1.1.1`），贴附仍走 WorkerW 主路径，落位仍为
`(2184,1184)-(2544,1384)`。

拖拽行为需再次人工确认。

## 修订 1.1.2：放弃 WorkerW 重定父，改为钉底顶层窗口

1.1.1 人工验收结果：**点击项目图标也没反应**。这推翻了 1.1.1 对"拖不动"的归因——不是命中测试坐标算错，
而是窗口根本收不到任何鼠标输入。

根因是 WorkerW 方案的固有限制：承载壁纸的 `WorkerW` 位于 `SHELLDLL_DefView`（桌面图标层）**之下**，
而 DefView 覆盖整个屏幕并吞掉桌面区域的全部鼠标消息。重定父后的窗口能被绘制出来（透过 DefView 可见），
但点击一律落在桌面图标层，永远到不了活动坞。因此"贴 WorkerW 换取 Win+D 随桌面露出"与"窗口可交互"
在 Explorer 的层次结构下互斥，无法兼得。

活动坞的核心价值是点击项目，交互优先级高于 Win+D 行为，因此放弃重定父：

- 窗口恢复为普通顶层窗口，鼠标输入完整；
- 在 `WM_WINDOWPOSCHANGING` 中把 `hwndInsertAfter` 改写为 `HWND_BOTTOM` 并清除 `SWP_NOZORDER`，
  z-order 因此被钉死在最底，任何普通窗口都盖在它之上，"不遮挡其他页面"仍然成立；
- 选 `WM_WINDOWPOSCHANGING` 而不是在 `WM_WINDOWPOSCHANGED` 里再调 `SetWindowPos`，是为了避免递归；
- 保留 `WS_EX_NOACTIVATE` 与 `WS_EX_TOOLWINDOW`，点击不抢前台焦点；
- `ApplyAnchor` 回归 WPF 的 `Left`/`Top`（不再重定父，屏幕坐标重新有效），命中测试仍用
  `GetWindowRect` 取真实矩形，两种情形都正确。

`DesktopLayer` 相应缩减：删除 `Attach`/`Mode`/`ParentOrigin`/`IsParentAlive`/`MoveTo` 与全部 WorkerW
查找代码，只保留 `Prepare`、`PushToBottom`、`PinToBottom` 和 `TryGetWindowRect`。

**行为变化（需接受）**：`Win+D` 显示桌面时活动坞会跟普通窗口一起被隐藏，不再随桌面露出。这是换取可点击
的直接代价。

模块版本 `1.1.1` → `1.1.2`，Release 构建 0 warning / 0 error，Smoke 通过，已同步入槽并热重载
（`模块 dock 1.1.2`），`layer.log` 记录 `已置为桌面底层窗口(可点击，不遮挡其他窗口)`，窗口重新出现在
顶层窗口枚举中，落位仍为 `360×200 @ (2184,1184)`。

点击与拖拽行为需再次人工确认。
