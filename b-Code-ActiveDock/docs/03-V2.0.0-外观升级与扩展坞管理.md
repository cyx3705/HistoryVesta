# V2.0.0 外观升级与扩展坞管理

> 日期：2026-08-03  
> 状态：已实施并同步入槽；自动验证通过，观感与交互项待人工确认  
> 前置：`02-V1.1.0-桌面层固定与尺寸调整.md`（含 1.1.1 / 1.1.2 两次修订）

## 目标

1. 底色改为深色半透明；
2. 项目选项配色改为低饱和度；
3. 项目图标外圈按权重发光，权重越高光圈越亮；
4. 加入 OHS 入口，点击打开 OHS 主界面；
5. 收录策略改为"近期打开频率高"，以周为时效单位；
6. 活动坞最低显示条数可调；
7. 在 OHS 界面中加入扩展坞管理页面，支持手动固定。

模块版本 `1.1.2` → `2.0.0`。命令域仍为 `dock`，命令条数增加，见"命令与投影影响"。OHS 与 AppShell 均不改动。

## 第 1 项：深色半透明底色

按决定不做系统毛玻璃，只做一层平涂深色半透明。这同时规避了原方案最大的风险：系统毛玻璃要求拆掉
`AllowsTransparency`，而 1.1.x 已经在窗口基础样式上翻过两次车（坐标基准错乱、鼠标输入丢失）。

做法：保留 `WindowStyle=None` + `AllowsTransparency=true` 的现有分层窗口，只把内容边框的
`Background` 由不透明浅色 `#F8F9FA` 改为半透明深色（建议 `#CC1E2126` 起步，实机调）。窗口被钉在
z-order 最底，因此透出的是桌面壁纸；被其他窗口覆盖时看不到，属预期。

配套的前景色必须整体反相，否则深底上的深字不可读：

| 元素 | 现值 | 改为 |
|---|---|---|
| 面板背景 | `#F8F9FA` 不透明 | `#CC1E2126` 半透明 |
| 面板边框 | `#C4C9CF` | `#33FFFFFF`（浅色描边，低对比） |
| 项目标签文字 | `#2A2F34` | `#E6EAEE` |
| 空列表提示文字 | `DimGray` | `#8A9199` |

不引入任何 Win32 合成 API，无兼容性风险，无降级路径需求。

## 第 2 项：低饱和度配色

`ProjectIconGenerator.Palette` 现为 6 个中高饱和色，改为同色相降饱和的版本。注意底色已改深，**不能沿用
"降饱和同时提亮度"的做法**——提亮后的浅色块在深底上会显得刺眼且与白色光圈混作一团。应降饱和并略降
亮度，让色块沉在深底里，靠图标上的白色短标签承担识别。

项目按钮的悬停态由"浅色高亮"改为"浅色半透明叠加"（如 `#1AFFFFFF`），避免在深底上出现白块。

**必须同时把图标缓存键从 `"v1:" + projectName` 改为 `"v2:"`。** 图标按该键的 SHA-256 命名并落盘缓存于
`%AppData%\OneHistoryStudio\ActiveDock\icons`，不改键则存量项目的图标不会重绘，配色改动完全不生效。
旧 `v1` 文件不主动清理，回退到 1.1.2 时仍可复用。

对比度底线两处，均不低于 4.5:1：图标上的白色短标签与图标色块之间，以及图标下方的项目编号文字
（`#E6EAEE`）与面板深底之间。

## 第 3 项：权重光圈

不在活动坞上显示权重数值或"最近打开"文字，改为在项目图标的圆角矩形外侧加一圈光晕：权重越高越亮。

做法：给图标容器加白色 `DropShadowEffect`，`ShadowDepth = 0`（即纯发光而非投影），把归一化权重映射到
`Opacity` 与 `BlurRadius`：

- 权重 0 → 完全不发光，与普通项目无差别；
- 权重 1（当前列表最高）→ 最亮，建议 `Opacity 0.85`、`BlurRadius 18`；
- 中间线性插值；固定项不因"固定"而获得光圈，光圈只表达使用频率。

光圈统一为白色，不随项目主色变化。归一化基准取当前列表内的最大权重，保证任何时候都有对比度，不会全暗
或全亮。底色改深之后白色光圈的对比度天然成立，原先"白光圈落在浅底上可能辨识不足"的顾虑不再存在。

性能：`DropShadowEffect` 是逐元素的位图特效，列表上限 12 项时开销可接受；若实机出现卡顿，退化为
"仅前 3 名发光"。

## 第 4 项：OHS 入口

在项目列表最前固定一个 OHS 入口按钮，点击打开 OHS 主界面。

OHS 是单入口产品：桌面前端与服务宿主是同一个 `OneHistoryStudio.exe`，靠 `--service-host` 参数区分。
活动坞运行在服务进程内，因此 `Environment.ProcessPath` 就是要启动的目标，不需要任何配置项或路径推断。

行为：

1. 已有桌面前端进程时，把它的主窗口唤到前台（必要时先还原最小化），不重复启动；
2. 没有前端进程时，以无参数方式启动 `Environment.ProcessPath`；
3. 失败写 `layer.log`，静默失败，不弹窗打断。

判定"已有前端进程"必须看命令行是否含 `--service-host`，不能只按进程名，否则会把服务宿主自己当成前端。

入口按钮使用 OHS Logo，不参与排序，不可取消，不发光。

## 第 5 项：收录策略

### 系统数据的实际可用性（先看这里）

按"直接读取系统的文件夹打开次数"的要求做了实测，结论是**Windows 不提供文件夹打开次数**：

| 来源 | 实测结果 | 可用性 |
|---|---|---|
| 系统"频繁访问"文件夹 `shell:::{3936E9E4-...}` | 只返回桌面/文档/图片三个默认项，无任何项目文件夹 | 不可用 |
| 快速访问跳转列表 `f01b4d95cf55d32a.automaticDestinations-ms` | 仅 5KB，最后写入停在 7/28，内容为空；且为未公开二进制格式 | 不可用 |
| `Recent` 目录 `.lnk` | 命中 9 个项目文件夹，含最后打开时间；**没有次数** | 可用，但只有时间 |
| UserAssist 注册表 | 面向可执行程序与快捷方式，对任意文件夹不可靠 | 不可用 |

因此"次数"只能由模块自己累计。这不构成跨项目耦合——被否决的是"OHS 向模块上报"，而模块自身计数完全
自给自足，OHS 一行不改。

### 三信号权重

| 信号 | 来源 | 作用 |
|---|---|---|
| 点击次数 | 模块自己累计，写入 `state.json` 的 `Usage` | 主信号，一次点击记 1.0 |
| 最近在资源管理器打开 | `%AppData%\Microsoft\Windows\Recent` 下 `.lnk` 的时间戳 | 补充信号，一次折算 0.5 |
| git 最后活动时间 | 现行 `ReadLastActivity` | 冷启动回退，保证首次安装不是空列表 |

**只统计项目主文件夹。** `.lnk` 必须解析出目标路径，且该路径与项目根目录（`工作树根\<项目名>`）完全相等
才计入；项目下任何层级的子文件夹一律忽略。按目标路径而非文件名匹配，同时解决了不同项目库下同名文件夹
互相污染、以及 `xxx (2).lnk` 这类重名变体的问题。

时效以周为单位：权重按时间衰减，**半衰期 7 天**。一周前的一次点击折算为半次，两周前折算为四分之一，
使"上周天天开、这周没碰"的项目自然下沉。

排序：手动固定项恒在最前 → 按加权频率降序 → 同权重按最近时间降序。

### 最低显示条数

新增策略项 `MinItems`（缺省 6）与现有上限并存：即使通过频率阈值的项目不足，也按排序补足到 `MinItems` 条，
避免长时间不用后活动坞变空。上限仍为 12，两者均可在管理页面调整。

## 第 6 项：扩展坞管理页面

### 归属

管理页面**由 ActiveDock 模块自己提供**，作为停靠型工具窗口注册进 OHS 主窗口，默认停靠右侧、比例
`0.38`（与 GitHubConnection 一致），不写进 OHS 产品源码。理由与 2.8.3 迁出 GitHub 专属页面一致：
OHS 不内置模块专属界面。

ActiveDock 从 2.0.0 起同时占据两个承载面：

| 进程 | 界面 | 判据 |
|---|---|---|
| 无窗服务宿主 | 活动坞窗口 | 未被注入 `IShellUiRegistrar` |
| 桌面 Shell | 扩展坞管理页面 | 被注入 `IShellUiRegistrar` |

1.1.2 之前桌面侧是"弃权不建窗"，2.0.0 起改为"注册管理页面"。宿主判据本身不变，仍是 `IShellUiAware`
是否被注入。

### 跨进程约束（关键）

管理页面在**桌面进程**，活动坞状态在**服务进程**的进程内静态状态里，两者不共享内存。

管理页面**不得只改自己进程的静态状态**：直接改只会动到桌面进程那一份，界面看着变了、活动坞纹丝不动
——这正是 V2.8.4 之前 `dock.hide` 失效的同一个坑。

> 实施时改用了另一条等效路径：`state.json` 文件监视。管理页面写文件，服务进程的活动坞收到变化后重载
> 偏好并刷新，双向同步且不依赖命令路由。本节原定的"必须走命令总线"以此为准，见文末实施结果。

### 页面功能

- 项目列表：当前权重、点击次数、最近打开时间、是否固定、是否排除；
- 手动固定/取消固定。**固定项无论打开次数如何都显示**，且恒在最前；
- 手动排除/恢复收录；
- 清除某项或全部使用记录；
- 策略参数：最低显示条数、最大显示条数、半衰期（缺省 7 天）。

## 命令与投影影响

管理页面的写操作需要新命令支撑，`dock` 域由 6 条增加到约 11 条：

| 命令 | 用途 |
|---|---|
| `dock.open` | 打开 OHS 主界面（命令侧复用第 4 项逻辑） |
| `dock.usage` | 列出使用记录与当前权重（只读） |
| `dock.forget` | 清除指定项目或全部使用记录 |
| `dock.exclude` / `dock.include` | 手动排除或恢复收录 |
| `dock.policy` | 查看或设置最低/最高条数与半衰期 |

命令条数变化会改变 OHS 运行时命令总数与 MCP 工具目录，但不影响 OHS 源码命令手册的 82 条（模块命令不进
源码手册）。Smoke 中"dock 指令数必须与聚合期保持一致"的断言需相应更新。

## 状态兼容

`state.json` 在现有 `Pins` / `Hidden` / `Width` / `Height` 基础上新增 `Usage`、`Excluded` 与 `Policy`。
旧文件缺字段按缺省处理，不做迁移脚本。1.1.2 遗留的 `Left` / `Top` 仍然忽略。

## 风险

1. 模块首次同时占据两个承载面，热重载时两侧 UI 都要正确销毁，否则会残留停靠窗口；
2. 解析 `.lnk` 目标路径需要 Shell 链接解析。模块已引用 WPF，但没有现成的 `.lnk` 解析能力，需自行读取
   Shell Link 二进制格式或经 COM `IShellLink`。若解析失败，该信号整体降级为不可用，只用点击次数与 git
   活动时间，不得因此阻断活动坞刷新；
3. 权重是"自己数的点击"，与用户直觉的"我打开过多少次"不完全一致（在资源管理器里直接进的目录只贡献时间
   信号、不贡献次数）。管理页面需要把两类信号分开展示，避免用户困惑。
