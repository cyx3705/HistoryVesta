# V2.1.0 Windows 资源管理器 OHS 项目入口更新计划

> 状态：计划书，仅记录设计，不修改代码、版本号、清单或部署产物。
> 基线：ActiveDock V2.0.1。

## 1. 目标

将 ActiveDock 的项目入口接入 Windows 资源管理器左侧导航栏，注册一个稳定的“**OHS 项目**”入口。用户可以从资源管理器、文件打开/保存对话框和其他依赖 Windows Shell 的软件进入同一项目根目录，不再依赖桌面 `.lnk` 快捷方式，也不要求其他软件直接调用 ActiveDock 的 `CommandBus` 指令。

活动坞窗口可以继续作为可选的快速入口，但不再把它当成 Windows 快捷方式或外部软件可扫描的文件系统对象。

## 2. 入口模型

### 2.1 单一根入口

资源管理器左侧只注册一个入口：`OHS 项目`。该入口打开当前 `proj.worktreeroot`，默认值仍为：

`C:\OneHistory\OneHistory-Projects`

入口下显示真实的项目文件夹，项目目录仍由现有的 `YYYY-NNN-项目名` 规则管理。

不为每个项目单独注册导航节点，不把动态活动列表写入 Windows Shell 命名空间。Windows 左侧导航适合稳定目录入口；动态注册多个项目会产生残留节点、刷新延迟、权限和卸载清理问题。

### 2.2 原生路径行为

“OHS 项目”必须解析为真实文件系统路径，而不是只在 ActiveDock 内部处理的虚拟按钮。打开项目、选择文件、保存文件和第三方软件的浏览对话框都应落到资源管理器的标准目录视图。

项目入口不创建桌面快捷方式，不依赖 `%AppData%\\Microsoft\\Windows\\Recent` 的 `.lnk` 记录作为事实来源。

## 3. 注册与生命周期

### 3.1 注册范围

- 默认使用当前用户注册表（`HKCU`），不要求管理员权限。
- 使用固定 CLSID 和明确的显示名称 `OHS 项目`。
- 注册项包含目标目录、图标、导航栏可见性和 Shell 文件夹属性。
- 注册前校验工作树根存在且为目录；路径无效时不写入半成品注册项。
- 注册操作幂等：重复启用不得产生第二个入口。

实现可采用 Windows Shell 的文件夹快捷入口机制；若该机制无法在目标 Windows 版本上稳定解析真实路径，再评估最小化 Shell Namespace Extension。不得为了动态项目列表直接引入完整虚拟文件夹实现。

### 3.2 启用、更新、卸载

ActiveDock 提供明确的启用/禁用流程（可由模块指令或管理页面触发）：

1. 读取 `proj.worktreeroot`；
2. 创建或更新 `OHS 项目` 的 Shell 注册项；
3. 通知资源管理器刷新命名空间；
4. 禁用时只删除 ActiveDock 自己拥有的 CLSID 和关联值，不触碰用户其他 Shell 配置。

工作树根改变后只更新目标路径，不更换入口标识。更新失败必须保留上一份可用注册项并记录原因。

### 3.3 安全与数据边界

- 只写 `HKCU\\Software\\Classes` 下 ActiveDock 自有键。
- 不写 `HKLM`，不安装系统级 DLL，不修改 Explorer 全局策略。
- 注册表写入前备份旧值到 ActiveDock 状态目录，便于回滚。
- 不把模块文档、发布附件或运行槽路径注册到资源管理器。

## 4. 与活动坞现有能力的关系

活动坞当前仍然负责项目扫描、固定、排序和使用记录。项目按钮继续直接打开真实路径，并写入 `state.json` 的 `Usage`。

资源管理器入口是面向 Windows 和第三方软件的稳定集成面：

- 第三方软件通过 Windows Shell 看到 `OHS 项目`，不需要知道 `dock.list`；
- ActiveDock 的活动排序不会改变资源管理器的目录结构；
- `.lnk` 只作为用户自行创建的普通文件存在，不再是 ActiveDock 识别项目的必要条件；
- 未来若需要从资源管理器记录打开活动，可另行评估 Shell 事件或文件系统信号，不在本版本伪造打开次数。

## 5. 计划中的接口

V2.1.0 不修改现有项目转换、模块注册或 AppShell 公共接口。ActiveDock 内部新增一个 Shell 集成边界，至少包含：

- `RegisterOrUpdateProjectRoot(path)`；
- `RemoveProjectRootRegistration()`；
- `IsProjectRootRegistered()`；
- `RefreshExplorerNamespace()`。

如果需要对外暴露管理能力，使用现有 `dock` 命令域增加只读状态和启用/禁用命令；不要求外部软件通过命令打开项目。

## 6. 验收门禁

- 资源管理器左侧出现且只出现一个“ OHS 项目 ”入口。
- 点击入口打开配置的工作树根，路径和普通文件夹完全一致。
- Windows 文件打开/保存对话框可以看到并进入该入口。
- 修改 `proj.worktreeroot` 后入口目标更新，旧目标不再打开。
- 重启 Explorer、OHS 和 ActiveDock 后入口仍然存在且不重复。
- 禁用模块后入口可完整移除，不留下空白导航项或错误 CLSID。
- 无管理员权限的普通用户可以完成启用、更新和卸载。
- 删除桌面 `.lnk` 不影响入口和项目打开。
- 活动坞原有项目扫描、固定、排序、点击记录无回归。
- 注册失败时不破坏上一份有效配置，日志包含注册表路径和具体错误。
- 不改变 Worker、Contracts、CAD COM、OHS 模块注册和 AppShell 产品代码。

## 7. 暂不实现

- 不为每个项目动态创建 Explorer 左侧节点。
- 不实现完整虚拟 Shell 文件夹、搜索提供程序或 Windows Search 索引扩展。
- 不把 ActiveDock 伪装为 `.lnk` 供其他程序扫描。
- 不删除现有活动坞窗口，是否在后续版本将其降为可选 UI 另行决策。
- 不在本版本修改模块版本号、`module.manifest.json`、发布槽或正式部署。

## 8. 后续实现顺序

1. 先做当前用户注册表的离线注册/卸载 Smoke，验证幂等、回滚和路径转义；
2. 在临时 Windows 用户配置下验证 Explorer 左侧显示、打开和刷新；
3. 验证文件打开/保存对话框和第三方程序的路径可见性；
4. 再实现 ActiveDock 管理页面/指令接入；
5. 完成真实机验收后再升为 V2.1.0 并部署。
