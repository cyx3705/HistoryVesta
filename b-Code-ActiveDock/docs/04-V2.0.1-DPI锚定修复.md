# ActiveDock V2.0.1 — DPI 锚定修复

## 问题

主窗口切换或重新显示后，桌面活动坞没有贴在物理主屏右下角。在 150% 缩放的
2560 × 1440 显示器上，窗口依据 WPF 的 DIP 工作区 `1707 × 933` 定位，实际落在
`995,719–1691,917`，而主显示器工作区是 `2560 × 1400`。

## 修复

`DesktopLayer.AnchorToPrimaryBottomRight` 以同一 Win32/User32 坐标系读取主显示器
工作区、当前窗口矩形并调用 `SetWindowPos`。因此 DPI 感知上下文变化时不再把 WPF
逻辑单位与 HWND 坐标混用。

活动坞还会在以下事件后异步复位：窗口显示、应用激活状态变化、显示器变化、DPI
变化和工作区设置变化；用户调整窗口尺寸期间不触发复位，避免打断拖拽。Win32 查询
失败时保留原 WPF 路径作为降级，窗口不会丢失可见位置。

## 边界与验收

- 不改变项目列表、命令域、管理页或持久化格式。
- 版本由 `2.0.0` 升至 `2.0.1`，程序集、模块信息与注册清单同步更新。
- Smoke 增加 2560 × 1400 原生工作区锚定断言；构建、Smoke 和正式槽哈希核验后再同步。
