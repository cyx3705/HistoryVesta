# MateMatchProbe

SE2SW V3.5 的只读匹配探针。它回答一个问题：**Solid Edge 关系给出的几何，
能不能在对应的 SolidWorks 组件上唯一定位到一个面。**

不是生产入口，不产出任何进入管线的文件。设计依据见
[`docs/25-V3.5-装配关系重建.md`](../../docs/25-V3.5-装配关系重建.md) §5。

## 跑法

需要两样输入：带关系的装配探查结果，和对应的一套 `.SLDASM`（由 V3.3 管线产出）。

```powershell
dotnet run --project .\tools\MateMatchProbe\MateMatchProbe.csproj -c Release -- `
  --probe-result "<装配探查结果.json>" `
  --sw-dir "<含 .SLDASM 的 SW 目录>" > mate-match.json
```

判定文案到标准错误，完整数据到标准输出。退出码 0 成功、1 故障、2 用法错误。

## 它怎么工作

对每个装配文档，打开对应的 `.SLDASM`，把该层的每条关系拿来：

1. 按 SE occurrence 名找到 SW 组件。**不能按实例号配对**——SE 的编号有跳号
   （实测 `太阳能板子.par` 的实例是 1/3/5/7/10/12/14/16，而 SW 是 -1..-8）。
   按"同一源文件 + 变换最接近"配对，与生产门禁同一套办法。
2. 递归收集该组件及其全部后代的平面、圆柱、圆锥面，产出候选签名。
3. 喂给生产用的 `MateGeometryMatcher`，统计唯一命中率。

## 两个用数据回答的问题

**曲面参数在哪个坐标系？** 探针把两种假设都算一遍，各出一个命中率，让数据自己选——
沿用 V3.0 确定 `MathTransform` 布局时的同一套办法。

实测结论：**零件坐标系**。必须乘组件的 `GetTotalTransform(true)` 才能和关系几何对上。
按装配系解释只有 24/53 命中。

**A 路成不成立？** 即被关系引用的面，识别后是否还在。

实测结论：**成立**。哑实体与识别版两轮都是 53/53、106 侧全中，100%。

## 实测中推翻的三个假设

| 项 | 原以为 | 实际 |
|---|---|---|
| 曲面参数坐标系 | 未定 | 零件系 |
| 多个候选 | 歧义，拒绝猜测 | **假歧义**——SW 把一个几何面切成多块拓扑面，候选按构造等价 |
| 子装配组件的面 | 未考虑 | `GetBodies3` 返回空，实体在子组件里，必须递归 |

第二条影响最大：首轮 106 侧里 43 侧被误判为歧义，命中率被压到 37.7%。
能通过筛选的候选按构造必然共面或共轴（筛选条件就是"法向平行 + 点在其上"），
给出完全相同的约束，没有选错的可能。`MateGeometryMatcher` 因此改为
等价性判定 + 确定性挑选，**不等价才判歧义**。

## 只读保护

- 只 `OpenDoc6` + `CloseDoc`，不保存、不修改、不新建文档；
- 附着到用户已开的 SolidWorks 会话时不调用 `ExitApp`；
- 不碰 Solid Edge——关系数据来自已有的探查结果 JSON。
