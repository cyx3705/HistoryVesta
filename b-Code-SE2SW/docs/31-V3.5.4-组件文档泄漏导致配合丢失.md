# SE2SW V3.5.4 组件文档泄漏导致配合丢失

> 日期：2026-08-03
> 版本：3.5.3 → 3.5.4
> 触发：用户报告"3.5.3 已经把特征识别的 bug 修好了，但是又出现了新 bug，大多数零件的装配关系全部都无了"
> 性质：**V3.3 引入的回归**，与特征识别无关

## 1. 一句话

`SolidWorksNestedAssemblyBuilder` 打开组件文档后**只释放引用、从不关闭**，
文档在 SolidWorks 会话里越堆越多，后续节点 `OpenDoc6` 撞上
`swFileWithSameTitleAlreadyOpen (65536)` —— 组件插不进去，
**该组件连同它的全部配合一起消失**。

## 2. 这不是识别的问题

复现时特征识别是**关着**的（门禁未传 `--recognize`，事件流里零个 `FeatureOutcome`），
失败纯粹发生在装配阶段：

```
正在生成第 3 层装配：测试装配3.SLDASM（2 个组件）
测试装配3.SLDASM 配合重建：3/4 条
正在生成第 2 层装配：测试装配1.SLDASM（4 个组件）
装配转换失败：组件文档打开失败：…\SW\测试零件4.SLDPRT，errors=65536, warnings=0
```

`65536` = `swFileLoadError_e.swFileWithSameTitleAlreadyOpen`。

3.5.3 修好识别之后这条才露出来——不是它引入的，是它让转换能跑到这一步了。

## 3. 回归是怎么来的

V3.0 的展平版 `SolidWorksAssemblyBuilder` 在 `finally` 里是**关文档**的：

```csharp
foreach (var part in openedParts)
{
    if (interop is not null && ownership.OwnsInstance)
        TryRun(() => interop.CloseDocument(interop.GetTitle(part)));
    ComRelease.Final(part);
}
```

V3.3 新写的 `SolidWorksNestedAssemblyBuilder` 只保留了后半句：

```csharp
foreach (var document in openedDocuments)
    ComRelease.Final(document);          // ← 少了 CloseDocument
```

**展平版一个批次只生成一个装配文档，泄漏一批文档也看不出来；
嵌套版一个批次生成 N 个节点、每个节点开一批文档，泄漏是累积的。**
同一段疏忽在两种架构下的后果完全不同——这正是它躲过 V3.3 全部门禁的原因。

## 4. 修复

### 4.1 关闭组件文档

补回 V3.0 就有的收尾。注释里写明了为什么这行不能再丢。

### 4.2 真撞上"同名已打开"时的容错

嵌套装配里"上一层已经把某个零件作为组件打开过"是常态，因此
`OpenComponentDocument` 遇到 `swFileWithSameTitleAlreadyOpen` 时不再直接失败：
按绝对路径找那个已打开的文档，**路径完全相同才复用**。

**同名不同路径必须失败**——复用它等于把别人的几何插进装配，
和 28 号文档里那起"5 个零件全变成同一个方块"是同一类错误。

判定抽成纯函数 `SolidWorksInteropBridge.CanReuseOpenDocument`，
由 `SE2SW.Smoke` 的 `TestComponentDocumentReuseGuard` 锁死：
大小写不同、路径可规范化为同一个 → 允许；不同目录同名、拿不到路径 → 拒绝。

| 逐层 | — | 测试装配3 3/4、测试装配1 8/9、风滚子 42/43 |
| 叶组件位置 | — | 22/22，平移 2.43e-09 m、旋转 4.00e-15 |

### 5.2 独立读回文件核对

不采信 Worker 的自报结果，用 `AssemblyProductionGate --audit-assemblies`
重开产物、直接枚举配合特征树：

| 装配 | 组件 | 固定 | 配合特征 |
|---|---|---|---|
| `测试装配3.SLDASM` | 2 | 1 | **3** |

### 5.3 离线

`SE2SW.Smoke` 全过，新增 `TestComponentDocumentReuseGuard`。

## 6. 门禁的盲区

**这个缺陷躲过了 V3.3 与 V3.5 的全部真机门禁**，因为门禁每次都在干净会话里跑一次转换，
而文档泄漏只有在**同一会话里连续转换**时才累积到出错。

建议补一档"连续转换两次同一装配"的门禁——资源泄漏这类问题只在重复运行里现形，
单次通过说明不了任何事。本版未做，记在这里。

## 7. 教训

**把一段逻辑重写成新架构时，最危险的不是写错，是漏抄。**

`ComRelease.Final(document)` 单看完全正常，评审时也不会觉得少了什么；
只有把它和 V3.0 的对应段落并排看，才会发现少了 `CloseDocument`。
新旧两条路径并存时，应当逐行比对收尾逻辑，而不是"照着意思重写一遍"。
