# SE2SW V3.0 工程实施记录

> 日期：2026-08-01  
> 版本：3.0.0  
> AppShell 公共合同：`OneHistory.AppShell.Core 3.0.3`

## 交付结果

V3.0 在 V2.3.1 零件管线之上增加了 `.asm → .SLDASM` 第 0 档转换。装配窗口是独立的 AppShell
普通工具窗口 `se2sw-asm`，与既有 `se2sw` 同时注册；不修改 AppShell 或 OHS 产品代码。

装配转换分两次 Worker 调用：

1. `--probe-assembly` 只读打开 `.asm`，递归生成 occurrence 清单；
2. UI 展示真实层级、规划唯一零件和全部输出并执行前置检查；
3. `--assembly` 复用零件导出/导入管线，再按每个 occurrence 的世界矩阵展平插入、固定并保存。

旧 `--request` 的 JSON 和执行语义保持兼容。`ConversionStage`、`ConversionErrorClass` 只在末尾追加，
`WorkerEvent.Assembly` 为可空追加字段。

## 输出目录

外界零件和装配统一使用：

```text
<源目录>\
  *.par / *.asm
  XT\*.x_t
  SW\*.SLDPRT
  SW\<装配名>.SLDASM
```

扫描、输入路径编辑和装配探查都不创建 `XT/SW`。转换点击后先验证 Worker 与两个 CAD COM，再一次性检查
两个目录名是否被文件占用；任一冲突时不创建另一目录。旧平铺 `.x_t/.SLDPRT` 仍标记为已有产物，
不覆盖、不移动。

## 关键实现结论

### 世界矩阵

SE 矩阵到 SW 数组的固定映射为：

```text
SW[0..8]  = SE[0,1,2, 4,5,6, 8,9,10]
SW[9..11] = SE[12..14]
SW[12]    = 1
SW[13..15]= 0
```

旋转不转置。`SubOccurrence.GetMatrix` 已经返回顶层世界矩阵，生产代码直接使用；不再乘父矩阵。

### 保存锁时序修复

首次生产门禁发现 `SaveAs3` 成功后，Worker 在装配文档仍打开时读取临时 SLDASM，因 SolidWorks 独占锁
等待完整稳定性超时。第一次关闭又使用了保存前的未命名标题，实际没有关掉文档。最终顺序固定为：

```text
SaveAs3
  → 保存后重新 GetTitle
  → CloseDoc(保存后标题)
  → FileProbe 稳定性校验
  → TemporaryOutput.Commit
```

该时序已由 L0/L1/L2 生产门禁重复通过。

### 失败策略

- 缺失引用在探查阶段阻断；
- 同名不同路径零件归类 `DuplicateOutputName`，不自动改名；
- 非 `.par/.asm` 引用跳过并报告；
- 隐藏件正常插入并在 UI 警告；
- FeatureWorks 在装配窗口默认关闭；
- 任一零件失败默认不生成 SLDASM；即使显式允许继续，全部零件失败时也拒绝生成空装配。

### SE 2020 抑制边界

Solid Edge 2020 的 `Occurrence/SubOccurrence` 类型库没有可持久化组件 `Suppress` 属性。受控 fixture 把
`Occurrence.Activate=false` 保存后重开，值恢复；它是会话加载状态，不能作为抑制判断，否则会静默丢件。

生产代码不做该误判。活动配置没有枚举的 occurrence 会自然不进入清单；合同和 SW 下游仍保留
`IsSuppressed` 的跳过能力，供显式清单与后续版本使用。这是 V3.0 对“抑制件跳过”的 SE 2020 实际边界。

## 离线门禁

`SE2SW.Smoke` 覆盖：

- 新分层映射、扫描不建目录、旧平铺识别、双目录冲突原子阻断；
- 装配 JSON 往返、唯一零件去重、同名冲突、树层级；
- 16 元素矩阵映射和“子 occurrence 世界矩阵直用”；
- 装配 ViewModel 按钮/警告/源切换/默认 FeatureWorks 状态；
- 装配活动操作取消与 Dispose 等待；
- 两个工具窗口注册、默认普通右侧窗口语义和双句柄释放；
- 原 V2.3.1 零件生命周期、特征识别重试和输出原子提交回归。
