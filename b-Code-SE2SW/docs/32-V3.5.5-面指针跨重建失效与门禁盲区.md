# SE2SW V3.5.5 面指针跨重建失效 与 门禁盲区

> 日期：2026-08-04
> 版本：3.5.4 → 3.5.5
> 触发：用户报告"3.5.4 之后 bug 未解决，大多数零件的装配关系全部都无了"
> 结论：3.5.4 修的是另一个真实缺陷；本次现象另有根因，且**从未被门禁覆盖过**

## 1. 一句话

每加一条配合都要 `ForceRebuild` 一次，而候选面的 `Face2` 引用被缓存起来跨关系复用——
**重建让这些指针全部作废**，下一条配合选实体时抛 `0x80010108 RPC_E_DISCONNECTED`。

## 2. 为什么只在"识别 + 配合"同时开时出现

| 零件形态 | `ForceRebuild` 的实际行为 | 缓存的 Face2 |
|---|---|---|
| 哑实体（无特征树） | 近乎空操作 | 侥幸存活 |
| 识别版（有特征树） | 真的重建拓扑 | **全部失效** |

同一份代码：识别关着 53/56，识别开着 4/56。

失败模式是**每层第一条配合成功、之后全断**——第一条配合前缓存是新鲜的，
它成功后触发重建，缓存随即作废。

## 3. 用户产物与门禁的逐位吻合

用户运行（识别开启）的产物，用 `--audit-assemblies` 直接读回文件：

| 装配 | 组件 | 固定 | 配合 |
|---|---|---|---|
| `测试装配1.SLDASM` | 4 | 1 | 2 |
| `测试装配3.SLDASM` | 2 | 1 | 1 |
| `风滚子.SLDASM` | 18 | **17** | 1 |

合计 4 条。门禁加上 `--recognize --rebuild-mates` 后复现出**同样的 4 条、49 条被拒**，
诊断全部是 `RPC_E_DISCONNECTED`。

## 4. 修复

| 修复 | 说明 |
|---|---|
| 配合成功后立即清空候选缓存 | 这条配合触发了重建，缓存已作废 |
| 定位后主动探活 | 一次廉价的 `GetSurface` 读取；任一侧已断开就整表重建后重试一次 |

## 5. 门禁盲区：本版真正要修的东西

**这个缺陷之所以能跑到用户手里，不是因为它隐蔽，是因为没人跑过那个组合。**

V3.5 §5.1 用 `MateMatchProbe` 单独量出"识别版几何匹配率 100%"，
据此写下"两者不互斥、可以同时开"——**拿子系统探针的结果替代了组合路径的验收**。
V3.5.0 收口时的三档门禁（配合重建 / 不重建 / 安全重试）全部在识别关闭下运行，
而"识别 + 配合"恰恰是用户的实际用法。

### 5.1 新增：识别 + 配合组合档

`AssemblyProductionGate --recognize --rebuild-mates` 提升为**必跑档位**。
两个开关的四种组合里，只有它同时激活特征重建与配合求解，
是唯一会让"重建让指针失效"这类问题现形的路径。

### 5.2 新增：文档泄漏断言

31 号文档（3.5.4）建议补一档"同会话连续转换两次"来暴露资源泄漏。
本版改用更直接的做法：**门禁收尾时枚举 SolidWorks 会话里仍然打开的文档，非空即失败**。

```
转换结束后仍有 N 个文档留在 SolidWorks 会话里，
这类泄漏会在后续节点上表现为组件插入失败、配合整块丢失：…
```

比"跑两次"更好的地方：单次运行就能查出来，不依赖累积到出错；
而且报的是**泄漏本身**，不是它引发的次生现象。

3.5.4 那个缺陷（嵌套生成器漏 `CloseDocument`）如果当初有这条断言，
在 V3.3 的门禁里就会被拦下。

## 6. 验证

### 6.1 识别 + 配合组合档

| 项 | 修复前 | 修复后 |
|---|---|---|
| 配合落位 | 4 + 接地 3 / 56，**拒绝 49** | **53 + 接地 3 / 56，拒绝 0** |
| 逐层 | 1/4、2/9、1/43 | 3/4、8/9、42/43 |
| `风滚子` 固定组件 | 16 | 1（动量轮，无关系约束，如实报告） |
| 叶组件位置 | — | 22/22，平移 2.43e-09 m、旋转 4.00e-15 |
| 特征识别 | — | 14 个事件、48 个特征，真实运行 |

### 6.2 文件级独立核对

`--audit-assemblies` 重开产物枚举配合特征树：
`测试装配1` 8 条、`测试装配3` 3 条、`风滚子` 42 条，**共 53 条**真实存在于文件里。

`PartGeometryProbe`：12 个零件体积全部与 XT 基准一致——识别没有改坏几何。

### 6.3 离线

`SE2SW.Smoke` 全过，新增 `TestMateCandidateStalenessContract`：
`RPC_E_DISCONNECTED` 必须被识别为会话级故障（从而触发缓存重建，而不是被当成普通失败吞掉）；
重新收集候选后匹配结论与所选面必须不变。

## 7. 教训

**用子系统探针的成绩替代组合路径的验收，是这一轮所有事故的共同方法论错误。**

- 几何匹配率 100% → 推出"识别与配合可同时开"，没跑过组合；
- 单次转换通过 → 推出"资源管理正确"，没查过泄漏；
- 位置精度 1e-17 → 推出"产物正确"，没验过形状（28 号文档）。

每一条都是真实测量，每一条都不能替代它想代替的那个验收。
探针回答"这个零件能不能匹配"，门禁回答"用户按下按钮会得到什么"——两者不可互换。
