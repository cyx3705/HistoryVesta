# SE2SW V2.3.0 首件特征识别修复

> 日期：2026-07-31  
> 范围：SolidWorks FeatureWorks 识别链；不改变 `.par -> .x_t -> .SLDPRT` 文件语义  
> 兼容性：Worker JSON 合同不变，OHS 窗口 ID 和命令不变

## 问题

批处理第一个 Solid Edge 零件会固定显示“未识别”，后续零件可能正常。此前的补丁在同一导入文档上增加了十次 `RecognizeFeatureAutomatic` 重试，但仍没有完整处理首件的文档激活、FeatureWorks 自动化对象初始化和种子面 COM 生命周期。

FeatureWorks 只操作 SolidWorks 当前活动文档。Worker 附着用户已有 SolidWorks 会话时，原有装配体可能仍是活动文档；继续识别既会让当前零件返回 0，也存在命令误作用于用户文档的风险。生产实现还与已通过的探针存在两项差异：没有调用 `SetPerformanceOptions(0)`，并且在识别调用前已经 `FinalRelease` 选中的面和实体对象。

## V2.3.0 修复

1. `ActivateDoc3` 后有界泵送 STA 消息并读取 `ActiveDoc`，只有标题与当前导入零件一致才允许进入 FeatureWorks。
2. 当前零件激活后重新调用 `GetAddInObject("FeatureWorks.FeatureWorksApp")`，避免沿用无活动零件时取得的首件加载态对象。
3. 识别选项与成功探针对齐，同时调用 `SetAdvancedOptions(...)` 和 `SetPerformanceOptions(0)`。
4. 种子面选择改为租约：`Body2` 和 `Face2` 的 COM RCW 一直保留到 `RecognizeFeatureAutomatic` 返回后才释放。
5. 首件在完整识别尝试后仍返回 0 时，关闭未保存的导入文档、释放 COM 对象、泵送消息 750 ms，并从同一个 XT 重新导入一次。恢复只允许执行一次；后续零件、FeatureWorks 不可用和已经成功的结果均不触发。
6. `ActivateDoc3` 和 `ActiveDoc` 返回的共享 RCW 只释放本次 COM 引用，不再使用 `FinalReleaseComObject` 破坏导入循环持有的模型对象。

## 失败语义

- 活动文档无法切换到当前零件：降级诊断明确记录期望标题、实际活动标题和错误码，不执行识别。
- 首件重新导入后成功：完成消息记录“首件重新导入恢复”和首次诊断。
- 重新导入后仍返回 0：按现有 `ContinueWhenRecognitionFails` 设置降级为导入实体或失败，不再继续重试。
- FeatureWorks 缺失或授权不足：保持 V2.0 行为，不进行无意义的重新导入。

## 验证

离线 Smoke 新增以下回归：

- 活动文档标题大小写无关匹配，其他文档必须拒绝；
- 仅首件第一次零特征结果触发恢复；
- 第二次、后续零件、FeatureWorks 不可用和成功结果均不得触发恢复；
- 原有“前两次返回 0、第三次成功”和十次上限测试继续保留。

真实 CAD 验收要求：关闭或保存用户正在编辑的 SolidWorks 文档后，以至少两个可识别样件串行转换；首件必须产生可编辑特征，第二件不得发生首件恢复，输出均可重新打开。若测试时已有用户 SolidWorks 会话，必须确认转换结束后原会话仍存活且未被关闭。
