# 40 · V3.6.4 · FeatureWorks 的会话激活态

日期：2026-08-05
样件：`C:\Users\Administrator\Desktop\测试新建文件夹\XT\消解加热板.x_t`、`XJ10B-12导热块.x_t`
探针：`tools/RecognitionOptionMatrix`

---

## 1. 结论

**FeatureWorks 的自动识别接口 `RecognizeFeatureAutomatic`，只有在该 SolidWorks 进程里由人工完成过一次特征识别之后才会生效。**

| 属性 | 实测值 |
|---|---|
| 激活方式 | 在该 SolidWorks 里**人工执行一次特征识别**。在 Tools → Add-ins 里勾选加载项**不算激活** |
| 作用范围 | 仅该 SolidWorks 进程；同进程内跨文档、跨客户端进程有效 |
| 生存期 | 到进程退出为止。**File → Exit 正常退出也不写盘** |
| 未激活时的表现 | 返回 0，**不抛异常、不改几何、不报错**——静默失败 |
| 与选项掩码的关系 | 无关 |

未激活时的静默失败正是这个问题长期没被定位的原因：产物看起来是成功的，只是全部退化成哑实体。

## 2. 证据

同一台机器、同一个零件、同一份代码：

| 会话状态 | 掩码 63 | 掩码 61 | 掩码 3 |
|---|---|---|---|
| 温会话，未人工激活 | 0（连测 6 次） | 0（2 次） | 0（2 次） |
| 全新冷启动会话（每掩码独立进程） | 0 | 0 | 0 |
| **人工识别后立刻测** | **11** | 0 → **11** | — |
| 换客户端进程、换零件，仍在该会话 | **9** | — | — |
| 正常退出后新开会话，不做人工操作 | 0 | — | — |

判定依据：

* 掩码 63 是 61 与 3 的超集。63 在未激活时失败 11 次，激活后一次成功——**掩码不是控制变量**。
* 同一会话内，人工识别**之前** 0、**之后** 11，其间加载状态未变——**加载方式也不是变量**。
* 两个不同零件表现一致——**不是零件特性**。
* 全部 15 次测量 `体积比 = 1.00000`，钣金节点 0——**不是几何损坏或钣金误识别**。

## 3. 已排除的自动化激活手段

| 手段 | 结果 | 排除强度 |
|---|---|---|
| 让加载项走启动加载路径 | FeatureWorks 未注册在 `HKLM\SOFTWARE\SolidWorks\Addins` 下，`AddInsStartup` 对它无效；且该假设已被 §2 第二条证据独立排除 | 强 |
| 重复调用自动识别自我激活 | 未激活会话连调 6 次全 0 | 强 |
| 识别前先选中实体（`SelectByID2`） | 选中成功（True），识别仍为 0 | 强 |
| Win32 菜单枚举取命令 ID | `GetMenu` 返回 NULL，SW 2025 为自绘菜单 | 强 |
| `RecognizeFeatureInteractive` | 13 个候选类型名全部返回 False，随后 `RPC_E_SERVERFAULT` | **弱——类型名是猜的**，类型库未导出合法取值 |
| `ISldWorks.GetLocalizedMenuName` 枚举命令 ID | 该方法只返回菜单栏 9 个顶级名（文件/编辑/…），不是命令表 | 不适用，该次枚举结论作废 |
| `IFrame.GetSubMenus` 枚举 | 未取到可用数据，且调用后 `GetLocalizedMenuName` 由 9 项变 0 项，说明参数语义没吃准 | 弱 |

`IFeatureWorksApp` 全部成员只有 7 个（`RecognizeFeatureAutomatic`、`RecognizeFeatureInteractive`、`CreateFeatures`、`SetAdvancedOptions`、`SetPerformanceOptions`、`BubbleTipCallback`、`HelpErrCallback`），已全部核对：**类型库自身不含激活用的调用**。

但"自动激活不可能"这个更强的结论**尚未成立**——上表后三行的排除强度不足。仍未走通的方向：拿到 FeatureWorks 命令的官方命令号后用 `ISldWorks.RunCommand` 触发。

## 3.1 附带发现：未激活时选项设置也失败

未激活会话中：

```
选实体=True  高级选项=False  性能选项=False  → 识别 0
```

`SetAdvancedOptions` 与 `SetPerformanceOptions` **双双返回 False**。同一症状在 SolidWorks 官方论坛有独立报告（见 §8）。

对照已测完，结论成立：

| 会话 | `SetAdvancedOptions` | 识别数 |
|---|---|---|
| 冷会话，同一文档内连续重试 12 次 | 12 次全 False | 0 |
| 已激活会话 | 第 1 次即 True（3/3 复现） | 11 |
| 已激活会话中偶发的首次失败 | False → 下一次 True | 0 → 11 |

即：

* `SetAdvancedOptions == false` ⟺ 本次识别必然返回 0；
* 未激活会话里它**恒** false，重试救不回来；
* 已激活会话里它立即 true。

**这是一次调用即可判定激活状态的探针**，不需要浪费任何零件。V3.6.4 据此把判定改为直接使用该返回值（§4.2），"连续两件零识别"退化为兜底。

`SetPerformanceOptions` 在两种会话里都返回 false，与识别成败无关，不能用作判据。

## 4. 本版改动

### 4.1 不再销毁激活态（这是本版的核心修复）

`SolidWorksImporter.ShouldResetFeatureWorksSession` 改为恒 `false`。

V3.6.2 为隔离 COM 污染，在**附着用户已有会话**时会先 `UnloadAddIn` 再 `LoadAddIn`。按 §1 的结论，这一步会把人工激活状态一起清掉——用户明明激活过，整批仍然全是哑实体。原来的两条分支现在都是负收益：

* 借用会话时重载 → 清掉激活；
* 自有新会话时重载 → 那个会话本来就未激活，重载没有收益。

`FeatureRecognizer.RestoreIsolatedSessionState` 同理改为空实现：它原本会在"加载项本来没加载"时卸载还原，同样会清掉激活态。加载项留在会话里无副作用。

### 4.2 静默失败改为响亮失败

**主判据**：`FeatureRecognizer.Process` 取 `SetAdvancedOptions` 的返回值（原来被 `_ =` 丢掉了）。返回 false 时直接跳过识别，产出置 `FeatureOutcome.SessionNotActivated = true` 的哑实体降级结果——识别根本没跑，几何原样保留。父 Worker 见到该标志，**在第一个零件上就定案**。

**兜底判据**：`SolidWorksPartImportIsolation` 仍统计连续识别到 0 个特征的零件数，达到 `UnactivatedSessionThreshold = 2` 时同样定案，覆盖"加载项没报告但识别确实全零"的情形。

任一判据触发时：

* 以 `FeatureWorksUnavailable` 报出明确诊断，写清补救办法；
* 把本批次剩余零件降级为哑实体导入（`RecognizeFeatures = false`），不再每件白跑一次识别。

阈值取 2 而非 1：单个零件确实可能本就没有可识别特征，连着两个不可能是巧合。

## 5. 对并行方案的影响

**19 号性能文档里的多实例并行池，在当前状态下不成立。** 池中每个新实例都是未激活的，识别全部返回 0。并行化必须等到激活可自动化之后再谈。

## 6. 使用约束（需要写进用户可见说明）

启用特征识别时，机器上必须有一个**已人工激活过 FeatureWorks 的 SolidWorks 会话在运行**。转换器通过 `Activator.CreateInstance` 附着到它。

激活操作：打开 SolidWorks → 打开任意零件 → 执行一次 FeatureWorks 特征识别。该会话在其存活期间可服务任意多个批次。会话关闭后需要重做。

## 9. 关于"XT 导入诊断"的假设

现场观察到打开 `.x_t` 时 SolidWorks 会跑一轮导入诊断，怀疑它塑造了手工环境。

现有数据不支持它是激活机制：探针的每一次 `Measure` 都重新 `LoadFile4` 导入同一个 XT，冷会话里因此已经跑过多轮导入诊断，`SetAdvancedOptions` 仍然 12 次全 false。导入诊断是**每文档**发生的，而激活是**每进程**的、且跨文档保持。

但它可能解释另一个次级现象：已激活会话里偶发的"首次 false、第二次 true"。该现象不影响判据（第二次即恢复），暂不深究。

已定的产品行为：**能附着到已激活的 SolidWorks 会话就做识别，否则识别失败、按哑零件产出**，不阻断批次。

| 装载 | `module.list` 显示 `se2sw 3.6.4`，2 条指令 |
| 哈希 | 正式槽与 Release 来源 **7/7 SHA-256 一致** |
| 离线烟测 | PASS |

回退：把当前 `Modules\SE2SW` 整体移出，从上述备份恢复，`module.reload` 后核验 `module.list` 回到 3.6.2。不得在槽内混合覆盖不同版本文件。

真机验收尚未做（需要一个已人工激活的会话跑多零件批次）。

## 7. 待验证

`UnloadAddIn` + `LoadAddIn` 是否确实清除激活态，尚未直接实测（需要一个已人工激活的会话做对照）。§4.1 的改动不依赖这条验证——即使重载不清除激活，该改动也只是去掉一个无收益操作。
