# SE2SW V1.1 工程实施与验收

- 版本：1.1.0
- 日期：2026-07-27
- 环境：Solid Edge 2020、SolidWorks 2025 SP5、Windows x64
- 前置研究：[Opus 5 Solid Edge 导出验证报告](04-Opus5答复-SolidEdge导出验证报告.md)

## 1. V1.1 交付结论

正式 Worker 已在复制到系统临时目录的样件上完成真实链路：

```text
beaker150.par
  -> Solid Edge PartDocument.SaveBody
  -> beaker150.x_t
  -> SolidWorks ISldWorks.LoadFile4
  -> ModelDocExtension.SaveAs3
  -> beaker150.SLDPRT
```

本机单次最终验收耗时 14.68 秒，Worker 退出码为 `0`。生成的 XT 为 10,542 字节，头部
`FORMAT=text`；SolidWorks 零件为 159,187 字节，`SaveAs3` 错误码和警告码均为 0。样件副本转换前后
SHA-256 相同。已有 Solid Edge 会话 PID 29216 在转换前后保持存活，SolidWorks 转换前后均无残留进程。

## 2. Solid Edge 实现

生产导出调用固定为：

```csharp
document.SaveBody(
    temporaryXtPath,
    2,             // seSaveBodyAsParasolidText
    0,             // seParasolidCurrentVersion
    Type.Missing,  // 全部 Model
    Type.Missing);
```

每项按以下顺序执行：

1. 计算源 `.par` SHA-256。
2. 打开文档并导出到同目录、保留 `.x_t` 末扩展名的唯一临时文件。
3. `Close(false)` 后调用 `Application.DoIdle()`，显式释放文档 RCW。
4. 连续 3 次、间隔 100 ms 检查文件可读、非空且长度稳定，最长等待 180 秒。
5. 以 Latin-1 一一映射头部字节，只解析 ASCII 标记并要求 `FORMAT=text`。
6. 再次计算源哈希；一致后将临时文件原子移动到正式路径。

应用启动前后记录 `Edge.exe` PID，并使用 `Application.hWnd` 对应 PID加强所有权证明。无法证明为 Worker
自建实例时立即停止，不修改可见性、不调用 `Quit()`。`DisplayAlerts` 在退出前恢复，文档关闭后调用
`DoIdle()`，只退出确定自有的实例。

## 3. SolidWorks 实现

SolidWorks 2025 的部分 API 没有通过 `IDispatch` 可靠暴露；使用 `dynamic` 调用 `IFrameObject`、
`GetImportFileData` 或 `LoadFile4` 会返回 `TYPE_E_ELEMENTNOTFOUND (0x8002802B)`。V1.1 不复制厂商
Interop，也不硬编码安装路径，而是：

1. 从 `SldWorks.Application` 的 CLSID `LocalServer32` 读取已注册的 `sldworks.exe`。
2. 定位同一安装目录的 `api\redist\SolidWorks.Interop.sldworks.dll`。
3. 运行时加载程序集，通过 `IUnknown` 查询 `ISldWorks` 强类型接口。
4. 通过该接口调用 `IFrameObject().GetHWndx64()`、`LoadFile4`、`CloseDoc` 和 `ExitApp`。
5. 通过 `IModelDoc2`/`IModelDocExtension` 调用文档类型、标题、`SaveAs3`。

Parasolid 在部分版本中没有专用 `GetImportFileData` 对象；该调用失败时传 `null` 给
`LoadFile4(path, "r", null, ref errors)`。导入结果必须是 `swDocPART = 1`。保存使用同目录临时
`.SLDPRT`，保存后重新读取文档标题再关闭，因为 `SaveAs3` 会改变标题；关闭和释放后才检查稳定性并提交。

进程所有权由 `SLDWORKS.exe` 启动前后 PID 快照与窗口句柄共同判断。只有所有权明确时才设置自动化状态并
调用 `ExitApp()`。

## 4. 取消、超时与诊断

- Worker 主入口为同步 `[STAThread]`，避免 `async Main` 在首次 `await` 后切换到 MTA，导致
  `CoRegisterMessageFilter` 失败。
- UI 通过 `--cancel` 指定的信号文件请求取消；Worker 每 100 ms 轮询。
- OLE busy 重试预算为 60 秒。取消期间出现的 `RPC_E_CALL_REJECTED` 还原为 `Cancelled`。
- UI 检测到连续 180 秒无进度时写取消信号，宽限 15 秒后终止隔离 Worker。
- 输出只在完整验证后提交，失败或取消会删除临时文件；已成功生成的正式 XT 在后续 SW 失败时保留。
- `WorkerEvent.errorClass` 区分注册、启动、许可、输入、输出、超时、调用拒绝、导出、导入、保存和实例
  所有权问题；UI 结果列显示分类名。

## 5. 自动验收

```powershell
dotnet build .\src\SE2SW\SE2SW.csproj -c Release -p:NuGetAudit=false
dotnet run --project .\tests\SE2SW.Smoke\SE2SW.Smoke.csproj -c Release -p:NuGetAudit=false
```

最终结果：Release 构建 0 警告、0 错误；`SE2SW.Smoke: PASS`。烟测覆盖 OHS 目录移动与回滚前置检查、
外界模式映射、输出冲突、临时输出原子提交、Parasolid 文本头和 schema 解析、二进制头拒绝。

真实 Worker 请求中的枚举按数字序列化，`mode=0` 为 OHS，`mode=1` 为外界模式。验收必须操作样件副本，
不得覆盖原始 `.par`。

## 6. 未闭环风险

以下场景尚不能标记为已验证：

- 多实体 `.par` 的全部 Model 导出及 SW 多实体结果；
- 纯曲面零件与空零件；
- 无 Solid Edge/SolidWorks 许可环境下的实际 HRESULT；
- 长路径、大零件和批量压力；
- SE 源件与 SW 结果的实体数、体积、包围盒和几何容差自动比较；
- SolidWorks 3D Interconnect 开关对特征结构和后续编辑体验的影响。

当前成功条件证明文件链路和生命周期闭环，不等价于所有几何类别已经完成保真验收。补齐上述基准样件后，
应按实体数、体积和包围盒公差建立可重复回归，而不是比较每次都会变化的文件哈希。

## 7. OHS 部署验收

2026-07-27 已将 V1.1 部署到：

```text
%AppData%\OneHistoryStudio\Modules\SE2SW
```

模块槽包含 `module.manifest.json`、主模块 DLL/XML、Contracts 和独立 Worker 的 5 个运行产物。OHS 日志确认
`se2sw 1.1.0` 以精准暴露方式装载，注册 `se2sw.show`、`se2sw.hide` 两条指令。首次部署验收发现
`RadioButton.IsChecked` 对只读模式属性使用默认 TwoWay 绑定，已改为显式 `Mode=OneWay`；修复后的新 OHS
实例创建 UI 无警告。

使用部署槽内的 `SE2SW.Worker.exe` 对 `C:\Users\Administrator\Desktop\临时测试` 执行外界模式：

- 输入：`1-蜀牛低型烧杯150ml.par`，转换前后 SHA-256 一致；
- XT：10,470 字节，`FORMAT=text`；
- SLDPRT：159,294 字节，保存错误码/警告码均为 0；
- 耗时 16.1 秒，退出码 0；
- 已有 Edge PID 29216 前后不变，SolidWorks 前后均无残留进程。

本次只在所选外界目录生成同名 `.x_t` 和 `.SLDPRT`，未创建 OHS B 级目录，也未移动 `Unused`。
