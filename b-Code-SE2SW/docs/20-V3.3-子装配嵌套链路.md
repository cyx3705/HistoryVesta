# SE2SW V3.3 子装配嵌套链路

> 日期：2026-08-03
> 版本：3.2.0 → 3.3.0
> 范围：子装配递归生成嵌套 `.SLDASM`、局部矩阵采集、装配树标注
> 明确不做：在 SW 中生成任何配合（Mates）
>
> 前置：[18-V3.2-装配关系探针.md](18-V3.2-装配关系探针.md) 与
> [19-V3.2-装配关系实测报告.md](19-V3.2-装配关系实测报告.md)。本版路线由 19 号报告 §7 的实测结论定下。

## 1. 本版要解决的问题

**把子装配这条链路做成真嵌套。**

V3.0 把子装配递归展平成叶零件，每个叶零件单独输出 `.SLDPRT` 插进顶层装配，装配树层级丢失。
V3.3 改为**每个子装配生成自己的 `.SLDASM`，父级把它当一个组件插入**，层级完整保留。

这条路不需要任何新的 SE API：世界矩阵、`ParentId`、`AddComponent5 + Transform2 + FixComponent`
全部是 V3.0 已实测通过的机制。真正的新问题只有一个——**局部矩阵怎么来**，见 §3.3。

### 1.1 本版明确不做

| 不做项 | 原因 | 计划 |
|---|---|---|
| 在 SW 中创建配合 | 本版只做结构，配合是独立命题 | V3.5 |
| 装配级 Parasolid 导出进生产 | 实测证明它落地成装配壳，不如直接嵌套 | 不做；结论留档备查 |
| 面 ID / 面签名映射 | 实测证明 V3.5 可用世界系点/向量定位，此项降为可选 | V3.5 视需要 |
| 装配阵列、齿轮、凸轮关系的还原 | V3.2 已采集，本版不消费 | V3.5 起逐类评估 |
| 柔性子装配、可调件的还原 | 无 1:1 映射 | 按当前状态几何处理并记入报告 |

## 2. 前置结论

V3.2 探针给出的两条与本版直接相关的实测事实（详见 19 号报告）：

1. **`AssemblyDocument.SaveCopyAs(<路径>.x_t)` 可用**：单参数、文本 Parasolid、无对话框、源文件零改动。
   但 SE 导出的是**带装配结构的 Parasolid**，SolidWorks 的 `LoadFile4` 一律建成装配体文档，
   `swImportMultBodyAsPartData` 与 `swImportDissolveTopLevelAssemblyOnOpen` 置真都无效。
2. **子装配 `.asm` 可以作为独立顶层文档打开并枚举 occurrence**，读到的矩阵就是该文档自身坐标系下的值。
   这条是 §3.3 方案 A 的实测依据，已在三层样件上数值验证。
3. **关系分别存放在各自那层的装配文档里**（`测试装配1` 9 条、`测试装配3` 4 条、`风滚子` 43 条），
   不会全部堆在顶层。这支持 §3.1.1 的每层同构原则，也决定了 V3.5 的配合天然落在正确的层。

## 3. 子装配嵌套链路

### 3.1 链路定义

```
顶层 .asm
├─ 叶零件 .par ──→ .x_t ──→ .SLDPRT ──┐
└─ 子装配 .asm                        │
    ├─ 叶零件 .par ──→ .x_t ──→ .SLDPRT
    └─ 生成 <子装配名>.SLDASM  ←──────┘  按局部矩阵插入自己的组件、全部固定
                    │
                    └──→ 作为一个组件插入父级，用它在父级里的局部矩阵定位、固定
```

### 3.1.1 每层同构：本版的核心原则

**每个装配节点只关心本层的直接子项，不关心自己被谁引用、也不关心子项内部长什么样。**

也就是说，子装配的转换与顶层装配的转换**走完全同一条管线**：打开一个 `.asm`、读它的一级 occurrence、
把每个子项按局部矩阵插进一个新建的 `.SLDASM`、全部固定、原子提交。顶层只是"没有父级的那一层"。

这条原则直接决定了几件事：

| 问题 | 由同构原则自动解决 |
|---|---|
| 三层、四层、N 层嵌套 | 不需要为层数写任何分支；递归只是把同一个函数用在不同节点上 |
| 同一子装配被多次引用、各实例姿态不同 | 姿态由**父级**的插入矩阵承担，与子装配自身的生成无关；生成一次，插入 N 次 |
| 子装配内部的关系归属（V3.5） | 关系本来就分别存在各自那层的文档里（实测：`测试装配1` 9 条、`测试装配3` 4 条），配合天然落在正确的层 |

实现上必须守住的推论：**生成某一层时，绝不去读父级或祖先的任何信息。** 一旦某段代码需要
"我在谁下面"才能算出结果，就说明它违反了同构原则，八成是又在拿世界矩阵当局部矩阵用。

### 3.1.2 要点

- **叶零件的转换管线一个字不改。** 无论它在顶层还是嵌在三层子装配里，都走既有
  `SaveBody → .x_t → LoadFile4 → .SLDPRT`，并按规范化绝对路径全局去重，只转一次。
- **每个唯一的子装配 `.asm` 生成一个 `.SLDASM`**，同样按绝对路径去重：同一子装配被引用 N 次时
  只生成一次文件，插入 N 次。
- **自底向上生成**：父级要插入子级的 `.SLDASM` 文件，所以必须先有子级。见 §3.4。
- 顶层 `.SLDASM` 的组件数 = 顶层一级 occurrence 数（零件 + 子装配），不再是全部叶零件数。

这条路完全复用 V3.0 已实测通过的机制（`AddComponent5`、`Transform2`、`FixComponent`、
`TemporaryOutput` 原子提交、装配模板回退），不引入任何新的 CAD API。

### 3.2 装配级 Parasolid 导出：不进生产

初稿方案是把子装配整体导出为一个多实体零件。探针实测（[19 号报告](19-V3.2-装配关系实测报告.md) §7）：

- `AssemblyDocument.SaveCopyAs(<路径>.x_t)` 单参数可用，文本 Parasolid，无对话框，源文件零改动；
- 但 SE 导出的是**带装配结构的 Parasolid**，SolidWorks 的 `LoadFile4` 一律把它建成**装配体文档**；
- `swImportMultBodyAsPartData` (220) 与 `swImportDissolveTopLevelAssemblyOnOpen` (701) 置真都无效；
- 导入结果是一个装配壳，里面只有 1 个把全部几何揉在一起的虚拟组件。

即：**为了"不做嵌套"，反而要额外做一次"装配体另存为零件"的降级转换。** 代价比直接做嵌套更高，
产物还更差（不可编辑、BOM 无结构）。因此该分支不进生产管线。

结论保留在 19 号报告里：将来若出现"把子装配当刚体交付"的真实需求，`SaveCopyAs` 这条路已经验证可用。
探针的 `--export-check` 动词也保留，作为调查工具。

### 3.3 局部矩阵：本版唯一的新问题

V3.0 已实测确认：**`Occurrence/SubOccurrence.GetMatrix` 返回的是顶层装配坐标系下的世界矩阵**，
不是相对父级的局部矩阵（这也是 V3.0 严禁与父矩阵累乘的原因）。

但嵌套需要的恰恰是局部矩阵：把叶零件插进它所属的子装配 `.SLDASM` 时，位置必须相对**该子装配自己的原点**。

两条取法：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（采用）** | 把每个唯一子装配 `.asm` 作为**独立顶层文档**打开，直接读它自己 `Occurrences` 的矩阵——那本来就是该文档坐标系下的值 | 无矩阵求逆，无数值误差累积；探针已实测走通（`测试装配1.asm` 独立打开读出 3 个 occurrence，原点为其自身坐标系） |
| B（备选） | 一次打开顶层递归读世界矩阵，再算 `局部 = 父级世界矩阵⁻¹ × 子级世界矩阵` | 少开几次文档，但引入 4×4 求逆；旋转部分求逆要靠正交性转置而非通用求逆，写错不抛异常，只表现为姿态错乱 |

**采用 A（2026-08-03 已批准）。** 理由与 V3.0 选择"直接用 `GetMatrix` 不累乘"同源：
能从 CAD 直接读到的量，不要自己算。代价是每个唯一子装配多打开一次 Solid Edge 文档；
子装配数量远小于零件数量，可接受。方案 A 也是 §3.1.1 同构原则的直接体现：
读某一层的矩阵时根本不需要知道它的父级是谁。

**三层样件的数值验证**（2026-08-03 实测，见 19 号报告 §10）：

| 对象 | 独立打开该文档读到的 Y | 从顶层世界系换算 | 结论 |
|---|---|---|---|
| `测试装配3` 在 `测试装配1` 里 | 0.244 | 0.482 − 0.238 = 0.244 | 一致 |
| `测试零件6` 在 `测试装配3` 里 | −0.030 | 0.452 − 0.482 = −0.030 | 一致 |

方案 A 直接读到的就是正确的局部矩阵，**三层嵌套下无需任何换算**。

### 3.3.1 第二道防线：局部/世界自校验

探查结果里同时有两套**独立**数据：Solid Edge 直接给出的世界矩阵，和逐文档读出的局部矩阵。
`SE2SW/AssemblyTransformVerifier.cs` 把局部矩阵按层复合，与世界矩阵逐元素比对，
阈值 1e-9（与 V3.0 姿态判据同口径）。任何一层的参考系用错都会当场超差，
不需要 CAD、不需要人眼看图。

复合口径：行主序、行向量约定（平移在 12..14），点先经子级局部变换再经父级世界变换，
所以 **`世界 = 局部 × 父世界`**。

**这里有个陷阱**：顺序写反、或者把复合偷懒写成"平移相加"，在没有旋转的样件上照样"通过"。
因此离线用例必须带旋转——`TestAssemblyTransformVerifierWithRotation` 用的就是
"子装配绕 Z 转 90°、叶零件在其中沿 +X 偏 0.1"，正确结果是世界 (0, 0.338, 0)，
平移相加会得到 (0.1, 0.238, 0)，当场失败。

2026-08-03 真机实测（三层样件、含旋转实例）：**24 个实例全部匹配，最大逐元素偏差 5.55e-17**。

顶层组件（含子装配组件）的插入矩阵仍直接用顶层文档里读到的世界矩阵，与 V3.0 完全一致。

### 3.4 生成顺序与递归

按依赖自底向上：

```
1. 探查阶段递归采集全部 occurrence（已有），得到：
     - 唯一叶零件集合
     - 唯一子装配集合 + 每个子装配的直接子项
2. 转换全部唯一叶零件 → .SLDPRT（既有管线，一个字不改）
3. 按拓扑序（被依赖者优先）逐个生成子装配 .SLDASM
4. 生成顶层 .SLDASM，插入顶层一级 occurrence
```

- 拓扑序由子装配之间的引用关系决定；本批样件只有两层，但算法必须按任意层数写。
- **循环引用**（A 引用 B、B 又引用 A）在 SE 里不该出现，但探查阶段必须检出并报
  `SubAssemblyCycleDetected`，不能进入无限递归。
- 任一子装配生成失败时，按 `ContinueWhenPartFails` 的既有语义处理：默认中止，不产出缺件装配。

### 3.5 跨层复用与副本策略

零件或子装配被多层同时引用（例如某个小装配既出现在大装配里、又出现在中间层里）是正常情况。

**默认行为：不产生副本。** 按规范化绝对路径全局去重，一个源文件对应一个产物，
被引用 N 次就插入 N 次。嵌套方案天然做到这一点——初稿"整体导出"方案里"同一几何出现两份副本"的
代价随之消失，这是选嵌套的实际收益之一。

**但本版不为了消除副本增加任何机制**（2026-08-03 确认）：

- 不做跨层的引用合并、不做产物归并、不因为"这个零件在别处已经有了"而改变任何行为；
- 若因命名、路径或后续版本的策略变化真的出现了副本，**不视为缺陷、不报错、不阻断转换**，
  只在报告里如实列出；
- 副本的合并留给将来真正需要时再做，不在本版预埋。

理由与 V3.0 的"不自动改名"同源：迁移场景里用户依赖产物与源件一一对应，
为了消除副本而引入的自动归并会造成难以发现的错配，代价高于副本本身。

### 3.6 命名与冲突

```
<源目录>\SW\零件A.SLDPRT
<源目录>\SW\测试装配1.SLDASM
<源目录>\SW\风滚子.SLDASM      ← 顶层
```

全部产物同级放在 `SW\`，使 SolidWorks 按同目录规则解析组件引用最稳（与 V3.0 §2.2 一致）。

冲突判定并入既有 `DuplicateOutputName`，并扩两档：

| 冲突 | 判定 |
|---|---|
| 两个同名不同路径的 `.par` | 既有规则，明确失败 |
| 两个同名不同路径的 `.asm` | **新增**，明确失败 |
| 顶层 `.asm` 与某个子装配 `.asm` 同名 | **新增**，明确失败（都要写同一个 `.SLDASM`） |

策略不变：**明确失败，不自动改名。**

### 3.7 复用判定的过期规则

`AssemblyPartReusePlanner` 现在按"产物比源文件新"判定可复用。这条规则对装配**不成立**：
`测试装配1.asm` 本身没改，但里面的 `测试零件1.par` 改了，`测试装配1.SLDASM` 就已经过期。

装配产物（含顶层）的复用判定改为：

```
可复用  ⟺  产物存在且非空
        且  产物晚于 .asm 自身
        且  产物晚于该 .asm 递归依赖的每一个 .par / .asm
```

递归依赖表由探查阶段顺带产出，不额外开销。**任一依赖读不到修改时间即判为不可复用**——
宁可重转一次，不出静默旧几何。叶零件的复用判定不变。

### 3.8 固定与配合

V3.2 仍然**全部组件固定**，不产生任何配合：

- 每个子装配 `.SLDASM` 内部的组件全部固定；
- 顶层 `.SLDASM` 里的组件（含子装配组件）全部固定。

配合是 V3.5 的命题。届时"解除固定 + 加配合 + 校验回滚"要逐层进行，
而嵌套结构正是配合重建的前提——子装配内部的关系应该落在子装配文档里，而不是全部拍平到顶层。
本版把这个结构提前建好，V3.5 才有地方放配合。

### 3.9 特征识别

叶零件的特征识别行为不变（装配模式下默认关闭，可选开启）。
装配文档本身没有几何，不涉及特征识别。

## 4. 契约变更

沿用 `10-V3.0` §4.1 的规则：**所有新枚举值追加在末尾**，新字段可空或带默认值。

> **2026-08-03 实施记录**：本节已按实际交付的代码更新，与初稿有三处偏离，见 §4.6。

### 4.1 装配子项与文档读数

嵌套需要把"哪个装配包含哪些直接子项、每个子项在该装配里的局部矩阵"表达出来。
`AssemblyOccurrence` 是按顶层世界系设计的，不改它，新增两个记录：

```csharp
/// 某个装配文档里的一个直接子项。
public sealed record AssemblyChild(
    string Name,                      // occurrence 实例名
    string SourcePath,                // 子项源文件（.par 或 .asm）
    bool IsSubAssembly,
    bool IsHidden,
    double[] LocalTransform,          // 16 元素，行主序 4x4，米，相对**本装配**原点
    string? Diagnostic = null);

/// 一个装配文档的一级读数。每个唯一 .asm 一条，含顶层。
public sealed record AssemblyDocumentReading(
    string SourceAssemblyPath,
    IReadOnlyList<AssemblyChild> Children,
    IReadOnlyList<string> Warnings);
```

`LocalTransform` 的口径与 V3.0 的 `WorldTransform` 完全一致（旋转 `0,1,2/4,5,6/8,9,10`，
平移 `12..14`，米），差别只在参考系。**顶层节点的局部矩阵就等于世界矩阵**——
顶层的参考系就是世界系。这一点已写进契约注释，否则很容易被当成两套东西。

### 4.2 装配节点与装配图

```csharp
/// 一个待生成的 .SLDASM 及其直接子项。列表按拓扑序：被依赖者在前，顶层在最后。
public sealed record AssemblyNode(
    string SourceAssemblyPath,
    string OutputPath,
    bool IsRoot,
    int Depth,                             // 顶层为 1；被多处引用时取最深的一条路径
    IReadOnlyList<AssemblyChild> Children,
    IReadOnlyList<string> Dependencies);   // 递归依赖闭包，供 §3.7 复用判定
```

节点由 `SE2SW/AssemblyGraphBuilder.cs` 从读数列表构建，产出：

```csharp
public sealed record AssemblyGraph(
    IReadOnlyList<AssemblyNode> Nodes,
    int MaxDepth,
    IReadOnlyList<string> Cycles,            // 非空即不可转换
    IReadOnlyList<string> MissingDocuments); // 引用了但没有读数的 .asm
```

**它是纯数据变换，不碰 CAD**，因此整套拓扑序、去重、深度、依赖闭包、成环检出、缺失检出
都由离线 Smoke 覆盖。成环时不产出任何节点——半张图比没有图更危险。

### 4.3 探查结果

`AssemblyProbeResult` 末尾追加一个可空字段：

```csharp
IReadOnlyList<AssemblyDocumentReading>? Documents = null   // null 表示 V3.0 格式的旧结果
```

**`UniquePartPaths` 的语义不变**——仍是"全部唯一叶零件"，因为嵌套方案下每个叶零件
照样各自输出一个 `.SLDPRT`。初稿要把它收窄为"顶层一级 `.par`"，随整体导出方案一起作废。

### 4.4 结果与错误

`AssemblyOutcome` 追加：

```csharp
int SubAssemblyTotal,       // 需要生成的 .SLDASM 数（不含顶层）
int SubAssemblyBuilt,       // 实际生成成功的数量
int MaxDepth                // 实际嵌套层数
```

`ComponentTotal` / `ComponentInserted` 的语义随之变化：从"全部叶零件"变为
**"全部装配节点的直接子项之和"**。这是语义变更而非字段追加，必须在契约注释里写明，
并由 Smoke 用例锁死。

`AssemblyBatchRequest` 末尾追加：

```csharp
IReadOnlyList<AssemblyNode>? Nodes = null   // null 时退化为 V3.0 的展平行为
```

`ConversionErrorClass` 末尾追加：

```
SubAssemblyBuildFailed        子装配 .SLDASM 生成失败
SubAssemblyCycleDetected      装配引用成环，拒绝递归
SubAssemblyReuseStale         复用候选因依赖更新而被拒绝（信息级，不中止）
```

初稿计划的 `SubAssemblyExportFailed` / `SubAssemblyBodyCountMismatch` 随装配级导出方案一起作废，
**不要加进枚举**——枚举值一旦发布就不能删。

### 4.5 关系相关契约：本版不加

探针的输出是独立 JSON，不进 `SE2SW.Contracts`。关系记录类型等 V3.5 动手时再定义。
19 号报告已经把字段清单实测出来了，届时是照抄不是猜测。

### 4.6 与初稿的三处偏离

| 项 | 初稿 | 实际交付 | 理由 |
|---|---|---|---|
| `ConversionJobKind` | 追加 `Part` / `SubAssembly` 枚举 | **不加** | 嵌套方案下子装配不是"零件作业"，而是装配节点，这个枚举没有消费者。按 §4.4 自己的原则——枚举值一旦发布就不能删——不发布用不上的值 |
| 装配节点的产出位置 | 由 Worker 在探查阶段产出，塞进 `AssemblyProbeResult` | Worker 只产出**逐文档读数**，图由 UI 侧的 `AssemblyGraphBuilder` 构建 | Worker 引用不到 UI 程序集，而 Smoke 引用得到；把纯逻辑放在能离线测的一侧，CAD 交互留在 Worker。数据流与既有的 `Occurrences`（探查 → UI → 请求）一致 |
| `AssemblyNode.Depth` | 无 | 有 | UI 摘要行、门禁的最大层数断言都要它；顺带让"被多处引用时取最深路径"这条规则有地方落 |

## 5. 界面：装配树标注

`AssemblyViewModel` / `AssemblyTreeNode` 的改动限定在**显示与说明**，不引入新的交互路径。

| 节点 | 标注 |
|---|---|
| 零件 | 正常显示，对应唯一零件清单里的一行 |
| 子装配 | 标注「生成 <名称>.SLDASM」；层级本身已经把子项展示在树里，不再重复计数 |
| 重复实例 | **同层**同源的实例显示 `×N`；跨层的不合并计数（那是两个不同装配里的事） |
| 隐藏件 | 保留 V3.0 的标注，仍然插入 |

状态栏解析摘要（实际交付）：`N 个实例、K 个唯一零件、M 个子装配，最大 D 层；按层级生成嵌套装配`。

**关系统计不进 V3.3 界面。** 生产代码本版不读关系，界面上显示关系数会让用户以为配合会被转换。
等 V3.5 真正消费关系时再一并加。

状态栏文案更新：V3.0 的「本版按展平方式组装，装配树层级不保留」**必须删掉**——它从本版起就是错的。
改为「按源装配的层级生成嵌套装配体；全部组件固定，不含配合」。

## 6. 验收判据

### 6.1 硬性判据

V3.0 §6.1 的五条里，第 3 条随本版语义变化，其余不变，另加两条：

1. **位置精度**：每个组件原点与源 occurrence 原点偏差 **< 1e-6 m**。**在顶层装配坐标系下逐层核算**——
   子装配内部组件的世界位置 = 子装配组件变换 × 该组件的局部变换，必须与 SE 中同一叶零件的世界矩阵一致。
   这是本版位置判据与 V3.0 的唯一差别，也是最容易出错的地方。
2. **姿态精度**：旋转矩阵逐元素偏差 < 1e-9，同样逐层核算。
3. **数量一致（改）**：每个装配节点的组件数 == 该节点的直接子项数；总和 == 全部节点子项之和。
4. **全部固定**：每个 `.SLDASM` 内 `ComponentFixed == ComponentInserted`。
5. **无缺件**：顶层 `.SLDASM` 打开后无未解析引用，逐层展开后同样无。
6. **层级一致（新）**：SW 装配树的层级结构与 SE 装配树同构——节点数、每层子项数、父子关系全部一致。
7. **源文件零改动（新）**：`风滚子.asm`、`测试装配1.asm` 及全部 `.par` 的 SHA-256 转换前后一致。

### 6.2 真实样件门禁

`tools/AssemblyProductionGate` 扩展一档，对 `风滚子.asm` 端到端跑生产 Worker 并独立重开产物核验。
预期值取自 §2.1 的实测结构：

| 核验项 | 预期 |
|---|---|
| `.SLDASM` 产物数 | 3：`风滚子`、`测试装配1`、`测试装配3` |
| `风滚子.SLDASM` 组件数 | 18 |
| `测试装配1.SLDASM` 组件数 | 4（含 `测试装配3` 这个子装配组件） |
| `测试装配3.SLDASM` 组件数 | 2 |
| `.SLDPRT` 产物数 | 12 |
| 装配树最大层数 | 3 |
| 每个叶零件的世界位置 | 逐层复合核算后偏差 < 1e-6 m |
| 固定状态 | 每个 `.SLDASM` 内全部组件固定 |
| 源目录哈希 | 未变 |

**三层复合核算的重点样本**：`测试零件6` 的世界位置必须由
`风滚子 → 测试装配1(Y=0.238) → 测试装配3(局部 Y=0.244) → 测试零件6(局部 Y=−0.030)`
三级复合得出 `Y = 0.452`，与 SE 中该叶零件的世界矩阵一致。这条穿透了全部三层，
是整个门禁里最有价值的一条断言。

### 6.3 离线 Smoke 覆盖

进 `tests/SE2SW.Smoke`，全部不启动 CAD：

- occurrence 树 → `AssemblyNode` 列表的构建：节点去重、直接子项归属、`IsRoot` 判定；
- **拓扑序生成**：被依赖者在前；多层嵌套；同一子装配被多处引用只出现一次；
- **成环检出**：A→B→A 必须报 `SubAssemblyCycleDetected` 而不是栈溢出；
- 局部矩阵与世界矩阵的逐层复合（§3.3.1）：**必须带旋转**，否则"平移相加"这种写法也能蒙混过关；
  另配一条"故意把局部当世界"的用例，验证参考系用错会被检出、且偏差等于漏掉的父级平移；
- 输出路径计算（`SW\` 落位）与旧平铺产物兼容判定；
- 命名冲突三档（`.par` 撞 `.par`、`.asm` 撞 `.asm`、顶层撞子装配，见 §3.6）；
- 复用过期规则（§3.7）：依赖中任一文件更新即拒绝复用，依赖时间不可读也拒绝；
- 契约往返序列化：`AssemblyNode` / `AssemblyChild` / 新枚举 / 旧 JSON 缺字段时的默认值；
- 装配树构建与标注状态（§5）；
- 探针侧：类型库成员表序列化、只读保护路径逻辑（§2.7）。

SE 的 COM 成员名、SW 的插入与固定行为必须真机验证，不进离线测试。

## 7. 风险边界

- 探针只读。默认在临时副本上操作，`--in-place` 也做哈希前后比对；源样件目录永不写入。
- **局部矩阵是本版唯一的静默错误源。** 取错参考系不会抛异常，只表现为子装配整体错位或姿态错乱。
  三道防线：§3.3 选方案 A 不自己算；§3.3.1 用世界矩阵与局部矩阵互相印证；
  §6.3 的离线用例带旋转，堵死"平移相加"这类看似正确的写法。
- 装配引用成环必须检出，不能靠递归深度限制兜底。
- 子装配复用判定比零件严格（§3.7）：宁可重转，不出静默旧几何。
- 外界模式仍然永不移动、永不删除用户目录；`XT` / `SW` 只创建与写入。
- `CadProcessOwnership` 规则不变：SolidWorks 单实例，附着用户会话时绝不 `ExitApp`、绝不改可见性。
- 每个 `.SLDASM` 都走 `TemporaryOutput` 临时文件 + 原子提交；中途失败不留半成品。
- 全部组件固定；用户后续手工加配合前需自行解除固定。转换完成提示中说明。
- OHS 零件模式、V2.3.x 特征识别修复、V3.1.x 界面一律不动。

### 8.1 真机门禁实测（2026-08-03）

对三层样件 `风滚子.asm` 端到端跑生产 Worker，退出码 0：

| 核验项 | 结果 |
|---|---|
| 装配节点 / 最大层数 | 3 / 3 |
| 层级同构 | `测试装配3` 2/2、`测试装配1` 4/4、`风滚子` 18/18 |
| `.SLDPRT` 产物 | 12 |
| 局部/世界自校验（§3.3.1） | 24 个实例，最大偏差 5.55e-17 |
| 叶组件世界位置（SW `GetTotalTransform`） | 22 个，最大平移偏差 **5.55e-17 m**（阈值 1e-6） |
| 最大旋转偏差 | **4.00e-15**（阈值 1e-9） |
| 全部固定 / 源哈希未变 / 模板恢复 / CAD 进程收束 | 全部通过 |

位置判据用了**两条独立路径**：转换前由本项目的 `AssemblyTransformVerifier` 复合局部矩阵，
转换后由 SolidWorks 自己的 `GetTotalTransform` 复合。两条都落在机器精度上才算数——
只用自己的算法验自己的算法，等于没验。

叶组件 22 个而 occurrence 24 个：差的 2 个是 `测试装配1`、`测试装配3` 这两个子装配实例，
它们在 SW 里是装配组件而不是叶零件。各节点直接子项之和 2+4+18 = 24，与新的
`ComponentTotal` 语义（§4.4）一致。
