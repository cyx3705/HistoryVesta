# SE2SW V3.7.0 页面空间与输出路径更新计划

> 日期：2026-08-04  
> 计划版本：3.6.1 -> 3.7.0  
> 状态：设计完成，尚未实施  
> 范围：SE2SW 单页界面、运行状态入口、输出目录选择和 OHS 注册窗口名称  
> 不涉及：Worker 协议、Contracts JSON、CAD COM、FeatureWorks、装配关系算法、构建、部署或真实 CAD 转换

## 1. 背景与目标

V3.6.1 已将零件文件夹转换和装配体转换收敛到一个来源自适应页面，但页面仍有三处不必要的空间和交互成本：

1. 页面内部仍保留“SE2SW / Solid Edge 转 SolidWorks”标题栏。OHS 工具窗口本身已有窗口标题，这一层重复标题占用垂直空间，没有提供操作能力。
2. 探查或转换时，页面底部额外出现状态、动态进度条和取消按钮，导致主表区域高度变化，也让取消入口与当前来源相互分离。
3. 顶部 XT、SW 路径段只能打开已有目录，无法为当前转换指定输出位置。

V3.7.0 计划把顶部三段路径条升级为页面的统一来源、输出和运行状态入口，同时把 OHS 注册窗口标题收敛为更通用的“SE2SW”。这一命名为未来加入 SW 模型修复、SE 转 SW 模型更新等能力预留空间，但本版本不实现这些功能。

## 2. 页面空间更新

### 2.1 删除内部标题栏

- 删除页面内部高度为 60 px 的“SE2SW / Solid Edge 转 SolidWorks”标题区。
- 统一转换页面直接占满 OHS 注册窗口的内容区域。
- OHS/AppShell 提供的窗口标签、拖动条、停靠、浮动和最大化能力保持不变。
- 页面最小高度随标题区删除而相应收紧，但不降低装配树、零件表和转换选项的可用尺寸。

### 2.2 删除底部运行区

- 删除底部状态文本、独立动态进度条和“取消”按钮所在的整行布局。
- 删除后页面在空闲、探查、转换和取消过程中均保持相同的行结构，主数据区域不得因任务状态发生跳动。
- 零件表中的状态、特征、草图和结果明细继续按现有 Worker 事件更新；本计划不改变这些字段的含义。

### 2.3 顶部路径条承担运行指示

- 顶部“来源 / XT 目录 / SW 目录”继续拼接为一个统一圆角矩形。
- 在该圆角矩形底边内嵌一条 3 px 高的强调色运行条，不新增外部高度。
- 装配探查、装配转换或文件夹零件转换运行期间，运行条使用不定进度滚动动画；只表达“任务仍在运行”，不推算或显示虚假的完成百分比。
- 任务完成、失败或取消后立即隐藏运行条，并保持顶部路径条原有高度和边框。
- 本版本不增加完成色、失败色或进度百分比；具体结果仍以零件行、装配结果和既有状态数据为准。

## 3. 取消入口

- 来源段右键菜单新增“取消当前操作”。
- 同一入口覆盖三类活动任务：装配体只读探查、装配体转换和零件文件夹批量转换。
- 空闲时菜单项禁用；运行时即使来源段因 `CanEdit=false` 禁止左键切换，右键菜单仍必须能够打开并触发取消。
- 取消继续调用现有 ViewModel 生命周期和 Worker 取消文件机制，不新增第二套取消状态，不直接终止非本模块启动的 CAD 进程。
- 一次右键操作只能发送一次取消请求；重复点击不得创建并行取消流程。
- `Escape` 仍只负责关闭来源选择浮层，不改为转换取消快捷键。

## 4. XT 与 SW 输出目录

### 4.1 默认规则

未设置自定义目录时，保持 V3.6.1 的原有规则：

```text
<来源目录>\XT\*.x_t
<来源目录>\SW\*.SLDPRT
<来源目录>\SW\*.SLDASM
```

默认模式继续识别既有分层产物和历史平铺产物，保持当前安全复用、不覆盖用户文件和扫描阶段不创建目录的合同。

### 4.2 自定义规则

- 左键点击 XT 段打开文件夹选择器，设置当前来源的 XT 输出目录。
- 左键点击 SW 段打开文件夹选择器，设置当前来源的 SLDPRT 和 SLDASM 输出目录。
- 两个目录独立设置；未设置的一侧继续使用默认规则。
- 目录选择对话框被取消时不改变当前路径。
- 运行期间禁止修改 XT 或 SW 目录。
- 自定义目录只在当前来源期间有效；切换 `.asm` 或零件文件夹时清除两个自定义值，并按新来源重新计算默认目录。
- XT 与 SW 可选择同一目录，因为产物扩展名不同；仍须执行现有同名文件、可写性和产物冲突检查。
- XT、SW 段的右键菜单提供“打开目录”和“恢复默认目录”，以保留目录定位能力并提供明确的复位入口。

自定义某一侧后，该侧以选定目录为唯一目标，不再把默认分层目录或源目录中的历史平铺文件视为该侧的既有目标。未自定义的一侧继续遵守原有旧平铺兼容规则。这样可以避免用户明确指定新目录后，转换又因其他位置的旧产物而跳过。

### 4.3 创建与安全边界

- 扫描、来源切换和装配探查只计算与校验路径，不创建 XT、SW 或自定义目录。
- 用户点击转换且 CAD 环境检查通过后，才创建缺失的有效输出目录。
- 目录路径被同名文件占用、目录不可写或目标产物冲突时，以前置错误中止。
- 不清空、不迁移、不覆盖用户已有目录和文件。

## 5. 装配规划与零件扫描

- 装配规划使用最终生效的 XT、SW 目录，统一生成唯一零件、全部嵌套 `AssemblyNode.OutputPath` 和顶层 SLDASM 路径。
- 装配探查完成后修改输出目录，只重新执行纯内存规划，不重新启动 Solid Edge COM，也不重复读取装配体。
- 为此页面生命周期需要保留最近一次成功的只读探查结果；切换来源时与旧装配树、计划和源哈希一起清空。
- 文件夹模式扫描和转换必须消费同一组最终生效目录；修改目录后立即重新扫描对应位置的已有产物状态。
- 自定义目录不得改变零件名称、扩展名、嵌套层级、装配矩阵、固定状态或装配关系重建请求。

## 6. OHS 注册名称

- OHS 注册窗口标题由“SE2SW 转换”改为“SE2SW”。
- 窗口 ID 继续为 `se2sw`，避免破坏已保存布局、`win.show name=se2sw` 和热重载行为。
- 模块名、指令数量、MCP 暴露策略和 AppShell 3.0.3 公共接口不变。
- 本版本只完成通用命名和页面空间基础，不新增 SW 模型修复、模型更新、页面路由或新的 CommandBus 指令。

## 7. 实施边界

后续实施允许修改 SE2SW UI 和纯规划层，但必须遵守以下边界：

- 不修改 Worker 动词、请求文件格式或取消文件协议。
- 不修改 Contracts JSON 字段和枚举数值。
- 不修改 Solid Edge、SolidWorks、FeatureWorks COM 调用链。
- 不修改矩阵、嵌套装配、固定组件或装配关系重建算法。
- 不修改 AppShell 或 OHS 产品代码。
- 版本仍由 `build/SE2SW.Version.props` 作为唯一真源，清单只能由现有脚本生成；这些变更仅在后续正式实施时执行。

## 8. 后续实施门禁

### 8.1 UI Smoke

1. 页面内部不存在重复标题栏，底部不存在状态、动态进度和取消区域。
2. 顶部三段路径条在空闲与运行状态下尺寸完全一致，滚动条不推动或遮挡路径文本。
3. 常规和紧凑窗口中，来源、XT、SW 长路径使用省略号，不与转换选项或主按钮重叠。
4. OHS 注册窗口显示名称为“SE2SW”，窗口 ID 仍为 `se2sw`。

### 8.2 生命周期 Smoke

1. 装配探查、装配转换和零件批次运行时均显示顶部不定进度滚动条。
2. 三类任务均可通过来源段右键取消，取消后滚动条隐藏且页面恢复可编辑。
3. 空闲时不能发出取消；重复取消不创建并行任务或遗留 Worker。
4. 模块热重载与 `Dispose()` 仍会收束活动任务。

### 8.3 路径 Smoke

1. 覆盖默认目录、仅自定义 XT、仅自定义 SW、两侧均自定义和恢复默认。
2. 取消目录对话框不改变路径；切换来源清除自定义目录。
3. 自定义装配目录覆盖唯一零件、全部嵌套 SLDASM 和顶层 SLDASM。
4. 修改装配目录只重新规划，不重复执行 Solid Edge 探查。
5. 文件夹模式修改目录后重新扫描，转换请求与页面显示使用相同路径。
6. 扫描和探查不创建目录；同名文件占位、不可写目录和已有目标冲突仍被阻断。

### 8.4 回归与发布门禁

- Release build、`SE2SW.Smoke`、`SE2SW.UiSmoke` 和 `dotnet format --verify-no-changes` 全部通过。
- 版本真源、生成清单和 Release `SE2SW.dll` 统一为 3.7.0。
- Worker、Contracts JSON、CAD COM 和装配关系算法的既有回归全部保持。
- 正式发布前只需在临时样件副本上验证一次自定义零件目录和一次自定义嵌套装配目录；源文件 SHA-256 必须不变，Worker、Edge、SLDWORKS 不得遗留自有进程。

## 9. 本次文档提交边界

当前提交只新增本计划书，不表示 V3.7.0 已经实现、构建、发布或部署。本次不得同时修改：

- `build/SE2SW.Version.props`；
- `z-SE2SW/module.manifest.json`；
- XAML、ViewModel、Planner、Worker 或测试代码；
- Release 产物和 OHS 正式模块槽。
