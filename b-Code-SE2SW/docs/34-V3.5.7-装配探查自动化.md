# SE2SW V3.5.7 装配探查自动化

> 日期：2026-08-04  
> 版本：3.5.6 -> 3.5.7  
> 范围：装配转换页面的探查入口与信息密度  
> 不涉及：CAD COM、Worker 协议、转换结果、配合重建、AppShell/OHS 产品代码

## 1. 目的

装配转换的第一步是选择单个外界 `.asm`。原页面在选中有效文件后又要求用户点击“解析装配体”，该动作没有
新增输入、不能改变探查策略，只会增加一次重复操作。同时，按钮右侧的提示栏长期占据装配树的垂直空间。

## 2. 交互调整

- 点击顶部路径条的“装配文件”段，选择有效 `.asm`；
- 选择成功后立即调用既有 `AssemblyViewModel.ProbeAsync()`，使用原有的只读 Worker 探查链路；
- 删除“解析装配体”按钮和紧邻它的提示栏；
- 探查期间仍显示进度与取消入口；完成后继续以装配树、唯一零件清单、转换按钮可用状态表达探查结果；
- 源文件切换仍会清空旧探查结果。用户取消文件对话框时不触发探查，也不改变现有状态。

本变更不创建 `XT` 或 `SW` 目录，不会提前调用 SolidWorks，也不改变“必须先成功探查才可转换”的前置条件。

## 3. OHS CommandBus 边界

OHS 继续作为模块宿主和组合根；AppShell 3.0.3 保持冻结。模块注册器把模块方法登记到统一
`CommandRegistry`，控制台、MCP 与 Web 最终都通过同一个 `CommandBus` 执行，因此注册指令的执行回显和返回值
天然可以进入 OHS 控制台。

当前差距不在日志接口，而在 SE2SW 只注册了 `se2sw.show/hide`，装配解析和转换仍是页面直接调用 ViewModel；
同时 `module.manifest.json` 明确使用 `mcpExposure: hidden`。V3.5.7 只移除冗余提示栏，不伪造“已进入命令总线”。
后续应在 OHS 模块合同下完成以下收口：

1. 注册装配解析、转换、取消和状态指令；
2. 页面通过 OHS 提供的模块命令入口执行同一指令，不再平行维护第二条业务入口；
3. Console、MCP、Web 共用指令的参数、确认、取消、返回值和审计；
4. 按风险重新决定 SE2SW 的 `mcpExposure`，转换类指令不得因暴露而绕过宿主确认。

这条路线不新增 `IShellLogAware`，不要求模块化 OHS，也不启动 AppShell 4.0 工程。

## 4. 验收

1. Release build、离线 Smoke 与格式检查通过；
2. 装配页渲染中不存在“解析装配体”按钮或其警告栏；
3. 选择 `.asm` 的处理器仅在文件对话框确认后启动一次 `ProbeAsync()`；
4. 无 `.asm`、取消选择或忙碌状态不触发新的探查；
5. 不执行 CAD 真机转换，本次只验证 UI 调度与既有探查入口。
