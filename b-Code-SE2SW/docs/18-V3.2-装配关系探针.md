## 1. 本版要解决的问题

**把"SE 到底能读出什么装配关系"从猜测变成实测。**

V3.5 要做配合重建，但仓库里现在一行 `Relations3d` 代码都没有：关系的类型枚举、几何引用的取法、
所属 occurrence 的追溯方式全部是空白。凭这个状态去写设计，写出来的是猜测不是合同。

本版交付一个只读探针把这块空白填成一张实测表，外加它自己的测试。
**探针不产出任何进入管线的文件，不改生产代码。**

顺带用同一次会话回答一个属于子装配链路的问题：SE 装配文档能不能整体导出 Parasolid、
导出物在 SolidWorks 里落地成什么形态。这个问题的答案决定了 V3.3 走哪条路。

## 2. 装配关系探针

### 2.1 定位

新增 `tools/RelationProbe`，沿用 `tools/AssemblyProbe` 的骨架：独立 `net8.0-windows` x64 STA 控制台程序，
dump JSON 到标准输出，用退出码做门禁。与既有探针的唯一结构性差别是：**它对样件完全只读**。

### 2.2 为什么不自己造 fixture

`AssemblyProbe` 用 `Occurrences.AddWithMatrix` 脚本化生成受控 fixture，那是因为 occurrence 只需要
路径和矩阵两个已知量。装配关系不同：建立一条关系需要传入几何引用，而"几何引用怎么取"正是探针要
发现的东西——脚本化造关系会形成鸡生蛋，而且用 API 造出来的关系不等于用户在 SE 界面里用 FlashFit
点出来的关系。

**本版探针只读真实样件。** 样件位于 `C:\OneHistory\OneHistory-Push\.claude\测试零件`：

| 文件 | 角色 |
|---|---|
| `风滚子.asm` | 顶层装配，17 个零件实例 + 子装配 `测试装配1.asm` |
| `测试装配1.asm` | 第 2 层，3 个零件 + 子装配 `测试装配3.asm` |
| `测试装配3.asm` | 第 3 层，2 个零件 |

样件于 2026-08-03 扩充为三层，复测结论见 19 号报告 §10。跨层复用的策略由 V3.3 §3.5 定。

### 2.3 只读保护

样件是生产资产，不是可再生 fixture。探针默认**把整个 `测试零件` 目录复制到临时目录再打开**
（只复制不移动，源目录零改动）；`--in-place` 才直接读原件。两种模式都执行与
`SolidEdgeAssemblyExplorer.Probe` 相同的 SHA-256 前后比对，任一 `.asm` / `.par` 哈希变化即判失败。
打开一律 `document.Close(false)`，`DisplayAlerts = false`，`CadProcessOwnership` 规则不变：
附着到用户已开的 Solid Edge 会话时绝不 `Quit`。

复制整个目录而不是单个 `.asm`，是因为 `.asm` 内记录的是绝对路径引用，只复制装配文件会让引用
指回原目录，等于没隔离。

### 2.4 核心手法：先读类型库，再取值

已有代码里的 `TryGet<T>(() => occurrence.XXX, fallback)` 是"猜成员名 + 吞异常"。对 occurrence 够用
（成员就那么几个），对关系不够用：关系有十几种类型，每种成员不同，猜漏了不会报错，只会静默少采集。

**探针第一步不取值，而是 dump 类型信息。** 通过 `IDispatch::GetTypeInfo` 拿到
`System.Runtime.InteropServices.ComTypes.ITypeInfo`，枚举 `GetFuncDesc` / `GetVarDesc` 并沿继承链
展开，用 `GetDocumentation` 读出真实成员名、种类、**形参类型与 in/out 方向**。
**第二步才按这张表逐个取值。**

这样得到的是"SE 2020 这个类型库里到底有什么"，而不是"我猜它有什么"。

**带参方法必须按真实 VT 播种 byref 变体。** 关系最有价值的数据都不在无参属性上
（`GetGeometry1` 的 7 个 out 参数、`Face.GetRange` 的两个 ref 数组）；用空 VARIANT 调它们恒返回
`DISP_E_TYPEMISMATCH`，很容易被误判成"这个 API 不能用"。按类型库给出的 `I4` / `R8` 构造初值即可。

只试探"全部结果都从参数出来"的方法：任何必填的纯输入参数都意味着要先知道传什么，那就不是试探而是猜测。
`Add` / `Set` / `Delete` / `Save` 等可能改状态的动词一律不碰。

### 2.5 采集清单

对目录下**每个 `.asm` 分别**执行，各层结果并列输出——子装配自己的关系存在哪一层，
是 V3.3 链路设计与 V3.5 配合归属的直接输入。（实测：关系分别存在各自那层的文档里，见 19 号报告 §10.2。）

**A. 集合层**

| 项 | 目的 |
|---|---|
| `AssemblyDocument` 上名字含 `Relation` 的全部成员 | 定位真实入口，不预设叫 `Relations3d` |
| 集合的可枚举方式与索引基 | 遍历写法 |
| 该集合上的 `AddXxx` 方法全签名 | **V3.5 建配合的反向依据，本版只记录不调用** |

**B. 关系对象层**（逐条）

| 项 | 目的 |
|---|---|
| 类型库报出的接口名 + `Type` 数值 | 建立类型对照表 |
| 全部无参属性的实测值 | 参数矩阵 |
| 读不出来的成员及其 HRESULT | 区分"没这个成员"与"这次读不出来" |
| 参与的 occurrence 如何追溯 | V3.5 必须把关系挂到组件上 |
| 几何引用与几何数据的取法 | V3.5 的定位依据 |

**C. 几何层**（逐个被引用的元素）

| 项 | 目的 |
|---|---|
| 元素类型与所属零件文档 | 定位到哪个 `.par` |
| 面：曲面类型、面积、ID、包围盒、持久键 | 备选的面签名字段 |
| 坐标系：值在零件局部系还是装配世界系 | **决定 V3.5 要不要做面 ID 映射** |
| 单位是否为米 | 与 V3.0 已确认口径核对 |

C 组里"坐标系"一项价值最高：它直接决定 V3.5 的形态。实测结果见 19 号报告 §4、§6。

### 2.6 装配级导出探查（`--export-check`）

同一次 Solid Edge 会话里追加一个动词，回答 V3.3 的路线问题：

| 待确认项 |
|---|
| `AssemblyDocument` 上导出 Parasolid 的成员与参数语义 |
| 产物是单体、多体还是带装配结构 |
| 文本还是二进制（V1.1 起全线要求 `FORMAT=text`） |
| 是否弹交互对话框（批处理必须无人值守） |
| 是否修改源 `.asm` |
| SolidWorks 导入后落地成什么文档 |

导出产物落在 `<work-dir>\export\`，与样件副本分开，已存在同名产物时拒绝覆盖。
`--sw-verify` 时会临时改 SolidWorks 导入首选项并**必须恢复**，与 `FeatureRecognizer`
处理英文特征名同一原则：临时改、必恢复、不留痕。

### 2.7 退出码

| 码 | 含义 |
|---|---|
| 0 | 关系采集成功，至少一个文档有关系 |
| 1 | 真故障 |
| 2 | 用法错误 |
| 3 | **结论而非故障**：全部文档的关系集合都能正常打开且 `Count` 都是 0 |

**"无关系"与"真故障"用普遍性区分**：

| 现象 | 判定 | 退出码 |
|---|---|---|
| 所有文档的关系集合都能打开、`Count` 都读到 0 | 结论：样件靠拖放定位，这类装配在 V3.5 里走固定 | 3 |
| 集合能打开，部分文档有关系、部分为 0 | 正常，`Count == 0` 只是那个文档的事实 | 0 |
| 集合打不开 / 枚举抛异常 / 关系读不出接口类型 / 样件被改动 | 真故障 | 1 |

**体数与叶零件数不符不判失败**——它是一条要写进实测报告的事实，由生产门禁去卡，
不由探针替它下结论。判定文案里会明确列出差异。

### 2.8 探针的测试

探针本身要有测试，否则"探针跑通了"只是一句口头结论。

**离线部分**（进 `tests/SE2SW.Smoke`，不启动 CAD）：

- 类型库成员表与形参记录的 JSON 往返序列化；
- 成员矩阵的合并与去重（同类型多实例时成员表只出一份）；
- byref 播种表：给定形参 VT 与 SAFEARRAY 标志，构造出的初值类型正确
  （`I4→int`、`R8→double`、`SAFEARRAY(R8)→double[3]`、`GetMatrix→double[16]`）；
- "可试探"判定：含必填纯输入参数的方法被排除，全 out / in-out 数组的方法被接受；
- 只读保护的路径逻辑：整目录复制、`--in-place` 分支、哈希比对的变化/新增/消失三种判定。

**真机部分**（探针自身的退出码即断言）：

- 对 `风滚子.asm` 与 `测试装配1.asm` 各跑一次，退出码 0 或 3；
- 跑完核验源目录全部文件哈希未变；
- 连跑两次结果一致（关系顺序、类型、元素数稳定，排除会话相关的随机性）。

## 4. 对后续版本的结论

两条由实测直接推出、写进后续设计的结论：

1. **V3.3 不走"子装配整体导出为多实体零件"。** SE 导出的是带装配结构的 Parasolid，
   SolidWorks 一律建成装配体文档，导入选项压不回零件——为了"不做嵌套"反而要额外做一次降级转换。
   详见 19 号报告 §7，路线见 20 号文档。
2. **V3.5 的面 ID 映射从"必须"降为"可选"。** `GetGeometryN` 已经在装配世界系里给出平面的
   "点 + 法向"和轴的"点 + 方向"，而 V3.0 保证了 SW 组件世界变换与 SE 精确一致，
   因此不需要把 SE 的面 ID 映射到 SW 的面 ID。且轴关系根本取不到 `Face`，
   **只有 `GetGeometryN` 这一条路对所有关系类型都成立**。详见 19 号报告 §5、§6。
