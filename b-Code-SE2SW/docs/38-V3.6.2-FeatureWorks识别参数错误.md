# SE2SW V3.6.2 FeatureWorks 识别参数错误修复与验证记录

> 日期：2026-08-04  
> 基线：V3.6.1  
> 严重级别：P0，识别结果语义错误  
> 状态：门禁复核未通过；`消解加热板` 的自动特征树与手工金标准不等价，禁止据此发布  
> 范围：普通 Solid Edge `.par` 导入后的 FeatureWorks 自动识别参数、结果校验与安全降级

## 1. 用户报告

V3.6.1 开启“识别特征”后，普通机械零件的识别结果反复表现为：

- 特征树出现钣金相关节点；
- 同时仍保留导入体；
- 没有得到用户在 SolidWorks 中手工执行特征识别时能够得到的普通拉伸、旋转、切除、孔等可编辑特征。

同一零件由用户在 SolidWorks 中手工识别可以得到正常结果，因此本问题不归因于源零件、XT 几何或 SolidWorks 的基础识别能力。当前首要嫌疑是 SE2SW 调用 FeatureWorks COM 时传入的识别参数与手工流程不一致。

这是严重的正确性缺陷。现有代码把 `RecognizeFeatureAutomatic` 返回非零且 `CreateFeatures` 返回 `true` 视为识别成功，但“成功调用”不等于“识别语义正确”。一个几何体积没有变化、文件能够保存的零件，仍可能带着错误的钣金特征类型或未被真正参数化。

## 2. 当前调用与参数风险

生产代码当前固定执行：

```text
选择一个种子面
SetAdvancedOptions(fwAdvAddConstraintsToSketch | fwAdvAllowWizardHoleRecognition)
SetPerformanceOptions(0)
RecognizeFeatureAutomatic(0x3FF)
CreateFeatures(fwAddConstraintsToSketch)
```

`0x3FF` 会同时打开 `fwAutomaticRecognitionOptions_e` 的全部 10 位：

| 位 | 值 | 含义 |
|---|---:|---|
| `fwExtrudeOption` | 1 | 拉伸 |
| `fwVolume` | 2 | 体积特征 |
| `fwRevolve` | 4 | 旋转 |
| `fwHoles` | 8 | 孔 |
| `fwChamfils` | 16 | 倒角/圆角 |
| `fwRibs` | 32 | 筋 |
| `fwBaseFlange` | 64 | 基体法兰 |
| `fwSketchedBend` | 128 | 草图折弯 |
| `fwAutoEdgeFlange` | 256 | 自动边线法兰 |
| `fwAutoHemFlange` | 512 | 自动褶边 |

后四位均为钣金识别能力。SE2SW 当前只接收普通零件 `.par`，不支持 Solid Edge 钣金 `.psm`，却对每个普通零件无条件开启全部钣金选项。这与用户观察到的“钣金 + 导入体”结果直接一致，是当前最强的参数根因候选。

V2.0 文档曾记录：当时的样件使用 `61` 等部分掩码会返回 0，而 `0x3FF` 能返回非零。该结论只能证明 `0x3FF` 在当时环境中让调用产生结果，不能证明它是普通零件的正确参数，更不能作为跨 SolidWorks 版本的永久合同。尤其是当年的部分掩码 `61` 没有包含 `fwVolume=2`，因此不能据此否定不含钣金位的标准零件掩码 `0x3F`（63）。

## 3. V3.6.2 修复原则

1. 不再把“全部枚举位”当成自动识别的默认值。
2. 普通 `.par` 只能使用经真机证明与手工识别等价的标准零件参数，不得开启钣金识别位。
3. 生产候选先收紧为不含钣金位的 `0x3F`，但参数矩阵完成前不发布或部署。
4. 识别成功判据必须同时检查调用结果、特征树语义和几何一致性。
5. 无法得到可信普通特征时，必须重新导入 XT 并输出完整哑实体；错误特征树不能作为“成功识别”交付。

V3.6.1 的单零件 Worker 隔离、3 分钟无进度降级、导入身份校验和几何守卫继续保留。本问题发生在 FeatureWorks 参数与结果语义层，不撤销已有生命周期修复。

## 4. 真机参数探针

先扩展现有 `tools/SolidWorksRecognizeProbe`，使用同一份 XT、全新隔离 SolidWorks 会话和相同种子面，执行参数矩阵。探针只操作临时副本，不写正式转换目录。

最低矩阵如下：

| 组 | Automatic options | 目的 |
|---|---:|---|
| 当前生产值 | `0x3FF` | 稳定复现钣金误识别 |
| 标准零件全集 | `0x3F` | 拉伸、体积、旋转、孔、倒圆角/倒角、筋，不含钣金 |
| 历史实体组合 | `0x3D` | 复核旧文档记录的 61 |
| 无 Volume | `0x3D` 与逐项组合 | 确认 `fwVolume` 对返回 0 和类型选择的影响 |
| 手工等价值 | 由手工流程实测确定 | 作为最终生产候选，不预设数值 |

每组必须记录：

- 输入文件 SHA-256、SolidWorks 版本和 FeatureWorks 版本；
- 传入的十六进制/十进制掩码和每个枚举成员；
- 种子面的实体类型、选择是否成功以及活动文档标题；
- `RecognizeFeatureAutomatic` 返回数；
- `CreateFeatures` 返回值；
- 创建前后的完整一级特征树：名称、类型名、抑制状态；
- 是否出现 `SheetMetal`、`BaseFlange`、`SketchedBend`、`EdgeFlange`、`Hem` 或残留 `Imported`/`BaseBody`；
- 体积、包围盒、实体数和源/结果文件哈希；
- 保存并独立重开后的特征树与几何结果。

不得在同一份已被 FeatureWorks 改写的文档上连续测试不同掩码。每一组都必须从同一 XT 重新导入，并使用独立 Worker，避免前一组选择集、加载项状态或特征树污染后一组。

## 5. 手工流程对照

参数探针必须和用户成功的手工操作建立一对一对照，至少记录：

- 用户选择的是自动识别还是交互识别；
- FeatureWorks 界面中选择的特征类别；
- 是否选择了“标准特征”“钣金特征”或类似模式；
- 手工识别前选中的面、实体或整个导入体；
- 手工结果的特征类型顺序和数量。

最终“可编辑特征”生产参数以“同一 XT、同一 SolidWorks 版本下，COM 结果与成功手工结果语义一致”为门禁。仅凭 SDK 枚举名称、返回值大于 0 或某一个样件成功，不足以锁定参数。

如果手工流程实际使用 `RecognizeFeatureInteractive` 而不是 `RecognizeFeatureAutomatic`，文档必须据此停止假设两者等价。V3.6.2 应先评估能否在无人值守条件下稳定复现相同选择；不能复现时宁可安全降级，也不能用全量自动掩码伪造成功。

## 6. 生产参数合同

探针通过后，生产实现应建立有名称、可审计的标准零件识别配置，而不是继续使用裸常量：

```text
StandardPartRecognitionOptions = <真机锁定值>
```

合同要求：

- 值只能由普通机械特征位组成；钣金四位必须为 0；
- 每次识别事件和诊断记录实际掩码及配置名称；
- UI 的“识别特征”仍表示普通零件特征识别，不暗含钣金识别；
- `.psm` 未来若进入范围，必须使用独立来源类型、独立参数配置和独立门禁，不能重新把两类位掩码合并；
- `SetAdvancedOptions`、`SetPerformanceOptions` 和 `CreateFeatures` 参数也要进入探针记录，防止只修 Automatic options 后仍与手工流程不一致。

## 7. 识别结果语义守卫

现有几何守卫只能保证形状没有被改坏，不能证明特征类型正确。V3.6.2 需要在 `CreateFeatures` 后读取特征树并增加语义守卫。

对于普通 `.par`，出现以下任一情况均不得报告识别成功：

- 出现钣金、基体法兰、折弯、边线法兰或褶边类型；
- `RecognizeFeatureAutomatic > 0`、`CreateFeatures=true`，但最终仍只有导入体，没有任何普通可编辑特征；
- 创建特征数与最终可编辑普通特征树明显矛盾；
- 特征树无法枚举，不能证明结果类型；
- 几何守卫、导入身份守卫或独立重开校验失败。

语义守卫失败时：关闭未保存的识别文档，从原 XT 重新导入，关闭本件 FeatureWorks，生成几何完整的哑实体，并报告明确的“识别参数/结果类型不可信”诊断。不得继续保存带错误钣金树的文档，也不得把它交给装配构建器。

建议新增独立错误分类 `FeatureRecognitionSemanticMismatch`，与以下情况区分：

- `FeatureRecognitionEmpty`：没有识别出特征；
- `FeatureRecognitionTimeout`：识别长时间无进度；
- `FeatureCreationFailed`：候选特征无法创建；
- `GeometryChanged`：创建后几何不一致；
- `FeatureRecognitionSemanticMismatch`：几何可能正确，但特征类型或特征树语义错误。

## 8. 验收样件与判据

至少使用四类样件，每类都同时保留 XT、手工识别结果和 COM 识别结果：

1. 已知应识别为旋转的烧杯样件；
2. 含拉伸、切除和孔的官方或稳定基准样件；
3. 用户本次发现“钣金 + 导入体”的实际失败零件；
4. 简单立方体或基础拉伸件，用于确认不会被误判为钣金。

每个样件必须满足：

- COM 结果不包含任何钣金特征类型；
- 普通可编辑特征的类型和主要顺序与手工结果一致；
- 不以孤立 `Imported`/`BaseBody` 冒充识别成功；
- 体积、实体数和包围盒与 XT 基准一致；
- 保存并独立重开后特征树仍然有效且无重建错误；
- 源 `.par`、`.asm` 和 XT 输入 SHA-256 不变；
- 单件隔离结束后无遗留 SE2SW Worker、自有 Edge 或 SLDWORKS 进程。

参数必须在至少两个不同几何类别上通过后才能写入生产常量。一个样件成功不构成发布证据。

## 9. 自动化与回归

- Smoke 覆盖标准参数不含任何钣金位，禁止未来再次使用 `0x3FF` 或“全部枚举位”写法。
- 对特征树分类器覆盖普通特征、钣金特征、自动调用返回 0 但已产生钣金副作用、纯导入体、混合树、空树和枚举失败。
- 覆盖语义不匹配后的重新导入哑实体路径及错误分类 JSON 往返。
- 重跑 V3.6.1 的识别超时降级、V3.5.2 的单件隔离、导入身份校验和几何守卫。
- 装配回归确认普通识别件与降级哑件仍通过同一组件插入、固定和可选配合重建管线。
- Release build、`SE2SW.Smoke`、相关真机探针和 `dotnet format --verify-no-changes` 全部通过后才允许升版。

## 10. 临时使用建议与发布边界

V3.6.2 修复通过真机门禁前，用户应关闭“识别特征”，继续使用 XT 导入生成几何正确的哑实体。V3.6.1 的超时与几何兜底不能保证当前错误参数产生正确特征语义，不能作为继续开启识别的理由。

V3.6.2 必须用两个用户实件验证自动识别成功。未识别、超时、语义错误或几何越界时仍沿用干净
重导入保护；安全哑实体只能证明降级安全，不能作为特征识别验收通过条件。

## 11. 最终实施与真机证据（2026-08-04）

用户重新完成两个样件的手工识别后，手工金标准为：

- `XJ10B-12导热块.SLDPRT`：`Extrusion + 6 HoleWzd + Chamfer + Fillet`；
- `消解加热板.SLDPRT`：包含 `Extrusion / Thicken / HoleWzd / Fillet` 等普通可编辑特征。

界面截图确认手工条件是“自动 / 标准特征”，拉伸、体积、拔模、旋转、孔、圆角/倒角和筋均选中，
“本地识别实体”为空。对应 API 合同是 `RecognizeFeatureAutomatic(0x3F)`，调用前执行
`ClearSelection2(true)`，不是预选任意面。

根因实验全部使用相同 XT、独立自有 SolidWorks 2025 SP5 进程：

| 参数与选择 | 导热块结果 | 结论 |
|---|---|---|
| `0x3F` + 首个面 `mark=8` | 连续 10 次返回 0 | SDK 示例中的特定圆角面不能推广为任意“种子面” |
| `0x3F` + 无预选 | 第 2 次返回 9，创建成功 | 与手工金标准特征树同构 |

第二个样件在 `0x3F + 无预选` 下返回 6，生成 `5 HoleWzd + Fillet`，并保留一个基体导入节点。
当时的弱语义守卫按“至少存在一个普通可编辑特征”放行了该混合树；第 13 节已经证明这是错误结论。

FeatureWorks 重建并非逐位保持 Parasolid 几何。两个手工金标准及自动结果的体积比稳定为：

| 样件 | SW / XT 体积比 | 面数 |
|---|---:|---:|
| 消解加热板 | `0.9999990626287` | `32 -> 32` |
| XJ10B-12 导热块 | `1.0000141829165` | `85 -> 83` |

原 `1e-9` 容差会误杀正确的导热块结果。生产几何守卫和 `PartGeometryProbe` 统一使用 `2e-5`
相对体积上限；它覆盖已验证的 `1.418e-5`，仍会拒绝超过该边界的形状破坏。

当时实施的生产改动（其验收结论已由第 13 节撤销）：

- 标准零件掩码固定为 `0x3F`，包含 `fwVolume=0x02`，且与钣金位 `0x3C0` 无交集；
- 每次识别尝试前只清空选择，不创建首面、面选择数据或 `mark=8`；
- 保留活动文档确认、加载项刷新、异步重试、钣金/残留导入体语义守卫和干净重导入降级；
- Smoke 锁定无预选重试合同和 `2e-5` 几何边界；
- `SolidWorksRecognizeProbe --inspect` 使用自有 PID 只读重开并输出结构化特征树。

当时完整 Worker 从两个 `.par` 重新导出 XT 并自动识别：导热块返回 9、加热板返回 6。
旧门禁把两者都记为 `SemanticMismatch=false`；后续与手工金标准逐项复核证明，加热板的该结论错误。
几何一致、可以重开和进程无残留只证明产物可用，不证明特征语义等价。

## 13. 门禁复核与结论撤销（2026-08-04）

用户复核 `消解加热板.SLDPRT` 后指出自动树与手工树不同。重新读取两份树确认：

- 手工金标准核心序列为 `Extrusion, ICE, RefSurface, Thicken, ICE, RefSurface, Thicken,
  HoleWzd x5, Fillet`；
- 旧自动结果只有 `BaseBody, HoleWzd x5, Fillet`。

因此第 12.1 节把 `BaseBody + 5 HoleWzd + Fillet` 记为健康识别是错误的。返回数量大于零、
`CreateFeatures=true`、几何一致和文件可重开都不能替代特征树语义门禁。

补充探针使用同一 XT、同一 SolidWorks 2025 SP5 会话验证了以下调用：

| 调用 | 结果 | 结论 |
|---|---|---|
| `0x3F` 连续调用，最后只建树一次 | 第二轮稳定返回 0，仍为 `BaseBody + 5 HoleWzd + Fillet` | 重复全量掩码无效 |
| `Volume -> Extrude -> Revolve -> Holes -> Chamfils -> Ribs` | `BaseBody + 13 ICE + Fillet` | 体积优先会改变语义，仍不等价 |
| `Extrude -> Volume -> Holes -> Chamfils` | `BaseBody + 13 ICE + Fillet` | 分类型顺序不能复现手工树 |
| `0x3F -> Volume` | 后续 Volume 返回 0 | 不能补全首轮遗漏 |
| `Volume` 单独调用（无选择或首面 mark=0） | 连续十次返回 0 | 体积位存在不等于体积识别生效 |
| 首阶段保存、重开、再次 `0x3F` | 连续十次返回 0 | 中间保存重开也不能补全 |

`SolidWorksRecognizeProbe --inspect --expect-core-signature` 已新增有序核心签名断言，不再以候选数量代替语义：

- `消解加热板` 手工金标准签名
  `Extrusion, ICE, RefSurface, Thicken, ICE, RefSurface, Thicken, HoleWzd x5, Fillet` 通过；
- `XJ10B-12导热块` 手工金标准签名
  `Extrusion, HoleWzd x6, Chamfer, Fillet` 通过；
- 旧加热板自动结果的实际签名为 `BaseBody, HoleWzd x5, Fillet`，对手工签名断言失败并返回退出码 1。
- 修复后的 Worker 降级产物核心签名精确为 `BaseBody`，证明错误的孔/圆角混合树已被丢弃后重新导入。

探针同时支持按 PID 附着既有 SolidWorks；附着模式只关闭探针打开的文档，并无条件禁止 `ExitApp`，
即使附着前没有活动文档也不能退出用户会话。

本轮恢复生产调用为单次 `RecognizeFeatureAutomatic(0x3F)` 后单次 `CreateFeatures`，不采用未经证明的
多轮建树。语义守卫改为：创建后只要仍存在 `BaseBody`、`ImportedBody` 或 `Imported`，即判定自动树
不等价于手工识别，丢弃该树并从原 XT 干净重导入哑实体。这样不能把 `消解加热板` 自动重建成手工树，
但能阻止错误的部分识别再次冒充成功。

正式 3.6.2 槽仍是第 12 节记录的旧二进制；本轮未部署。后续只有在纯 COM 路径得到手工等价树，或产品
明确接受该样件安全降级为哑实体后，才能重新执行发布门禁。

## 14. 手工命令追踪与公开 API 边界（2026-08-04）

新增 `tools/FeatureWorksTraceProbe`，按 `SolidWorks_PID_<pid>` 只读附着现有 SolidWorks。探针不加载或
卸载插件，不保存或关闭文档，不调用 `ExitApp`。它记录 App 级命令事件、活动命令、文档切换、选择集和
完整一级特征树快照。首次实现曾对 SolidWorks 返回的共享 RCW 调用 `FinalReleaseComObject`，在文档切换时
触发 `RPC_E_DISCONNECTED`；修复后不再显式释放任何 SolidWorks API RCW，也不订阅容易与文档切换竞争的
PartDoc 事件，只保留 App 事件和 100 ms 轮询。

有效日志：

`%LOCALAPPDATA%\Temp\SE2SW-FeatureWorksTrace-20260804-manual-heater-6.jsonl`

手工流程使用未识别的 `消解加热板.x_t`，界面为“自动 / 标准特征”，拉伸、体积、拔模、旋转、孔、
圆角/倒角和筋全部选中，本地识别实体为空。核心时间线如下：

| elapsed ms | 事件或树签名 |
|---:|---|
| 70,959 | 新导入文档为 `BaseBody` |
| 73,425 | “输入诊断”命令关闭 |
| 75,384 | 活动用户命令标题变为 `FeatureWorks` |
| 77,756 | FeatureWorks 以 `reason=-2` 提交关闭 |
| 79,411 | `BaseBody` 被移除 |
| 80,211 | 出现 `Extrusion` |
| 81,419 | 出现 `Extrusion, ICE` |
| 82,239 | 出现第一组 `RefSurface, Thicken` 和第二个 `ICE` |
| 85,096 | 完成金标准树：`Extrusion, ICE, RefSurface, Thicken, ICE, RefSurface, Thicken, HoleWzd x5, Fillet` |

手工创建阶段内部短暂运行 `swCommands_ExtrudedBossBase=8`，并三次以
`swCommands_Sketch=45` 收口。`CommandInProgress` 在整个阶段仍报告 `false`，因此不能用它判断 FeatureWorks
是否完成；`PmOK` 后约 1.65 秒才开始改树，约 7.34 秒才完成。

基于该日志扩展 `SolidWorksRecognizeProbe` 后，使用同一 XT 和隔离 SolidWorks 2025 SP5 完成以下验证：

| 路径 | 结果 |
|---|---|
| `RecognizeFeatureInteractive("Volume", 0)`，无选择 | 返回 `false`，保持 `BaseBody` |
| 同上，首面 `mark=0` | 返回 `false`，保持 `BaseBody` |
| 自动 `0x3F`，Advanced=`0x6`，Create=`0x2` | 仍为 `BaseBody + HoleWzd x5 + Fillet` |
| `ImportDiagnosis(true,true,true,0)` 后自动 `0x3F` | 诊断返回 `1`，识别树仍不等价 |
| `RunCommand(1999)` 后 `RunCommand(-2)`，隐藏实例 | 两次均返回 `true`，等待 15 秒后仍为 `BaseBody` |
| 同一 RunCommand 路径，可见隔离实例 | 仍为 `BaseBody` |

因此不能把界面中文“体积”机械映射为交互式 FeatureType 字符串，也不能只调整 Advanced/Create 参数或
补一轮 Import Diagnostics。原生 PropertyManager 使用了公开 `IFeatureWorksApp` 之外的内部状态和增量创建
流程；`RunCommand` 可以打开和提交命令，但公共 COM 没有暴露该页面的模式、复选项和内部识别计划，不能
作为无人值守生产合同。

V3.6.2 当前生产决策保持不变：继续使用受支持的自动 API；若结果残留 `BaseBody`、`ImportedBody` 或
`Imported`，必须丢弃错误混合树并从 XT 干净重导入为哑实体。`消解加热板` 的手工等价自动识别门禁仍未
通过，本轮不部署，也不得把 RunCommand 探针路径迁入 Worker。
