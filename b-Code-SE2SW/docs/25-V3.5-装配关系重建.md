# SE2SW V3.5 装配关系重建

> 日期：2026-08-03
> 版本：3.3.2 → 3.5.0
> 范围：把 Solid Edge 的装配关系翻译成 SolidWorks 配合，逐条校验、失败回滚、如实报告
> 明确不做：追求 100% 还原
>
> 事实依据：[19-V3.2-装配关系实测报告.md](19-V3.2-装配关系实测报告.md)（关系类型、参数、几何取法全部已实测）
> 结构依据：[20-V3.3-子装配嵌套链路.md](20-V3.3-子装配嵌套链路.md)（每层同构、局部矩阵、逐层复合）

## 1. 目标

**能重建的重建，重建不了的那个组件保持固定，并逐条报出原因。**

不定"全量还原配合"这个目标——它做不到（阵列配合、齿轮/凸轮、路径关系在 SW 里没有 1:1 映射）。
本版的产物必须**永远可用**：位置精度不退化，配合是净增益。

### 1.1 交付判据的性质变化

V3.0–V3.3 的位置精度是"插入即达成"：组件全部固定，写进去什么就是什么。
**V3.5 起组件要浮动，位置由 SolidWorks 的约束求解器决定。** 这是本版最根本的风险：
加一条配合可能让整个装配跳位。

因此位置判据从"验证写入"升级为"验证求解结果"：每加一条配合，
立即核对全部组件相对 V3.3 基线的漂移 < 1e-6 m，超差就把这条配合删掉。

### 1.2 明确不做

| 不做项 | 原因 |
|---|---|
| 齿轮 / 凸轮 / 路径 / 阵列配合 | 本批样件未出现；无 1:1 映射，需逐类研究 |
| 关系的 `RangeLow` / `RangeHigh` 限位 | SW 的限位配合语义不同，先不映射，记入报告 |
| 过约束的自动消解 | 冲突即回滚该条，不试图重排 |
| 配合的命名与 SE 对齐 | SW 自动命名即可 |

## 2. 已实测的事实（照抄，不再猜测）

来自 19 号报告，本版直接消费：

| 事实 | 出处 |
|---|---|
| 入口是 `AssemblyDocument.Relations3d`，`Item(1..Count)`，索引基 1 | §1 |
| 样件出现三种类型：`GroundRelation3d` / `AxialRelation3d` / `PlanarRelation3d` | §1 |
| `Occurrence1` / `Occurrence2`（Ground 只有 `Occurrence`）直接给出组件，无需从几何反查 | §2 |
| 实例名形如 `测试零件2.par:1`，可读 `PartFileName` 绝对路径 | §2 |
| Planar 参数：`FixedOffset` / `Offset` / `NormalsAligned` / `RangedOffset` / `RangeLow` / `RangeHigh` | §3 |
| Axial 参数：`Orientation` / `ParallelOffset` / `FixedParallelOffset` / `Offset` / `FixedRotate` | §3 |
| **条件可读**：`RangedOffset=false` 时读 `RangeLow` 抛 `0x8000FFFF`；`ParallelOffset=false` 时读 Axial 的 `Offset` 抛 `0x80004005` | §3 |
| `GetGeometry1(out 类型, out 点XYZ, out 向量XYZ)`；类型 1=平面（面上一点+法向），2=轴（轴上一点+方向） | §4 |
| **几何值在装配世界系**，单位米 | §4 |
| `TopologyReference.Object` 对 Planar 成功（74/74 返回 `Face`），对 Axial **恒 E_FAIL**（0/20） | §5 |
| 关系分层存放，每层各有自己的 `GroundRelation3d` | §10.2 |

**两条直接决定架构的**：

1. **`GetGeometryN` 是唯一对所有关系类型都成立的几何来源。** 轴关系拿不到 `Face`，
   所以"取 Face → 算签名 → 在 SW 里配面 ID"这条路走不通。必须用点/向量定位。
2. **条件可读不是故障。** 生产代码必须先读开关再读值，否则会把正常状态误报成读取失败。

## 3. 架构

### 3.1 每层同构，第三次适用

关系存在各自那层的文档里，而 V3.3 已经让每层生成自己的 `.SLDASM`。因此：

> **某个 `.asm` 的关系，只翻译到它自己那个 `.SLDASM` 里。**

不需要跨层归属推断，不需要把子装配内部的关系提升到顶层——V3.0 展平方案下会出现的
"子装配内部约束变成顶层配合导致过约束"，在嵌套结构里根本不会发生。

### 3.2 坐标系：又一次白拿

`GetGeometryN` 返回的是**装配世界系**的值。而 V3.3 的方案 A 已经确立：
每个 `.asm` 都作为独立顶层文档打开。**在那个会话里，"世界系"就是该文档自己的坐标系。**

于是读某层的关系几何时，拿到的点和向量天然就在该层 `.SLDASM` 的坐标系里，
不需要任何换算。与 §3.1 合起来：**一层的关系、一层的几何、一层的装配文件，三者同一个参考系。**

这条必须在实现里写死为断言：读关系时若当前打开的不是关系所属的那个文档，直接抛错。

### 3.3 实体定位：几何枚举，不用坐标点选

在 SW 里选中配合实体有两条路：

| 方案 | 做法 | 取舍 |
|---|---|---|
| A 坐标点选 | `SelectByID2("", "FACE", x, y, z, ...)` 用世界点拾取 | 一行代码；但重合面、相切面处会静默选错，且点必须精确落在面上 |
| **B 几何枚举（采用）** | 遍历组件实体的面，读曲面类型与参数，与关系给出的点/向量比对 | 代码多；但**候选数可数**——0 个或 >1 个都能当场判定为"定位失败"而不是猜一个 |

选 B 的理由与本项目一贯口径一致：**宁可明确降级，不交付看起来正确的错误产物。**
A 方案选错面不会报错，只会生成一条语义错误的配合，而配合是用户后续设计的基础。

匹配规则（容差 1e-6 m / 1e-9 方向余弦）：

| 关系几何类型 | 在 SW 里找 | 判定 |
|---|---|---|
| 1 平面 | 平面面：法向与给定向量平行（同向或反向），且给定点在该平面上 | 唯一命中才接受 |
| 2 轴 | 圆柱/圆锥面：轴线方向与给定向量平行，且给定点在轴线上 | 唯一命中才接受 |

**候选 0 个 → `MateEntityUnmatched`；候选 >1 个 → `MateEntityAmbiguous`。两者都不猜，跳过该条关系并报告。**

### 3.4 类型映射

| SE 关系 | SW 配合 | 参数 |
|---|---|---|
| `PlanarRelation3d`，`Offset == 0` | 重合（Coincident） | 对齐方向由 `NormalsAligned` 决定 |
| `PlanarRelation3d`，`Offset != 0` | 距离（Distance） | 距离取 `Offset`，方向同上 |
| `AxialRelation3d`，`ParallelOffset == false` | 同轴（Concentric） | — |
| `AxialRelation3d`，`ParallelOffset == true` | 距离（Distance） | 距离取 `Offset`（**先判开关再读**） |
| `GroundRelation3d` | 固定该组件 | 见 §3.5 |

`Suppress == true` 的关系跳过并记入报告——它在 SE 里本来就没生效。

### 3.5 固定与浮动策略

V3.3 把所有组件固定。V3.5 改为**逐层**处理：

1. 该层有 `GroundRelation3d` → 固定它指名的那个组件；没有 → 固定第一个组件作为基准，并记入报告；
2. 其余组件浮动；
3. 逐条加配合（§3.6）；
4. 收尾时，**仍未被任何成功配合约束到的组件重新固定**，并在报告里列出——
   这些是"配合没建起来"的组件，固定它们才能保证位置不退化。

第 4 步是本版"产物永远可用"承诺的落点。

### 3.6 校验回滚引擎

对每条关系，顺序是：

```
记录全部组件当前变换（基线）
  → 定位两侧实体（§3.3），失败则跳过并报告
  → AddMate5
  → 检查返回的 errorStatus
  → 强制重建，读回全部组件变换
  → 与基线逐元素比对
     漂移 < 1e-6 m 且 < 1e-9 旋转 → 保留，计入成功
     否则或 AddMate5 报错          → 删除该配合，恢复，计入失败并报告原因
```

**基线是 V3.3 已验证的位置**，不是上一条配合之后的位置——否则误差会逐条累积，
最后整体偏了也没人发现。

配合一条一条加、一条一条验，不批量提交。慢，但每条失败都能精确定位到是哪条关系。

## 4. 契约变更

`ConversionErrorClass` 末尾追加（枚举值发布后不能删，只加本版真会用到的）：

```
MateEntityUnmatched     关系的几何在 SW 组件里找不到对应实体
MateEntityAmbiguous     找到多个候选，拒绝猜测
MateRejected            AddMate5 报错或求解后位置漂移超差，已回滚
MateTypeUnsupported     该关系类型本版不翻译
```

新增记录（结构照抄 19 号报告实测出的字段，不发明）：

```csharp
/// 一条 SE 装配关系。由 Worker 逐文档读出。
public sealed record AssemblyRelation(
    string SourceAssemblyPath,   // 关系属于哪个 .asm——决定它翻译到哪个 .SLDASM
    int Index,
    string InterfaceName,        // GroundRelation3d / AxialRelation3d / PlanarRelation3d
    string? Occurrence1,         // 实例名，与 AssemblyChild.Name 同源
    string? Occurrence2,
    RelationGeometry? Geometry1,
    RelationGeometry? Geometry2,
    double Offset,
    bool NormalsAligned,
    bool ParallelOffset,
    bool IsSuppressed,
    string? Diagnostic);

/// GetGeometryN 的产物。参考系 = 所属装配文档自身的坐标系（§3.2）。
public sealed record RelationGeometry(
    int GeometryType,            // 1=平面，2=轴
    double[] Point,              // 3 元素，米
    double[] Direction);         // 3 元素，单位向量

/// 随 Completed 事件回传。
public sealed record MateOutcome(
    int RelationTotal,
    int MateRebuilt,
    int SkippedSuppressed,
    int SkippedUnsupported,
    int FailedUnmatched,
    int FailedAmbiguous,
    int FailedRejected,
    int ComponentsLeftFixed,
    double MaxDriftMeters,
    IReadOnlyList<string> Diagnostics);
```

`AssemblyDocumentReading` 追加可空 `IReadOnlyList<AssemblyRelation>? Relations = null`；
`AssemblyBatchRequest` 追加 `bool RebuildMates = false`。**默认关闭**——本版是新能力，
不改既有默认行为。

## 5. 与特征识别的关系：两条路，由实测裁决

> **终局约束（2026-08-03 确认）：所有零件最终都必须完成特征识别与草图完全定义，
> 否则整件事没有意义。** 因此"关掉识别来保配合"不是一个可接受的终局，最多是过渡态。

FeatureWorks 把导入的哑实体重建成特征树后，面的划分可能改变（合并或拆分）。
§3.3 的几何匹配依赖面的存在与参数。识别是否会破坏匹配，**没有实测过，不能靠推断决定架构**。

两条路：

| 路 | 做法 | 成立条件 |
|---|---|---|
| **A 并行** | 装配里直接用识别后的 `.SLDPRT`，在其几何上匹配并建配合 | 识别后，关系引用的那些平面/圆柱面仍然存在且参数不变 |
| **B 零件替换** | 先在**哑实体**上建配合（几何来自 XT，匹配必然成功），再把组件替换为识别版，最后删除哑零件 | 替换后配合能存活或能重指派 |

A 更简单，B 是 A 不成立时的退路。**B 就是最初流程图里那个"零件替换"环节**——它在这里第一次有了真实用途。

### 5.1 裁决结果：走 A（2026-08-03 实测）

`tools/MateMatchProbe` 在三层真实样件上量了两轮，结论是 **A 路成立，B 路不需要**。

| 轮次 | 零件几何 | 带几何的关系 | 两侧唯一命中 | 命中率 |
|---|---|---|---|---|
| 1 | 哑实体（`RecognizeFeatures=false`） | 53 | 53 | **100%** |
| 2 | **识别版**（11/12 识别成功，51 个特征，草图 43/43 完全定义） | 53 | 53 | **100%** |

**特征识别不破坏几何匹配。** §5 原本担心的"识别后面被合并或拆分导致匹配失败"没有发生——
第 2 轮里 1 个零件降级为哑实体、11 个是真特征树，混合几何下命中率仍是 100%。

因此：配合重建与特征识别**可以同时开**，不做互斥开关，也不需要"零件替换 + 删哑零件"那条退路。
这与终局约束（所有零件都必须特征识别 + 草图完全定义）是一致的。

### 5.2 实测推翻的三个设计假设

这一轮把三条我事先写错的设计改了过来，每条都是"不实测就会静默做错"的：

| 项 | 原设计 | 实测 | 后果 |
|---|---|---|---|
| 曲面参数坐标系 | 未定 | **零件系**，必须乘组件 `GetTotalTransform(true)` | 按装配系解释只有 24/53 命中 |
| 多个候选 | 判为 `MateEntityAmbiguous`，拒绝猜测 | **假歧义**：SW 把一个几何面切成多块拓扑面（一个通孔 2~3 个圆柱面、一个大平面多块共面面），候选按构造等价 | 首轮 106 侧里 43 侧被误判为歧义，命中率被压到 37.7% |
| 子装配组件的面 | 未考虑 | `GetBodies3` 在子装配组件上返回空，**实体在其子组件里，必须递归** | 5 条引用子装配实例的关系恒不命中 |

第二条最值得记：我原本的"唯一命中才接受"是为了防选错面，但**能通过筛选的候选按构造必然共面或共轴**
（筛选条件就是"法向平行 + 点在其上"），它们给出完全相同的约束，根本没有选错的可能。
现在的实现改为：多候选时显式两两验证等价性，等价则确定性地挑一个
（优先法向与关系同向，其次按 Key 取序），**不等价才判歧义**——安全网保留，误判去掉。

## 6. 验收判据

### 6.1 硬性判据

1. **位置不退化**：加完全部配合后，每个叶零件的世界位置与 SE 的偏差仍 < 1e-6 m。
   **这是本版的一票否决项**——配合建得再多，位置错了就是失败产物。
2. **无重建错误**：`.SLDASM` 打开后无配合错误、无过定义标记。
3. **计数自洽**：`MateRebuilt + SkippedSuppressed + SkippedUnsupported + Failed* == RelationTotal`。
4. **报告完整**：每条未重建的关系都有一条注明类型与原因的诊断。
5. **V3.3 判据全部保持**：层级同构、组件数、源文件零改动。

### 6.2 真机门禁（2026-08-03 实测，三档全绿）

`AssemblyProductionGate` 增加 `--rebuild-mates` 档。三层样件、独立重开核验：

| 档 | 结果 |
|---|---|
| **A 配合重建** | 56/56 落位（53 配合 + 3 接地），失败 0，计数自洽；叶组件平移偏差 **2.43e-09 m**、旋转 4.00e-15 |
| **B 不重建（回归）** | 与 3.3.2 逐位一致：22/22、5.55e-17，全部组件固定 |
| **C 安全重试** | 复用 2 个子装配 + 全部零件产物，只重建顶层：43/43 落位，偏差同 A |

固定统计：`测试装配3 1/2`、`测试装配1 1/4`、`风滚子 2/18`——每层只剩基准件，
外加顶层的 `动量轮`（无关系约束，如实报告）。其余组件全部由配合约束。

**重建率不设阈值**这条保留：本轮恰好是 100%，但它是量出来的结果，不是目标。
下一批样件出现相切/角度/齿轮关系时，`MateTypeUnsupported` 会如实把它们报出来。

### 6.3 离线 Smoke

不启动 CAD 可覆盖的：

- 条件可读的开关判定（`ParallelOffset=false` 时不去读 `Offset`）；
- 类型映射表：给定关系参数 → 期望的 SW 配合类型与对齐方向；
- 几何匹配的纯数学部分：点是否在平面上、点是否在轴线上、方向是否平行（含反向）；
- 候选 0 个 / 1 个 / 多个三种判定；
- 回滚判定：给定基线与求解后变换，漂移是否超差；
- 计数自洽（§6.1 第 3 条）；
- 契约 JSON 往返。

## 7. 风险边界

- **位置退化是本版唯一不可接受的失败。** 校验回滚引擎的基线必须是 V3.3 的已验证位置，
  不是上一条配合后的位置。
- 几何匹配的容差是 1e-6 m；样件里若存在间距小于该值的平行面，会被判为歧义并跳过——
  这是有意为之，不放宽。
- 浮动组件后求解器可能整体重排；§3.6 每条都验、超差即回滚，是唯一防线。
- 关系读取只读打开，沿用 V3.2 探针与 V3.3 采集的 SHA-256 前后比对。
- 本版不改零件管线、不改 V3.3 的嵌套生成逻辑；`RebuildMates=false` 时行为与 3.3.2 完全一致。
