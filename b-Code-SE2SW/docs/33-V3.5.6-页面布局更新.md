# SE2SW V3.5.6 页面布局更新

> 日期：2026-08-04  
> 版本：3.5.5 → 3.5.6  
> 范围：零件转换、装配转换、OHS 兼容三种模式的 WPF 页面布局  
> 不涉及：CAD COM、Worker 协议、转换语义、配合重建或 AppShell/OHS 产品代码

## 1. 目标

处理两个已知的界面摩擦点：

1. 所有页面的“转换选项”此前只能向下展开，展开后会占用数据表或装配树的垂直空间；
2. 装配页把源 `.asm`、XT 目录、SW 目录拆成两行，用户想查看或打开产物目录时需要先在文件管理器中另行定位。

## 2. 交互变更

| 页面 | V3.5.5 | V3.5.6 |
|---|---|---|
| 零件转换 / OHS 兼容 | 选项向下展开，两个复选框纵向排列 | 选项在当前工具行向右展开，两个复选框横向排列 |
| 装配转换 | 选项向下展开；源文件与输出目录分两行 | 选项向右展开；源 `.asm`、XT、SW 在顶部同一行 |
| 装配路径条 | 源文件输入框、独立“选择 .asm”按钮和两个分散目录框 | 三段直接拼接为一个统一长圆角路径条；点击源文件段选择 `.asm`，点击 XT/SW 段打开目录 |
| 装配 XT / SW | 仅显示不可操作的路径文字 | 目录段可点击：目录存在即用系统文件管理器打开 |

点击尚未创建的 XT 或 SW 目录不会写入文件系统，也不会提前创建空目录；界面会提示该目录将在成功转换时创建。
这保持了当前转换合同中的“扫描/探查不创建输出目录”边界。

## 3. 实现边界

- `SE2SWView.xaml` 与 `AssemblyView.xaml` 的 `Expander` 均指定 `ExpandDirection="Right"`；
- 选项内部统一为横向 `StackPanel`，避免展开后增高页面；
- `AssemblyView.xaml.cs` 只使用 `Process.Start(..., UseShellExecute=true)` 打开已存在目录，不读取、修改或删除转换产物；
- 版本只从 `build/SE2SW.Version.props` 升至 `3.5.6`，清单由 `eng/Update-SE2SWManifest.ps1` 生成；
- 不修改 Contracts、Worker、装配树、零件扫描和 CAD 调用链。

## 4. 验收

1. Release build 与离线 Smoke 通过；
2. `SE2SW.UiSmoke` 分别以零件、装配、OHS 兼容和紧凑窗口尺寸渲染，确认选项展开后仍保持单行且不遮挡主操作按钮；
3. 装配页选择 `.asm` 后，XT/SW 路径在同一行更新；目录已存在时点击可打开，目录不存在时仅提示、不得创建目录；
4. 这次是 UI 更新，不重新运行 CAD 转换门禁；已有 V3.5.5 的“特征识别 + 配合重建”组合真机结论仍是转换链路的基线。
