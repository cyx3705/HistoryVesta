# SE2SW 当前转换合同

> 当前发布线：V3.6.0
> 机器真值：`build/SE2SW.Version.props`、自动生成的 `z-SE2SW/module.manifest.json`、离线 Smoke 与当前源代码。
> 历史文档：`01`–`21` 是需求、探针、设计及验收记录；与本文冲突时，不作为现行行为依据。

## 1. 单页来源与输入

SE2SW 是 AppShell 中 ID 为 `se2sw` 的普通工具窗口。页面只有一个来源入口，点击后在两种外界来源中选择：

- 选择装配体：选择单个 `.asm` 后立即只读探查装配树，再允许转换；
- 选择零件文件夹：只扫描所选目录顶层 `.par`，转换全部尚无 XT/SLDPRT 的零件。

装配来源显示装配结构与唯一零件双栏；文件夹来源收起装配结构，零件表占满主区域。文件夹模式不提供勾选、
全选或清空，已有新分层或旧平铺产物的条目标记“已存在”并跳过，转换结束后自动重扫，失败项保持可重试。
来源切换会清空上一来源的树、计划、零件结果与输出状态；取消选择对话框不改变当前来源。

OHS `ConversionMode.Ohs`、旧零件 ViewModel 和项目解析器仍保留，保证历史 JSON 与未来恢复入口的兼容性，
但 V3.6.0 页面不提供 OHS 兼容入口。

“转换选项”在当前操作行横向展开。顶部同一行呈现来源、XT 输出目录和 SW 输出目录；选择 `.asm` 后立即启动
只读探查，不需要额外的“解析装配体”按钮。
点击已有的目录路径会在系统文件管理器中打开它。转换前目录尚未创建时，界面说明原因而不创建空目录。

OHS 是模块宿主和组合根。模块注册器产生的模块指令进入统一 `CommandRegistry`，再由 `CommandBus` 执行；
控制台、MCP 与 Web 共用这条管线。装配页已移除紧邻文件条的提示栏；当前页面解析仍是 ViewModel 内部调用，
不伪装成已经进入命令总线。后续应在 OHS 模块合同中把装配解析、转换、取消与状态注册为正式模块指令，并按
清单策略决定 MCP/Web 暴露，不为日志单独扩展 AppShell，也不推动 OHS 模块化或 AppShell 4.0。

## 2. 外界输出、复用与写入边界

外界模式以被选择源文件所在目录为根：

```text
<根目录>\XT\<零件名>.x_t
<根目录>\SW\<零件名>.SLDPRT
<根目录>\SW\<装配名>.SLDASM
```

扫描/装配探查不会创建 `XT`、`SW`。仅在用户点击转换、环境检查通过后才创建它们。若目录名已被同名文件占用，立即失败；不清空、不迁移用户数据。

旧版平铺在根目录的 `.x_t`、`.SLDPRT` 仍可作为安全复用候选。复用要求文件非空、不会早于源文件；XT 还必须通过 Parasolid 文本检查。装配产物必须不早于所有递归依赖。无法安全复用的既有文件不覆盖，要求用户移走后重试。

## 3. 转换语义

- 零件：`.par → .x_t → .SLDPRT`，XT 由 Solid Edge COM 导出，SolidWorks COM 导入；识别特征与完全定义草图默认关闭，后者依赖前者。
- 装配：每个唯一 `.par` 最多转换一次；每个唯一 `.asm` 生成对应的嵌套 `.SLDASM`；父级把子装配作为组件插入。
- 每层只使用该层的直接子项与局部矩阵。默认所有插入组件固定；用户可选把已支持的 SE 装配关系重建为 SW 配合，失败关系回滚并如实报告。
- 未解析引用、引用环、同名不同路径导致的输出冲突都会在写入前阻止转换。隐藏件插入，抑制件跳过；非 `.par/.asm` 引用跳过并报告。
- 默认任一零件失败即不生成缺件装配；用户显式开启后才允许缺件继续。
- 文件夹批量零件转换始终逐件继续；“零件失败时继续”和“重建装配关系”在文件夹来源下均取消并禁用，二者只控制装配体生成策略。

不支持 `.psm`、`.dft`、材料、属性或配置迁移；未实测的 Mate 类型不猜测、不转换。

开启 FeatureWorks 时，每个零件使用独立子 Worker，并在附着既有 SolidWorks 单实例时逐件重置加载项。
单件会话故障允许有界隔离重试；仍失败时只保留经过导入身份和几何守卫确认的哑实体，不得污染后续零件。
未开启特征识别时保持原批量导入路径。

CAD 进程所有权必须由启动前后 PID 差集或窗口句柄证明。全新自有 SolidWorks 会话不在首个文档前
重载 FeatureWorks；启动前已有会话永不退出。自有隐藏 CAD 在正常退出超时后，只允许按已记录的唯一 PID
回收。零件阶段没有得到可验证的 SLDPRT 时，装配阶段必须中止。

## 4. Worker 协议

UI 与独立 x64 STA Worker 使用 Contracts 中唯一的协议定义：

```text
--request <BatchRequest JSON> --cancel <signal>
--probe-assembly <AssemblyProbeRequest JSON> --cancel <signal>
--assembly <AssemblyBatchRequest JSON> --cancel <signal>
```

Worker 内部另使用 `--import-part <PartImportRequest JSON> --cancel <signal>` 完成单零件隔离导入；
它不是 UI 或外部模块入口。

`WorkerEvent` 保持旧字段可读，并追加可空的 `Artifact`、`ReuseKind`、`Feature`、`Assembly`、`Mate`。
UI 仅依据结构化字段呈现状态，不解析中文消息文本。

## 5. 版本与发布边界

`build/SE2SW.Version.props` 是 UI、Contracts、Worker 的唯一版本源；`ModuleInfo.Version` 从 UI 程序集版本读取。`eng/Update-SE2SWManifest.ps1` 从该 props 生成 `z-SE2SW/module.manifest.json` 的版本字段。

发布前必须通过 Release build、`SE2SW.Smoke`、`SE2SW.UiSmoke`、格式检查和需要时的 CAD 真机门禁。V3.6.0 已于 2026-08-04 经 `tool.sync name=SE2SW` 进入正式槽，回退点为部署前完整 3.5.7 槽备份。SE2SW 的设计、探针和 CAD 验收材料只保留在本项目 `docs/`、`tools/`；OHS 的 `b-Office/evidence` 只记录宿主集成事实，不上抛模块实现文档或转换附件。
