# SE2SW V2.0 设计：特征识别与草图完全定义

> 状态：**已实现并实测通过**（见 §11 实现记录）
> 前置版本：V1.0（`.par` -> `.x_t` -> `.SLDPRT`，输出为无特征的哑实体）
> 验证日期：2026-07-27
> 相关文档：[04-Opus5答复-SolidEdge导出验证报告](04-Opus5答复-SolidEdge导出验证报告.md)

---

## 0. 结论摘要

V2.0 要做的两件事都可实现，并且已经在本机跑通完整链路，不是纸面推导：

1. **特征识别**：SolidWorks 通过 FeatureWorks 加载项提供 COM 接口
   `SolidWorks.Interop.fworks.IFeatureWorksApp`，两个方法就够：
   `RecognizeFeatureAutomatic(options)` 与 `CreateFeatures(options)`。
2. **草图完全定义**：`ISketchManager.FullyDefineSketch(...)` 就是界面上"完全定义草图"的 API 版本，
   对识别出来的每个草图逐个执行即可。

实测结果（详见 §2）：

| 样件 | 识别特征数 | 生成的特征 | 草图数 | 完全定义成功 |
|---|---:|---|---:|---|
| SolidWorks 官方样件 `holes_pockets_dimxpert_mm` | 12 | 1 凸台拉伸 + 3 切除拉伸 + 8 异形孔 | 4 | 4/4 |
| 项目样件 `1-蜀牛低型烧杯150ml` | 1 | 1 旋转 | 1 | 1/1 |

**但有 6 条不查文档绝对踩坑的约束**，其中两条会让整个功能"静默失效"（不报错、返回 0、
特征树不变）。这 6 条是本文最重要的内容，见 §3。

## 1. 已核实的 API 与环境

### 1.1 环境

- SolidWorks 2025 SP5，`ISldWorks.RevisionNumber()` = `33.5.0`
- ProgID `SldWorks.Application`，CLSID `{6AF263BB-EB9F-4176-89E9-4F892EB0CA3D}`
- FeatureWorks 随产品安装：
  - `…\SOLIDWORKS\fworks\fworks.dll`（进程内 COM 服务器）
  - `…\SOLIDWORKS\fworks\FWorksFunc.dll`（识别引擎，6.2 MB）
  - ProgID `FeatureWorks.FeatureWorksApp`，CLSID `{7CF8CA03-1DCE-11d1-A89B-0020AF351FA9}`
  - `InprocServer32` 值是**相对路径** `.\fworks\fworks.dll`
- 官方 Interop：`…\SOLIDWORKS\api\redist\SolidWorks.Interop.fworks.dll`（17 KB）
- API 帮助：`…\SOLIDWORKS\api\fworksapi.chm`、`sldworksapi.chm`

### 1.2 特征识别 API

`SolidWorks.Interop.fworks.IFeatureWorksApp`（`api\redist\SolidWorks.Interop.fworks.dll` 反射确认）：

```csharp
int  RecognizeFeatureAutomatic(int options);      // 返回：识别到的特征数
bool RecognizeFeatureInteractive(string featureType, int options);
bool CreateFeatures(short creationOptions);       // 返回：是否创建成功
bool SetAdvancedOptions(short options);
bool SetPerformanceOptions(short options);
```

文档依据（`fworksapi.chm`）：

- 主题 `SolidWorks.Interop.fworks~…IFeatureWorksApp~RecognizeFeatureAutomatic.html`：
  "Recognizes imported features automatically in a SOLIDWORKS part document."，
  Return Value "Number of features recognized"。
- 主题 `…~CreateFeatures.html`："Creates recognized imported features in a SOLIDWORKS part document."
- 主题 `GettingStarted-fworksapi.html` 给出官方流程，并明确写着
  **"The FeatureWorks DLLs must be loaded before calling the FeatureWorks API."**
  同一主题还写明不支持的能力：
  "FeatureWorks operations such as combining, re-recognizing features, and recognizing patterns
  are not supported. The FeatureWorks Local Feature Recognition and Recognize Similar options
  are also not supported."
  → **不支持重新识别和阵列识别**，这限制了 V2.0 的返工策略，见 §7。
- 主题 `Recognizing_Features_Automatically.htm` 是官方 VBA 示例，
  取对象的写法是 `swApp.GetAddInObject("FeatureWorks.FeatureWorksApp")`，
  并且在识别前**先 `SelectByID` 选了一个面**。

选项枚举（`SolidWorks.Interop.fworks`）：

| 枚举 | 成员 = 值 |
|---|---|
| `fwAutomaticRecognitionOptions_e` | `fwExtrudeOption=1`、`fwVolume=2`、`fwRevolve=4`、`fwHoles=8`、`fwChamfils=16`、`fwRibs=32`、`fwBaseFlange=64`、`fwSketchedBend=128`、`fwAutoEdgeFlange=256`、`fwAutoHemFlange=512` |
| `fwFeatureCreationOptions_e` | `fwAddConstraintsToSketch=1`、`fwAllowFailFeatureCreation=2` |
| `fwAdvancedOptions_e` | `fwAdvAddConstraintsToSketch=1`、`fwAdvAllowFailFeatureCreation=2`、`fwAdvAllowWizardHoleRecognition=4` |
| `fwPerformanceOptions_e` | `fwDoNotPerformBodyCheck=1`、`fwDoNotPerformIntrusionCheck=2` |
| `fwInteractiveRecognitionOptions_e` | `fwChainFeatures=1`、`fwNormalToSketch=2`、`fwRecognizeSimilar=4` |

`fwAddConstraintsToSketch` 很关键：让 FeatureWorks 在生成特征时就给草图加几何关系，
后面 `FullyDefineSketch` 要补的东西会少很多。

### 1.3 草图完全定义 API

`ISketchManager.FullyDefineSketch`（`sldworksapi.chm` 主题
`SolidWorks.Interop.sldworks~…ISketchManager~FullyDefineSketch.html`，"Fully defines a sketch."）：

```csharp
int FullyDefineSketch(
    bool   EntitiesToFullyDefine,   // true = 全部实体；false = 仅已选实体
    bool   UseRelations,
    int    RelationsToApply,        // swSketchFullyDefineRelationType_e 位掩码
    bool   UseDimensions,
    int    HorizontalDimScheme,     // 0=Chain 1=Baseline 2=Ordinate
    object HorizontalDatumDisp,     // null 时使用"选择标记 = 6"的实体作基准
    int    VerticalDimScheme,
    object VerticalDatumDisp,
    int    HorizontalDimPlacement,  // 0=草图上方 1=下方
    int    VerticalDimPlacement);   // 0=草图右侧 1=左侧
```

关系类型 `swSketchFullyDefineRelationType_e`：
`Equal=1`、`Horizontal=2`、`Vertical=4`、`Tangent=8`、`Perpendicular=16`、
`Colinear=32`、`Concentric=64`、`Parallel=128`、`Midpoint=256`、`Coincident=512`。

**返回值不可信**：帮助里 Return Value 一栏原文是 "Not currently defined"。
唯一可靠的验收手段是 `ISketch.GetConstrainedStatus()`，返回 `swConstrainedStatus_e`：
`swUnknownConstraint=1`、`swUnderConstrained=2`、`swFullyConstrained=3`、
`swOverConstrained=4`、`swNoSolution=5`、`swInvalidSolution=6`、`swAutosolveOff=7`。

官方示例 `Fully_Define_Underdefined_Sketch_Example_CSharp.htm` 给出的调用序列：

```csharp
swFeature.Select2(false, 0);
swSketchManager.InsertSketch(false);                    // 进入草图编辑
swModelExtension.SelectByID2("Point1@Origin", "EXTSKETCHPOINT",
    0, 0, 0, false, lMarkHorizontal | lMarkVertical, null, 0);   // 2|4 = 6
lStatus = swSketchManager.FullyDefineSketch(true, true, relations, true,
    1, null, 1, null, 1, 1);
swSketchManager.InsertSketch(true);                     // 退出并重建
```

## 3. 六条必须写进实现的约束

这一节是本文档的核心。前两条如果不满足，功能会**静默失效**：不抛异常、
`RecognizeFeatureAutomatic` 返回 0、特征树一动不动，日志里看不出任何毛病。

### C1. 必须预选一个种子面

不做任何选择直接调用 `RecognizeFeatureAutomatic`，**恒返回 0**。
实测：同一零件、同一参数，只差一句 `SelectFirstFace`，结果就是 0 与 12 的区别。

```csharp
var body  = ((object[])part.GetBodies2((int)swBodyType_e.swSolidBody, false))[0] as Body2;
var face  = body.GetFirstFace() as Face2;
((Entity)face).Select4(false, null);
int count = fw.RecognizeFeatureAutomatic(options);
```

官方 VBA 示例里那句看似无关的 `Part.Extension.SelectByID(…, "FACE", …)` 不是装饰，是前提。

### C2. 识别选项必须传满 `0x3FF`

只传"实体类"选项 `fwExtrudeOption|fwRevolve|fwHoles|fwChamfils|fwRibs`（= 61）**恒返回 0**。
单独传 `fwVolume`(2)、`fwExtrudeOption`(1)、`fwHoles`(8)、`fwChamfils`(16) 也都是 0。
把 `fwAutomaticRecognitionOptions_e` 全部 10 位置上（`0x3FF` = 1023）才会真正识别。

实测序列（同一零件、同一次会话、每次都预选了种子面）：

| 传入 options | 返回 |
|---|---:|
| 61（1\|4\|8\|16\|32） | 0 |
| 2（fwVolume） | 0 |
| 1（fwExtrudeOption） | 0 |
| 8（fwHoles） | 0 |
| 16（fwChamfils） | 0 |
| **1023（0x3FF）** | **12** |

**这条没有官方文档支持，是黑盒实测结论。** 推测是钣金相关的 4 个位
（`fwBaseFlange`/`fwSketchedBend`/`fwAutoEdgeFlange`/`fwAutoHemFlange`）参与了某种内部校验，
但没有证据，所以不写成解释。实现里就固定传 `0x3FF`，并在注释里指向本节。

### C3. FeatureWorks 加载项默认不启用，必须先 `LoadAddIn`

`GetAddInObject("FeatureWorks.FeatureWorksApp")` 在加载项未启用时返回 `null`，不抛异常。
FeatureWorks 也**不在** `HKLM\SOFTWARE\SolidWorks\Addins` 的加载项列表里，
不能靠遍历那个键来判断可用性。

正确做法（探针已实现，不硬编码安装路径）：

```
1. 读 HKCR\CLSID\{7CF8CA03-1DCE-11d1-A89B-0020AF351FA9}\InprocServer32
   -> 得到相对路径 ".\fworks\fworks.dll"
2. 读 HKCR\CLSID\{SldWorks 的 CLSID}\LocalServer32 -> 取出 SLDWORKS.exe 所在目录
3. 两者拼接得到 fworks.dll 绝对路径
4. swApp.LoadAddIn(绝对路径)  -> 返回 swLoadAddinError_e
5. 再次 GetAddInObject
```

`swLoadAddinError_e`：`swSuccess=0`、`swAddinNotLoaded=1`、`swAddinAlreadyLoaded=2`、
`swFileNotFound=3`、`swAddinsDisabled=4`、`swLoadConflict=5`、`swRegistrationError=6`、
**`swLicenseError=7`**、`swUnknownError=-1`。

**`swLicenseError=7` 就是"没有 FeatureWorks 授权"的判据**——FeatureWorks 属于
SOLIDWORKS Professional / Premium，Standard 授权拿不到。V2.0 必须在批次开始前做这个探测，
并在 UI 上明确降级为 V1.0 行为，而不是跑到一半才失败。

### C4. `FullyDefineSketch` 的返回值不能用

SDK 原文 "Not currently defined"。实测三次全部返回 0，而草图确实从
`swUnderConstrained` 变成了 `swFullyConstrained`。

**唯一验收手段**：完全定义后重新取 `ISketch`，读 `GetConstrainedStatus()`，
判定是否等于 `swFullyConstrained`。这和 V1.0 里"`SaveAs` 不抛异常不等于导出成功"是同一类问题。

### C5. SolidWorks 是单实例：`CreateInstance` 会附着到用户已有会话

实测：本机 SolidWorks 常驻运行时，`Activator.CreateInstance(SldWorks.Application)`
**每一次**都返回已有会话，新增进程数为 0（`CreatedNewInstance = false`）。
这和 Solid Edge 正好相反——Solid Edge 每次都新建独立的 `Edge.exe`。

对现有 `src/SE2SW.Worker/SolidWorksImporter.cs` 的直接影响：
那里的 `CadProcessOwnership` 在无法证明所有权时会抛
`CadProcessOwnershipUnknown` 并终止批次。保护意图是对的，但按实测行为，
**只要用户开着 SolidWorks，整批转换就会被这道门全部挡下**。

V2.0 必须明确策略，建议：

| 场景 | 行为 |
|---|---|
| 无已有 SW 进程，本工作进程新建 | 正常转换，结束时 `ExitApp()` |
| 已有用户会话，附着复用 | **继续转换**，但全程不 `ExitApp`、不改 `Visible`、结束时还原改过的用户设置；UI 上提示"正在使用你已打开的 SolidWorks" |
| 无法判定 | 按"附着"处理（保守：不退出） |

理由：直接拒绝转换的体验代价比复用会话大得多，而"复用但绝不关闭"已经能保住用户的未保存工作。

### C6. 中文界面下 `"Point1@Origin"` 选不中

官方示例用的是英文名。本机 SolidWorks 是中文界面，特征树里是
`前视基准面 / 上视基准面 / 右视基准面`。

`swUserPreferenceToggle_e.swUseEnglishLanguageFeatureNames`（= 262）打开后，
实测新建文档的特征名变成 `Front Plane / Top Plane / Right Plane`，
`SelectByID2("Point1@Origin", "EXTSKETCHPOINT", …)` 才稳定命中。

实现要求：进入批次前保存该开关原值、置为 `true`，批次结束在 `finally` 中还原。
**注意这是全局用户设置，会影响用户后续手动建的文档，必须还原。**
探针实测该开关对"已经打开的文档"不追溯生效，只影响之后创建的文档，
所以必须在 `LoadFile4` 之前设置。

## 4. V2.0 转换链

```text
Solid Edge .par
  └─ [SE Worker] PartDocument.SaveBody(x_t, seSaveBodyAsParasolidText, seParasolidCurrentVersion)
       └─ Parasolid .x_t (FORMAT=text, Parasolid 31.1)
            └─ [SW Worker] ISldWorks.LoadFile4(x_t, "r", null, ref errors)
                 └─ 哑实体 Imported1 [BaseBody]                       ← V1.0 到此为止
                      └─ 【新】LoadAddIn(fworks.dll) + GetAddInObject
                      └─ 【新】选种子面 + RecognizeFeatureAutomatic(0x3FF)
                      └─ 【新】CreateFeatures(fwAddConstraintsToSketch)
                           └─ 特征树：Sketch/Extrusion/Revolution/HoleWzd…
                                └─ 【新】遍历 ProfileFeature，逐个 FullyDefineSketch
                                └─ 【新】GetConstrainedStatus 逐个验收
                                     └─ ModelDocExtension.SaveAs3 -> .SLDPRT
```

### 4.1 单零件处理序列（伪代码，与探针一致）

```csharp
// 批次开始（每批一次）
oldEnglishNames = app.GetUserPreferenceToggle(swUseEnglishLanguageFeatureNames);
app.SetUserPreferenceToggle(swUseEnglishLanguageFeatureNames, true);
fw = EnsureFeatureWorks(app);          // C3：LoadAddIn + GetAddInObject，失败则降级

// 每个零件
model = app.LoadFile4(xtPath, "r", null, ref errors);
app.ActivateDoc3(model.GetTitle(), false, 0, ref err);      // FeatureWorks 只认 ActiveDoc

if (fw != null && request.RecognizeFeatures)
{
    fw.SetAdvancedOptions(fwAdvAddConstraintsToSketch | fwAdvAllowWizardHoleRecognition);
    model.ClearSelection2(true);
    SelectSeedFace(model);                                  // C1
    recognized = fw.RecognizeFeatureAutomatic(0x3FF);       // C2
    created    = fw.CreateFeatures(fwAddConstraintsToSketch);
}

if (request.FullyDefineSketches)
    foreach (sketchFeature in Features(model).Where(f => f.GetTypeName2() == "ProfileFeature"))
    {
        // 注意：原点是 "OriginProfileFeature"，不会被这个过滤器命中，正确
        sketchFeature.Select2(false, 0);
        sketchManager.InsertSketch(false);
        extension.SelectByID2("Point1@Origin", "EXTSKETCHPOINT", 0,0,0, false, 2|4, null, 0);
        sketchManager.FullyDefineSketch(true, true, allRelations, true, 1, null, 1, null, 1, 1);
        sketchManager.InsertSketch(true);
        status = sketch.GetConstrainedStatus();             // C4：唯一验收
    }

model.Extension.SaveAs3(tempPath, swSaveAsCurrentVersion, swSaveAsOptions_Silent, ...);

// 批次结束
app.SetUserPreferenceToggle(swUseEnglishLanguageFeatureNames, oldEnglishNames);
```

## 5. 契约与协议变更

### 5.1 `SE2SW.Contracts.BatchRequest` 新增

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `RecognizeFeatures` | `bool` | `true` | 是否执行 FeatureWorks 自动特征识别 |
| `FullyDefineSketches` | `bool` | `true` | 是否对识别出的草图执行完全定义 |
| `FeatureRecognitionTimeoutSeconds` | `int` | `120` | 单零件识别+创建的超时 |
| `ContinueWhenRecognitionFails` | `bool` | `true` | 识别失败时是否仍保存哑实体（降级为 V1.0 结果） |

### 5.2 `ConversionJob` 结果新增

| 字段 | 类型 | 说明 |
|---|---|---|
| `RecognizedFeatureCount` | `int` | `RecognizeFeatureAutomatic` 返回值 |
| `FeaturesCreated` | `bool` | `CreateFeatures` 返回值 |
| `SketchTotal` | `int` | `ProfileFeature` 数量 |
| `SketchFullyDefined` | `int` | 完全定义后状态为 `swFullyConstrained` 的数量 |
| `SketchStatuses` | `string[]` | 每个草图的 `swConstrainedStatus_e`，便于定位 |
| `DegradedToDumbSolid` | `bool` | 是否退回 V1.0 行为 |

### 5.3 `ConversionStage` 新增

`SolidWorksImport` 之后插入两个阶段：`FeatureRecognition`、`SketchFullyDefine`。
进度上报要能区分"在识别"和"在定义草图"，因为这两步各占数秒，静默会被当成卡死。

### 5.4 `ConversionErrorClass` 新增

| 分类 | 触发 |
|---|---|
| `FeatureWorksUnavailable` | `LoadAddIn` 返回 `swLicenseError`/`swFileNotFound`，或 `GetAddInObject` 仍为 null |
| `FeatureRecognitionEmpty` | `RecognizeFeatureAutomatic` 返回 0 |
| `FeatureCreationFailed` | `CreateFeatures` 返回 false |
| `SketchNotFullyDefined` | 完全定义后仍非 `swFullyConstrained` |
| `CadSessionShared` | 附着到用户已有会话（信息级，不是失败） |

## 6. UI 变更

「对战区」式的独立设置窗不需要，直接在 SE2SW 主界面转换选项区加两个复选框：

- ☑ **识别特征**（默认勾选）——未授权 FeatureWorks 时置灰并显示"当前 SolidWorks 授权不含 FeatureWorks"
- ☑ **完全定义草图**（默认勾选，依赖上一项）

结果列表每行增加两列：`特征 12`、`草图 4/4`。
`4/4` 用常规色，`3/4` 用警示色，`0/4` 或识别数为 0 用失败色但不阻断批次。

批次开始前做一次 FeatureWorks 可用性探测（`LoadAddIn` 的返回码），
把结论显示在批次摘要里，不要等到第一个零件失败才告诉用户。

## 7. 已知能力边界

来自 `GettingStarted-fworksapi.html` 的官方声明，不是推测：

- **不支持重新识别**（re-recognizing features）。识别一次不满意，只能丢弃重来。
  → V2.0 不提供"重新识别"按钮；用户不满意就取消勾选重跑。
- **不支持阵列识别**（recognizing patterns）。8 个规则排列的孔会被识别成 8 个独立的
  `HoleWzd`，不会变成阵列特征。实测的对照样件正是这个结果。
  → 文档和 UI 都要写清楚："识别为独立特征，不生成阵列"。
- **不支持局部特征识别和识别相似**（Local Feature Recognition、Recognize Similar）。
- **不支持合并**（combining）。

另外，`RecognizeFeatureInteractive` 需要人工指定特征类型和选择集，与无人值守批处理冲突，
V2.0 不使用。

## 8. 验收门槛

进入实现前先认可这套门槛；实现完成后逐条验收：

1. 同一批 10 个零件连续跑通，无残留 SolidWorks 进程（由本工作进程创建的那些）。
2. 用户已有 SolidWorks 会话在整批转换后仍然存活，且未被切换可见性、未留下被改动的用户设置。
3. `swUseEnglishLanguageFeatureNames` 在批次结束后回到原值（含异常退出路径）。
4. 每个成功零件的报告里，`SketchFullyDefined == SketchTotal`；不满足时该零件标记警告但不阻断批次。
5. FeatureWorks 不可用时，整批自动降级为 V1.0 哑实体输出，且 UI 明确告知，退出码不为失败。
6. 单零件识别+创建超时后能中止该零件并继续下一个。
7. 输出 `.SLDPRT` 能被 SolidWorks 重新打开，特征树可展开、无重建错误。
8. 源 `.par` 与中间 `.x_t` 的哈希在整批前后不变。

## 10. 不在 V2.0 范围内

- 不做交互式特征识别（`RecognizeFeatureInteractive`）。
- 不做阵列识别、重新识别、局部识别——API 明确不支持。
- 不做尺寸标注方案的可配置化（`HorizontalDimScheme` 等固定用示例给的取值）。
- 不处理 `.asm` / `.psm` / `.dft`，与 V1.0 范围一致。
- 不保证识别出的特征与 Solid Edge 原始特征树一致——Parasolid 中间格式不携带特征信息，
  识别结果是 SolidWorks 基于几何的重新推断。

### 11.3 实现期间新发现的问题

**种子面选择会偶发失败。** 刚 `LoadFile4` 完就调用 `Entity.Select4` 有时返回 `false`
（不抛异常），随后识别静默返回 0。同一个 `.x_t` 用探针再跑一次又能成功，说明是时序问题
而不是几何问题。

对策：`SelectSeedFaceWithRetry` 做有界重试（5 次、每次间隔 400 ms）。加上重试后连续 5 次全部
一次命中。这条已并入 §3 C1，实现里也有注释指回本节。

另一条：`ActivateDoc3` 偶发抛 `RPC_E_SERVERFAULT (0x80010105)`。已改为容错处理——
`LoadFile4` 之后文档通常已是活动文档，激活失败不影响后续，只记录到诊断信息里。

### 11.4 诊断字段

`FeatureOutcome.Diagnostic` 在降级时记录**具体卡在哪一步**，例如
`无法预选种子面：Entity.Select4 返回 false；标题=beaker.sldprt；活动文档=beaker.sldprt；ActivateDoc3 正常`。
这是为了避免 §3 C1/C2 那类"静默失效"再次变成无从下手的问题。

### 11.6 首件识别时序修复（2026-07-31）

批处理中第一个零件曾固定显示“未识别”，后续零件正常。原因是探针已经验证
`RecognizeFeatureAutomatic` 在 FeatureWorks 首次初始化时可能连续返回 0，但正式 Worker 只调用了一次，
首件因此被过早判定为无法识别。

正式实现现与探针保持一致：每次调用前重新选择种子面；返回 0 时泵送当前 STA 线程的 Win32 消息并等待
300 ms；最多尝试 10 次。只有 10 次均返回 0 才降级为导入实体，诊断信息同时记录实际尝试次数。
`SE2SW.Smoke` 增加了“前两次为 0、第三次成功”以及“达到上限后降级”的回归覆盖。
