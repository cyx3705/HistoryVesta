## 1. 关系入口

`AssemblyDocument` 上名字含 `Relation` 的成员（来自类型库，非猜测）：

```
CapturedRelationshipCount            get
GetCapturedRelationshipInformation   method
HasCapturedRelationships             get
Relations3d                          get   ← 实际入口
RelationshipsSelectSet               get
SegmentRelations3d                   get
```

**`Relations3d` 集合按 `Item(1..Count)` 枚举，索引基 = 1**，两个文档都成功。

| 文档 | 关系数 | GroundRelation3d | AxialRelation3d | PlanarRelation3d |
|---|---|---|---|---|
| `测试装配1.asm` | 6 | 1 | 1 | 4 |
| `风滚子.asm` | 43 | 1 | 9 | 33 |

样件里只出现了这三种类型。相切、角度、齿轮、凸轮等类型本批样件未覆盖。

`Type` 属性的数值每个接口稳定：

| 接口 | Type |
|---|---|
| `GroundRelation3d` | 1959028688 |
| `AxialRelation3d` | 1472929712 |
| `PlanarRelation3d` | -2058948880 |

数值虽稳定，但**生产代码应以类型库报出的接口名为准**，`Type` 只作为交叉校验——接口名是自解释的，数值不是。

## 2. 关系的组件归属

`Occurrence1` / `Occurrence2`（`GroundRelation3d` 只有 `Occurrence`）**直接给出组件**，
无需经几何元素反查 owner。`Part1` / `Part2` / `Part` 在本批样件里返回同一对象。

实例名形如 `测试零件2.par:1`，并可从同一对象读到 `PartFileName` 绝对路径。

## 3. 关系参数

| 关系 | 可读参数 |
|---|---|
| 共有 | `Index`、`Type`、`Status`、`DetailedStatus`、`Suppress` |
| `PlanarRelation3d` | `FixedOffset`、`Offset`、`NormalsAligned`、`RangedOffset`、`RangeLow`、`RangeHigh` |
| `AxialRelation3d` | `Orientation`、`ParallelOffset`、`FixedParallelOffset`、`Offset`、`FixedRotate`、`RangedOffset`、`RangeLow`、`RangeHigh` |
| `GroundRelation3d` | 只有共有项 + `Occurrence` |

实测样例（`测试装配1.asm` 首条平面关系）：`FixedOffset=true`、`Offset=0`、`NormalsAligned=true`、`Suppress=false`、`Status=1`。

**条件可读，不是故障**：

| 成员 | 何时抛错 | HRESULT |
|---|---|---|
| `RangeLow` / `RangeHigh` | `RangedOffset=false` 时 | `0x8000FFFF` |
| `AxialRelation3d.Offset` / `FixedParallelOffset` | `ParallelOffset=false` 时 | `0x80004005` |

生产代码必须**先读开关再读值**，不能把这两类异常当成读取失败上报。

## 4. 几何：`GetGeometryN` 是主路

签名（类型库读出，非猜测）：

```
GetGeometry1(out GeometryType: I4,
             out PointX: R8, out PointY: R8, out PointZ: R8,
             out VectorX: R8, out VectorY: R8, out VectorZ: R8)
```

| `GeometryType` | 含义 | 点 | 向量 |
|---|---|---|---|
| 1 | 平面 | 平面上一点 | 平面法向 |
| 2 | 轴 | 轴上一点 | 轴方向 |

**坐标系 = 顶层装配世界系。** 证据（`风滚子.asm` 第 3 条平面关系）：

| | 组件世界原点 | 几何点 | 向量 |
|---|---|---|---|
| 侧 1 `右边.par:1` | (0, 0.130, 0) | (0, 0.130, 0) | (0, −1, 0) |
| 侧 2 `杠.par:1` | (0, −0.045, 0) | (0, 0.130, 0) | (0, +1, 0) |

侧 2 的几何点不等于它自己的组件原点，而与侧 1 完全相同——两侧描述的是同一个世界平面。
若为零件局部坐标系，两侧数值不可能相等。轴关系同理：第 4 条 `AxialRelation3d` 两侧点
(−0.04, 0.1327, −0.04) 与 (−0.04, 0.1255, −0.04) 仅 Y 不同、方向 ±Y，共线。

两侧向量常为反向，与 `NormalsAligned` 配合表达贴合/对齐方向。

单位为米，与 V3.0 已确认口径一致。

## 5. 几何：`GetElementN` 与 TopologyReference

```
GetElement1(out IsTopologyReference: BOOL) → VT_DISPATCH
```

`IsTopologyReference` 实测恒为 `true`，返回对象是 **`TopologyReference`**：

| 成员 | 说明 |
|---|---|
| `Object` | 实际几何对象 |
| `GetReferenceKey(ref byte[], out size)` | SE 的持久拓扑键 |
| `GetMatrix(ref double[16])` | 引用相对变换 |
| `GetOccurrencesInPath(out 顶层 occurrence, out 层数, out 绑定数, ref occurrence[])` | 嵌套实例路径 |
| `Parent` | 所属 `Occurrence` |

**关键差异**：

| 关系类型 | `TopologyReference.Object` | 样本 |
|---|---|---|
| `PlanarRelation3d` | 成功，返回 `Face` | 74 / 74 |
| `AxialRelation3d` | **`0x80004005` E_FAIL** | 0 / 20 |

轴关系拿不到几何对象。这条路在轴向关系上不可用。

平面关系拿到的 `Face` 上可用作签名的字段：`Geometry`（本批全部为 `Plane`）、`Area`、
`ID`、`Tag`、`GeometryForm`、`Continuity`、`GetRange` / `GetExactRange`（各 2 个 3 元素数组）、
`GetReferenceKey`。`Plane` 自身提供 `GetPlaneData(根点, 法向)`、`GetRootPoint`、`GetNormalVector`。

## 6. 对 V3.5 的直接结论

**面 ID 映射从"必须"降为"可选"。**

`GetGeometryN` 已经在装配世界系里给出了平面的"点 + 法向"和轴的"点 + 方向"，
而 V3.0 的组件插入保证了 SW 中每个组件的世界变换与 SE 精确一致（偏差 < 1e-6 m）。
因此 SW 侧只需按同一个世界点/向量去定位配合实体，**不需要把 SE 的面 ID 映射到 SW 的面 ID**。

原设计里那套"几何签名匹配引擎"因此不再是 V3.5 的前置件；它退化为一个更小的问题：
在 SW 组件里找到"通过该点、法向为该向量的平面"或"以该直线为轴的圆柱"。

轴关系无法取得 `Face` 这一事实进一步支持这个选择：**只有 `GetGeometryN` 这一条路对所有关系类型都成立。**

### 7.1 推翻设计的一条：SolidWorks 把它导入成装配体

`LoadFile4(<x_t>, "r", importData)` 的返回文档：

```
运行时类型 = ModelDoc2Class
GetType()  = 2 (swDocASSEMBLY)
标题       = 测试装配1.sldasm / 风滚子.sldasm
路径       = <空，未保存>
```

强转 `IPartDoc` 报 `E_NOINTERFACE`——**它确实不是零件文档**。

原因：SE 的 `SaveCopyAs` 导出的是**带装配结构的 Parasolid**，不是一堆散体。
SolidWorks 识别出这个结构，直接建了装配体。

尝试用导入选项压回零件，**两个都无效**：

| 首选项 | 用户原值 | 置真后 |
|---|---|---|
| `swImportMultBodyAsPartData` (220) | false | 仍为装配体 |
| `swImportDissolveTopLevelAssemblyOnOpen` (701) | false | 仍为装配体 |

（`swImportIgnoreHiddenEntities` (702) 用户原值 false，本轮未单独验证其影响。）

导入后的装配是**未保存的虚拟装配**，`IAssemblyDoc.GetComponents` 返回 `null`；
必须走 `ConfigurationManager.ActiveConfiguration.GetRootComponent3(true)` 往下遍历。
遍历结果：**两个样件都只有 1 个叶组件**——即 SW 建了一个装配壳，里面装着一个承载全部几何的组件。

### 7.3 由此定下的路线

**「子装配 → 一个多实体 `.SLDPRT`」不能靠导入选项直接达成。** 要走这条路，就得在导入之后再做一次
"装配体另存为零件"的降级转换——**为了"不做嵌套"反而更贵，产物还更差**（不可编辑、BOM 无结构）。

因此改为**直接做真嵌套**，独立成版：[20-V3.3-子装配嵌套链路.md](20-V3.3-子装配嵌套链路.md)。
每个子装配递归生成自己的 `.SLDASM`，叶零件照常各出各的 `.SLDPRT`。这条路不需要任何新的 SE API，
全部复用 V3.0 已验证的 `AddComponent5 + Transform2 + FixComponent`，
而且顺带消掉了"同一零件出现两份几何副本"的代价。

装配级 Parasolid 导出因此**不进生产管线**；本节结论留档，将来若出现"把子装配当刚体交付"的真实需求，
`SaveCopyAs` 这条路已经验证可用。探针的 `--export-check` 动词保留为调查工具。

§7.2 的三项未完成项随之降为非阻塞，不再排期。

## 8. 过程安全

所有运行（共 8 轮）：

- `ChangedSampleFiles` 恒为空——样件目录 SHA-256 全量比对前后一致，一个字节没动；
- 探针在整目录副本上工作（`.asm` 内是绝对路径引用，只复制装配文件等于没隔离）；
- Solid Edge 进程由探针新建并收干净，`EdgeProcessesAfter` 为空；
- SolidWorks 首选项读原值 → 改 → 恢复，`ImportPreferenceRestored = true`；
- 探针拒绝覆盖已存在的导出产物。

## 9. 探针实现要点

留档三条，避免以后重蹈：

1. **先读类型库再取值。** 通过 `IDispatch::GetTypeInfo` 拿 `ITypeInfo`，枚举
   `GetFuncDesc` / `GetVarDesc` 并沿继承链展开，得到真实成员名、种类与**形参类型**。
   本报告里 `GetGeometryN` 的 7 个参数、`GetElementN` 的 out 布尔，都是读出来的，不是试出来的。
2. **byref 变体必须按真实 VT 播种。** 传空 VARIANT 调 `GetGeometry1` 恒返回
   `DISP_E_TYPEMISMATCH (0x80020005)`；按类型库给的 `I4` / `R8` 构造初值后一次成功。
   这是本次调查里最容易误判成"这个 API 不能用"的一处。
3. **递归要设边界。** 首版对关系的每个属性无差别递归，输出 53 MB；把
   `Occurrence1/2`、`Part1/2`、`AttributeSets` 改为标量采集后降到 4.6 MB。

## 10. 三层样件复测（2026-08-03）

样件当日扩充为三层后重跑探针，退出码 0。§0–§9 的全部结论不变，本节只记录新增事实。

### 10.1 结构

```
风滚子.asm                                        顶层
├─ 零件1 ×2、杠、动量轮、右边、太阳能板子 ×8、
│  螺母 ×2、盒子 ×2                                17 个零件实例
└─ 测试装配1.asm            世界原点 Y = 0.238     第 2 层
    ├─ 测试零件1、测试零件2、测试零件4              3 个零件
    └─ 测试装配3.asm        世界原点 Y = 0.482     第 3 层
        ├─ 测试零件5
        └─ 测试零件6
```

装配节点 3 个，唯一叶零件 12 个，最大层数 3。

### 10.2 关系按层分布

| 文档 | 关系数 | Ground | Axial | Planar |
|---|---|---|---|---|
| `风滚子.asm` | 43 | 1 | 9 | 33 |
| `测试装配1.asm` | 9 | 1 | 1 | 7 |
| `测试装配3.asm` | 4 | 1 | 0 | 3 |

**关系分别存放在各自那层的装配文档里，不会全部堆到顶层。** 每层都有自己的 `GroundRelation3d`，
说明每层各自锚定了一个基准件。这条决定了 V3.5 的配合天然落在正确的层，不需要额外的归属推断。

### 10.3 局部矩阵方案 A 的三层数值验证

同一对象分别用"独立打开该文档"与"从顶层世界系换算"两种方式取值：

| 对象 | 独立打开该文档读到的 Y | 从顶层世界系换算 | 偏差 |
|---|---|---|---|
| `测试装配3` 在 `测试装配1` 内 | 0.244 | 0.482 − 0.238 = 0.244 | 0 |
| `测试零件6` 在 `测试装配3` 内 | −0.030 | 0.452 − 0.482 = −0.030 | 0 |

**结论：把子装配 `.asm` 作为独立顶层文档打开，`Occurrences` 读到的就是该文档坐标系下的局部矩阵，
三层嵌套下无需任何换算。** 这是 20 号文档 §3.3 方案 A 的实测依据。
