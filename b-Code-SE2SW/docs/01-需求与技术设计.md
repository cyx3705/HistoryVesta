# SE2SW 需求与技术设计

## 1. 目标

在 OneHistoryStudio 中提供一个可视化批量转换工具，将 Solid Edge 零件转换为 SolidWorks 零件：

```text
Solid Edge .par
  -> Solid Edge COM 导出
  -> Parasolid .x_t
  -> SolidWorks COM 导入
  -> SolidWorks .SLDPRT
```

工具包含两种运行模式：

1. **OHS 兼容模式**：用户选择一个 OHS 项目根目录，工具按 OHS 目录约定自动定位输入和输出。
2. **外界模式**：用户选择任意文件夹，工具不创建或移动 OHS 目录，直接在所选位置生成文件。

首版以稳定完成零件几何迁移为目标，不把装配体、钣金、工程图或参数化特征迁移纳入范围。

## 2. OHS 模块约束

SE2SW 遵循 OHS 模块开发规则：

- 源码目录为 `b-Code-SE2SW`，注册目录规划为 `z-SE2SW`。
- 目标框架为 `net8.0-windows`，UI 使用 WPF。
- 模块清单设置 `"ui": true`，UI 生命周期通过 `AppShell.Core.Modules.IUiModule` 承接。
- `ModuleInfoBase.Open=false`，只精准暴露必要的业务入口。
- COM 转换属于本地有副作用操作，MCP 暴露档位规划为 `hidden`；批量转换只能由本机 UI 明确触发。
- 模块必须支持 OHS 热重载。UI 销毁时取消未开始任务并释放进度通道，不能在模块加载上下文中长期持有
  Solid Edge 或 SolidWorks RCW。

为避免 CAD COM 状态、原生 DLL 和 OHS 可回收 `AssemblyLoadContext` 相互影响，实际 COM 调用放入
独立的 x64 STA 工作进程。OHS 模块只负责目录解析、清单预览、用户确认、启动/取消工作进程和展示结果。

## 3. 界面与交互

### 3.1 页面结构

- 顶部使用分段控件切换“OHS 兼容”和“外界”模式。
- “项目/文件夹”输入框在两种模式复用，右侧提供文件夹选择按钮。
- OHS 兼容模式下显示解析后的 SE、GE、SW 三个目录；SE 输入目录只读。
- 外界模式下只显示一个工作目录，不展示或创建 OHS 目录。
- 文件表格显示：选择框、源文件、XT 输出、SW 输出、当前状态、错误摘要。
- 提供“全选”“取消全选”“重新扫描”和“取消”命令。
- 主按钮按模式区分：`按 OHS 目录转换` / `在当前文件夹转换`。
- 转换运行中锁定模式与路径，主按钮变为进度状态，避免目录在批处理中途改变。

### 3.2 扫描与选择

- 选择位置后自动扫描，另提供手动重新扫描。
- OHS 模式接受项目根或该项目的 `b-Module-SE` 本身；直接选择后者时自动回推项目根。
- 初始 OHS 模式下若选择或填写的普通目录顶层直接存在 `.par`，自动切换到外界模式并立即刷新列表；手动重新扫描采用同一判定。
- 首版只扫描目标目录顶层的 `*.par`，扩展名匹配不区分大小写。
- 扫描结果默认全部选中，用户可逐项取消。
- 不跟随符号链接或目录联接，不扫描 OHS 项目之外的路径。
- 文件在转换开始前重新检查存在性、可读性和输出冲突。

顶层扫描是首版的明确边界，可避免子目录同名文件在扁平输出时冲突。以后若需要递归扫描，应同时设计
相对目录映射，不能只把所有输出压平到一个目录。

## 4. 模式语义

### 4.1 OHS 兼容模式

用户可选择 OHS 项目根目录或其中的 `b-Module-SE` 目录，例如：

```text
2026-NNN-项目名/
├─ b-Module-SE/           输入 .par
├─ b-Module-GE/           输出 .x_t
├─ b-Module-SW/           输出 .SLDPRT
└─ Unused/
   ├─ b-Module-GE/        GE 未启用时的候选目录
   └─ b-Module-SW/        SW 未启用时的候选目录
```

目录解析规则：

| 用途 | 固定路径 |
|---|---|
| 项目根目录 | 用户选择项目根时取所选目录；选择 `b-Module-SE` 时取其父目录 |
| Solid Edge 输入 | `<项目根>\b-Module-SE` |
| Parasolid 输出 | `<项目根>\b-Module-GE` |
| SolidWorks 输出 | `<项目根>\b-Module-SW` |

转换前置流程：

1. 确认选择的是现存目录，且 `b-Module-SE` 存在。
2. 扫描 `b-Module-SE` 顶层的 `.par`，由用户确定本批次文件。
3. 检查 Solid Edge、SolidWorks COM 注册、许可和输出冲突。
4. 若 `b-Module-GE` 不存在，要求 `<项目根>\Unused\b-Module-GE` 存在且目标路径空闲。
5. 若 `b-Module-SW` 不存在，要求 `<项目根>\Unused\b-Module-SW` 存在且目标路径空闲。
6. 所有前置检查通过后，才把缺少的目录从 `Unused` **移动**到项目根目录；不得复制，也不得创建同名空目录替代。
7. 按文件串行执行 `.par -> .x_t -> .SLDPRT`。

如果 GE、SW 中任一缺失且其 `Unused` 候选目录也不存在，本批次在移动任何目录前失败。这样可避免只移动
一个目录后才发现另一个目录无法就位。

### 4.2 外界模式

用户在同一个路径输入框选择任意工作目录。对每个被选中的 `A.par`，直接生成：

```text
<工作目录>\A.par       输入
<工作目录>\A.x_t       中间文件
<工作目录>\A.SLDPRT    输出
```

外界模式：

- 不识别 OHS 项目编号。
- 不创建任何文件夹。
- 不移动 `Unused` 中的内容。
- 不写入 `b-Module-GE` 或 `b-Module-SW`。
- 复用扫描列表、冲突检查、进度和日志 UI，但通过独立的转换命令执行。

## 5. 文件名、冲突与失败策略

- 基础名保持不变，仅替换扩展名；输出扩展名规范为 `.x_t` 和 `.SLDPRT`。
- Windows 路径比较使用不区分大小写的规则。
- 默认冲突策略为**跳过已存在输出**，并在文件表格中标为“已存在”。首版不静默覆盖。
- 后续可增加“覆盖”选项；启用时应先写到同一输出目录的临时文件，成功后再原子替换目标。
- 一项失败不阻断后续项；每项分别记录 SE 导出结果和 SW 导入结果。
- SE 导出失败时不启动该项的 SW 导入。
- SW 导入失败时保留已成功生成的 `.x_t`，便于人工诊断和重试。
- 用户取消后停止领取新文件；当前 COM 调用允许在合理超时内收尾。超时后终止本批次工作进程，状态标为
  “结果未知”，不得自动重试写操作。
- 同一批次单线程串行处理；禁止同时控制多个 Solid Edge 或 SolidWorks 实例。

## 6. 组件边界

```text
SE2SW OHS UI 模块
├─ ModeState                模式、路径和控件状态
├─ OhsProjectResolver       固定目录解析与 Unused 移动计划
├─ FileScanner              顶层 .par 扫描与输出路径映射
├─ PreflightValidator       COM、许可、文件、冲突和移动前置检查
├─ BatchController          启动工作进程、取消、进度与结果汇总
└─ SE2SW.Worker.exe         独立 x64 STA 进程
   ├─ OleMessageFilter      COM busy/retry 处理
   ├─ SolidEdgeExporter     .par -> .x_t
   ├─ SolidWorksImporter    .x_t -> .SLDPRT
   └─ JsonLineProtocol      stdin 任务 / stdout 进度；stderr 诊断
```

工作进程按批次启动，用 JSON Lines 传递不可执行的数据结构，不接受任意命令文本。每条任务至少包含源路径、
XT 输出路径、SW 输出路径和冲突策略。所有路径在 UI 进程与工作进程两端都做绝对化和范围验证。

## 7. COM 生命周期

工作进程主线程必须是 STA，并注册 `IOleMessageFilter`。生命周期固定为：

1. 注册 OLE 消息过滤器。
2. 通过 ProgID 启动 Solid Edge 自动化实例，记录实例所有权。
3. 串行导出所有选中 `.par` 到 `.x_t`。
4. 关闭文档并释放 Solid Edge RCW；只退出由本工具创建的应用实例。
5. 通过 ProgID 启动 SolidWorks 自动化实例，记录实例所有权。
6. 串行导入成功的 `.x_t` 并保存为 `.SLDPRT`。
7. 关闭文档，释放 RCW；只退出由本工具创建的应用实例。
8. 撤销 OLE 消息过滤器并退出工作进程。

所有 COM 对象按“最内层对象先释放”的顺序处理，并在 `finally` 中关闭文档。不能依赖垃圾回收作为主要释放机制，
也不能通过按进程名结束用户已经打开的 CAD 会话。

## 8. 数据保真边界

Parasolid 是几何交换格式。首版验收关注实体能否打开和保存，不将以下内容视为必然可保留：

- Solid Edge 顺序/同步建模特征树；
- 草图、尺寸约束、变量表和公式；
- 材料、质量属性覆盖、自定义属性；
- PMI、颜色、贴图、参考平面命名；
- 配置、装配关系、钣金特征和工程图关联。

若一个 `.par` 包含多个实体，SolidWorks 的导入结果可能是多实体零件。首版保留导入器结果，不自动拆分。

## 9. 日志与可诊断性

- UI 显示总数、成功、跳过、失败和取消数量。
- 每项记录阶段、开始/结束时间、HRESULT/错误码和经过脱敏的错误摘要。
- 日志不得包含许可证信息、注册表密钥值或用户无关路径。
- 批次报告写到应用数据目录，不污染外界模式所选文件夹；OHS 项目目录只产生用户要求的 XT/SW 文件及
  必要的目录移动。
- 退出码：`0` 全部成功或按策略跳过，`1` 存在单项失败，`2` 前置检查失败，`3` 用户取消，`4` 工作进程异常。

## 10. 实施里程碑

1. **COM 探针**：各用一个最小样件验证 SE 导出和 SW 导入，记录实际 API、错误码和弹窗行为。
2. **无 UI 工作进程**：完成单文件和批量串行转换、结构化进度、取消与资源释放。
3. **目录与安全层**：完成两种模式、扫描清单、冲突策略和 `Unused` 双目录预检/移动。
4. **OHS UI 模块**：接入 `IUiModule`、清单、热重载和本机 UI 验收。
5. **回归验收**：覆盖空目录、同名输出、只缺一个 B 级目录、COM 未注册、CAD 忙、导入失败和取消。

## 11. V1.1 已冻结参数与待验风险

- Solid Edge 固定使用 `PartDocument.SaveBody(path, 2, 0, Type.Missing, Type.Missing)`，即文本
  Parasolid、Solid Edge 当前 Parasolid 版本、导出全部 Model；不再使用 `Document.SaveAs` 作为生产路径。
- SolidWorks 固定使用 `LoadFile4(path, "r", importData, ref errors)`；若 Parasolid 没有专用
  `GetImportFileData` 对象则传 `null`。保存使用 `ModelDocExtension.SaveAs3` 当前版本和静默选项。
- 两端均先写同目录临时文件，经稳定性和格式检查后再原子移动到正式路径。
- COM 重试预算为 60 秒；单阶段连续 180 秒无进度时，UI 进程发出取消信号，并在 15 秒宽限后终止 Worker。
- CAD 在不可见模式下可能出现的模式化提示框及抑制方式。
- 典型项目最大文件数、单文件大小和批次超时基线。
- 几何验收是否需要比较实体数、体积和包围盒，而不只是检查输出文件存在且可重新打开。
