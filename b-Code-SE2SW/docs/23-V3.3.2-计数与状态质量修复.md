# SE2SW V3.3.2 计数与状态质量修复

> 版本：3.3.1 → 3.3.2
>
> 状态：已实施并正式部署；发布认证见 [24-V3.3.2-发布收口.md](24-V3.3.2-发布收口.md)。
> 范围：只修正装配结果的统计与用户可见状态；不改动 Solid Edge / SolidWorks COM 调用、转换算法、输出布局或页面能力。

## 问题与修复口径

### 1. 复用装配不能伪装为本次实测

V3.3 的嵌套构建器命中已有 `.SLDASM` 复用时，曾以该节点的 `Children.Count` 同时累加
`ComponentInserted` 与 `ComponentFixed`。该文件本次没有打开，更没有执行 `AddComponent5`、变换校验或
`FixComponent`，因此这两个数字并非实测。

V3.3.2 规定：

- `ComponentInserted` 与 `ComponentFixed` 仅统计本次 Worker 实际操作并核验的组件；
- `ComponentTotal` 仍表示当前装配计划的直接组件总数；
- 新增 `ReusedAssemblyCount` 与 `ReusedAssemblyPlannedComponentCount`。后者只来自当前计划的直接子项，明确标为
  “未在本次运行中重新打开核验”，不能被解释为复用文件内容的实测数量；
- 完成事件在存在复用装配时必须显示这一区分。

不为了取得计数而重新打开复用 `.SLDASM`。复用仍只以“文件存在、非空、且不早于全部递归依赖”作为可复用前提；
V3.3.2 不把这个前提扩展成内容审计或几何验收。

### 2. 嵌套装配必须保留抑制件统计

`AssemblyBatchRequest.Occurrences` 是探查阶段得到的完整 occurrence 清单，包含 `IsSuppressed`。
嵌套构建路径此前向 `AssemblyOutcome.SkippedSuppressed` 写入字面量 `0`，即使清单中存在抑制件也会被静默归零。

V3.3.2 在进入 `SolidWorksNestedAssemblyBuilder` 时传入
`request.Occurrences.Count(item => item.IsSuppressed)`，并原样写回 `AssemblyOutcome`。这只改变统计口径，不改变
“抑制件不插入”的既有行为。

### 3. 异常文案不绑定过期版本

UI 预检和 Worker 请求校验均把“仅支持外界模式”写成 `V3.0`。该限制仍然成立，但版本号已经过期。
两处统一为“当前装配转换仅支持外界模式。”，避免以后每次版本升级都产生错误提示。

## 契约兼容性

`AssemblyOutcome` 在尾部追加两个带默认值的字段，因此旧 JSON 仍可反序列化；旧消费者读取原字段不受影响。
`WorkerEvent`、请求动词和零件转换协议不变。

## 回归门禁

离线 `SE2SW.Smoke` 必须验证：

1. 复用装配不会增加已插入/已固定的实测数；
2. 复用节点数与其计划直接组件数单列，并可经 Worker JSON 往返；
3. 嵌套路径的抑制件数不会归零，并可经 Worker JSON 往返；
4. UI 与 Worker 两道外界模式预检均不再显示 `V3.0`；
5. Release build、UI Smoke、`dotnet format --verify-no-changes`、清单版本同步和正式槽哈希核验全部通过。

本次没有修改 CAD 自动化语义；除非离线门禁或部署验证显示出边界变化，不重复宣称新的真实 CAD 通过结论。
