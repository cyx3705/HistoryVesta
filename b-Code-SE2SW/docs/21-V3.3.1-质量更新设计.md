# SE2SW V3.3.1 质量更新设计

> 日期：2026-08-03
> 计划版本：3.3.0 → 3.3.1
> 状态：已实施并发布；实施与正式槽认证见 [22-V3.3.1-实施与发布收口.md](22-V3.3.1-实施与发布收口.md)。
> 前置：V3.3 子装配嵌套功能已完成、真机验收并冻结。

## 1. 目标与不可变边界

V3.3.1 是**质量更新**，不增加转换能力，也不改变当前转换结果。其目标是消除同一业务事实由多处手工维护、
管道两端依赖显示文本和发布身份可能漂移的问题，使后续 V3.4/V3.5 的功能更新有稳定的单一真值基础。

本版必须保持以下行为不变：

- 三种页面模式及其边界：外界零件、外界装配、OHS 兼容零件；
- 外界输出布局 `XT\\*.x_t`、`SW\\*.SLDPRT`、`SW\\*.SLDASM`，以及旧平铺产物的安全复用；
- `.par → XT → SLDPRT`、嵌套 `.asm → SLDASM`、全部组件固定、无 Mates 的转换语义；
- V3.3 的逐层局部矩阵采集、世界/局部矩阵交叉验证、循环引用阻断和原子提交；
- Worker 的既有 `--request`、`--probe-assembly`、`--assembly` 调用方式与请求 JSON 可读性；
- OHS 模块槽、AppShell 3.0.3 消费边界、Solid Edge/SolidWorks COM 调用顺序。

不在 V3.3.1 中重写 COM 自动化、FeatureWorks、装配建造算法、ViewModel 生命周期模型或用户界面布局。
这些内容若需调整，必须作为后续功能版并以独立真机门禁验证。

## 2. 审查基线与问题归类

本设计以 V3.3 工作树为审查对象；该工作树在写本文时仍处于功能开发过程，故以下项目是**待冻结后的
改进目标**，不是对当前未完成代码的发布结论。

| 类别 | 当前症状 | 风险 |
| --- | --- | --- |
| 发布身份 | UI 项目、Contracts、Worker、`ModuleInfo`、z 清单各自写版本；审查时 UI/清单为 `3.3.0`，Contracts/Worker 仍有 `3.1.1` | 槽内 DLL、协议和清单可能不是同一版本，回退与排障失真 |
| 输出路径 | 零件扫描、装配规划、装配页预览分别拼接 `XT`、`SW`、扩展名和旧平铺路径 | 规则改动会漏改一端，出现扫描、预览、执行不一致 |
| Worker 协议 | UI 与 Worker 各自维护 JSON 选项、动词、取消参数和工作目录名称 | 任一方修改后可能协议仍能启动但运行时失败 |
| 进度语义 | 装配页通过中文 `WorkerEvent.Message` 是否包含 `XT` / `SLDPRT` 判断复用类型 | 文案改动会静默改变 UI 状态，机器语义被显示层绑死 |
| UI 呈现 | 两个 ViewModel 各自维护阶段文本、特征结果、错误格式化 | 细节已开始漂移，例如“跳过/复用”呈现不完全一致 |
| 文档真值 | 历史设计、实现记录和 README 都承载部分“当前规则” | AI 或维护者容易把历史输出规则误当现行合同 |

`PreflightValidator` 与 `WorkerRequestValidator` 的双重存在不列为重复缺陷。前者是用户操作前的友好反馈，
后者是跨进程请求的最后安全边界；V3.3.1 只共享无副作用的路径/扩展名规则，保留两次执行。

## 3. 目标架构

### 3.1 单一发布身份

新增唯一可编辑源 `build/SE2SW.Version.props`，只保存一个语义版本，例如 `3.3.1`。三个项目都导入它并使用
同一个 `Version`、`AssemblyVersion`、`FileVersion` 规则；不再各自写版本号。

`ModuleInfo.Version` 不再保存字符串副本，而是从主模块程序集版本格式化得到。发布脚本读取同一 props，生成
`z-SE2SW/module.manifest.json` 的版本字段并在生成后校验。清单是发布产物，不再是第二个人工版本源。

发布门禁必须同时读取以下值并要求完全相等：

```text
build/SE2SW.Version.props
SE2SW.dll / SE2SW.Contracts.dll / SE2SW.Worker.exe 的文件版本
ModuleInfo.Version
z-SE2SW/module.manifest.json.version
正式 Modules/SE2SW 槽中的 manifest 与运行产物
```

只有这一整组相等时才允许 `tool.sync name=SE2SW`。历史文档中的版本描述是历史记录，不参与上述机器真值判断。

### 3.2 共享的管道合同

在 `SE2SW.Contracts` 中增加只含不可变值对象与纯函数的共享合同；它不依赖 WPF、COM 或文件系统副作用：

- `WorkerProtocol`：三个 Worker 动词、`--cancel`、JSON 序列化选项、请求/探查文件名约定；
- `ConversionArtifactKind` / `ReuseKind`：XT、SW 零件、SW 装配以及“新生成/复用 XT/复用 SW”；
- `ConversionPathLayout`：从源目录解析 `XT`、`SW`、零件产物、装配产物和旧平铺候选；
- `ConversionPathRules`：合法扩展名、绝对路径与同名冲突所需的纯验证规则；
- `ModuleIdentity`：模块槽名、Worker 文件名与应用数据子目录名。

UI、Worker 和发布脚本只能消费这些定义；不得再手写 `"XT"`、`"SW"`、`.x_t`、`.SLDPRT`、`.SLDASM`、
`"SE2SW"`、Worker 动词或 JSON 选项。创建目录、写临时文件、检查 COM 环境仍由各自层负责。

### 3.3 结构化进度，不解析显示文本

`WorkerEvent` 在保持旧字段和 JSON 兼容的前提下，追加可空 `Artifact` 与 `ReuseKind`。Worker 在 `Skipped`、
导出、导入、装配生成时填写机器可读值；旧 Worker 或旧事件未填写时 UI 采用保守的“跳过”显示，而不解析中文
消息。

UI 项目新增无状态 `ConversionProgressPresenter`，统一承担：

1. `ConversionStage` → 行状态文本；
2. `WorkerEvent` → 行详情与特征结果；
3. 错误分类 → 用户可见消息；
4. `ReuseKind` → “复用 XT / 复用 SW”。

`SE2SWViewModel` 和 `AssemblyViewModel` 保留各自的扫描、探查、转换与取消生命周期，只调用同一个呈现器。
本版不将两者强行继承为同一个基类，避免改变异步调度与 Dispose 时序。

### 3.4 当前合同与历史文档分层

新增 `docs/00-当前转换合同.md` 作为唯一现行人工合同，覆盖模式、输入、输出、复用、覆盖、失败、协议、
版本和发布边界。README 只摘要并链接此文档。

`01` 至 `20` 号文档保留为需求来源、探针、版本设计和实测记录；每篇不再承担“当前实现唯一说明”的职责。
历史文档与当前合同矛盾时，以当前合同、测试和源码共同裁决。

## 4. 实施顺序

V3.3.1 必须在 V3.3 功能冻结后的干净基线中实施，顺序如下：

1. 为现有 V3.3 建立特征化测试：三模式、输出布局、旧平铺复用、Worker 三动词、嵌套图、矩阵验证和取消；
2. 引入版本 props 与只读版本解析，先让版本一致性测试失败，再收敛三个项目、模块信息和生成清单；
3. 引入共享路径/协议合同，以逐处替换方式移除重复常量；每替换一类即运行离线 Smoke；
4. 给事件追加结构化产物/复用语义，Worker 先写、UI 再读，最后删除文本推断；
5. 抽取共享进度呈现器，要求两个页面的既有测试截图、状态和取消用例不变；
6. 补写当前合同和发布脚本使用说明；
7. 完成 Release、格式、离线 Smoke、UI Smoke、真机 V3.3 回归和正式槽哈希核验后再发布 3.3.1。

任何一步出现 CAD 结果、输出路径、组件数、矩阵或旧协议回归，立即回到上一步，不继续做“顺带重构”。

## 5. 验收门禁

### 5.1 不依赖 CAD 的门禁

- 三个程序集、模块运行时版本、生成清单与正式槽版本一致；
- 输出布局对零件、顶层装配、子装配、旧平铺产物和目录名冲突的结果完全不变；
- Worker 三个动词的参数、JSON 命名和取消文件路径兼容 V3.3；
- 新旧 `WorkerEvent` 都能被 UI 读取；旧事件未带 `ReuseKind` 时不抛异常；
- 两个页面对同一阶段、特征结果、失败和取消给出同一文本；
- `SE2SW.Smoke`、`SE2SW.UiSmoke`、Release build 和 `dotnet format --verify-no-changes` 全部通过。

### 5.2 真机回归门禁

- 重跑 V3.3 三层装配基准：装配节点数、叶零件数、组件数、层级、固定状态和位置/姿态误差保持；
- 重跑 V2.3.1 双烧杯零件基准：XT 文本格式、SLDPRT、FeatureWorks 降级和首件生命周期保持；
- 源 `.asm/.par` 的 SHA-256 前后不变，自有 Worker、Solid Edge、SolidWorks 无遗留进程；
- 正式槽与 Release 输出逐文件 SHA-256 一致，失败可恢复到 3.3.0 槽备份。

## 6. 明确延期

以下项目价值较高，但会触及 V3.3 已验证的行为，不进入本次质量更新：

- 把两个 ViewModel 的完整生命周期、锁、队列和 Dispose 抽为继承层；
- 拆分 `FeatureRecognizer`、`SolidWorksInteropBridge` 等 COM 大类；
- 更改转换并发模型、超时阈值、COM 重试和进程回收策略；
- 实现 Mates、OHS 装配模式、钣金/工程图、材料/属性/配置迁移；
- 修改 AppShell、OHS 产品代码或 AppShell 3.0.3 公共接口。

这些事项应在未来功能版本先写独立设计与测试，不得借 V3.3.1 的“质量更新”名义混入。

## 7. 发布收口模板

实施完成后，本节应只记录事实：基线 3.3.0 备份路径、3.3.1 同步时间、版本一致性表、Release/Smoke/真机结果、
正式槽 SHA-256 和回退结论。设计阶段不得预填通过结论。
