# SE2SW V3.0.1 零件与装配双页入口修复

> 日期：2026-08-01  
> 版本：3.0.0 → 3.0.1  
> 状态：正式槽已部署；待 OHS 主界面下次打开后现场复核

## 问题

V3.0.0 把 `se2sw`、`se2sw-asm` 注册为两个同侧普通工具窗口。AppShell 3.0.3 会把同侧窗口合并进
现有右侧标签组，而后注册的装配窗口成为活动页。零件转换窗口并未从注册表消失，但用户进入模块时只看到装配内容，
效果等同于原零件页面被替换；与“进入 SE2SW 后明确选择零件或装配转换”的操作预期不一致。

## 修复决策

- AppShell 只注册一个普通工具窗口，稳定 ID 保留为 `se2sw`；
- 窗口内容改为 `SE2SWWorkspaceView`，顶部固定显示“零件转换 / 装配转换”两个页签；
- 默认选择“零件转换”，恢复原来的首屏与 OHS/外界模式操作；
- “装配转换”作为第二页，保留 V3.0 的装配探查、树、唯一零件、失败策略和转换功能；
- 移除独立 `se2sw-asm` 窗口注册，避免同一模块再次被 AppShell 外层标签切散；
- `se2sw.show/hide` 统一寻址 `win.show name=se2sw` / `win.hide name=se2sw`；
- 双页壳实现 `IDisposable`，热卸载时同时释放零件与装配 ViewModel 生命周期；
- 窗口仍是 AppShell 普通工具窗口，拖动、浮动、停靠、最大化、隐藏和热重载能力不变。

V3.0 文档中的双独立窗口设计作为历史基线保留；本文件覆盖其 UI 入口决策，不改变装配转换合同和文件协议。

## 同步修复

独立 UI Smoke 首次实际启动时发现装配页的 `IsExternalMode` 是只读属性，但 `RadioButton.IsChecked` 使用了
默认 TwoWay 绑定，WPF 会抛出 `InvalidOperationException`。V3.0.1 将其显式改为 `Mode=OneWay`，防止装配页
首次渲染时产生运行期异常。
