# SE2SW V3.0 装配体转换与输出目录分层

> 日期：2026-07-31
> 版本：2.3.1 → 3.0.0
> 范围：外界模式输出分层、装配体转换（第 0 档：结构 + 位置 + 固定）、独立装配转换工作窗口
> 明确不做：装配配合（Mates）、子装配层级、钣金 `.psm`、工程图 `.dft`、装配模式的 OHS 兼容模式

## 1. 目标与非目标

### 1.1 本版交付

1. **外界模式输出分层**。转换产物不再散落在源文件夹，按格式分入 `XT` 与 `SW` 两个子目录。
2. **装配体转换（第 0 档）**。输入单个 Solid Edge `.asm`，输出一个 SolidWorks `.SLDASM`，其中每个组件的空间位置与源装配**精确一致**，全部组件设为固定（Fixed），不含任何配合。
3. **独立装配转换窗口**。与现有零件窗口并列的第二个 AppShell 工具窗口，输入是单个文件而非文件夹。

### 1.2 本版明确不做

| 不做项 | 原因 | 计划 |
|---|---|---|
| 装配配合翻译 | 依赖"实体重识别 + 校验回滚"引擎，工作量远大于本版 | V3.1 起，可选开关 |
| 子装配层级保留 | 递归生成 `.SLDASM` 会引入嵌套命名与覆盖策略 | V3.1，协议已预留 |
| 装配模式 OHS 兼容 | 需要先确定装配体在 OHS 目录规范中的落位 | V3.1，界面先占位并禁用 |
| 阵列还原、镜像件、柔性子装配、可调件 | 无 1:1 映射，需逐类研究 | 展平处理，记入报告 |
| 装配特征、材料、属性、配置 | 与几何管线正交 | 独立版本 |
| 钣金 `.psm`、工程图 `.dft` | 本轮只做建模 | 不在路线内 |

### 1.3 第 0 档的价值边界

不含配合的装配体**不能**继续做运动学编辑。但它可用于出图、BOM、干涉检查、渲染、下游工装设计——即绝大多数迁移场景。全部组件固定意味着这是一个"诚实的哑装配"：用户一眼就知道需要自己加配合，不会误以为拿到了可编辑的设计意图。

这条原则与 V2.0 的 `DegradedToDumbSolid` 一致：**宁可交付明确的降级产物，不交付看起来正确的错误产物。**

## 2. 外界模式输出目录分层

### 2.1 现状

`SE2SWViewModel.Scan` 在外界模式下把三个目录全部指向所选目录：

```
SourceDirectory = XtDirectory = SolidWorksDirectory = <所选文件夹>
```

结果是 `.par`、`.x_t`、`.SLDPRT` 三种文件混在一起。

### 2.2 V3.0 布局

```
<所选文件夹>\
  零件A.par
  零件B.par
  XT\
    零件A.x_t
    零件B.x_t
  SW\
    零件A.SLDPRT
    零件B.SLDPRT
```

装配模式下 `.SLDASM` 与零件同级放在 `SW\`，使 SolidWorks 按同目录规则解析组件引用最稳。

### 2.3 目录名与冲突规则

| 情况 | 处理 |
|---|---|
| `XT` / `SW` 不存在 | 转换时创建 |
| 已存在且是目录 | 直接复用，**不移动、不清空** |
| 已存在且是同名文件 | 前置检查失败，报 `OutputNotWritable` 并给出路径 |

外界模式**永不移动用户目录**。OHS 模式的 `Unused` 目录移动逻辑（`OhsProjectResolver.PrepareOutputDirectories`）不受本次改动影响。

### 2.4 创建时机

`PreflightValidator.ValidateOutput` 要求输出路径的父目录已存在。因此顺序固定为：

```
用户点击转换
  → ValidateEnvironment
  → EnsureExternalOutputDirectories（新增，仅外界模式）
  → ValidateJobs
  → 启动 Worker
```

**扫描阶段不创建任何目录**，避免用户只是浏览就在其文件夹里留下空目录。

### 2.5 旧产物兼容

改动后，历史上产生在源目录平铺位置的 `.x_t` / `.SLDPRT` 不再位于新的输出路径上，若不处理会被判为"未转换"而重复生成。

`FileScanner.Scan` 的 `HasExistingOutput` 判定改为：

```
新位置存在  OR  旧平铺位置存在
```

任一命中即视为已存在、默认不勾选、状态显示"已存在"。这样旧数据不会被重复转换，也不会被删除或移动。

### 2.6 OHS 模式不变

OHS 模式继续使用 `b-Module-GE` / `b-Module-SW`，映射规则、`Unused` 移动、回滚逻辑全部保持 V2.3.1 行为。本节仅改外界模式。

## 3. 装配体转换设计

### 3.1 两阶段架构

装配树只能由 Solid Edge COM 读出，UI 进程无法预先知道装配体包含哪些零件。但既有设计原则要求"**所有输出路径在触碰 CAD 之前完成前置校验**"。两者冲突，解法是把装配转换拆成两次 Worker 调用：

```
阶段 A  装配探查 (Probe)
  UI → Worker(--probe-assembly)
  Worker 打开 .asm，递归遍历 Occurrence 树，写出清单 JSON，关闭 SE
  UI 读清单 → 展示装配树 + 唯一零件列表 → 计算全部输出路径 → 前置校验

阶段 B  装配转换 (Build)
  UI → Worker(--assembly)
  Worker 阶段 1：逐个零件走既有 SaveBody → .x_t 管线
  Worker 阶段 2：逐个零件走既有 LoadFile4 → .SLDPRT 管线
  Worker 阶段 3：新建 SW 装配体，按世界变换插入组件、全部固定、保存
```

代价是 Solid Edge 多启动一次。收益是保留了前置校验，并且用户在真正转换前能看到装配体里到底有什么、缺了什么。

### 3.2 Worker CLI 扩展

既有 CLI 校验严格要求 4 个参数（`Program.ReadPaths`）。V3.0 **不修改** `--request` 的语义与 JSON 结构，只新增两个动词，零件管线保持完全无回归：

| 动词 | 用途 | 版本 |
|---|---|---|
| `--request <json> --cancel <signal>` | 零件批次转换 | V1.0 起，不变 |
| `--probe-assembly <json> --cancel <signal>` | 装配探查 | V3.0 新增 |
| `--assembly <json> --cancel <signal>` | 装配转换 | V3.0 新增 |

`ReadPaths` 改为按 `args[0]` 分派，三种动词共用"绝对路径 + 请求文件必须存在"的校验。

### 3.3 遍历与展平

**展平（flatten）**：所有叶零件作为一级组件插入顶层 SW 装配体。真机探针已经证明
`SubOccurrence.GetMatrix` 直接返回顶层装配坐标系下的世界矩阵，生产代码必须直接使用，**禁止再与父矩阵累乘**；
否则会把父变换施加两次。

选择展平而非保留层级的理由：

- 保留层级需要为每个子装配生成 `.SLDASM`，引入嵌套输出命名、嵌套覆盖策略、子装配自身原点定义三个新决策点；
- 第 0 档的验收目标是"位置精确、可出图可查干涉"，展平完全满足；
- 展平的信息损失是**装配树层级与 BOM 层级**，可在 V3.1 补齐，且不需要改协议。

`AssemblyOccurrence.ParentId` 字段在 V3.0 就要采集并写入清单（UI 用它画树），只是转换阶段不使用。V3.1 启用层级时无需变更契约。

### 3.4 实例去重

同一个 `.par` 被引用 N 次时：

- **零件转换只做一次**，按规范化绝对路径去重；
- **组件插入 N 次**，每次用各自的世界变换。

去重键为 `Path.GetFullPath(...)` 后的 `OrdinalIgnoreCase` 比较，与 `PreflightValidator` 现有输出去重口径一致。

### 3.5 同名不同路径零件

展平后 `A\壳体.par` 与 `B\壳体.par` 都会映射到 `SW\壳体.SLDPRT`，构成真实冲突。

**V3.0 策略：明确失败，不自动改名。** 探查阶段即检出，列出全部冲突源路径，报 `DuplicateOutputName`，不启动转换。

不做自动加后缀（`壳体_2.SLDPRT`）的原因：迁移场景里用户高度依赖文件名与 SE 原件对应，静默改名会造成难以发现的错配。自动消歧列为 V3.1 的显式开关。

### 3.6 Occurrence 状态处理

| 状态 | V3.0 处理 |
|---|---|
| Suppressed（抑制） | 合同和下游管线支持跳过；SE 2020 occurrence COM 无可持久化 Suppress 属性，活动配置未枚举项自然不进入清单 |
| Hidden（隐藏） | 正常插入，不修改可见性，记入报告 |
| 阵列成员 | 当作独立 occurrence 展平插入，不还原为 SW 阵列 |
| 可调件 / 柔性子装配 | 按其当前状态的几何插入，记入报告并标警告 |
| 引用文件缺失 | 探查阶段即报 `OccurrenceUnresolved`，列出路径 |
| 非 `.par` / `.asm` 引用 | 跳过并记入报告 |

### 3.7 SolidWorks 端装配生成

```
1. 取装配体模板路径
   SldWorks.GetUserPreferenceStringValue(swDefaultTemplateAssembly)
   取不到 → AssemblyTemplateMissing，不硬编码任何安装路径
2. NewDocument(模板, 0, 0, 0) → AssemblyDoc
3. 对每个 occurrence：
   AddComponent5(sldprtPath, ...) → Component2
   MathUtility.CreateTransform(double[16]) → MathTransform
   Component2.Transform2 = transform
4. 全选组件 → FixComponent()
5. ModelDocExtension.SaveAs3(临时路径) → TemporaryOutput.Commit(最终路径)
```

复用既有基础设施：`SolidWorksInteropBridge`（官方 Interop 强类型调用）、`CadProcessOwnership`（进程所有权保护）、`TemporaryOutput`（临时文件 + 原子提交）、`FileProbe`（输出稳定性校验）、`OleMessageFilter` / `StaMessagePump`。

### 3.8 单位与矩阵约定

| 项 | 约定 | 状态 |
|---|---|---|
| 长度 | 米（SE COM 与 SW API 均为米） | 已由受控平移 fixture 确认 |
| 角度 | 变换矩阵直接表达旋转，不单独传角度 | 已由绕 X/Z 轴 fixture 确认 |
| 清单中的变换 | 16 元素 `double[]`，行主序 4×4 | 本文档定义 |
| SW `MathTransform` 数组 | `[0..8]` 旋转 3×3、`[9..11]` 平移、`[12]` 缩放、`[13..15]` 置 0 | 已确认，旋转不转置 |

`MathTransform` 的数组布局是本设计里最容易静默出错的一处：布局错了不会抛异常，只会把零件放到错误位置或错误姿态。
L0、L1、L2 受控 fixture 已用独立重开校验确认上述映射。

### 3.9 零件阶段失败时的行为

新增开关 `ContinueWhenPartFails`（默认 `false`），风格与既有 `ContinueWhenRecognitionFails` 一致。

- `false`：任一零件失败即中止，不生成 `.SLDASM`。缺件装配是误导性产物。
- `true`：跳过失败零件继续组装，在完成事件中明确报出缺件数量与清单。

### 3.10 特征识别在装配模式下的默认值

装配体动辄数十上百个零件，按现有 120 秒单件超时，全量 FeatureWorks 识别会让一次转换变成数小时。

**装配模式下 `RecognizeFeatures` 默认关闭**，界面上作为可选项并标注耗时提示。零件模式默认值不变（保持开启）。

## 4. 契约变更

### 4.1 枚举追加规则

`ConversionStage` 与 `ConversionErrorClass` 按数值序列化（README 已记录 `mode` 的数值枚举约定）。**所有新值必须追加在枚举末尾**，插入中间会导致 UI 与 Worker 的数值错位，且这类错位不会抛异常，只会显示错误的阶段名。

新增阶段：

```
AssemblyProbe      装配探查
AssemblyBuild      装配组装
```

新增错误类：

```
AssemblyOpenFailed        .asm 打开失败
OccurrenceUnresolved      occurrence 引用的文件缺失或不可读
DuplicateOutputName       展平后输出文件名冲突
AssemblyTemplateMissing   取不到 SW 装配体模板
ComponentInsertFailed     AddComponent5 失败
ComponentTransformFailed  Transform2 赋值失败或校验超差
AssemblySaveFailed        .SLDASM 保存失败
PartStageFailed           零件阶段失败且不允许继续
```

### 4.2 新增记录类型

```csharp
/// 装配树中的一个实例。V3.0 转换时展平，ParentId 仅用于 UI 画树与 V3.1。
public sealed record AssemblyOccurrence(
    string OccurrenceId,
    string? ParentId,
    string SourcePath,
    bool IsSubAssembly,
    bool IsSuppressed,
    bool IsHidden,
    double[] WorldTransform,   // 16 元素，行主序 4x4，米
    string? Diagnostic);

/// 阶段 A 输入。
public sealed record AssemblyProbeRequest(
    string BatchId,
    string SourceAssemblyPath,
    string ResultPath);

/// 阶段 A 输出。
public sealed record AssemblyProbeResult(
    string SourceAssemblyPath,
    IReadOnlyList<AssemblyOccurrence> Occurrences,
    IReadOnlyList<string> UniquePartPaths,
    int SuppressedCount,
    int UnresolvedCount,
    int OrderedPartCount,        // 有序建模零件数
    int SynchronousPartCount,    // 同步建模零件数
    IReadOnlyList<string> Warnings);

/// 阶段 B 输入。复用 ConversionJob 承载零件，装配层信息单列。
public sealed record AssemblyBatchRequest(
    string BatchId,
    ConversionMode Mode,
    string SourceAssemblyPath,
    string AssemblyOutputPath,
    IReadOnlyList<ConversionJob> PartJobs,
    IReadOnlyList<AssemblyOccurrence> Occurrences,
    bool Overwrite = false,
    bool RecognizeFeatures = false,
    bool FullyDefineSketches = false,
    bool ContinueWhenPartFails = false,
    int FeatureRecognitionTimeoutSeconds = 120);

/// 随 Completed 事件回传的装配结果。
public sealed record AssemblyOutcome(
    int ComponentTotal,
    int ComponentInserted,
    int ComponentFixed,
    int PartConverted,
    int PartFailed,
    int SkippedSuppressed,
    double MaxOriginDeviationMeters,
    long ElapsedMilliseconds,
    string? Diagnostic);
```

`WorkerEvent` 增加可空字段 `Assembly`，与既有 `Feature` 字段并列。可空追加不影响零件路径的反序列化。

### 4.3 探查顺带采集的调研数据

`AssemblyProbeResult` 里的 `OrderedPartCount` / `SynchronousPartCount` 不参与 V3.0 的转换逻辑，是为后续"特征指令翻译"可行性评估采集的样本数据。同步建模零件没有有序特征树，指令翻译对它们不成立；这两个计数直接决定后续路线是否值得投入。**一次探查，两个用途。**

## 5. 界面设计

### 5.1 独立工具窗口

`SE2SWUiModule.CreateUi` 注册**第二个**工具窗口，现有 `se2sw` 窗口零改动：

| 窗口 Id | 标题 | 输入 |
|---|---|---|
| `se2sw` | SE2SW 格式转换 | 文件夹（批量 `.par`） |
| `se2sw-asm` | SE2SW 装配转换 | 单个 `.asm` 文件 |

不做单窗口内的 Tab 切换。零件模式已有 OHS / 外界两个模式开关，再叠装配模式会形成三维组合，输入语义（文件夹 vs 单文件）也完全不同。两个窗口可独立开关、独立热重载，回归面最小。

### 5.2 装配窗口布局

- 探查结果的警告（缺失引用、抑制件、同步件比例）在装配树上方以摘要行呈现。

### 5.3 状态与生命周期

复用 `SE2SWViewModel` 已验证的并发模型：`_lifecycleGate` / `_dispatchGate` 双锁、`QueueUiUpdate` 批量投递、`Dispose` 时取消并等待。装配 ViewModel 单独实现，但结构对齐，不共享可变状态。

## 6. 验收判据

### 6.1 硬性判据（可自动校验）

1. **位置精度**：SW 中每个组件原点在装配坐标系下的位置，与 SE 中对应 occurrence 原点位置的偏差 **< 1e-6 m**。这是第 0 档的核心指标，由 `AssemblyOutcome.MaxOriginDeviationMeters` 回报。
2. **姿态精度**：组件旋转矩阵与源矩阵逐元素偏差 < 1e-9。
3. **数量一致**：插入组件数 == 非抑制 occurrence 数。
4. **全部固定**：`ComponentFixed == ComponentInserted`。
5. **无缺件**：`.SLDASM` 打开后无未解析引用。

### 6.2 测试样本梯度

| 级别 | 规模 | 目的 |
|---|---|---|
| L0 | 1 零件 | 验证 `MathTransform` 数组布局与单位 |
| L1 | 3~5 零件，单层，含重复实例 | 验证去重与多实例插入 |
| L2 | 20~50 零件，两层子装配 | 验证递归遍历与变换累乘 |
| L3 | 含抑制件、隐藏件、缺失引用 | 验证降级路径与报告 |
| L4 | 含同名不同路径零件 | 验证冲突检出并正确中止 |

### 6.3 离线 Smoke 覆盖

不启动 CAD 即可覆盖的部分，全部进 `SE2SW.Smoke`：

- 外界模式 `XT` / `SW` 目录路径计算与冲突判定
- 旧平铺产物的 `HasExistingOutput` 兼容判定
- occurrence 树展平与世界变换累乘（纯矩阵运算，构造两级嵌套手工验算）
- 唯一零件去重
- 同名不同路径冲突检出
- 探查清单 JSON 的往返序列化

`MathTransform` 布局、SE COM 成员名、模板路径获取必须真机验证，不进离线测试。

## 7. 实施前必须探针确认的 API

沿用 `tools/SolidEdgeExportProbe`、`tools/SolidWorksRecognizeProbe` 的模式，新增 `tools/AssemblyProbe`。
下表已在 2026-08-01 真机确认；详细数据见 `12-V3.0-真实CAD验收.md`。

| 侧 | 待确认项 | 风险 |
|---|---|---|
| SE | `AssemblyDocument.Occurrences` 集合成员名与枚举方式 | 高 |
| SE | occurrence 变换的取法（`GetTransform` 的输出语义 / 是否有矩阵形式） | **最高** |
| SE | occurrence 引用文件路径属性（是否为绝对路径） | 中 |
| SE | 子装配递归入口（子 occurrence 集合的取法） | 高 |
| SE | 抑制 / 隐藏 / 阵列成员 / 可调件的判定属性 | 中 |
| SE | 零件是有序建模还是同步建模的判定方式 | 中 |
| SE | 长度单位是否为米、角度是否为弧度 | 高 |
| SW | 装配体模板路径的用户偏好枚举值 | 中 |
| SW | `AddComponent5` 的参数语义与返回 | 中 |
| SW | **`MathTransform` 16 元素数组布局** | **最高** |
| SW | `FixComponent` 的选择前置条件 | 中 |
| SW | 装配文档的 `SaveAs3` 行为与既有零件路径是否一致 | 低 |

额外结论：Solid Edge 2020 的 `Occurrence/SubOccurrence` 类型库没有组件 `Suppress` 属性。
`Activate` 是会话加载状态，写为 `false` 后保存、重开会恢复，不能把它当成抑制状态。生产代码因此不做该误判；
隐藏状态使用持久化的 `Visible` 读取，真实 fixture 已验证。

两个"最高"风险项共同决定组件放置是否正确，且**错误时不抛异常**，只表现为零件位置错乱。L0 单件样本就是专门为验这两项设计的。

## 8. 风险边界

- 装配转换阶段 B 会连续占用 Solid Edge 与 SolidWorks；`CadProcessOwnership` 的现有保护规则不变——SolidWorks 是单实例，附着到用户已开会话时绝不 `ExitApp`、绝不改可见性。
- 外界模式永不移动、永不删除用户目录。`XT` / `SW` 只创建与写入。
- 旧平铺产物不迁移、不删除，只在扫描时被识别为"已存在"。
- 装配探查只读打开 `.asm`，不保存、不修改源文件。零件导出沿用既有的源文件 SHA-256 前后比对。
- 装配输出走 `TemporaryOutput` 临时文件 + 原子提交，中途失败不留半成品 `.SLDASM`。
- 展平会丢失装配树层级；这是设计选择，必须在界面上明说，不能让用户以为是缺陷。
- 全部组件固定；用户后续手工加配合前需自行解除固定。转换完成提示中说明。
- OHS 零件模式的目录映射、`Unused` 移动、V2.3.0 首件 FeatureWorks 修复、V2.3.1 模式识别逻辑一律不动。

## 9. 实施顺序

按依赖与风险排列，每步可独立验收：

1. **探针**（`tools/AssemblyProbe`）——打通第 7 节全表，产出 L0 样本的实测报告。
2. **输出目录分层**——独立于装配，可先单独发 2.4.0 验证，也可并入 3.0.0。含离线 Smoke 与旧产物兼容判定。
3. **契约扩展**——枚举末尾追加、新增记录类型、`WorkerEvent.Assembly` 可空字段。
4. **Worker CLI 分派 + 装配探查**（阶段 A）——只读，不产出文件，风险最低。
5. **装配 ViewModel 与工具窗口**——用阶段 A 的真实清单驱动界面，此时尚未接组装。
6. **装配组装**（阶段 B 阶段 3）——按 L0 → L4 梯度推进。
7. **版本收口**——`z-SE2SW/module.manifest.json` 升 3.0.0、README 更新范围声明、正式槽哈希核验与回退包。

第 1 步的结论可能推翻第 6 步的设计（例如变换语义与预期不符）。**探针不通过不进入第 3 步。**
