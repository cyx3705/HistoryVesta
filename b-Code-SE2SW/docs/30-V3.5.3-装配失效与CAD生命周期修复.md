# SE2SW V3.5.3 装配失效与 CAD 生命周期修复

> 日期：2026-08-03  
> 基线：V3.5.2  
> 范围：Worker CAD 生命周期、FeatureWorks 单零件隔离、装配组合回归  
> 不涉及：UI、装配矩阵、配合几何匹配和 AppShell/OHS 产品代码

## 1. 用户现象与根因

现象是开启特征识别后，后续装配大规模失效，并影响其他 SolidWorks 模块。V3.5.2 只验证了
“多零件识别”和“装配构建”各自成立，没有覆盖“逐零件识别后立即继续构建装配”的组合。

无界面组合门禁复现了两层问题：

1. `Activator.CreateInstance` 已返回 COM 对象，但 `SLDWORKS.exe` 尚未稳定出现在进程表。
   `CadProcessOwnership.Resolve` 只读取一次快照，误把本批新建的隐藏 SolidWorks 当成用户会话，
   因而不执行 `ExitApp`。后续子 Worker和装配构建继续接触遗留会话。
2. V3.5.2 对所有单零件子 Worker都执行 `UnloadAddIn/LoadAddIn`。该动作只在附着既有会话时
   有意义；全新会话在打开首个文档前重载 FeatureWorks 会扩大冷启动失败面。

在污染状态下，`LoadFile4` 对 12 个 XT 全部返回通用错误码 `1`，父 Worker最终得到 0 个 SLDPRT，
并正确以 `PartStageFailed` 拒绝生成空装配。问题不是“第三个零件”的几何；同一组已经识别的
12 个 SLDPRT 在隔离目录中仍能生成 3 个嵌套装配、插入 24/24 个直接组件，并重建 53/56 条
可应用关系，最大漂移 `2.43e-9 m`。

## 2. V3.5.3 修复

### 2.1 所有权稳定判定

`CadProcessOwnership.Resolve` 在启动前没有同名 CAD 进程时进行最多 10 秒的有界等待。
所有权只接受两类证据：

- 窗口句柄映射到启动后新增 PID；
- 启动前后差集中只有一个新增 PID。

多个新增 PID且没有句柄证据时仍保持未知。只有窗口句柄明确映射到启动前 PID时才立即按用户会话处理；
没有句柄证据时继续等待有界窗口，因为无界面 SolidWorks 实测会在已有隐藏实例时再次创建新进程。

### 2.2 FeatureWorks 会话分流

- 附着启动前已有 SolidWorks：保留 V3.5.2 的逐件 `UnloadAddIn/LoadAddIn`。
- 本批新建 SolidWorks：不在首个文档前重载，直接由 `FeatureRecognizer.Prepare` 按需加载。
- 未开启识别：不改变既有批量导入路径。

### 2.3 自有进程故障回收

所有 SE/SW Worker路径在 `ExitApp` 后等待正常退出。超时后只能终止 `OwnedProcessId` 指向的
那一个进程树；禁止按进程名、模糊窗口或当前活动进程清理。启动前已有的用户 CAD 永远不进入
该分支。SolidWorks 导入路径会把强制回收事实写入 Worker 事件。

这道边界的目标不是把失败伪装成成功，而是保证失败批次不会把损坏会话交给装配构建或其他模块。

## 3. 自动化与真机结果

离线 `SE2SW.Smoke` 新增所有权纯函数覆盖：无新增、唯一新增、已有用户 PID、多个新增歧义和
窗口句柄消歧；同时覆盖全新/既有 FeatureWorks 会话分流。Release build 为 0 警告、0 错误，
Smoke 通过。

真机组合对照：

| 档位 | 结果 |
|---|---|
| 已识别 SLDPRT + 装配/配合 | 3 个 SLDASM，24/24 插入，53/56 关系，漂移 2.43e-9 m |
| V3.5.2 从 XT 逐件识别 + 装配 | 12/12 `LoadFile4 errors=1`，曾遗留隐藏 SLDWORKS |
| V3.5.3 污染环境失败收容 | 明确失败，不生成装配，结束后无 SLDWORKS/Worker 遗留 |

不进入 OHS `b-Office/evidence`，也不随模块发布。

## 4. 当前门禁状态

本机 SolidWorks 2025 SP5 当前已进入进程外的导入服务故障状态：同一已知良好的 XT（哈希与下午成功
门禁一致）在全新进程中使用 `LoadFile4` 仍返回 `1`，`OpenDoc6` 对照触发
`0x80010105 RPC_E_SERVERFAULT`。这不是 V3.5.3 可以安全重启的用户态会话；不得擅自终止
系统级 `sw_d` 或重启工作站。

因此 V3.5.3 已完成代码、离线门禁和故障收容门禁，但“健康环境下 12 件识别后继续构建装配”
仍须在 SolidWorks/相关厂商服务恢复后重跑。正常发布策略是该门禁通过前不部署；2026-08-04
由项目所有者明确要求部署，按例外发布处理，风险和回退点记录在下节。

## 5. 发布判据

恢复健康环境后必须一次性满足：

1. 12 个唯一零件全部生成非空 SLDPRT，事件中不得有串件、几何改变或未收容会话故障；
2. 3 个嵌套 SLDASM 全部生成，叶组件与源清单一致；
3. 配合结果至少保持金标准 53/56，可应用关系最大漂移小于 `1e-6 m`；
4. 源 `.asm/.par` 哈希不变；
5. Worker、Edge、SLDWORKS 进程集合回到测试前基线；
6. Release、Smoke、格式检查和发布哈希全部通过。

正常发布时任一项失败都不部署 3.5.3，也不覆盖 3.5.2 正式槽。本次第 1 项受厂商导入服务故障阻塞，
按项目所有者明确指令执行例外部署；3.5.2 备份保留为强制回退点。
