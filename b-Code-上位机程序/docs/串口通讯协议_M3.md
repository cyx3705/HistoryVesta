# 咖啡冷萃机串口通讯协议 M3

## 基本约定

- 物理链路：USB CDC / UART 串口。
- 波特率：115200。
- 编码：UTF-8。
- 帧格式：一行一个 JSON 对象，以 `\n` 结束。
- 协议版本：`proto=1`。
- GPIO：GPIO15 为上液泵，GPIO16 为降液泵，高电平有效。
- 安全约束：设备执行方向切换时必须先关闭 GPIO15/GPIO16，再开启目标输出。

## 上位机到设备

### 握手

```json
{"id":1,"cmd":"hello","app":"cold-brew-host","proto":1}
```

### 心跳

```json
{"id":2,"cmd":"ping"}
```

### 请求状态快照

```json
{"id":3,"cmd":"state"}
```

### 设置输出

```json
{"id":4,"cmd":"set","mode":"up"}
{"id":5,"cmd":"set","mode":"down"}
{"id":6,"cmd":"set","mode":"stop"}
```

`mode=up` 只允许 GPIO15 激活，`mode=down` 只允许 GPIO16 激活，`mode=stop` 必须关闭两路。

## 设备到上位机

### 握手响应

```json
{"type":"hello","id":1,"device":"coffee-cold-brew-esp32","proto":1}
```

### 心跳响应

```json
{"type":"pong","id":2}
```

### 命令确认

```json
{"type":"ack","id":4,"cmd":"set","ok":true}
```

`ack` 只表示设备已接收并处理命令，不等同于上位机 UI 状态已生效。UI 以 `state` 快照作为实际状态来源。

### 状态快照

```json
{"type":"state","seq":10,"mode":"up","gpio15":true,"gpio16":false,"uptime":123456}
```

字段：
- `seq`：设备递增快照序号。
- `mode`：`idle` / `up` / `down` / `fault`。
- `gpio15`：GPIO15 实际输出状态。
- `gpio16`：GPIO16 实际输出状态。
- `uptime`：设备启动后的毫秒数。
- `error`：可选故障码。

### 错误

```json
{"type":"error","id":4,"code":"bad_mode","message":"mode must be up, down, stop, or idle"}
```

## M3 验收点

- 未连接、连接中、在线、超时、断开和通讯异常需要在 UI 中区分。
- 指令发送成功但未收到 `state` 前，不得把 UI 显示成动作已生效。
- 设备重启后，上位机以新的 `hello` 和 `state` 快照覆盖旧状态。
- 收到 GPIO15/GPIO16 同时有效时，上位机立即进入故障显示。
- 串口噪声、半包和非法 JSON 只记日志，不应导致 UI 崩溃。
